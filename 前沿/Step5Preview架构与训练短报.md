# Step 5 Preview 架构与训练（前沿短报）

> **主要来源**：[Inside Step 5 Preview: Architecture and Training for Agentic Work](https://platform.stepfun.ai/blog/inside-step-5-preview)；[Step-5-Preview](https://huggingface.co/stepfun-ai/Step-5-Preview)（截至 2026-10-15）。下文「博文」指阶跃星辰（StepFun）的技术博文，「HF 页」指 Hugging Face 模型页。
> **研究线**：架构思想（窄深结构、门控滑动窗口注意力与稀疏 GQA）· 训练稳定性（深层网络的数值精度与梯度处理）· 智能体强化学习（训推逐位对齐、轨迹重放、上下文压缩与信用分配）

> - ≠ [[低精度训练FP8与FP4]]：本篇不写 FP8 训练的一般配方，只写深层结构下暴露的精度问题。
> - ≠ [[RL训练系统与异步Rollout]]：本篇不写异步 RL 系统的一般架构，只写博文公开的对齐与重放做法。

> **意义**：博文把智能体负载对模型的要求落到三处：预填充阶段的隐式多跳推理要求足够深的网络，百万 token 上下文要求全注意力层稀疏化，长轨迹 RL 要求训练侧与推理侧在数值上严格一致。三处各给出了可复用的工程做法。

**一句话**：阶跃星辰于 2026-10-15 发布 Step 5 Preview 的架构与训练博文；HF 页给出 600B 总参、27B 激活、最长 1M token 上下文的稀疏 MoE 规格。博文的方法论集中在 92 层的窄深结构、3:1 交替的门控滑动窗口注意力与稀疏全注意力、FP8 训练下的深层稳定性处理，以及面向长轨迹的 RL 系统。

## 一、问题背景

智能体任务的轨迹长、工具调用多，每次调用都带来大段需要预填充（prefill）的上下文。博文的判断是：这种场景下模型没有多少机会做充分的显式思维链推理，尤其要考虑 token 效率，因此更依赖预填充阶段的隐式推理。长上下文同时让注意力计算越来越贵，长轨迹又给数据构建与强化学习带来新问题。

## 三、窄深结构

博文的论证分三步：多跳推理需要深度；智能体场景中这种推理多发生在预填充阶段；而 Transformer 预填充时的信息流沿时间轴与深度轴都是单向的，追踪多跳依赖链的语义表示只能在后续 token 上逐层向深处移动，网络不够深就会「用完层数」，隐式多跳推理便无法完成。

对「深度诅咒」，社区有循环或递归 Transformer 等研究方向，Step 5 Preview 选了最简单的做法：直接加深。它有 92 个 Transformer 块，博文称与 Qwen3.8-Max、Kimi K3 同样深，而总参与激活参数分别不到二者的四分之一和三分之一；博文称窄深结构以低得多的成本获得了与万亿级模型相当的长程智能体能力。这一比较是厂商自述。代价是训练不稳定，见第五节。

## 四、注意力：门控滑动窗口与 Sparse GQA

**3:1 交替。** 每三层高效注意力配一层（稀疏的）全注意力。高效注意力一侧选门控滑动窗口注意力（Gated SWA，Sliding Window Attention）：博文称比较过多种线性注意力替代方案与配置，其余方案即便更好，差距也很小，而门控 SWA 实现起来简单得多，尤其便于投机解码。门控与注意力汇的关系见 [[门控注意力与注意力汇]]。

**Sparse GQA。** 全注意力层基于门控的分组查询注意力（GQA，Grouped-Query Attention）。为支持最长 1M 上下文的训练与推理，博文在标准 GQA 中加入受 DSA 启发的稀疏索引：索引器为每个查询挑出最相关的历史位置，主路径只读这些位置的原始 K/V。博文指出，与 MQA、MLA 相比，GQA 会放大稀疏注意力的三个瓶颈：索引器开销、选中内容上的 GPU 利用率、选择粒度与读取量的权衡。选 GQA 的理由是长上下文准确率（博文称经实验验证）与多 GPU 并行下的高速推理。三种 KV 头共享方式的谱系见 [[注意力效率族MQA到MLA]]。

三项对应改动：

- **压缩索引器**：把相邻若干历史位置的索引键压成一个块表示（分块合并），而不是让多个 GQA 组共用一个索引器；博文称后者有损 GQA 的并行适配性且对模型质量影响较明显。块大小取 8，博文称索引与 top-k 选择的开销因此降为八分之一。
- **合并相邻 token 的计算**：相邻 token 语义相近，各自 top-k 选中的 K/V 高度重叠，实现上取并集后成组计算，以提高预填充时的 GPU 利用率。
- **块大小与 top-k 的权衡**：块越大索引越省，再用更大的 k 弥补选择变粗；博文称最终配置的 token 覆盖率接近逐 token 选择的参照配置。

与 NSA 等可训练稀疏注意力的对照见 [[原生稀疏注意力NSA]]。

## 五、深层训练的稳定性

Step 5 Preview 用 FP8 混合精度训练。博文称在放大窄深结构时观察到数值爆炸与梯度尖峰，而更小、更浅或更宽的网络很少出现。三项处理：

1. **FP32 隐状态**：大模型里普遍存在的少数巨大激活，在网络加深后若用 BF16 存储会迅速失控；改用 FP32 存隐状态及其梯度后稳定，博文称峰值降低近一个数量级、额外开销很小，原因仍不清楚。
2. **FP32 的 RMSNorm 缩放参数**：零中心 RMSNorm 的输出是 $y_i = x_i/\mathrm{RMS}(x)\cdot(1+\gamma_i)$。巨大激活所在维度的缩放通常很小，即 $\gamma_i$ 接近 −1，而 BF16 在 −1 附近精度不足；训练中 $\gamma_i$ 偶尔恰好等于 −1，整个通道被屏蔽，几步后又被权重衰减等扰动推开，如此反复导致输出振荡。改用 FP32 存 $\gamma_i$ 后行为平滑。
3. **细粒度梯度截断**：梯度尖峰在训练中期越来越频繁，博文称它们通常不来自数据噪声或输出头，而是出现在中间层并在几层内被放大几个数量级，数据重复似乎也有影响；博文推测原因是层冗余在反向传播中反复放大某一梯度信号。异常梯度很稀疏，因此只截断整条梯度流中最大的少数梯度向量，博文称每层截断极小比例的梯度值即可很好地压住尖峰。

低精度训练的一般问题见 [[低精度训练FP8与FP4]]，优化器侧的稳定性手段见 [[优化器与训练稳定性]]。同样处理梯度尖峰的另一种做法是按激活梯度截断，见 [[MAIBase2预训练报告短报]]。

## 六、智能体数据构建

博文把数据构建本身做成由智能体协作完成的流程，分四个部件：

- **统一上下文层**：把各领域的任务规格、流水线状态、环境配置、中间结果与历史反馈集中在共享上下文中，智能体可以跨任务复用经验，研究者在关键点提供先验并审核。
- **智能体驱动的知识溯源**：把预训练数据与 GitHub 等来源组织成结构化的知识空间，由智能体遍历，找出长尾、覆盖不足或模型缺失的知识，用来合成更难的任务。
- **质量调控**：博文称智能体在难度与多样性上有系统性偏差，倾向于造更容易的任务、反复落入熟悉的任务模式；难度用任务约束、参考补丁长度、测试用例数与多个前沿模型的表现来校准，多样性按方向跟踪分布并调整来源。另加入反奖励投机检查，审查任务规格与评测流程中可被利用的捷径。
- **分工**：专家给原则与先验、审核关键点，智能体在原则内协调流程，构建 Docker 镜像、检查任务验证、测量测试覆盖等确定性操作交给可复用的代码与工具。

博文用三条轴筛选可训练的任务：持续时长（智能体要维持多久的连贯进展）、深度（到达通过状态前累积多少次状态转移，实践中以改动的文件与行数衡量）、区分度（同组 rollout 之间的奖励方差）。前两条在设计任务时确定，第三条针对当前策略测量。

## 七、强化学习

**训推逐位对齐。** 在线 RL 的训练侧与推理侧由不同的算子实现，微小的数值差异会经 MoE 分发与网络深度放大，再与离策略的陈旧度（staleness）叠加。博文分两类处理：

- **陈旧度为 0 时完全对齐**：训练与推理的算子逐位对齐，两侧的 logprob 差恰好为零；除确定性内核外，还要消除滑动窗口注意力、MTP 与 top-k 选择等处的差异。优化的树形归约让结果与张量并行（TP）规模无关，训练用 TP=1、推理用 TP=8 仍逐位一致。博文称总开销低于 10%，对齐后 FP8 策略能复现 BF16 的行为，未对齐版本则会漂移到臃肿、无结构的单轮输出。
- **陈旧度大于 0 时轨迹重放**：训练侧重放推理侧的计算状态，包括冻结路由器、重放所选专家及其系数，重放 top-p 候选集、只在候选 token 上重算 logprob，并对 logit 梯度做零中心投影以去掉共模漂移。博文称这样熵不再衰减。

熵在 RL 中的作用见 [[RLVR能力边界与熵机制]]；异步 RL 系统的一般设计见 [[RL训练系统与异步Rollout]]。

**吞吐与不丢样本。** 推理已占总算力的大头。博文的做法包括：会话亲和的调度；SFT 后训练的 MTP 头（MTP 即多 token 预测）用于加速 rollout，见 [[MTP训练范式]]；原生 FP8 MoE 与多种扩大 KV 缓存容量的手段。博文还指出，样本丢失集中在最长、最难的 rollout 上，会使训练分布偏移，因此用一个生命周期账本把每条预期 rollout 追踪到唯一的终止状态。

**面向无限长程。** 两项设计：

- **上下文压缩进入策略训练**：预算将尽时，智能体把工作整理成可恢复的状态再继续，使任务长度不受上下文窗口限制；压缩作为策略的一部分，在同一任务奖励下端到端训练。
- **按行为的尺度分配信用**：token 级用可学习的评论家（critic）把结果奖励转成逐 token 基线，评论家预先训练以降低策略损失方差；轮次级对格式错误的工具调用等与前后无关的失败只惩罚该轮的回报；奖励投机检测器在 rollout 进行中拒绝投机动作并惩罚该轮，让智能体换一种做法继续。

## 八、意义

Step 5 Preview 的博文提供了三类可复用的做法。其一，以「预填充阶段的隐式多跳推理需要深度」论证窄深结构，并把深层结构带来的数值问题追到具体的存储精度与归一化参数上。其二，Sparse GQA 说明在 GQA 而非 MQA、MLA 上做稀疏注意力时，索引器开销与 GPU 利用率需要专门处理。其三，把训推不一致拆成可对齐的系统误差与不可对齐的陈旧度两部分，分别用逐位对齐与轨迹重放处理。

## 九、局限与争议

1. **Preview 版本**：名称即为预览版，博文称系统仍在演进。
2. **只有厂商材料**：没有技术报告，也未见独立复现；窄深结构「以更低成本达到万亿级模型的长程能力」、索引开销降为八分之一等都是厂商说法。
3. **消融只见于图**：梯度截断前后的损失曲线、块大小与 top-k 的权衡都以图给出，图中读数不写入本篇。
4. **模态口径两处不一**：HF 页导语称接受文本、图像与视频；同页规格表的输入一栏只写文本与图像。
5. **规格只见于 HF 页**：600B 总参、27B 激活与最大输出 1M token 只见于 HF 页，博文未给参数量；HF 页未标权重公开日期。参数口径两处并列：HF 页规格表写 600B 总参；同页侧栏的自动统计显示「Model size 604B params」。两者的统计范围未说明。HF 页称权重按 StepFun Model License 1.0 授权，许可证为 Apache 2.0 风格，另附署名与商用许可条件。
6. **原因未明**：FP32 隐状态为何有效，博文自称仍不清楚；梯度尖峰的层冗余解释是博文的假设。
