# MAI-Base-2 预训练报告（前沿短报）

> **主要来源**：[Frontier Pre-training at Microsoft AI](https://microsoft.ai/news/frontier-pre-training-at-microsoft-ai/)（截至 2026-10-16）。下文「报告」指 Microsoft AI 的这篇预训练报告网页版。
> **研究线**：规模定律（考虑数据重复的规模阶梯与超参数缩放律）· 训练基础设施（固定显存的无丢弃 MoE、Muon 的分片重排、激活梯度截断）· 数据（有机数据与原生视觉语料）
> **范围与相邻笔记**：
> - 本篇只写基座模型的预训练。MAI-Base-2 的后训练仍在进行，截至 2026-10-16 没有可用模型；权重计划经 Foundry 授权给受信伙伴，不是开放权重。
> - ≠ [[规模定律与预训练范式]]、[[缩放定律的扩展形态]]：本篇不写缩放律的一般结论，只写报告的阶梯设计与超参数律。
> - ≠ [[分布式训练并行策略]]：本篇不写 ZeRO 等并行方式本身，只写 Muon 与 ZeRO 分片的冲突及处理。
>
> **意义**：报告把一次万亿级预训练的方法论拆开公开：小规模实验怎样设计才能把结论迁移到大规模，怎样把「配方好」与「算力多」分开度量，以及模型与基础设施怎样协同取舍。

**一句话**：Microsoft AI 于 2026-10-16 发布预训练报告，MAI-Base-2 是 2.8T 总参、80B 激活、每层都用 MoE 的基座模型，原生支持视觉，只用有机数据、不从其他模型蒸馏；报告称其在自建留出评测上优于所测的全部开放权重模型。后训练仍在进行。

## 一、问题背景

报告称，MAI-Base-1 就其规模而言是强模型，但比前沿的开放权重与闭源模型小，下一步的路线是放大。放大要回答三个问题：小规模实验的结论能否迁移到 2.8T 参数；模型间的直接比较把配方质量与模型规模、训练算力混在一起，怎样单独度量配方；更大更稀疏的模型在既定算力预算内能否训得高效、稳定。

报告也写明 Microsoft 的定位：对训练 token 有清楚的数据来源，预训练只用有机数据、不从其他模型蒸馏，并据此计划经 Foundry 把权重授权给受信伙伴。

## 二、脉络

| 时间 | 节点 | 关系 |
|---|---|---|
| 报告所称「6 月」 | MAI-Thinking-1 | 在 MAI-Base-1 之上后训练的通用模型；MAI-Base-1 每隔一层用 MoE |
| 2026-08 至 2026-09 | MAI-Base-2 预训练 | 报告称在 16k 张 GB200 上训练 38 天 |
| 2026-10-16 | 预训练报告 | 后训练进行中；MAI-Base-3 的准备已经开始 |

## 三、规格与评测口径

- **规格**：2.8T 总参、80B 激活的 MoE，每层都是 MoE 层；原生视觉，采用无编码器的视觉语言模型（VLM）架构；网页数据的知识截止为 2026 年 3 月。
- **评测指标**：用每字节比特数（BPB，bits-per-byte）在留出文本上比较预训练模型，这一指标与各模型的分词器无关。留出代码取自 Microsoft AI 自己的代码库，STEM、数学与问答评测委托供应商编写以降低训练集污染风险，所有评测集都对训练数据做了去污。
- **对比对象**：DeepSeek-V4-Pro-Base 是对比中唯一的开放权重基座；Kimi K3、Qwen3.8-2.4T-A95B、MiMo-V2.6-Pro-RL 只有后训练检查点，报告注明后训练可能影响这些评测。

## 四、规模阶梯与 source scaling

**规模阶梯**：一族训练配方固定、尺寸不同的模型，每一级以层数 $L$ 命名，其余结构由 $L$ 决定；放大时保持每激活参数训练 token 数（TPP，tokens per active parameter）不变。

**source scaling**：大规模的正式训练会让部分数据集重复多遍，小规模实验若不做处理，每个数据集重复的次数就比正式训练少。source scaling 在低阶梯上人为限制可用的唯一样本，使每个数据集的重复次数与训练长度无关，都等于正式训练中的次数。报告举例：某数据集在 50T token 的全量训练中重复 8 遍，那么 5T token 的实验就在其十分之一上循环 8 遍。在固定 TPP 下，这等于保持唯一数据与参数之比不变。

报告给出的理由是：不做 source scaling，小规模实验会偏向正则不足的架构与超参数，这些选择在大规模下会过拟合；报告称把 source scaling 纳入阶梯是可靠放大到 2.8T 参数的关键。数据重复对缩放律的影响见 [[缩放定律的扩展形态]]。

## 五、把配方效率与算力分开

报告的做法是：估计「用自己的配方要多少算力才能追平一个强的外部基座」。参照物取 DeepSeek-V4-Pro-Base，报告称它是唯一已发布的万亿参数以上基座检查点，训练算力明显少于 MAI-Base-2。

步骤：对四项留出评测分别拟合 BPB 与训练 FLOPs 的缩放律，求出阶梯上的模型追平参照物 BPB 所需的算力；拟合时纳入 MAI-Base-2 的最终结果，使追平点落在已拟合模型的范围之内，而不是外推。再与参照物的训练算力比较，报告称自己的配方 FLOPs 效率高 4.2–12.3 倍，相对 MAI-Base-1 的进步为 6.3–12.7 倍；这些倍数都是 Microsoft AI 自测，参照物的训练算力取值方式报告未在网页正文中展开。报告把效率归因于数据的质量与相关性以及建模上的选择。

## 六、超参数缩放律

- **学习率与权重衰减联合扫描**：报告称模型表现对学习率（LR）与权重衰减（WD）的乘积最敏感，好的配置落在 $(\log LR, \log WD)$ 平面的一条窄对角带上，因此改在 $(\log LR, \log(LR\times WD))$ 上取网格；对每组模型规模与 TPP 拟合二维二次函数，取解析最小值。
- **结论**：$LR^*\times WD^*$ 主要随训练步数变化，对步数的指数接近 −1，与「解耦权重衰减的时间尺度 $1/(LR\times WD)$ 应占训练的固定比例」一致；$\log LR^*$ 还依赖 $\log \mathrm{TPP}$，对步数的指数接近 −0.5，与「批量翻倍时学习率乘以 $\sqrt{2}$」的经验法则一致。
- **dropout**：用同样方法拟合出 dropout 随激活参数量变化的律，形式为激活参数量对数的 sigmoid 函数。
- **验证**：这些律在小规模实验上估计，在中等规模上验证，报告称一致优于此前的经验规则，并用来确定 MAI-Base-2 的超参数。

## 七、模型与基础设施协同

**效率增益指标**：候选方案达到与基线相同评测损失所需算力之比，分按 FLOPs 计与按墙钟时间计两种。报告主要看墙钟时间，因为它反映当前基础设施；按 FLOPs 赢、按时间输的改动指出基础设施该往哪里投入。

**每层 MoE**：报告称每层都用 MoE 在 FLOPs 上一贯优于 dense 与 MoE 交替，但 MAI-Base-1 时因实现低效，按时间计每隔一层用 MoE 最优。MAI-Base-2 处理了两项低效：动态路由造成显存碎片，并为罕见的极端负载失衡预留显存；专家更多、更细带来的每专家开销。

- **固定显存的多轮无丢弃 MoE**：丢弃溢出 token 会损害效果，按最坏失衡预留显存又浪费。报告把每个专家并行 rank 上的专家分组，每组以固定的每专家 token 容量跑一轮或多轮「分发 → 计算 → 收集」，溢出的 token 进入额外轮次，过载专家可借用同组其他专家未用的容量；反向传播按同样的多轮调度做细粒度重算。显存因此与负载失衡无关，容量通常配置为稳态下只需一轮。负载均衡的一般问题见 [[MoE路由与负载均衡]]。
- **降低每专家开销**：按专家组合并计算与通信，用常驻设备的元数据并直接从 GPU 发起 all-to-all，用对称内存经 NVLink 直接交换 token，把各层的负载均衡损失合并为一次归约。

**Muon 的分片重排**：报告称放大到 MAI-Base-2 时，Muon 比 AdamW 训练动态更稳、效率增益大。Muon 用 Newton–Schulz 迭代对每个权重矩阵的动量做正交化，需要完整矩阵，这与 ZeRO 沿数据并行维度切分动量冲突。做法是在优化器步内重排：各 GPU 先更新本地动量分片，经一次按形状批量的 all-to-all 取得若干完整动量矩阵，本地做正交化，再经第二次 all-to-all 把更新送回原分片。MoE 路由器权重等少数参数在各 GPU 上复制而不切分。Muon 本身见 [[优化器与训练稳定性]]，ZeRO 见 [[分布式训练并行策略]]。

**激活梯度截断**：标准梯度截断作用于整个批次权重梯度的全局范数，而异常梯度通常只来自批次中的少量数据，一个异常就会把整批梯度都缩小。报告改为在网络中选定位置截断激活的梯度。报告称它让优化更稳定，且收益随规模增大，而多数改动的效率增益在不同规模上大致不变。报告还把它当作数据排错工具：一个被截断的样本追溯到代码数据中被拦腰截断的许可证头，进而发现了预处理流程的缺陷。

## 八、数据

- **有机数据**：所有训练 token 都在内部处理，不蒸馏其他模型；报告称以唯一训练 token 计，语料从 MAI-Base-1 到 MAI-Base-2 增长约 36%。
- **网页流水线**：改进质量分类、主题分箱、网页解析、去重与评测去污，处理的网页内容大幅增加；用基于嵌入的多样性采样优先选取新颖数据、减少重复内容。爬虫遵守 robots.txt 及相关元标签与 HTML 控制。
- **视觉语料**：与 MAI-Base-1 不同，MAI-Base-2 以无编码器 VLM 架构原生地带视觉预训练，语料包括图文对与图文交错的文档；报告称计入重复后视觉语言数据占 50T token 训练混合的 18%。

数据源之间的配比方法见 [[数据配比优化方法]]。

## 九、意义

报告的价值在方法而不在分数。source scaling 处理了「小规模实验数据重复不足、结论偏向正则不足的选择」这一常被忽略的迁移问题；以拟合曲线估计追平外部基座所需算力，给出了一种把配方效率与算力分开的度量；效率增益按 FLOPs 与按时间两种口径并用，把模型选择与基础设施投入放在同一个框架里。激活梯度截断兼作数据排错工具，也是少见的公开实践。

## 十、局限与争议

1. **仅基座**：后训练仍在进行，截至 2026-10-16 没有可用模型；报告称将分享更多结果，后训练版本截至 2026-10-16 尚未发布。权重计划经 Foundry 授权给受信伙伴，不是开放权重。
2. **评测自建**：BPB 评测集是 Microsoft AI 自建或委托编写的留出集，外部无法复现。
3. **对比对象不齐**：除 DeepSeek-V4-Pro-Base 外的对比模型只有后训练检查点，报告自己注明后训练可能影响这些评测。
4. **效率倍数为厂商自测**：4.2–12.3 倍与 6.3–12.7 倍依赖各自拟合的缩放律与参照物的训练算力，未经独立复现；报告导语写作「4-12x」，正文写作 4.2–12.3 倍，两处并列。
5. **图表读数说明**：规模阶梯的预测曲线、超参数扫描切片、梯度范数对比等只以图给出，图中读数不写入本篇。
6. **网页版之外的材料**：报告另附 PDF 下载，本篇依据网页版，未逐项对照 PDF。
