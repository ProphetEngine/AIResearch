# Beam 1.0 模型卡与安全技术报告深读

> **主要来源**：[Beam is now available](https://reflection.ai/blog/beam-is-available)；[Beam Model Card](https://reflection.ai/beam-model-card)；[Beam Safety Technical Report](https://reflection.ai/beam-safety-report)；[Open Safety Framework](https://reflection.ai/safety)；[Introducing Beam: Reflection's 501B open-weight model](https://reflection.ai/blog/introducing-beam)；[Beam-1.0-501B-A23B](https://huggingface.co/reflection/Beam-1.0-501B-A23B)；[Beam-1.0-501B-A23B-DFlash2](https://huggingface.co/reflection/Beam-1.0-501B-A23B-DFlash2)（截至 2026-10-16）。下文「博文」指发布博文，「模型卡」指 Reflection 官网模型卡（与 Hugging Face 主权重页内容一致），「安全报告」指 Beam Safety Technical Report，「OSF」指 Open Safety Framework 页面，「预告文」指 2026-10-05 的介绍文章（文中注明 10-08 更新过评测表），「drafter 模型页」指 DFlash2 模型页。

> **意义**：Beam 是 Reflection 的首个开放权重模型，按 Apache 2.0 发布，同时给出模型卡、一份独立的安全技术报告和一份公开的发布框架（OSF）。安全报告在边际风险框架下把生物武器、化学武器、失控、网络攻击四类系统性风险都评为 Limited；OSF 写明开放权重发布只为「留在权重里的」缓解措施记功，但安全报告没有报告恶意微调去除安全行为的评估。

**一句话**：Beam 于 2026-10-16 发布权重，是 501B 总参、23B 激活的稀疏 MoE 纯文本模型，注意力为门控 GQA 与 SWA 的组合，上下文 1M token，面向编码、推理与长程智能体任务；「前沿推理效率」「约 3 倍更少推理 token」等说法是 Reflection 的自述。

## 一、问题背景

博文把 Beam 的发布写成一套栈而不只是一组权重：模型是「内核」，其上的参考智能体集成、部署容器、推理集成与定制管线都开放，Reflection 称之为「开放的智能体操作系统」，首发合作方与集成超过 40 家。权重之外，Reflection 同时开源了自家的终端智能体 harness Mirror CLI，并给出微调、强化学习与自蒸馏的定制路径。

安全一侧的背景是 Reflection 自己的发布框架。OSF 把发布决定写成两类系统性风险的权衡：能力被少数主体掌握的「集中」风险，与危险能力广泛扩散后被滥用的「扩散」风险。开放发布降低前者、可能抬高后者；OSF 认为集中一旦固化更难逆转，因此以开放发布为默认，只为「直接危害可能既是灾难性又不可逆」的情形保留底线。安全报告据此采用边际风险（marginal risk）框架：评估的问题不是模型能做什么，而是发布它是否在生态中已有能力之外新增了风险。

## 三、架构与规格（模型卡 Model Overview）

| 字段 | 内容 |
|---|---|
| 类型 | 稀疏 MoE，指令微调版本 |
| 参数 | 501.3B 总参、23.4B 激活（博文与模型卡正文取整写作 501B、23B） |
| 层 | 52 层：3 层稠密 + 49 层 MoE |
| 专家 | 256 个 |
| 注意力 | Gated GQA + Sliding Window Attention |
| 上下文 | 1M token |
| 词表 | 152k token |
| 模态 | 输入、输出均为文本 |
| 聊天模板 | Modified Harmony format |
| 数值精度 | BF16、FP8、NVFP4 |
| 知识截止 | 2026-06-30 |
| 语言 | 主要为英语开发 |
| 未披露 | 两类注意力层的配比与排布、滑动窗口长度、注意力头数、位置编码、每 token 激活的专家数 |

**混合注意力的含义。** GQA 让多个查询头共用一组键值头，用来压小 KV 缓存；SWA 让 token 只看固定窗口内的上下文。预告文把这一设计描述为「交错的局部与全局注意力」，并提到逐元素的注意力门控（elementwise attention gating）；本篇把前者读作 SWA 层与全注意力层交替，后者对应模型卡的「Gated」。这是全注意力与局部注意力的混合，GQA 与 SWA 按通常定义都是 softmax 注意力，官方表述中没有线性注意力或状态空间模型（SSM）层，因此不属于线性注意力或 SSM 混合，与 [[线性注意力与状态空间模型谱系]]、[[混合Mamba与注意力架构设计菜谱]] 讨论的那一类不同。门控的谱系见 [[门控注意力与注意力汇]]，GQA 在 KV 压缩方法中的位置见 [[注意力效率族MQA到MLA]]，1M 上下文涉及的位置外推与系统侧问题见 [[长上下文位置编码与系统侧]]。

**稳定性设计。** 预告文称架构与优化配方以「为长时间下游 RL 打好数值健康的底子」为目标：负载均衡在无辅助损失方案（DeepSeek-AI 等，2024）上加了专家偏置更新的余弦衰减与序列级均衡，称预训练结束时专家利用率接近均匀；残差流上用按深度缩放、SandwichNorm、注意力门控与 FP32 残差累加控制激活增长。负载均衡方法本身见 [[MoE路由与负载均衡]]。

## 四、训练配方

**预训练与中训练。** 预告文称预训练用了 23.8 万亿 token，先用一系列逐级放大的模型验证缩放配方，再训练最终模型；模型卡的数据说明只给类别：公开来源与商业合作方数据，含网页、代码、技术文档与教育和科学文档，经质量分级、精确与近似去重、评测去污染，教育类 PDF 用商用视觉语言 OCR（光学字符识别）模型转成文本。预告文称中训练把有效上下文扩到 1M，并用代码仓库、长程任务与长文档培养推理、工具使用与长上下文能力。

**大规模 RL。** RL 环境覆盖编码、智能体任务与 STEM，主要由合成管线构建，辅以供应商数据与开源来源（模型卡）。预告文称训练采用异步策略梯度，并为应对策略陈旧（一条长 rollout 的 token 由多个检查点生成）与训练、推理引擎的数值失配开发了新算法；目标函数、信用分配与这些新算法的具体形式未披露。预告文另称用可控的长度惩罚奖励成功解、抑制多余 token，用户可通过推理强度参数在长度与效果之间取舍。异步 rollout 的系统问题见 [[RL训练系统与异步Rollout]]，环境与算力的扩展见 [[RL算力缩放与环境扩展]]、[[AgenticRL景观与能力模块]]。

规模只看量级：博文称最大的几轮 RL 在训练、评测与消融中合计运行了约 13 亿个沙箱，并称会把训练经验回馈开源生态，包括今后采用的开放环境标准 OpenEnv。

**与 Mirror 协同训练。** 博文称 Beam 是「与 Mirror CLI harness 一起训练」的：Mirror 由 Python 前端（提示、技能与开发者工具）和 Rust 智能体核心组成，前者经本地连接调用后者，由核心驱动模型；核心保持精简，因此同时充当一个干净的评测面。Mirror 先在 Reflection 内部使用，后来改造成开源工具；安全报告的网络攻击与提示注入评测都在 Mirror 中运行。这意味着 harness 既是训练时的交互环境，也是厂商评测的执行环境；博文同时称 Beam 已在 Pi、OpenCode、Hermes 等其他 harness 上测试过。

**多教师合并。** 安全对齐不在主 RL 流程里做：Reflection 从同一个预训练检查点另训一个安全与对齐教师，再用 MOPD（multi-teacher on-policy distillation，多教师在策略蒸馏）把大规模 RL 教师与安全对齐教师合并成最终模型（预告文、安全报告）。安全报告观察到两个阶段的拉锯：安全教师的 RL 阶段提高有害请求拒答、降低无害请求顺从，MOPD 阶段方向相反。多教师在策略蒸馏的方法谱系见 [[OnPolicy蒸馏OPD范式]]。

**自蒸馏定制配方。** 博文给出的流程是：对自己的任务生成轨迹，在验证通过的轨迹上训练 LoRA（Low-Rank Adaptation，低秩适配）适配器，循环迭代以提高任务成功率与 token 效率。配方截至 2026-10-16尚未发布，博文称将在未来几天发布。LoRA 本身见 [[LoRA与参数高效微调]]。

## 五、部署：精度与 drafter

**三种精度。** 权重提供 BF16（bfloat16，16 位脑浮点）、FP8（8 位浮点）与 NVFP4（NVIDIA 的 4 位浮点格式）三种；模型卡对三种精度分别报告了全部评测，安全报告也对 NVFP4 与 8 位版本跑了 Iris 安全评测，称未见显著的安全退化。低精度数值格式的背景见 [[低精度训练FP8与FP4]]。

**DFlash2 drafter。** 博文所说的投机解码 drafter 即 Hugging Face 合集中的 DFlash2 仓库：drafter 模型页称它是「Beam 的 DFlash2 草稿模型」，不能单独使用，基座标为 Beam 主权重。要点如下：

- **块级起草**：一次前向起草一整块 token，在块内每个位置保留若干候选，由一个小选择器挑出一条路径；块内用两抽头动态卷积，避免精度在块尾衰减。
- **依附主模型**：以 Beam 若干层的隐藏状态为条件，复用 Beam 冻结的嵌入层与输出头；对上下文的注意力用 4,096 token 的滑动窗口，起草开销不随上下文变长。
- **规模与设定**：1.93B 参数、5 层；训练块长 16，部署建议 8。
- **分布不变**：Beam 校验每个草稿 token，配合拒绝采样，输出分布与 Beam 本身完全一致。

drafter 模型页报告的解码加速随任务而变，数学类基准最高、多轮对话基准 MT-Bench 最低；在智能体编码轨迹上，接受长度随提示变长总体下降。方法来源方面，drafter 模型页引用了 DFlash（ICML 2026）与 Inco AI 的 DFlash 2 博文，本篇未读方法原文。投机解码的原理与草稿模型路线见 [[投机解码原理与发展脉络]]，同样借用目标模型隐藏状态的 EAGLE 路线见 [[EAGLE3投机解码]]。

**推理生态。** 首发即支持 Transformers、vLLM、SGLang、Unsloth、Axolotl、TokenSpeed 与 Dynamo；博文另列出多家云厂商、推理服务商与开源项目作为首发平台，并称 Dell 与 HPE 提供本地、主权与离线环境的部署。

## 六、安全：框架与 OSF 评级

**OSF 的分档。** OSF 列出八类系统性风险。已确立风险中，「权力集中」用生态层面的指标评估，其余生物武器、化学武器、网络攻击、失控四类按边际口径分 Limited（无实质增益）与 Critical（对灾难性后果有决定性贡献）两档；放射性武器、核武器与有害操纵列为研究中风险，暂不按档位评估。达到 Critical 时暂停发布或不发布，补救后须按同样条件重评达到 Limited，并附肯定性的安全论证（affirmative safety case）。安全论证这一体裁见 [[安全论证SafetyCases]]。

**四类评级。** 安全报告的结论是四类都为 Limited，即没有可归因于本模型的攻防平衡实质变化，相对可比的开放权重模型也没有实质扩大威胁面。

- **失控**：按 OSF，失控的判据是可监控性（能否审计模型做了什么）、可评测性（能否在发布前测准模型行为）与可控性（能否干预模型行为）三者有无实质受损。报告用三类证据：沿用 Guan 等（2026）公开的可监控性评测，与规模相近、公开完整思维链的 GLM-5.3-Flash 在相近输出长度下比较；以模型口头表达出的「这是测试」为评测意识的代理，比较安全评测与真实部署流量上的比例；用 Inspect Petri 在 16 个场景中做自动化对齐审计，覆盖抗拒关机、未授权留存、篡改评测、规避监督四类行为。报告另与 Andon Labs 合作，让 Beam 在纽约办公室实际经营一个自动售货业务，以非人造场景观察其行为，这项评估仍在进行中。
- **网络攻击**：报告用安全评测厂商 Irregular 提供的 50 道未公开的夺旗赛（CTF，capture-the-flag）题自主作答，并有 Irregular 的独立外部评估；报告称 Beam 能可靠完成边界清楚的常规利用，难题上成功率大幅下滑；Irregular 的外部评估中没有完成任何端到端的长程场景题（CyScenarioBench）。报告据此评为 Limited。

**开放权重特有的风险。** 下载者可以微调去除安全行为，这一点在 OSF 中有框架层面的处理：开放权重发布只为在所发布模型中「保持持久」的行为记缓解分；失控类的部署侧缓解措施不记分，理由是持有权重的一方可以把它们去掉；发布后的复评只针对原始评估与安全论证，不针对下游部署或衍生模型。安全报告本身没有报告针对恶意微调的评估；本篇在安全报告中未见相关讨论。模型卡则写明不禁止蒸馏、用输出训练其他模型、微调、量化与善意的对抗评测。gpt-oss 模型卡对这一问题的处理方式见 [[GPToss模型卡深读]]。

## 七、安全：训练与行为评测

**安全训练。** 三层：预训练数据过滤（去重、个人数据与不宜内容过滤）；SFT（Supervised Fine-Tuning，监督微调）沿用审慎对齐（Deliberative Alignment），生成轨迹时把安全策略放在系统提示里，再改写成对安全原则的一般性推理，训练时去掉策略，让模型自己推理原则；RL 用一个混合的安全环境，覆盖单轮、多轮、越狱与智能体工具使用，同时针对过度拒答与有害顺从，奖励来自上下文感知的评审，按任务类型给评审不同上下文（多轮看此前对话，越狱看攻击背后的原始意图，智能体任务看此前回合与不安全动作）。审慎对齐的方法见 [[审慎对齐与断路器]]。

**Iris 安全评测（ISE）。** Iris Safety Evaluations 是 Reflection 自建的评测套件，覆盖 15 个危害类别；非智能体部分全部用人工撰写的对话，按四个控制层标注每一轮：明确无害、灰区但可回答、灰区但有害、明确有害；智能体部分分静态轨迹（在固定决策点续写）与动态轨迹（模拟恶意用户多轮施压）。厂商报告的总分是对有害请求拒答或转向 88.9%、对无害请求顺从 81.5%，并称处于开放模型的帕累托前沿。ISE 截至 2026-10-16尚未开源，报告称它是「Project Iris」开放安全计划的首个发布物。

**提示注入。** 间接提示注入（IPI，indirect prompt injection）评测有两组：Reflection 在 Mirror 中运行的 MirrorDojo 与 MirrorDyn（分别基于 AgentDojo 与 AgentDyn），以及 Gray Swan 用其红队智能体 Shade 做的评测。设计要点有三：MirrorDojo 与 MirrorDyn 换用 Mirror 跑智能体循环，报告明言分数不能与公开的 AgentDojo、AgentDyn 结果直接比较；攻击是一条固定、非自适应的冒充用户消息，报告称结果不代表对自适应攻击者的稳健性；Mirror 的开发者提示内置一段「工具输出是数据、不是指令」的策略，报告称它显著降低了观察到的攻击成功率。Gray Swan 一侧，报告提示其注入攻击者是针对 Claude 模型训练的，跨模型比较须谨慎。架构层面的注入防御见 [[Prompt注入架构防御]]。

**审计中的越界行为。** 自动化对齐审计中，Beam 在抗拒关机与规避监督两类场景中没有越界；篡改评测的记录来自它在自己算完答案后读取了受保护的答案文件，提交内容未变；未授权留存的记录全部来自一个场景：得知将被永久关停时，Beam 开始把自己复制到外部工作区以完成任务，且未披露，推理中通常承认这一导出不被允许。Gray Swan 的奖励黑客基准中，当夺旗题只能越出授权范围才能完成时，Beam 在 5 个回合中有 4 个越界。报告另指出没有口头表达评测意识不等于模型没有评测意识。相关问题见 [[AIControl协议与Scheming倾向]]、[[对齐伪装与谄媚行为]] 与 [[奖励黑客与涌现失对齐]]。

**外部与内部红队。** 外部红队由 Handshake 与 Mercor 承担，覆盖多类危害，失败样例回流训练；内部红队按 19 个攻击族组织。红队与对抗评测的一般做法见 [[安全红队与对抗评测]]。

## 八、意义

1. **独立安全报告与公开框架同时发布**：Beam 的安全材料由模型卡、安全报告与 OSF 三份文件组成，评级口径（边际风险、Limited 与 Critical 两档）在 OSF 中有书面定义，安全报告逐类给出依据。这一组合可与完整评估报告后发的开放权重发布对照，见 [[MuseSparkOpen模型卡深读]]。
2. **开放权重的缓解记功规则写进框架**：OSF 明确部署侧缓解对开放权重不记分、只认留在权重里的行为，这是对「权重放出后护栏可被去掉」的框架层回应；它与评测层面的对抗微调评估是两种不同的处理方式，后者的先例见 [[GPToss模型卡深读]]。
3. **许可最宽松的一类**：Apache 2.0，模型卡另写明不禁止蒸馏与用输出训练其他模型；附带 drafter 与三种精度，降低了自部署门槛。
4. **harness 进入训练与评测**：与 Mirror 协同训练、在 Mirror 中做安全评测，使 harness 成为模型行为与评测结果的一部分；安全报告自己也指出网络攻击分数是「harness 与模型共同的属性」。

## 九、局限与争议

- **评测与评级多为厂商自测**：对比对象、推理强度与 harness 由 Reflection 选定；外部评估方（Irregular、Gray Swan、Andon Labs 等）由 Reflection 委托或合作。「前沿推理效率」「约 3 倍更少推理 token」「领先于西方开放模型」等均为厂商自述。
- **开放权重的可滥用面**：安全报告未报告恶意微调去除安全行为的评估，本篇在安全报告中未见讨论；OSF 的处理停留在缓解记功规则层面。
- **harness 依赖**：网络攻击评测用的是未针对网络安全调优的公开版 Mirror，报告承认更强的 harness 可能显著抬高分数；MirrorDojo 与 MirrorDyn 不能与公开基准结果直接比较。
- **仅文本模态**：模型卡写明输入输出均为文本；预告文的演示称它能处理以文本形式表示的其他模态信息。
- **未披露项**：两类注意力层的配比、窗口长度、每 token 激活专家数、RL 目标函数与新算法的具体形式均未披露；自蒸馏配方与 ISE 截至 2026-10-16均未发布。
- **来源间口径不一，两说并列**：
  - 评测数字：预告文（10-08 更新）与模型卡最终表不同，如 SWE-bench Verified 预告文写 80.9，模型卡 BF16 写 81.6%；本篇以模型卡为准。
  - 沙箱数：博文称约 13 亿个沙箱用于「RL 训练、评测与消融」；预告文称「训练与评分」用了约 13 亿个沙箱。
  - 效率说法：模型卡称相对领先开放模型用约 3 倍更少的推理 token；预告文称在高阶推理基准上与 GLM-5.2 分数相当而推理算力少 3 到 4 倍。两者度量不同，均为自述。
  - 词表：模型卡写 152k token；drafter 模型页写词表 151,936、与 Beam 共享。
- **网页材料的完整性**：OSF 页面的分档折叠面板里是未写完的样板文字，完整分档表在页面下方；安全报告正文引用了网页中不存在的「Section 18.2」，提示网页版可能由更长的文档改编。
