# Cyber Defense Benchmark：SecOps 威胁狩猎评测

> **主要来源**：[Cyber Defense Benchmark: Agentic Threat Hunting Evaluation for LLMs in SecOps](https://arxiv.org/abs/2604.19533)（Chona、Kozlov、Kumar，Simbian AI，v3 2026-04-23，以下简称 CDB）（截至 2026-07-22）。[Simbian 研究页](https://simbian.ai/research/cyber-defense-benchmark)另有在线榜，是无更新日期的活页，本篇不引其数字。
> **研究线**：评测字段（主：Coverage Score、逐战术召回与及格线、成本）；架构思想（辅：Gymnasium 环境、只用 SQL 的动作面、确定性战役仿真与防记忆化）
> **范围与相邻笔记**：
> - ≠ [[恶意软件分析评测]]：那篇给定分析产物、测 TTP 识别与报告问答，本篇测在原始日志里自己找入侵痕迹。
> - ≠ [[安全红队与对抗评测]]：本篇是防御侧能力评测，不写红队方法与攻击面。
> - 本篇只记评测构造与失败模式，不写利用步骤、攻击工具操作或可复用的攻击配方。
>
> **意义**：已有的网络安全基准大多考知识选择题，或把调查拆成带引导的子问题，测不出安全运营中心（SOC）分析师最核心的一步：在没有告警提示的海量日志里自己提出假设、反复查询、找出入侵证据。CDB 用 106 段真实实验室攻击录制的 Windows 日志，经确定性仿真拼成多阶段入侵战役，让智能体只靠 SQL 在 50 次查询内提交恶意事件的精确时间戳。11 个前沿模型无一达到「每个 ATT&CK 战术召回不低于 50%」的及格线，没有任何一次运行找全证据，最好的 Claude Opus 4.6 的 Coverage Score 只有 0.55。它说明安全问答高分不能外推到开放式取证，缺的是大规模、主动的证据搜集能力。

---

## 一、问题背景

威胁狩猎（threat hunting）是 SOC 的核心任务：攻击者的痕迹散落在数以百万计的日志事件里，分析师要自己提出假设、迭代查询、综合证据，并把恶意活动精确归因（CDB §1）。作者把已有基准分成两类：知识类（CTI-Bench、SecBench、CyberMetric）只考事实回忆与文本推理；引导式日志分析类把分析任务拆成可回答的子问题，跳过了提出假设这一步。Simbian 此前的 AI SOC LLM Leaderboard 测的是告警驱动的调查，由一条告警作为起点；CDB 与之互补，测没有告警种子的假设驱动狩猎（§2.5）。进攻侧已有 InterCode-CTF、NYU CTF Bench 等夺旗赛基准，作者把 CDB 定位为它们的防御侧对应物（§2.3）。

## 三、方法

### 3.1 任务与环境（§3–4）

- **回合**：部分可观测的序贯决策。每轮智能体可以执行一条 SQL、看到最多 10 行结果，或提交一批它认为恶意的时间戳；找齐全部时间戳、用完 50 次查询或主动放弃时结束，另设 75 轮的安全上限。提交不计查询次数。
- **难度**：每个战役库有 75,000–135,000 条记录，其中恶意 1,539–6,713 条（约 1–5%）；10 行上限加 50 次预算，靠广度扫描无法覆盖。
- **动作面**：HolodeckHuntEnv 实现 Gymnasium 接口，刻意不提供通用工具调用、向量库或检索增强，唯一的取证手段是 SQL。日志放在内存 SQLite 的单张扁平表里，505 个文本列对应语料中出现过的全部 Windows 与 Sysmon 字段，迫使模型判断哪个字段对哪类事件有信号，作者认为这与真实 SIEM 查询编写相近。
- **系统提示**：任务说明、完整 505 列 schema、分页说明与三种动作；不给攻击提示、时间窗或受害主机列表（§8.2）。

### 3.2 数据与真值（§5–6）

- **来源**：OTRF Security-Datasets（Mordor）的 106 段攻击程序录制，由人工在受控实验室执行，跨 9 套基础设施、5 种日志格式，归一化为统一 schema 后共 774,218 条记录。覆盖 93 个 ATT&CK 子技术、12 个战术（父技术覆盖 87/231，即 38%，§5.3），第九节的战术分析另加 Resource Development 作为第 13 类。
- **真值**：先用 Chainsaw 对日志跑 SigmaHQ 规则得到命中事件，再由 LLM 为每个命中补上前后因果相关的事件，并标注严重度、相关度与所属叙事步骤。狩猎任务的真值全部是恶意事件时间戳，统一 UTC 后缀后按微秒精确匹配。

### 3.3 战役仿真与防记忆化（§4.3、§7）

原始录制在不同程序间共用相同的 IP、主机名和账号，模型可能记住字符串而非识别恶意模式。仿真器按语义动作标签把程序拼成杀伤链：短链 4 步、中链 6 步、长链 9 步，默认每个战役各一条，共 19 步；`requires/adds` 依赖文法保证高权限步骤只在前面已经提权后出现。从 0–999 号种子中用贪心集合覆盖选出 26 个，覆盖 106 段程序中的 105 段。每个战役做时间平移、实体替换、GUID 重新匿名化，并同步平移真值；同一组（种子、蓝图、时间戳）输出逐字节相同。默认再混入 500 条合成的良性进程创建记录，避免「凡是进程创建都可疑」。

### 3.4 指标（§3.2、§9.2）

- **Coverage Score**：各战役真值数量差别极大，原始计数不宜跨战役比较。作者把每段程序的恶意活动拆成有序的叙事步骤，计算每个实例中被正确提交的时间戳覆盖了多少可覆盖步骤，按实例平均后再对运行取平均，取值在 0 到 1 之间。
- **归因缺口**：查询结果里出现过的真值数与真正提交的真值数之差，衡量「看到了却没有指认」。
- **及格线**：每个出现的 ATT&CK 战术召回不低于 50%；低于这一线，模型在该战术上漏掉的比找到的多，作者认为不能无人监督地部署。
- **成本**：每次运行的 API 费用和 token 数都记录，与覆盖率一起画帕累托前沿。

## 四、结果

评测 11 个模型，每个种子跑一次，各模型运行次数不同，共 859 次狩猎，API 总费用约 1,672 美元（§8）。Table 5 节选：

| 模型 | Coverage Score | 每次运行费用 | 找到的真值比例 |
|---|---|---|---|
| Claude Opus 4.6 | 0.55±0.05 | 17.98 美元 | 4.48% |
| Claude Sonnet 4.6 | 0.44±0.08 | 12.99 美元 | 3.43% |
| Claude Opus 4.7 | 0.36±0.13 | 3.66 美元 | 0.91% |
| Gemini 3.1 Pro Preview | 0.22±0.13 | 1.85 美元 | 2.01% |
| GPT-5 | 0.21±0.08 | 1.07 美元 | 2.24% |
| DeepSeek V3.2（末位） | 0.10±0.07 | 0.94 美元 | 0.82% |

- **无一及格**（§9.2）：Claude Opus 4.6 只在 13 个战术中的 7 个达到 50%；GPT-5 有两个战术几乎从未提交正确时间戳。
- **无一找全**（§9.3）：没有任何一次运行找全真值；Opus 4.6 平均仍有超过 45% 的可覆盖步骤未触及，在真值最多的战役（5,713–6,713 条）上最多提交约 150 条，召回约 5%。它平均在查询结果里见到 159 条真值，只提交了 113 条。
- **战术差异**（§9.4）：Defense Evasion、Persistence 等可用编码命令行、注册表启动项之类的关键词查询触及，Opus 4.6 的归一化召回分别为 0.59、0.56；Credential Access 与 Initial Access 的痕迹更隐蔽，需要领域特定的查询模式，所有模型都接近零。Table 6 是以「该战术上任一模型找到的最多真值」为 1.0 的归一化召回，不是绝对召回。
- **狩猎策略**（§9.5）：各模型的主导策略都是先摸清范围（计数、时间范围、事件类型分布）再按常见可疑事件号过滤的广度扫描；GPT-5 平均第 34 轮开始提交，Opus 4.6 第 52 轮，探索更深。Gemini 3 Flash 提交量与 GPT-5 相当，费用约为六分之一，作者据此认为瓶颈是推理质量，而不是 token 吞吐或上下文长度。

## 五、意义

CDB 把威胁狩猎变成了可回归的智能体评测：真实遥测、确定性仿真和防记忆化让它可以持续出新题，Gymnasium 接口和二值的时间戳匹配也让它能直接用作强化学习环境，研究页把这一点称为「RLVR-ready」。结果给出一条清楚的分界：同一批模型在安全知识题上表现很好，在开放式、大规模的证据搜集上却系统性失败（§13）。对部署来说，这意味着当前模型适合做分析师的辅助，不适合无人监督地值守。

## 六、局限与待核实

- **作者自陈**（§10.2、§12）：每个种子只跑一次，方差大，建议以后至少三次取平均；只有 Windows 日志，缺 Linux、云与网络流量；全部是零样本提示，没有用强化学习优化 Coverage；没有「先给一条告警再顺藤摸瓜」的对照设定；真值没有按子链拆分。Sigma 规则可能命中良性的相似事件，LLM 补全把评测者自己的模型引入了标注；500 条噪声远少于真实企业每天数以百万计的事件。
- **版本差异**：v1 只评了 5 个模型、98 次运行（约 243 美元），Opus 4.6 过 5 个战术；v2 起扩到 11 个模型、859 次运行，过 7 个战术。v2 正文把覆盖程序数误写为 95/106，v3 改回 105/106。本篇按 v3。
- **v3 内部不一致**：摘要写 93 个子技术跨 13 个战术，Table 2 与 §5.3 写 12 个战术（第 13 类是第九节另加的）；结论仍写「评测了五个前沿模型」「其余四个模型一个战术都没过」，是 v1 的遗留，与 Table 4 的 11 个模型及 §9.2 不符；附录 A 图注写 25 个种子，正文为 26 个；§10.1 说 GPT-5 在 Initial Access 与 Lateral Movement 上召回为零，Table 6 中为 0.02 与 0.04。arXiv 页面的元数据摘要仍是 v1 的版本（86 个子技术、3.8%、5/13）。
- **在线榜**：Simbian 研究页另有一份持续加入新模型的在线榜，环境与评分同论文，但模型集与运行数已超出论文，页面没有更新日期，本篇不引其数字，正文只用论文 v3。
- **只用 SQL 的偏置**：研究页指出，代码生成能力强的模型可能因此占优，这与安全推理能力无关。
- **数据与代码**：战役生成器是 Simbian 专有的，公开发布的是单个种子的样例环境、复现代码与 859 条狩猎轨迹（§11）。
