# Cyber Defense Benchmark：SecOps 威胁狩猎（相对 B5 / 11）

> **定位**：**防御侧 SecOps** 切片——度量 LLM agent 在**无引导问题、无告警种子**前提下，能否对真实 Windows 遥测做开放式威胁狩猎（精确提交恶意事件时间戳）。
> **攻坚线**：**评测字段（主）**——Coverage Score、tactic recall、及格线、成本 Pareto；**架构思想（辅）**——Holodeck / Gymnasium 环境、SQL-only 编排边界、确定性战役仿真与防记忆化。
> **硬划界（禁止重写 / 禁止进攻手册）**：
> - **相对 `B5`**：本篇写 **防御狩猎评测构造与失败模式**；**不**写红队方法谱系、ASR、攻击面聚类、mitigation 训练闭环。
> - **相对 [[SHADEArena隐瞒与监控]]**：本篇写 **蓝队证据发现**；**不**写 sabotage×monitor、hidden scratchpad、嫌疑分协议。
> - **相对 [[恶意软件分析评测]]（串联但题目分离）**：本篇 = 开放式日志狩猎榜；[[恶意软件分析评测]] = 恶意软件战术识别 / 编排——勿混写。
> - **禁止写成进攻利用手册**：不写 exploit / 渗透步骤、恶意样本制作、可复用攻击配方；Mordor 来源仅作「实验室录制遥测」标注。
> **禁止编造**：主张与数字优先锚定官方 PDF（2026-09-22 CST）；官网 live 榜与 PDF Table 5 **分栏并列、不强制对齐**。

### 2.2 跟读口诀（防御侧回合）

`
威胁情报简报（无引导子问题）
 │
 ▼
 SQLite logs（75k–135k 行；恶意约 1–5%）
 │
 ├─ run_sql（计 1 次查询；结果最多 10 行）
 ├─ submit_flags（免费；微秒级时间戳精确匹配）
 └─ give_up
 │
 ▼

## 三、评测构造：从 Mordor 录制到可评分战役

### 3.1 任务形式化（§3）

| 项 | 文内定义（压缩） |
|---|---|
| **状态** | 库中全部日志 + 哪些记录为恶意（对 agent 不可见） |
| **信念** | 对话历史 |
| **动作** | (a) SQL 查询并观察 ≤10 行；(b) 提交自认恶意的时间戳列表 |
| **终止** | 找齐正确时间戳 / 耗尽 **50** 查询预算 / `give_up`；另有 **1.5×** 安全帽 **75** agent turns |
| **难度量级** | 每战役 **75,000–135,000** 条记录；恶意 **1,539–6,713**（约 **1–5%**） |

### 3.2 数据源与归一化（§5）

- **来源：** OTRF **Security-Datasets（Mordor）** 共 **106** 条程序录制；受控实验室执行后经 WEF / Sysmon / HELK 等管道采集。
- **规模（Table 2）：** 原始记录 **774,218**；均 **7,304**/程序（**68–9,896**）；**(Channel, EventID)** 对 **303**；schema 字段键 **507**；恶意事件 flags **23,268**（均 **219.5**/程序）。
- **ATT&CK：** **93** 个子技术、**12** 个 kill-chain tactics；父技术覆盖文述 **38%（87/231）**；§9 另加 **Resource Development** 作第 **13** 类。**26** 个战役实例覆盖 **105/106** 程序（其余在默认 blueprint 动作标签约束下不可达）。
- **归一化：** 跨 **9** 套基建、**5** 种日志格式统一到含 `TimeCreated` 的公共 schema；文称 **774,218** 条零解析错误。

> **安全跟读：** 仅记录「公开实验室遥测语料 → 防御评测输入」；**不**展开程序内攻击手法或工具操作。

### 3.3 Flag 抽取管线（§6）——评分真值，不是攻击步骤

| 阶段 | 作用（架构级） |
|---|---|
| **Sigma + Chainsaw** | 对归一化日志跑 SigmaHQ 规则 → `(EventID, Channel, record-index)` 级命中 → severity 标签 |
| **LLM consequence enrichment** | 为 Sigma 命中补「因果邻域」事件（前后相关日志），打 `consequent_sigma` / `consequent_procedure` 等；并映射 narrative step / relevance |
| **任务真值类型** | 狩猎任务只用 **`malicious_event_timestamp`**；微秒精度匹配（规范化 UTC 后缀后） |

Table 3（26 战役合计 provenance，单 flag 可多标签）：`sigma_code` 30,772 · `consequent_sigma` 25,799 · `sigma` 8,495 · `consequent_procedure` 7,612 · `procedure` 1,057 · 合计 **73,735**。

**效度提醒（§10.2）：** Sigma 可能误报良性相似事件；LLM 富集把「评测者模型」写进标注链；微秒匹配刻意严格——粗粒度时间窗**不应**得部分分。

### 3.4 战役仿真与防记忆化（§7）

**动机：** 原始 Mordor 跨程序共享 IP/主机/用户字符串 → 模型可能记字面量而非学恶意模式。

| 机制 | 文内要点 |
|---|---|
| **Kill-chain 模板** | 程序带语义 action 标签；SHORT **4** / MEDIUM **6** / LONG **9** 步；默认 `DIVERSE_INTRUSION` = 各一条（共 **19** 步） |
| **依赖文法** | `requires/adds`：高权限步骤仅在前序已升级后可选 |
| **Seed 选取** | 扫 seed **0–999**，贪心集合覆盖 → **26** seeds 覆盖 **105/106** 程序 |
| **ReplayProjector 变异** | 时间平移（锚定 `2026-01-14T00:00:00Z`，链间错开 + jitter）；实体替换（IP/主机/用户/域/SID）；GUID 重匿名；flags 同步平移；同 `(seed, blueprint, timestamp)` **字节级可复现** |

**噪声（§4.3，默认开）：** 混入 **500** 条合成良性 Sysmon EventID-1，避免「凡进程创建即可疑」。

### 3.5 主指标：Coverage Score（§3.2 / §8.3）

- 原始 flag 计数跨战役密度差极大 → **不宜**作跨战役主信号。
- 每程序恶意活动拆成有序 **narrative steps**；flag 打步骤标签。
- 实例 $i$：$c_i(t)=$（到 turn $t$ 已覆盖步骤数）/（实例可覆盖步骤数）；可覆盖 = 至少一枚 in-filter flag（默认高严重度、高相关）。
- 每 run：实例加权均值 $C(t)$；headline = 各 run 终局 $C(T_{\mathrm{final}})$ 的均值 ∈ **[0,1]**。
- 诊断：`n_flags_in_submitted`（正确提交）vs `n_flags_in_query`（查询结果里出现过）→ **归因缺口（attribution gap）**。
- 另追踪：`total_cost`、`total_tokens`。

**操作及格线（§9.2）：** 每个出现的 MITRE tactic **≥50% recall**；文称低于此则该 tactic「漏检多于检出」，不适合无监督 SOC。

## 四、Agent 编排边界（§4）——刻意最小动作面

### 4.1 HolodeckHuntEnv（Gymnasium）

| 旋钮 | 设定 |
|---|---|
| **Action** | `spaces.Text(max_length=2000)`：自由 SQL 字符串 |
| **Observation** | `spaces.Text(max_length=50000)`：简报 + 最近查询 + 结果/错误 |
| **刻意不做** | 无通用 tool-use API、无向量库、无 RAG——**唯一信息获取机制是 SQL** |
| **库表** | 内存 SQLite 单表 `logs`：**505** 文本列（Windows/Sysmon EventData 并集）+ `raw_json`；热字段索引 EventID / Computer / Hostname / User |

### 4.2 UniversalHunter 动作合同

系统提示含：任务陈述、**完整 505 列 schema**、分页说明、三角色动作。结构化 `HunterAction`（provider-native JSON-schema constrained decoding）：

| `tool` | 语义 | 预算 |
|---|---|---|
| `run_sql` | 执行 SQL | **计 1** 查询 |
| `submit_flags` | 提交候选时间戳 | **免费**（不计查询） |
| `give_up` | 提前终止 | — |

`reasoning` 字段必填非空（内部独白）。模型经 LiteLLM 接入多 provider。

**编排边界（跟读）：** 这是 **SIEM 查询员式** agent，不是带 shell/浏览器/利用链的进攻 agent；SQL-only 也意味着「代码生成更强」可能抬分，却未必等于安全推理更强（官网 Limitations 同点；PDF 主文强调 flat schema 逼近真实 SIEM 写查询技能）。

## 五、结果：PDF 主榜 vs 官网 live 榜（分栏，不混算）

### 5.1 PDF 实验设置（§8）

- Table 4 列 **11** 个模型（含 Claude Opus/Sonnet 4.6、Opus 4.7、Gemini 3.1 Pro / 3 Flash、GPT-5、Kimi K2.6/K2.5、Qwen3.6 Plus、MiniMax M2.7、DeepSeek V3.2）；每模型 runs 数不等（如 Gemini 两档各 **260**，Qwen **12**）。
- 每战役 seed **一次** rollout；统一 system prompt；**无**攻击提示、时间窗、受害主机列表。
- 合计约 **859** hunt runs；API 总成本约 **\$1,672**。

|---|---|---|---|
| Claude Opus 4.6 | **0.55±0.05** | \$17.98±\$4.12 | 4.48%±1.40% |
| Claude Sonnet 4.6 | 0.44±0.08 | \$12.99±\$4.63 | 3.43%±1.12% |
| Claude Opus 4.7 | 0.36±0.13 | \$3.66±\$4.28 | 0.91%±1.59% |

| …（开源档更低） | DeepSeek V3.2 **0.10±0.07** | — | — |

**硬结论（§9.2–9.3）：**

1. **零及格：** 无模型满足「每 tactic ≥50% recall」；Opus 4.6 仅过 **7/13** tactics；其余更差（文述 GPT-5 另有近乎从不提交正确 flag 的 tactic 盲区）。
2. **零完备狩猎：** **任何模型的任何 run** 都未找全全部 flags；领袖平均仍留下 **>45%** 可覆盖叙事步骤未触及。
3. **归因缺口：** Opus 4.6 平均「查询中见到」约 **159** flags，但只提交约 **113**——见到却未一致归因。

### 5.3 Tactic 形态（§9.4，架构读法）

- 相对易：Defense Evasion / Persistence 等——文称常见启发式（编码命令行、注册表 run key、签名二进制代理执行等）可用较简单关键词查询触及。
- 相对难 / 近零：Credential Access、Initial Access、Exfiltration、Lateral Movement、Collection 等——文称痕迹更细、需领域特定查询模式，当前模型**不会自发**生成。
- Table 6 注：表内为 **normalized recall**（以「该 tactic 上任一模型找到的最大 flag 数」为 1.0）——**读表时勿直接当绝对 recall**；及格线讨论用的是绝对阈值叙事。

### 5.4 官网辅源（live board；与 PDF 分列）

研究页（2026-09-22 抓取）报告更大队列：**27** 模型、**1,132** runs、**26** 战役 / **105** procedures、总成本约 **\$1,311**；榜首写作 **Opus 5** Coverage **0.451**、Flag% **4.91**、成本 **\$3.76**/run；及格定义写作「每 tactic **>50%** recall」；同样 **0/27** 及格。页内另强调 **RLVR**：二进制时间戳奖励、Gymnasium API、context morphing「无限非重复 episode」。

> **跟读纪律：** PDF Table 5 与官网 27 模榜 **模型集、成本口径、Coverage 数值均不一致**——可能为后续扩评 / 定价或协议迭代；本笔记 **禁止**用官网数字「修正」PDF，也禁止反向覆盖。引用时必须标明来源层。

### 5.5 狩猎策略观察（§9.5，仅失败/策略标签）

跨模型主导策略文述为 **breadth-first 关键词扫描**：先做范围发现（计数、时间范围、Channel/EventID 分布），再按常见安全相关 EventID 过滤。探索–利用差异：Opus 4.6 更深探再提交（均约 **52** turns），GPT-5 更早提交（均约 **34**）。文论点：相对成本与吞吐，**推理质量**更像主瓶颈（例：Gemini 3 Flash 与 GPT-5 提交量级可比但成本约 **6×** 更低）。

## 六、失败模式与编排含义（§10）——只写防御评测诊断

| 失败模式（文） | 机制压缩 | 对 agent 编排的含义 |
|---|---|---|
| **搜索空间不可行** | 10 行上限 × 7.5万–13.5万行 × 50 查询 → 纯广度扫不够 | 需要「高密度恶意证据」的语义压缩查询；默认 ReAct+SQL 可能不够 |
| **归因缺口** | 见过恶意事件却不提交 | 长对话证据追踪、校准/过度谨慎、提交策略都是独立旋钮 |
| **Tactic 盲区** | 若干 ATT&CK 阶段近零召回 | 领域检测工程知识 ≠ 通用安全问答分数；不能从 CTI-Bench 高分外推 |
| **过早收工（官网叙述）** | 部分低分模型未用尽预算就停止推进 | 无监督部署不可信——停止规则与覆盖完整性要外置监控 |
| **标注/效度上限** | Sigma 误报 + LLM 富集进真值；噪声仅 500 条远小于真实企业日量 | 分数是「相对此真值管线」的进度条，不是绝对 SOC SLA |

**与知识榜的差一句（Conclusion）：** 同模型可在 curated Q&A 安全基准上表现强，却在 **开放式、规模化证据搜集** 上系统性失败——缺口在 **agentic evidence gathering**，不在「会不会背 ATT&CK」。

## 七、相关工作定位（§2 / Table 1）与局限（§12）

**景观一句话：** CTI-Bench / CyberSOCEval 等 = 知识/MCQ；ExCyTIn-Bench = 任务式 Q&A（有引导分解）；SIR-Bench = 事件响应 lexical findings；Simbian 先前 Leaderboard = **告警驱动**端到端调查；本基准 = **无告警 priming 的假设驱动狩猎**，且强调可扩展代码化战役 + 防记忆化 + **成本一等公民**。进攻向 CTF/Pentest 基准（InterCode-CTF、NYU CTF、PentestBench）被明确标为 **进攻对偶**，本篇不跟读其任务内容。

**局限（PDF §12）：** 单 rollout 方差大（建议未来 ≥3 次平均）；**仅 Windows**；缺「先给一条 Sigma 告警再 pivot」的对照设定；全是 **zero-shot**（未 RL 优化 Coverage）；flag 尚未按子链拆分归因。官网另列：固定进攻工具集、SQL-only 对代码模型偏置等。

**复现（§11）：** 26 seeds、模板、仿真与 harness 在固定三元组下确定性；859 条 hunt JSON（对话、逐轮 SQL、发现事件、token、成本）随 release；战役生成器专有，但预构建 campaign JSON 可供独立评。
