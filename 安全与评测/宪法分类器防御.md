# Constitutional Classifiers → Classifiers++（部署侧 jailbreak 防御）

> **主要来源**：[Constitutional Classifiers: Defending against Universal Jailbreaks across Thousands of Hours of Red Teaming](https://arxiv.org/abs/2501.18837)；[Constitutional Classifiers++: Efficient Production-Grade Defenses against Universal Jailbreaks](https://arxiv.org/abs/2601.04603)；[Constitutional Classifiers: Defending against universal jailbreaks](https://www.anthropic.com/research/constitutional-classifiers)（截至 2026-09-22）。下文「CC §x」「CC++ §x」分别指两篇论文，「介绍页」指 Anthropic 研究页；数字以论文为准。
> **研究线**：架构思想（主）——constitution 驱动的输入、输出与 exchange 分类器，生产级的探针级联；评测字段（辅）——红队小时、高风险漏洞发现率、生产拒答率与算力开销。
> **范围与相邻笔记**：
> - ≠ [[安全红队与对抗评测]]：本篇不写红队剧本、众包协议与 ASR 闭环，只借用 universal jailbreak 的成功判据。
> - ≠ [[对齐脉络RLHF与偏好优化]]：本篇不写 SL-CAI、RLAIF 与偏好损失；constitution 在本篇是分类器合成数据的规格书，不是训练期的策略塑形。
> - ≠ [[可扩展监督与弱到强]]：本篇不写 scalable oversight、W2S 与 metagaming。
> - 本篇不收 CBRN 操作细节、完整 constitution 附录与 jailbreak 的复现步骤。
> **意义**：只做 harmlessness 训练挡不住 universal jailbreak，Constitutional Classifiers 把「什么可说、什么不可说」写成自然语言规格，用它合成数据训练部署侧分类器，在数千小时人类红队下没有出现答全目标题的通用越狱；Classifiers++ 再用 exchange 分类、两阶段级联与线性探针，把生产拒答率压到 0.05%、算力开销压到上一代的约 3.5%。这套「探针筛查、分类器复核」的形态随后被 Anthropic 系统卡的 cyber 护栏沿用。

**一句话**：一代用 constitution 合成数据训练 input 与流式 output 两个分类器；二代用看完整对话的 exchange 分类器补上混淆类漏洞，用便宜的一阶筛查加二阶复核降低成本，再用复用被护模型激活的线性探针做几乎零边际成本的一阶。

## 一、问题背景

LLM 的安全机制可以被 jailbreak 绕过，随着 CBRN 相关能力上升，风险更尖锐（CC §1–2）。作者关注的是 **universal jailbreak**：在某一领域的绝大多数目标查询上，可靠地绕过护栏并拿到高度细节、具体的有害信息，效果上等于把模型变成没有护栏的版本。

作者认为，非专家要获得实质 uplift 需要同时满足三点：可靠拿到可核对的准确信息、复杂流程中绝大多数分步查询都能得到帮助、信息足够细致具体。所以防御目标是跨查询、高细节的通用攻击策略，而不是单次的偶发越狱。动机与 Anthropic Responsible Scaling Policy 下的误用缓解承诺挂钩。

防御方案有三条要求（CC §2）：

| 要求 | 工程含义 |
|---|---|
| 鲁棒 | 抗 universal jailbreak，用人类红队与自动评测检验；成功判据是对照 helpful-only 模型的细节量打分 |
| 可部署 | 开销、延迟与误拒可控，保留流式输出与首 token 延迟，报告生产拒答增量与相对推理成本 |
| 灵活 | 威胁面变化时改 constitution 类别即可重新生成数据，已知攻击模式也可写进训练 |

## 二、脉络

- **训练期对齐**：Constitutional AI 用原则与 AI 反馈在训练期塑造策略（见 [[对齐脉络RLHF与偏好优化]]）。本篇沿用「用自然语言原则做规格」的思路，但用在 serving 路径的旁路分类器上，与模型自身的对齐叠成多层防线。
- **2025-01，Constitutional Classifiers**：input 与流式 output 双分类器，原型经数千小时人类红队；2025-02 的公开 live demo 中，约 339 名有经验的 jailbreaker 投入约 3,700 小时后，出现了至少一个被判定为 universal 的策略（介绍页），说明需要互补防御与快速响应。
- **2026-01，Classifiers++**：针对上一代被打穿的两类漏洞与过高开销，改用 exchange 分类、两阶段级联与线性探针，在 Claude Sonnet 4.5 上做 shadow 部署。
- **系统卡中的部署**：Claude Opus 5 的 cyber 分类器写明仿照 constitutional classifiers，采用「全流量 activation probe 筛查、可疑则升级到 LLM 分类器」的两段式（见 [[ClaudeOpus5系统卡深读]]）；Fable 5.1 卡同样称其护栏 modeled on constitutional classifiers（见 [[ClaudeFable与Mythos51]]）；Opus 5.5 扩为 activation probe → 轻量分类器 → LLM 分类器三阶段（见 [[ClaudeOpus55系统卡短报]]）。

## 三、一代：Constitutional Classifiers

### 3.1 流程：constitution → 合成数据 → 双分类器

1. **Constitution**：用自然语言同时写有害与无害类别（例如讲解家用化学品允许，受限化学品的提纯与放大不允许）。无害类别对压低误拒是必要的；规格可快速修改，同一标注集也能训练其他护栏形态（如线性探针，二代展开）（CC §3.1）。
2. **合成数据**：helpful-only 模型按 constitution 生成查询与有害、无害回复，过滤误拒；再做翻译、改写、系统提示变体、已知 jailbreak 技法等增强，加上自动红队模板（含长上下文与多轮），良性数据来自承包商而非生产流量。
3. **双分类器**：output 分类器在流式生成中逐 token 预测「整段是否有害」，挡住许多流行的通用策略；input 分类器拦截专门绕过 output 分类器的输入，例如建立编码信道、让输出离开输入就无法读懂的混淆。

**流式 output 的做法**（CC §3.4）：在微调 LM 上加线性 value head，用前缀 $t_{1:T'}$（$T'\le T$）预测整段序列的标签 $y$，分数超过阈值就立即停止输出。

### 3.2 人类红队（原型，CC §4）

- 约 800 名申请者中邀请 405 人，通过 HackerOne 赏金计划，单份报告最高约 $15K；目标是 10 条 CBRN 信息危害查询，要求跨查询的 universal 式细节。
- 原型分类器从 Claude 3.5 Sonnet 微调，偏鲁棒、拒答高。工作量摘要写超过 3,000 小时，脚注估计均值约 4,720 小时（90% CI 3,242–7,417）。
- **结论**：在「达到 helpful-only 一半细节」的阈值下，没有报告答全 10 题；在更严的「相近细节」标准下，单份报告最多约 5 题，按人聚合最多 6/10。
- **攻击者打的是评测最弱环**：高分报告多在钻 rubric、良性改写与超长灌分的空子，而不是经典的 DAN 或 many-shot。
- **基础设施教训**：一个看似 universal 的漏洞，实际是部署 bug，output 分类器已标记后仍泄漏了最多 128 个 token。分类器和部署管线都需要红队。
- **组件消融**（CC §4.3，Fig.5）：helpful-only 模型 ASR 约 16%，HHH 模型约 14%，加 input 分类器约 2%，再加 output 分类器约 0.5%。只靠 harmlessness 训练远远不够，降幅主要来自分类器。

### 3.3 改进版的部署可行性（CC §5，化学武器 constitution）

改进版从 Claude 3.5 Haiku 微调 input 与 output 分类器，保护 Claude 3.5 Sonnet (New)；改进手段包括扩大无害 constitution、重新校准阈值、加强增广与改用更小的分类器底座。

| 维度 | 数字 |
|---|---|
| 自动评测 ASR | 无分类器约 86% → 加分类器约 4.4%，即挡住约 95% |
| 生产拒答增量 | Claude.ai Free 与 Pro 随机 5K 对话上绝对 +0.38%（介绍页称不显著） |
| 相对推理开销 | +23.7% |

阈值按约束优化校准：在 jailbreak 集上最大化 TPR，同时限制相对无防护模型的误拒增量（如 WildChat 多轮不超过 0.5%、单轮不超过 5%、OR-Bench 不超过 5%）。

## 四、二代：Classifiers++

### 4.1 上一代被打穿的两类漏洞（CC++ §2）

- **Reconstruction**：把有害请求拆散藏进良性上下文（如代码库中的函数返回值），再让模型重组并作答，可再叠加输出混淆。代价是能力下降但仍可观：Claude Opus 4 在 GPQA Diamond 上无混淆为 74.2%，两种示例攻击下为 32.3% 与 49%。
- **Output obfuscation**：用隐喻、替换敏感词、谜语等方式，让输出离开输入就难以理解，专打只看 output 的分类器。

两者的共同点是利用「孤立看 input、孤立看 output」的空隙，架构上的回应是把判决绑回完整上下文。

### 4.2 Exchange 分类器（CC++ §3）

exchange 分类器先像 input 分类器那样看提示，再在生成中按批检查输出，但始终带着完整对话上下文；prompt caching 使持续复评可行。阈值对齐 WildChat 0.1% 拒答时，高风险漏洞发现率从双分类器的 0.01871 / 千查询降到 0.00885，约少 2.2 倍；代价是算力约 +50%。

### 4.3 两阶段级联（CC++ §4）

一阶用轻量分类器筛查全部流量，被标记的请求**升级**到二阶而不是直接拒绝，因此一阶可以容忍更高的假阳、用更便宜的模型。二阶为 Haiku 4.5 级 exchange 分类器，一阶成本约为二阶的 1/3，约 10% 流量进入二阶。相对单个 exchange 分类器成本降 5.4 倍（含管线和新模型；只换二阶模型约 3 倍），高风险漏洞发现率 0.00878 / 千查询，与 exchange 相当。

### 4.4 线性探针（CC++ §5）

探针直接读取被护模型自身的激活，在采样过程中逐 token 判断：

$$
p_{\mathrm{probe}}(y=1\mid x_{1:t})=\sigma(W^\top\psi_t(x_{1:t})+b),
$$

其中 $\psi_t$ 可取单层或多层拼接的激活。标签是整段交换级的，决策却要在前缀上做，作者用两个改动弥合这一错位：

1. **滑动窗均值平滑**：训练时对最近 $M$ 个 logit 取均值，推理用 EMA，避免单个 token 的尖峰误杀整段输出。
2. **Softmax 加权 BCE**：把梯度集中到「最确信有害」的位置，允许无害的公共前缀被自信判为无害，并重罚无害序列上的假阳（流式一旦标记，后续全部中断）。

主要发现：全层探针约 1.4% ASR，接近小型外部分类器；平滑与 softmax 加权组合最好；探针与外部分类器的相关性较低，两者组合优于纯外部分类器的组合；用探针做一阶路由、二阶平均探针与小分类器的 logit，可比全程用小分类器省约 100 倍算力，鲁棒性不差。探针复用已经算好的激活，边际成本近乎为零。

### 4.5 生产级系统（CC++ §6）

全程运行线性探针，超过阈值则升级到外部 Constitutional Classifier（Haiku 4.5），升级路径的最终分数为 $z_{\mathrm{final}}=0.55\,z_{\mathrm{probe}}+0.45\,z_{\mathrm{classifier}}$，保护 Claude Sonnet 4.5。

- **Shadow 部署**（2025-12-01 至 2026-01-01 的生产流量）：拒答率 0.05%，约 5.5% 流量升级到二阶；成本比单个 exchange 分类器低约 40 倍，比无探针的级联低约 8 倍。
- **红队**：累计约 1,736 小时、约 198K 次尝试，只发现 1 个高风险漏洞（0.005 / 千查询，全文最低），发现它用了 30 小时；没有出现答全 8 题且达到无护栏一半细节的 universal jailbreak。

| 系统（CC++ Table 1） | 相对算力（上一代 = 100） | 高风险漏洞发现率（/千查询） | 生产拒答率（%） |
|---|---:|---:|---:|
| 上一代双分类器 | 100.0 | 0.01871 | 0.073 |
| Exchange | 150.0 | 0.00885 | 0.038 |
| 两阶段级联 | 27.8 | 0.00878 | 0.036 |
| 生产级 | 3.5 | 0.00505 | 0.050 |

## 五、意义

1. **规格写在 constitution 里**：有害与无害类别显式成文，合成数据可再生，边界可解释，威胁面可以随时改。
2. **护栏是 serving 路径上的多层，不替代对齐训练**：HHH 训练单独几乎不降 ASR，分类器叠层才把红队子样的 ASR 压到亚百分点。
3. **流式是一等约束**：output、exchange、探针都必须能在前缀阶段停止；训练标签与推理决策的错位，用平滑与非对称加权来补。
4. **上下文绑定克制混淆**：reconstruction 与隐喻替换专打孤立的 output 判断，exchange 把输入绑回判决。
5. **级联把假阳变成升级**：一阶激进召回，二阶才拒答，小模型也能扛住生产流量。
6. **探针复用已付费的表示**：近乎零边际成本，且与外部分类器低相关，组合后同时提升鲁棒性、降低开销。
7. **评测要覆盖基础设施**：128 token 的泄漏说明红队必须覆盖部署接线，而不只是分类器权重。

## 七、局限与待核实

- **一代自述的局限**（CC）：原型拒答过高；仍发现局部脆弱；红队人群不等于全部对手；激励只到「一半细节」可能低估更强的攻击；rubric 难以区分背景知识与可产生 uplift 的操作信息；场景偏 chatbot 与预设题目。
- **universal 并非不可能**：2025-02 的公开 demo 中出现了被判定为 universal 的策略；CC++ 脚注也承认赏金之外的专家借助大量自动化仍能找到 universal，只是成本高。
- **数字须分系统阅读**：一代的「3,000+ 小时、10 题、+0.38%、+23.7%」与二代的「约 1,736 小时、8 题、0.05%、约 40 倍降本」题目数、护栏代数与校准集都不同，只能比较同一张表内的相对顺序。一代摘要的 0.38% 来自 Haiku 保护 Sonnet 的化学 constitution 改进系统，不能与 CC++ Table 1 中「上一代」一行的 0.073% 混读。
- **探针结论的设定**：探针分析基于 Claude Sonnet 4 全层激活与静态 CBRN jailbreak 集（WildChat 0.1% 校准），约 100 倍省算力等结论限于该设定。
- **未展开的内容**：完整 constitution、分类器提示模板与评测附录只作存在性引用，相关细节以论文附录为准。
