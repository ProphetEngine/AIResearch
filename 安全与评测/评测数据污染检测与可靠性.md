# 评测数据污染：检测方法、可靠性鸿沟与抗污染基准

> **主要来源**：[Data Contamination Quiz](https://arxiv.org/abs/2311.06233)（Golchin & Surdeanu，v7）；[Towards Data Contamination Detection for Modern Large Language Models: Limitations, Inconsistencies, and Oracle Challenges](https://arxiv.org/abs/2409.09927)（Samuel、Zhou & Zou，v2）；[The Reliability Gap in Benchmark Auditing](https://arxiv.org/abs/2606.03305)（Zarzecki、Dubiński & Cygert，v2）；[LLM Benchmark Datasets Should Be Contamination-Resistant](https://arxiv.org/abs/2605.19999)（Al-Lawati、Lucas、Lee & Wang，v1）（截至 2026-07-01）。
> **研究线**：评测字段 · 方法局限（主）；基准发布规范（辅）
> **范围与相邻笔记**：
> - ≠ [[评测与排行榜可靠性]]：污染概念三分、Claude 4 / o1 System Card 个案、thinking / 路由 / scaffold 可比性在那篇；本篇只写「怎么测污染、测为何不准、发布时如何抗污染」。
> - 本篇沿一条问题链展开：怎么测（检测轴与 DCQ）→ 测不准（2409 的不一致、Reliability Gap 的野外失效）→ 改发布（Contamination-Resistant Dataset，下称 CRD）。
>
> **意义**：污染检测不是单一仪表。语料侧 n-gram / canary 管「进没进训练语料」，行为侧 quiz / 补全 / 概率探针管「像不像背过」；2024 年的系统评估显示这些探针互不一致，2026 年的野外审计中三种 SOTA 数据集推断方法在 335 次评测里只答对 201 次。缺协议的「污染率」与缺检测轴说明的「已去污」同样不可信，基准设计因此开始转向「发布时就抗污染」。

## 一、问题背景

评测数据污染指评测题（或其改写、答案）进入了模型的训练数据，使榜分反映记忆而非能力。按谁能拿到什么，检测分两路：

- **有语料权的训练方**：直接比对训练语料与评测题（exact / n-gram / substring），或依靠评测集里的 canary 字符串排除。
- **只能调用模型的第三方**：只能从模型行为推断它是否见过某题或某数据集（quiz、补全重叠、似然统计、数据集推断）。

两路都有失效模式，评测社区的回应也分两步：先承认事后检测靠不住，再把抗污染前移到基准发布环节。

## 三、核心思想：检测轴地图

下列各轴是不同的工具族，测的不是同一个量，不能互相替代。

| 轴 | 信号 | 谁能用 | 典型失效 |
| --- | --- | --- | --- |
| 语料侧 n-gram / exact / substring | 训练语料与评测题的高阶 n-gram 或精确重叠 | 有语料的训练方；给出近似比例而非铁证 | 改写、翻译、蒸馏造成的间接泄漏难以匹配；fuzzy 阈值决定假阳性 |
| Canary 字符串 | 评测集嵌入可机读标记，训练方据此排除或检索 | 数据发布方与训练方合作 | 依赖训练方遵守；改写后标记丢失 |
| Quiz（词级扰动选择题） | 能否在原句与近义改写中认出原词面，作为 verbatim 记忆代理 | 黑盒 I/O 即可 | 扰动不如原文流畅、专名数字成捷径，可能高估 |
| 补全 / token overlap | 给数据集名与前缀，看后续是否逐字复现 | 黑盒；近匹配常由另一模型裁判 | 裁判歧义与偏见；前缀选取影响结果 |
| 概率侧 Min-K% / canonical order | 最低概率 token 的均值；规范序与打乱序的似然差 | 需 logits 或参数 | 阈值难定；假设强；计算成本高 |
| 数据集推断（LLM DI / Post-Hoc DI / CoDeC） | 聚合成员推断特征做假设检验，或看同数据集上下文是否降低置信 | 需 logits 与参考集 | 参考集与可疑集不 IID 时误报；基准太小时欠功率（第六节） |
| 时间窗 / cutoff 纵向 | 截止前后同难度题的通过率落差，或只报晚于 cutoff 发布的题 | 需持续收题与可信 cutoff | cutoff 自报；纵向可比性依赖题目难度一致 |

工业界有语料时的实际做法可参照 [[ClaudeOpus45系统卡深读]] 2.4 节：substring 剔除、20-gram fuzzy 匹配、canary 三法并用加人工抽查，仍承认存在疑似记忆的泄漏个例。

## 四、Data Contamination Quiz（2311.06233）

### 4.1 假设与题型

- **核心假设**（§2）：若实例曾 verbatim 进入训练，模型应能在「原句 + 若干词级近义改写」中认出原词面。
- **五选一**：1 个原文选项 + 3 个由 GPT-4 生成的词级扰动（保意、保结构、彼此不同）+「E) None of the provided options」。
- **只输出 A–E 一个字母**：降低采样噪声，也更容易绕过「不得复述版权内容」一类安全过滤（相对开放式复述）。

### 4.2 位置偏差补偿

| 步骤 | 作用 |
| --- | --- |
| BDQ（Bias Detector Quiz） | 四个选项全是扰动加 E，找出被选频率低于随机的 non-preferred 槽位 |
| BCQ（Bias Compensator Quiz） | 把原文放进 non-preferred 槽，多轮置换，估出污染区间 [min, max]，兼顾高估与低估 |

作者说明：方法以 memorization 为检测依据，文中把 memorization 与 contamination 当作可互换的概念使用（脚注）。读结论时要记得这层代理关系。

### 4.3 作者自述的边界

- 只估 verbatim 污染，metadata 级、非逐字污染不在范围内。
- 私有或半私有评测不能当长期解。作者举例：o3 在 ARC-AGI-1 上接近人类水平，在难度相近、新发布的 ARC-AGI-2 上只得个位数（Limitations）。

## 五、方法局限的系统评估（2409.09927）

### 5.1 设定

五种方法 × 四个模型（GPT-4、Claude 3 Sonnet、LLaMA-3-Chat 70B、LLaMA-2-Chat 70B）× 八个基准；另以 LLaMA-2-70B-chat 全参微调，按不同比例掺入六个较新的难基准、并把答案替换为 LLaMA-2-70B 生成的 CoT 解答，构造已知污染比例的 oracle。

五种方法：

1. Token Completion Overlap
2. Min-K% Prob
3. Word Perturbation Quiz（WPQ，即 DCQ 一族）
4. Instance Local Order Quiz（作者试点：问原数据集中哪一条紧接在目标之后）
5. Canonical Order Statistical Testing

### 5.2 各方法的局限（据文内）

| 方法 | 局限 |
| --- | --- |
| Min-K% | 「发布前即污染」的假设过强；实际使用缺阈值 |
| Canonical order | 长实例、分片与置换的成本高；依赖「网页仍保留规范序」等强假设 |
| Token overlap | 近匹配常交给 GPT-4 裁判，有歧义与偏见；前缀选哪一段会影响结果 |
| WPQ / DCQ 族 | 扰动常不如原文流畅；专名、数字、未扰动的标签可成捷径，可能高估污染 |
| Local order quiz | 既要见过局部顺序，又要语义检索成功，任务本身极难 |

### 5.3 三条总判

1. 方法的假设与落地都有非平凡限制：在传统基准和早期模型上有效，不等于在难基准和当代模型上可信。
2. 在「指令微调 + CoT 答案增强」的 oracle 上，五种方法都难以稳健反映已知污染比例；微调后所有 Min-K% 值反而下降，与「原题仍在训练数据里」的直觉相反。
3. 方法之间的 Spearman 相关很弱（Table 3），几种公认方法不可能同时都对，不能凭单一方法判定某模型在某数据集上「污染了百分之几」。

作者还提醒：Table 1 中 WPQ 在多个模型和数据集上准确率偏高，更可能是模型识别出了扰动痕迹，而不是真的检出污染。引用 WPQ / DCQ 数字时应带上这一保留。

## 六、Reliability Gap：野外审计为何失真（2606.03305）

### 6.1 问题与总账

现有成员推断与数据集推断工具几乎只在「大而同质的预训练语料 + 透明的单阶段管线」上验证过。作者锁定两个欠研究的失败模式：

1. **分布偏移**：可疑集与参考（validation）集违反 IID；
2. **规模约束**：基准比预训练语料小若干个数量级。

评测对象为三种范式（LLM Dataset Inference、Post-Hoc Dataset Inference、CoDeC），覆盖 Pythia、OLMo 2、医疗 LLM、波兰语 PLLuM 等共 25 个模型（21 个开放指令微调模型加 4 个仅预训练模型，最大 27B），并延伸到工业模型族。335 次评测中只有 201 次正确（约 60%）。

### 6.2 三种方法的接口

| 方法 | 核心检验 | 判决阈值（文内） | 脆弱点 |
| --- | --- | --- | --- |
| LLM DI | 在可疑集与未见参考集上聚合弱 MIA 特征，单侧 t 检验 | $p < 0.1$ 判为训过 | 参考集须未见且与可疑集近似 IID；split 难度或风格差异导致假阳性 |
| Post-Hoc DI | 用小生成器造合成后缀作参考集，比较「纯文本分类」与「文本 + MIA」能否区分 | $p < 0.1$（相对文本基线） | 基准规模下生成器太弱，真实与合成的分布差异淹没记忆信号 |
| CoDeC | 同数据集的上下文样例是否降低下一 token 置信；分数为 $\Delta(x)<0$ 的样本比例 | $>0.8$ 强污染，$<0.6$ 无，中间不确定 | 只适合粗粒度 provenance；近 IID 的 train / test 难区分 |

配置（§4.1）：LLM DI 每侧用 250 个样本训线性分类器，至少 1,000 篇文本做 t 检验；Post-Hoc DI 每个子集取 2,000 篇，由 LoRA 微调的 Llama-3.1-8B 生成 128-token 后缀，以 GPT-2 文本分类器作校准基线；CoDeC 只用 1 个随机上下文样例，从第 10 个 token 起平均 log-prob。

### 6.3 四个任务

- **Task 1 · 有限参考数据**（Pile 子样 n = 2,000，Pythia）：能给出真 IID 参考集时，LLM DI 在 Hacker News / Stack Exchange 一组达到 16/16，Pile CC / Europarl 一组 12/16；Post-Hoc DI 多在 4–8/16；CoDeC 常给 train 与 test 同样高的分（8/16 量级），高分可能来自见过 train，也可能只因两个 split 分布太近。
- **Task 2 · OLMo 2 的 split 级判定**（已知 GSM8K train 进入后训练，MMLU / DROP train 未进入）：LLM DI 12/18，但对未训过的 MMLU / DROP train 仍出现假阳性，作者解释为同基准 train / test 看似 IID，仍可能因难度或构造差异驱动检验；Post-Hoc DI 13/18（GSM8K test 过小，标为 n/a）；CoDeC 9/18，GSM8K 分数偏高符合已知暴露，但 DROP / MMLU 只略低，且分数随模型变大而下降（Fig. 2）。
- **Task 3 · 专科后训练**（医疗 QA 与 PLLuM 的 SFT / Alignment 数据）：信号更不稳。MedQA-USMLE 上 LLM DI 漏检全部 train；PLLuM 的小 split（Automatic 约 1,600、Manual 约 1,150）上 LLM DI 对 SFT 数据反复假阴性，对 Alignment 数据又出现假阳性；CoDeC 跨家族方差大。
- **Task 4 · 工业模型比较**（Gemma 3、Qwen 3、Llama 3.2，无成员真值）：多数家族在 GSM8K / MMLU / DROP 上 CoDeC 偏高且常被 LLM DI 旗标；Gemma 3 是例外，CoDeC 更低，且是 GSM8K train 上唯一未被 LLM DI 旗标的系列，作者据此推断它不大可能训过 GSM8K train（比较性推断，非定论）。

### 6.4 失败诊断（§5.5）

- **LLM DI：IID 是致命弱点。** 可控 IID 时成功，改用 test 作参考集代理后出现假阳性，说明检验捕捉的是 split 分布差而非训练暴露。没有分布对齐时，不宜把 LLM DI 当作榜单完整性的唯一裁决。
- **Post-Hoc DI：基准规模下欠功率。** 基准规模下纯文本基线 AUC 已高于 0.78，加 MIA 特征几乎无增益，分类由「真实 vs 合成」的分布差主导，校准检验只答对 12/32；改用作者发布的、几乎用全量子集训练生成器的 held-out 集后，基线 AUC 降到约 55%，正确数升到 23/32。失败的原因是标准基准的文本量不足以训出匹配的生成器，而不是方法本身无效。
- **CoDeC：粗 provenance 可用，细 split 不够。** Pythia 上预训练语料的分数远高于只出现在评测中的基准，但同一语料的 train / test 几乎同分；OLMo 2 上聚合后呈「预训练 > 后训练 > 仅评测」的粗序，相邻组重叠大。适合多模型同基准的比较与找离群，不适合认证单个 split。

### 6.5 作者的实践建议

| 工具 | 可用条件 | 不宜用途 |
| --- | --- | --- |
| LLM DI | 确有未见且近似 IID 的参考集 | 默认拿 test 当参考集来担保榜单完整 |
| Post-Hoc DI | 能独立评估合成 held-out 的质量，且数据量足够训生成器 | 在标准基准规模上开箱即用 |
| CoDeC | 粗比较、家族间相对信号 | 认证某个评测 split |
| 共同 | 作为互补证据 | 替代透明的数据 provenance |

作者自述局限（§6）：使用共享接口的默认超参；开放模型审计最大到 27B；工业模型没有成员真值；没有提出克服这些失败的新检测器，「能容忍多大偏移、需要多少数据」仍是开放问题。

## 七、Contamination-Resistant：发布时就抗污染（2605.19999）

### 7.1 立场与定义

**立场**：基准应以 contamination-resistant 形式发布，即对公开释放的形态不可学习（unlearnable），但仍支持推理（support inference）。

**Definition 2.1（CRD）**：相对模型 $M$ 与变换 $\phi$，公开形态 $\phi(D)$ 满足：推理效用 $M(\phi(D))$ 仍然有效；而在 $\phi(D)$ 上的训练步 $\nabla_\theta L(M_\theta,\phi(D))$ 无法提升泛化表现。

三条性质（§2.3）：

1. **Irreversibility**：在现实的对抗能力下，从 $\phi(D)$ 恢复明文 $D$ 在计算上困难或不经济；
2. **Equivalence**：$M(\phi(D)) \approx M(D)$；
3. **Interoperability**：可把 $\phi(D)$ 迁到另一模型 $M_1$ 的 $\phi_1(D)$，仍满足前两条。

明文一旦上网就可能被爬取，所以文本要抗污染，必须映射到潜空间或推理专用的形态，不能整包释放明文题干。

### 7.2 机制：Transformer 训练与推理的不对称（§3）

- **训练**需要整段 token，才能算出各位置各层的隐状态与下一 token 损失；微调同样需要整段序列。
- **推理**主要依赖各层 KV cache $\{K_{1:t}^{(l)}, V_{1:t}^{(l)}\}$ 与倒数第二层末位隐状态 $h_t^{(L-1)}$。

因此发布格式取（式 3）：

$$
\big(\{K_{1:t}^{(l)}, V_{1:t}^{(l)}\}_{l=1}^{L},\; h_t^{(L-1)},\; Y\big)
$$

模型可据此继续生成并接受评测，但拿不到预训练所需的原始 token 序列。标签 $Y$ 可以明文发布，因为没有配对的输入就无法把答案绑回问题。

### 7.3 评测流程（Fig. 2）

| 阶段 | 做什么 |
| --- | --- |
| Curation | 用一个或多个锚模型把 test 题干投到潜表示，只释放推理所需的形态；附 datacard 与少量明文样例，供跨模型翻译 |
| Discovery | 评测方把 CRD 翻译到目标模型；同一锚模型到目标模型的映射可复用于后续同锚 CRD |
| Evaluation | 翻译后的表示喂给目标模型自回归生成，目标模型始终看不到明文题干；输出对明文 $Y$ 用 Exact Match、语义相似度等常规方式打分 |

### 7.4 互操作的两种范式（§4）

| 范式 | 做法 | 文内技术锚 |
| --- | --- | --- |
| 近程：锚模型 + 子空间对齐 | 指定一个广泛使用的锚模型编码 KV 与隐状态，目标侧计算对齐映射 | Cross-LoRA、Trans-LoRA、LoRA-X；对齐只依赖权重，不碰明文，从而保住不可逆性 |
| 远程：相对表示 | 相对一组固定锚样本，把各模型的潜表示投到共享坐标 | relative representations、semantic alignment；锚样本通常 100–500 个，且不与受保护的评测内容重叠 |

等价性风险（§5）：长序列翻译可能漂移，可用蒸馏对齐、prompt tuning、自适应温度等方式校准；社区可用锚模型配对评测或分布检验，审计编码后是否仍在测同一种能力。

### 7.5 适用边界、存储与对替代路径的批评

- **较适用**：单轮 QA（MMLU、SQuAD、HumanEval）、分类、多模态图文对、代码生成、摘要等输入输出结构可分的任务。
- **较难**：多轮对话、高度动态的 agent、自适应换题、金标依赖轨迹的任务（CoQA、WebShop、DynaBench、GAIA、MLE-bench 等），或只对子组件采用 CRD。
- **存储**：文中引用 LLaMA-2 7B 上 100K token 的 KV cache 约需 50GB 磁盘；用 PyramidKV 等压缩后可降到约 350MB / 100K tokens。
- **架构限制**：依赖 Transformer，不适用于 Mamba 等非 Transformer 模型；Transformer 各家族在注意力与位置编码上的差异如何影响安全与保真，作者称超出范围。

| 替代路径（§6） | 文内主要批评 |
| --- | --- |
| 私有评测（如 TRUCE） | 能防泄漏，但抬高独立验证门槛、吞吐与开源成本；专有模型难以交出权重 |
| 动态基准 | 新题很快再被摄入；纵向可比性差 |
| 词面混淆 / 改写 | 现代模型常已见过改写形态，新的污染甚至更难过滤 |
| 去污 / n-gram 过滤 | 召回与精度难兼顾；难挡改写、翻译、蒸馏造成的间接泄漏；语料越大越不够 |

社区呼吁（§7）：推进 CRD 方法与 stitching 等低摩擦采用方式；把锚模型标准化为通用编码器；把 CRD 校验接入现有数据集管线（文中以 Hugging Face 为例）。

## 八、合读：测、测不准、改发布

| 问题 | 检测方法（第三至五节） | Reliability Gap | Contamination-Resistant |
| --- | --- | --- | --- |
| 榜分虚高怎么办 | 有语料时做 n-gram / canary；无语料时用行为探针，但结论只是区间或代理 | 统计旗标不能单独认证，需要数据 provenance | 从发布形态切断「可预训练」 |

## 九、常见误区

1. **把 DCQ 区间当成语料审计报告**：DCQ 给的是 memorization 代理下的 verbatim 污染区间。
2. **把 quiz 高分直接等同「榜分造假已查明」**：2409 显示 WPQ 高分可能来自识别扰动痕迹；检索泄漏、格式或分布污染也不在 quiz 能测的范围内。
3. **把 LLM DI 的 $p<0.1$ 写成「该榜已污染认证」**：参考集不 IID 时它会误报。
4. **把 CoDeC 高分写成「某个 test split 必然泄漏」**：同一语料的 train / test 几乎同分。
5. **把 Task 4 的家族间比较写成「已证实某厂商训过某数据集」**：作者只做比较性推断。
6. **把 CRD 写成又一种私有排行榜**：CRD 公开释放推理形态，由评测方独立翻译与打分。
7. **把 KV 反演攻击文献当成「CRD 已被攻破」**：作者讨论了 GQA 等现代注意力下反演更难，并列出加噪、差分隐私、KV-Cloak 等防御，结论取决于威胁模型。
8. **把某家后来的去污流程倒推到早期版本**：引用 Claude 的去污流程要注明是哪一版 System Card（见 [[评测与排行榜可靠性]] 2.4 节）。

## 十、意义

- **把「污染率」从一个数字还原成一组带假设的探针**：引用任何污染结论时，要先问用的是哪条检测轴、谁能拿到什么、在什么基准与微调设定下验证过。
- **给出野外审计的可靠性下限**：Reliability Gap 用 335 次评测说明，统计审计目前只能作为互补证据，替代不了训练方公开数据 provenance。
- **把抗污染前移到发布环节**：CRD 利用 Transformer 训练与推理的不对称，提出「可推理、难预训练」的发布形态，与事后去污、私有评测、动态换题形成可比较的几条路线。

## 十一、局限与待核实

- **DCQ 的代理关系**：只估 verbatim 污染，且以 memorization 代替 contamination；非逐字污染无法覆盖。
- **2409 的 oracle 范围**：只在 LLaMA-2-70B-chat 一个模型、六个基准上构造已知污染，结论能否推广到其他微调配方未验证。
- **Reliability Gap 的范围**：默认超参、开放模型最大 27B、工业模型无真值，作者未提出新检测器；文内给出的代码地址是匿名评审仓库，无法公开访问，代码未核对。
- **CRD 尚无实证系统**：2605.19999 是立场文，没有独立的检测或编码代码仓；不可逆性在真实反演攻击下能维持多久、长序列翻译的等价性能否保持，均待后续工作。
- **工业去污流程**：各家去污附录（fuzzy 阈值、假阳性处理）只以个别系统卡为例，本篇未逐家核对。
- **LiveCodeBench 时间窗**：LiveCodeBench 原论文的去污协议本篇未核，不展开。
- **版本**：所引数字依据 2311.06233v7、2409.09927v2、2606.03305v2、2605.19999v1。
