# Malware analysis agents / evals：TTPDetect + 开源小模型编排

> **主要来源**：[Identifying Adversary Tactics and Techniques in Malware Binaries with an LLM Agent](https://arxiv.org/abs/2602.06325)；[Small, Free, and Effective: Orchestrating Open-Weight Small Language Models to Outperform Single LLM for Malware Analysis](https://arxiv.org/abs/2607.20216)（截至 2026-09-22）。下文「TTPDetect §x」「SLM 编排 §x」分别指两文章节。
> **研究线**：评测字段（主）——函数级 P/R/F1、报告覆盖率、CyberSecEval exact-match 与难度分层；架构思想（辅）——混合检索入口、按需上下文探索、推理时对齐指南，以及「证据管道 + 接地辩论」的 hybrid 编排。
> **范围与相邻笔记**：
> - ≠ [[网络防御基准]]：本篇不写开放式日志狩猎榜（Coverage Score、SQL-only Holodeck 战役）。
> - ≠ [[安全红队与对抗评测]]：本篇不写红队 ASR、攻击面聚类与 mitigation 训练闭环。
> - ≠ [[多智能体辩论]]：本篇不写 MAD 协议通史，只取「无接地的辩论会漂移」一句。
> - 本篇不收恶意样本制作、利用步骤、渗透手册与可复用攻击配方；案例只作评测输入形态与失败模式的索引。
> **意义**：两文把防御侧恶意软件分析收成可回归的评测：给定分析产物，测 agent 能否贴对 ATT&CK 标签、答对结构化问题，并要求编排增益同时对照单模型和「同一证据管道」下的强模型。结论是证据接地带来与模型规模无关的增益，但最好的开源编排 35.30% 的准确率只够做分析师辅助。

**一句话**：TTPDetect 把「从剥离符号的二进制里认出 TTP」拆成检索入口、按需上下文、推理时对齐三段，函数级 P 93.25% / R 93.81%；SLM 编排在引爆报告问答上让 Qwen3-4B + Foundation-Sec-8B 的 hybrid 达到 35.30%，超过最强的未接地 frontier（Gemini 34.77%），但仍低于接入同一管道的 Gemini（38.22%）。

## 一、问题背景

ATT&CK 是 MITRE 维护的对手战术与技术知识库，TTP 指其中的战术、技术与过程。两文都要从分析产物中给恶意样本贴 TTP 标签或回答分析问题，区别在输入：

- **静态二进制侧**（TTPDetect §2）：剥离符号后，一个二进制有数百到数千个函数，要对 200 多个 TTP 逐一判断，穷举不可行；恶意行为常跨多个函数，单看一个函数容易漏检或被函数名误导；表面线索还会把相邻 TTP 搞混（如看到「removal」就误标 T1070）。
- **动态报告侧**（SLM 编排 §3）：沙箱引爆报告是很长的 JSON，单次调用 LLM 会遇到三类失败：报告超出上下文被迫截断、按关键词表面匹配到错误的家族意图、缺少 ATT&CK 细分技术的领域知识。SLM 编排还加了一条现实约束：只用单卡（≤8B、4-bit、一颗 RTX 4090）、零 API 费用，能否追上单颗大模型。

两文都测「解释已有行为」的分析理解与归因，不测如何制作样本或利用漏洞。

## 二、脉络

防御侧 cyber agent 评测在 2026 年分出几道题。TTPDetect（2026-02）做静态二进制上的函数级 TTP 识别；[[网络防御基准]]（2026-04）测无引导问题、无告警种子的开放式日志狩猎，要求在 Windows 遥测里提交恶意事件时间戳；SLM 编排（2026-07）回到给定分析产物的设定，用 CyberSecEval 的 Malware Analysis 子集（CyberSOCEval）测引爆报告问答，并把「编排能否替代大模型」作为研究问题。

本篇两文和狩猎榜的分界在输入：狩猎榜问的是能否在海量遥测里**发现**恶意事件，本篇问的是给定分析产物后能否**贴对 TTP、答对结构化题**，以及编排相对单模型是否真有增益。

## 三、TTPDetect：静态二进制上的 TTP 识别

### 3.1 任务形式化

令 $F_{\mathrm{bin}}=\{f_1,\ldots,f_n\}$ 为剥离二进制恢复出的函数集，$T=\{t_1,\ldots,t_m\}$ 为待判的 ATT&CK TTP，目标是对每个 $(f,t)$ 判定 $f$ 是否实现 $t$（TTPDetect §3）。三段策略与上述三个难点一一对应：

| 难点 | 解法 | 作用 |
|---|---|---|
| 入口爆炸 | 混合检索：dense top-$k$ 保召回，再由 LLM 宽松提议 TTP 并按置信度 $P(t\mid f)>\tau$ 剪枝 | 完整管道相对纯 dense 的候选对减少约 85.89%（TTPDetect Fig. 9） |
| 部分可观测 | Context Explorer：以工具方式按需取 caller / callee 上下文，剪掉通用 utility | 补足跨函数行为，主要抬召回 |
| 推理错位 | 推理时对齐：离线从 ATT&CK 为每个 TTP 合成指南（正负指标、区分准则），推理时当 checklist | 约束判断，主要抬精度 |

### 3.2 管道与数据

- **预处理**：重命名 agent 自底向上，用函数体与直接 callee 的摘要生成名称和 1–3 句说明，缓解反编译后地址式标识符没有语义的问题（TTPDetect §4）。
- **实现**：AutoGen v0.6.1，主模型 Claude 3.7 Sonnet，IDA Pro 7.6 反编译，ATT&CK v16.1；检索用 text-embedding-3-large 与 FAISS。
- **Dataset I**（函数级真值）：18 个公开泄露的 C/C++ 项目编译后剥离，Linux 与 Windows 均有，覆盖 12 个家族、42 个独特 TTP、210 个函数–TTP 对；编译后的函数数可达源码的约 40 倍（TTPDetect §5.1，Table 1）。
- **Dataset II**（二进制级）：8 个来自 MalwareBazaar / VirusShare 的真实样本，只有 2 份有专家报告可算报告覆盖率；家族级 ATT&CK 表不能直接当作单样本真值。
- **标注效度**：两名作者独立标注、附代码级证据后协商；为缓解预训练泄漏，用训练截止后出现的 Umbrellastand / DamascenedPeacock 作检验（TTPDetect §6）。

## 四、TTPDetect 的证据

函数级评测选出现至少 5 次的 14 个 TTP，共 181 个函数、2,534 个二元分类实例（TTPDetect §5.2，Table 2）：

| 系统 | Precision | Recall | F1 |
|---|---:|---:|---:|
| Baseline I：剥离反编译代码 + 自由式提示 | 72.28 | 68.45 | 68.59 |
| Baseline II：同上 + LLM 生成的名称与摘要 | 82.87 | 75.03 | 76.34 |
| TTPDetect | **93.25** | **93.81** | **92.61** |

- 相对 Baseline II，精度高 10.38 pp、召回高 18.78 pp。
- **二进制级**（TTPDetect §5.3）：Dataset II 预测 95 个 TTP，确认 83 个，precision 87.37%；有报告的子集报告覆盖 6/7 = 85.7%，另有 24 个报告未列的 TTP，人工确认 21 个，平均每个样本约 10.5 个未报告 TTP。
- **消融**（TTPDetect §5.5，Table 4）：去掉 Explorer，P/R 降到 85.43 / 74.30，以漏检为主；去掉指南，P/R 降到 77.83 / 86.63，以假阳为主。两个组件分工互补。
- **换骨干**（TTPDetect §6）：gpt-4o-2024-08-06 为 P 76.40% / R 74.5%，gpt-4.1-2025-04-14 为 P 89.50% / R 77.90%。管道可迁移，但幅度随底层推理能力变化，评测必须声明骨干模型。

## 五、SLM 编排：引爆报告问答

### 5.1 题面

- **基准**：CyberSecEval Malware Analysis，输入是 Hybrid Analysis 的 JSON 引爆报告，不是原始二进制逆向。
- **题型**：多主题、多难度的多标签选择题（最多 9 个选项），指标为 exact-match accuracy，另报 Jaccard 部分分。
- **规模**：$N=609$（Easy 451、Medium 136、Hard 22）。Overall 按样本量加权，Easy 占 74%，读总分时必须同时看分层。
- **幻觉的操作定义**：rationale 中出现报告或富集证据不支持的断言（SLM 编排 §3、§4.1）。

### 5.2 四种编排

每种编排对应一类单次调用的失败：

| 系统 | 针对的失败 | 证据与状态约定 |
|---|---|---|
| Agentic | 上下文过载 | 分段读入报告、只读检索；MITRE 富集由关键词或 Txxxx 编号确定性触发（不经 LLM），evidence miner 按余弦相似度筛证据 |
| Debate | 表面模式匹配 | 多轮同伴批判，同意即停；没有强制证据束，Easy 题容易漂移 |
| Consult | 领域知识缺口 | 被试持有整题；网络专家模型看不到原题，只回答子问题（无状态 oracle） |
| Hybrid | 三者兼顾 | 先用 agentic 前四段收集证据束，再让两个代理辩论且每条主张须映射到证据（相似度阈值 $\lambda=0.55$），最后由 verifier 把关；失败则回退到证据直接支持的答案 |

主配置：Agent A 为 Qwen3-4B，Agent B 为 Foundation-Sec-8B，辩论默认 7 轮（在 Hard 增益与 Easy 退化之间折中）。工具只在静态报告文件上做只读 `grep` / `jq`，不联网。

## 六、SLM 编排的证据

### 6.1 相对单模型

单模型基线（SLM 编排 Table 1）：最强的未接地 frontier 为 Gemini 3 Pro Preview 34.77%，Claude Opus 4.5 为 33.15%；最强 cyber 专用模型 Llama-Primus-Nemotron-70B 为 22.54%；Foundation-Sec-8B 单跑 19.96%，Qwen3-4B 单跑 16.58%。参数量不单调预测本题能力，Qwen3-4B 超过多个 7–8B 模型。

以 Qwen3-4B 为骨干的编排（Table 2，单位 %）：

| 配置 | Easy | Med | Hard | Overall |
|---|---:|---:|---:|---:|
| Solo | 18.40 | 12.50 | 4.55 | 16.58 |
| Agentic | 26.50 | 21.30 | 20.00 | 25.11 |
| Debate（× Sec-8B，7 轮） | 25.50 | 19.80 | 22.73 | 24.13 |
| Consult（× Sec-8B，7 轮） | 24.50 | 19.10 | 9.09 | 22.74 |
| Hybrid（× Sec-8B） | **38.14** | **27.21** | **27.27** | **35.30** |

### 6.2 公平对照：同一管道下的 frontier

只和未接地的 frontier 比会高估编排。把同一 hybrid 管道接到大模型上（Table 4）：Gemini 从 34.77% 升到 38.22%（+3.45 pp），Claude 从 33.15% 升到 36.85%（+3.70 pp）。作者据此认为证据接地编排是与模型规模无关的通用增益：开源 SLM 在本地零 API 费的路径上收窄了差距，但没有消除与接地 frontier 的差距。

### 6.3 消融与成本

- **消融**（Table 3）：去掉证据（约等于纯辩论），Easy 降 12.64 pp；去掉辩论（约等于纯 agentic），Hard 降 7.27 pp；去掉接地约束，Overall 为 33.79%；去掉 verifier，Overall 只降 0.26 pp。证据收集稳住 Easy、辩论抬 Hard，verifier 更像一致性闸门。
- **成本与时延**（Table 5）：Hybrid 本地每题 105.6 s，Qwen3-4B 单跑 1.8 s；609 题的 API 费 Gemini 约 $7.54、Claude Opus 4.5 约 $96.22。本地数字不含电费与硬件摊销，不是完整 TCO。
- **部署边界**（SLM 编排 §5 与伦理附录）：作者明确写 35.30% 的 exact-match 不足以自治决策，定位为分析师辅助，证据束与输出需人工核验。

## 九、意义

1. **静态 TTP 归因有了可复现的三个维度**：入口剪枝、按需上下文、领域 checklist；缺 Explorer 伤召回，缺指南伤精度。
2. **证据接地是辩论的稳定器**：无接地辩论抬 Hard、伤 Easy，接地后两者可兼得。
3. **编排增益必须做「同证据」对照**：只比未接地的 frontier 会高估 SLM hybrid，接地后 frontier 仍领先。
4. **分数绑定协议**：骨干模型、检索阈值、辩论轮次、难度加权、是否允许工具，缺一项榜单就不可比。

## 十、局限与待核实

- **TTPDetect 的数据规模**：函数级标注成本高，有专家报告的真实样本只有 2 份；指南对近邻 TTP（如 T1547 与 T1053）的区分仍不足。Dataset II 的「新发现 TTP」是分析覆盖增益加人工确认的 TP，不是攻击能力展示。
- **SLM 编排的外推边界**：exact-match 不等于运营中的精确率与召回率，多选格式不等于开放式 triage；检索可能被诱饵关键词或事件洪水干扰（文中未评）；沙箱逃避导致报告残缺时任何模型都无解。35.30% 不能读成可替代 SOC。
- **两题尚未统一**：静态二进制 TTP agent 与报告问答编排没有在同一协议下评测过，两组数字不可直接比较；[[网络防御基准]] 的 Coverage Score 与 50 次 SQL 预算也不适用于本篇。
- **提升幅度的口径**：TTPDetect 摘要的「+10.38 / +18.78 pp」与 Table 2 中相对 Baseline II 的差值一致，相对 Baseline I 的差距更大，引用时须注明基线。
