# Malware analysis agents / evals：TTPDetect + 开源小模型编排

> **定位**：**防御侧恶意软件分析评测** 切片——度量 LLM / SLM agent 在**已给定静态反编译函数或沙箱引爆报告**上，能否做 **ATT&CK TTP 识别**与**结构化问答**；主轴是 **任务定义、证据接地、相对单模型基线的增益**。
> **攻坚线**：**评测字段（主）**——函数级 P/R/F1、报告覆盖率、CyberSecEval exact-match / 分难度层；**架构思想（辅）**——混合检索入口、按需上下文探索、推理时对齐指南；以及证据管道 + 辩论的 hybrid 编排。
> **硬划界（禁止进攻手册 / 禁止与 [[网络防御基准]] 混题）**：
> - **相对 [[网络防御基准]]**：本篇 ≠ 开放式日志狩猎榜。[[网络防御基准]] = 无引导问题、对 Windows 遥测 SQL 狩猎提交时间戳；**本篇 = 恶意软件战术识别 / 引爆报告问答 + 编排相对基线**。勿把 Coverage Score / Holodeck 战役写进本篇正文。
> - **相对 `B5`**：本篇写 **防御向分析评测**；**不**写红队 ASR、攻击面聚类、mitigation 训练闭环。
> - **相对 [[多智能体辩论]]**：可取「辩论会引入漂移 / 需接地」接口一句；**不**重写 MAD 协议通史。
> - **禁止**：恶意样本制作、利用步骤、渗透/进攻手册、可复用攻击配方；案例仅作「评测输入形态 / 失败模式」索引，不展开操作细节。
> **禁止编造**：主张与数字锚定官方 PDF（2026-09-22 CST）；图内未列表格处不读点。

## 三、任务定义 A · TTPDetect（函数/二进制 TTP 识别）

### 3.1 问题形式化（§3）

令 $F_{\mathrm{bin}}=\{f_1,\ldots,f_n\}$ 为剥离二进制恢复的函数集，$T=\{t_1,\ldots,t_m\}$ 为考虑的 ATT&CK TTP。目标：对每个 $(f,t)$ 判定 $f$ 是否实现 $t$。

策略分解为三阶段（文 Eq. 2）：

| 阶段 | 作用（架构级） |
|---|---|
| **(1) Retrieve** | dense top-$k$ + 神经检索置信度阈值 $P(t\mid f)>\tau$ → 剪枝函数–TTP 对 |
| **(2) Explore** | $\pi_{ctx}(F_{ctx}\mid f)$：按需取 caller/callee 上下文 |
| **(3) Reason & Decision** | 预合成指南 $g\sim\pi_g(\cdot\mid t)$；$\pi_{reason}(v\mid F_{ctx},t,g)$，$v\in\{\mathrm{true},\mathrm{false}\}$ |

### 3.2 三挑战 → 三解（§2，评测动机）

| 挑战 | 现象（文内） | 解法 |
|---|---|---|
| **入口爆炸** | 数百～数千函数 × 200+ TTP；穷举不可行 | **混合检索**：dense（召回）+ LLM over-inclusive neural（再剪枝） |
| **部分可观测** | 行为常跨多函数；单函数易 FN/过度解读名字 | **Context Explorer**：工具式增量取上下文，剪掉通用 utility |
| **推理错位** | 表面线索把相邻 TTP 搞混（如「removal」→ 误标 T1070） | **推理时对齐**：离线自 ATT&CK 合成指南（正/负指标、区分准则），推理时当 checklist |

### 3.3 管道步骤（§4，只记评测相关）

1. **重命名 agent**：自底向上；函数体 + 直接 callee 摘要 → 名称与 1–3 句摘要（缓解地址标识符无语义）。
2. **混合检索**：TTP 定义 ↔ 函数表示 embedding（文用 text-embedding-3-large + FAISS）；再对函数做 over-inclusive TTP 提议 + 置信度剪枝。完整管道相对纯 dense 候选对约 **−85.89%**（Fig. 9）。
3. **Presence 分析**：Explorer 工具 `retrieve_function` / `retrieve_caller`；指南合成含行为导向 vs 意图关键 TTP 分类、正负例对比。

**实现锚点（可复现协议，非进攻细节）：** AutoGen v0.6.1；主 LLM Claude 3.7 Sonnet；IDA Pro 7.6 反编译；ATT&CK **v16.1**。

### 3.4 数据集（§5.1，真值来源）

| 集 | 形态 | 规模要点（Table 1） |
|---|---|---|
| **Dataset I** | 有源码 → 编译剥离 → **函数级** TTP 人工标注 | 18 公开泄露 C/C++ 项目；Linux/Windows；12 家族 / 8 威胁类；**42** 独特 TTP；**210** 函数–TTP 对 / **122** 函数；二进制函数数可达源码的约 **40×**（编译器/库膨胀） |
| **Dataset II** | 无源码真实二进制；**二进制级** TTP | 8 样本（MalwareBazaar / VirusShare）；仅 **2** 份有专家报告可做 report coverage；家族级 ATT&CK 表 **不可**直接当单样本真值 |

**标注效度（§6）：** 两作者独立标注 + 代码级证据 + 协商；外部效度威胁含数据集多样性与预训练泄漏——文用训练截止后出现的 Umbrellastand / DamascenedPeacock 作缓解。

## 四、评测字段 A · 相对单模型 / 自由式基线

### 4.1 RQ1 函数级（§5.2，Table 2）

- **构造：** 选出现 ≥5 次的 **14** 个 TTP → 140 正例对 / 93 函数；再采样无标签与域外 TTP 函数 → 共 **181** 函数；每 TTP 扫全部函数 → **2,534** 二元分类实例。
- **主结果（TTPDetect 平均）：** Precision **93.25%** · Recall **93.81%** · F1 **92.61%**。
- **相对基线：**
 - Baseline I：直接对剥离反编译自由式提示（无定制）→ P **72.28%** / R **68.45%** / F1 **68.59%**
 - Baseline II：同提示 + LLM 名称与摘要 → P **82.87%** / R **75.03%** / F1 **76.34%**
 - 文述相对基线约 **+10.38** pp P、**+18.78** pp R（相对更弱一端的提升叙事与摘要一致；逐表以 Table 2 为准）。

### 4.2 RQ2 二进制级（§5.3）

| 指标 | 文内数字 |
|---|---|
| Dataset II 总体 | 预测 **95** TTP，确认 TP **83** → precision **87.37%** |
| 有报告子集（Table 3） | 报告覆盖 **6/7 = 85.7%**；新发现 **24** 中人工确认 TP **21**（该子集 precision **90.0%**）；均约 **10.5** 未报告 TTP/样本（摘要） |

### 4.3 RQ4 消融（§5.5，Table 4）——组件 ↔ 指标角色

| 去掉 | Precision | Recall | 解释（文） |
|---|---|---|---|
| **Explorer** | 93.25 → **85.43** | 93.81 → **74.30** | 缺上下文 → 漏检为主 |
| **Reasoning Guideline** | 93.25 → **77.83** | 93.81 → **86.63** | 缺约束 → 假阳为主 |
| 完整 | **93.25** | **93.81** | 互补：Explorer 抬召回，指南抬精度 |

### 4.4 跨模型替换（§6，威胁效度）

分析 agent 换掉 Claude 3.7 Sonnet：gpt-4o-2024-08-06 → P **76.40%** / R **74.5%**；gpt-4.1-2025-04-14 → P **89.50%** / R **77.90%**。说明管道可迁移，但幅度随底层推理能力变化——**评测应声明骨干模型**。

## 五、任务定义 B · 开源小模型编排（引爆报告问答）

### 5.1 评测题面（§3 / §4.1）

- **基准：** CyberSecEval **Malware Analysis**（CyberSOCEval）；输入是 **Hybrid Analysis JSON 引爆报告**，不是原始二进制逆向。
- **题型：** 多主题、多难度、多标签选择题（最多 9 选项）；指标 **exact-match accuracy** + Jaccard 部分分；按 Easy / Medium / Hard 分层。
- **规模：** $N=609$（Easy **451** · Med **136** · Hard **22**）。Overall 为样本量加权——Easy 占 **74%**，解释总分时必须同时看分层。
- **幻觉操作定义（文）：** rationale 中出现 **报告/富集证据未支持** 的断言。

**研究问题（文）：** 在固定 **单卡** 预算下（文：≤8B、4-bit、一颗 RTX 4090），编排开源 SLM 能否在**结构化引爆报告问答**上匹配或超过单颗 LLM？

### 5.2 失败模式 → 编排假设（§3 开头）

| 单次 LLM 失败 | 对应干预 |
|---|---|
| **上下文过载**（JSON 超窗被迫截断） | agentic 分段 ingestion + 只读检索 |
| **表面模式匹配**（关键词 → 错误家族意图） | debate 同伴批判 |
| **领域知识缺口**（ATT&CK 细技术） | consult 网络专家；enrichment 拉 MITRE 描述 |

### 5.3 四种编排（只记任务边界与证据契约）

| 系统 | 假设 | 证据/状态契约 |
|---|---|---|
| **Agentic** | 任务分解 + 工具检索抬 Easy | 共享 state；chunk 512 tok / 64 overlap；enrichment 为 **确定性** 关键词/ Txxxx 触发（非 LLM）；evidence miner cosine $\tau=0.65$（all-MiniLM-L6-v2） |
| **Debate** | 多轮批判抬 Hard | $N$ 轮；同意则停；可注入 MITRE 描述；**无**强制证据束 → Easy 易漂 |
| **Consult** | 按需领域专家 | 被试 $M_A$ 持全题；专家 $M_E$ **看不到** $q_{\mathrm{task}}$，只答子问（stateless oracle） |
| **Hybrid** | 证据收集 + 接地辩论 | Phase1 = agentic 前四段 → $E_{\mathrm{final}}$；Phase2 = 两代理辩论且声称须映射证据（相似度 $\lambda=0.55$）；Phase3 verifier；失败则回退到证据直接支持的答案 |

**主配置：** Agent A = **Qwen3-4B**；Agent B = **Foundation-Sec-8B**；辩论默认 **7** 轮（Hard 增益与 Easy 退化折中）。

## 六、评测字段 B · 相对单模型基线（核心）

### 6.1 单模型基线（Table 1，摘关键）

| 类别 | 代表 | Overall |
|---|---|---|
| 最强 ungrounded frontier | Gemini 3 Pro Preview | **34.77%** |
| 次强 frontier | Claude Opus 4.5 | 33.15% |
| 最强 cyber 专用（开源谱） | Llama-Primus-Nemotron-70B | **22.54%** |
| 最强开源 SLM solo | Qwen3-4B | **16.58%** |
| Foundation-Sec-8B solo | 8B cyber | 19.96% |

要点：参数量 **不**单调预测本题能力（Qwen3-4B 超过多个 7–8B）。

### 6.2 编排相对同骨干 SLM（Table 2）

以 **Qwen3-4B** 行为例（Overall）：

| 配置 | Easy | Med | Hard | Overall |
|---|---|---|---|---|
| Solo | 18.40 | 12.50 | 4.55 | **16.58** |
| Agentic（工具） | 26.50 | 21.30 | 20.00 | **25.11** |
| Debate（× Sec-8B，7 轮） | 25.50 | 19.80 | 22.73 | **24.13** |
| Consult（× Sec-8B，7 轮） | 24.50 | 19.10 | 9.09 | **22.74** |
| **Hybrid**（× Sec-8B） | **38.14** | **27.21** | **27.27** | **35.30** |

**读法：** Hybrid **首次**使开源编排在**所有难度层**同时超过最强 **未接地** frontier（34.77%）；但仍应与「同证据管道的 frontier」对照（下节）。

### 6.3 公平性：接地 frontier 对照（Table 4）

| 系统 | Overall |
|---|---|
| Gemini ungrounded | 34.77% |
| Claude ungrounded | 33.15% |
| **SLM Hybrid** | **35.30%** |
| Gemini **+ 同 hybrid 管道** | **38.22%**（+3.45 pp） |
| Claude **+ 同 hybrid 管道** | **36.85%**（+3.70 pp） |

**结论句（文）：** 证据接地编排是 **模型规模无关的通用增益**；开源 SLM 在本地零 API 费路径上 **收窄** 差距，**未消除** 与 grounded frontier 的差距。

### 6.4 Hybrid 消融（Table 3）——证据接地 ↔ 指标

| 配置 | Easy | Hard | Overall |
|---|---|---|---|
| Full hybrid | 38.14 | 27.27 | **35.30** |
| − evidence（≈ pure debate） | 25.50（**−12.64** pp） | 22.73 | 24.13 |
| − debate（≈ pure agentic） | 26.50 | 20.00（**−7.27** pp） | 25.11 |
| − grounding constraint | 36.21 | 26.14 | 33.79 |
| − verifier | 37.82 | 26.52 | 35.04 |

**互补：** 证据收集稳住 Easy（防辩论漂移）；辩论抬 Hard；verifier 更像一致性闸门（去掉后 overall 仅 −0.26 pp）。

### 6.5 成本/时延字段（Table 5，评测协议的一部分）

| 系统 | 延迟（s/题） | API 费（609 题，文估） |
|---|---|---|
| Gemini API | 3.2 | $7.54 |
| Claude Opus 4.5 API | 4.8 | $96.22 |
| Qwen3-4B local | 1.8 | $0 |
| Hybrid local | **105.6** | $0 |

文强调：本地数字 **非** 完整 TCO（未含电/硬件摊销）。

### 6.6 部署边界（§5 / 伦理附录）

文明确：**35.30% exact-match 不足以自治恶意软件分析决策**；定位为 **分析师辅助**，证据束与输出需人工核验。双用途风险自评：编排模式已见于通用 LLM 文献；本文聚焦 **解释已有行为**，不提供生成/投递基础设施。工具仅静态报告上只读检索。

| **标签空间** | ATT&CK TTP（函数级二元 / 二进制级集合） | 多标签多选（行为/持久化/风险等） |
| **主指标** | P / R / F1；report coverage；binary precision | Overall Acc（难度加权）；分层 Acc |
| **必报基线** | 自由式 LLM（±重命名摘要） | Solo SLM / cyber / **ungrounded & grounded** frontier |
| **证据接地** | Explorer 按需取码；指南 checklist | Evidence bundle + citation 约束 $\lambda$ |
| **编排增益声明** | vs Baseline I/II；组件消融 | vs solo；vs 同管道 grounded LLM |
| **明确非目标** | 家族粗分类 alone；动态沙箱全集依赖 | 二进制逆向；开放式 triage；检测率误读 |

**与 [[网络防御基准]] 一句话划界：** [[网络防御基准]] 问「能否在海量遥测里 **发现** 恶意事件时间戳」；[[恶意软件分析评测]] 问「给定分析产物后，能否 **正确贴 TTP / 答结构化题**，以及编排相对单模型是否真增益」。

## 八、可迁移主张 / 开放问题 / 跟读坑

### 8.1 可迁移主张（有表支撑）

1. **入口剪枝 + 按需上下文 + 领域 checklist** 是静态 TTP 归因的可复现三维；缺 Explorer 伤召回，缺指南伤精度。
2. **证据接地是辩论的稳定器**：无接地辩论抬 Hard、伤 Easy；接地后两者可兼得。
3. **编排增益必须做「同证据」对照**：只比 ungrounded frontier 会高估 SLM hybrid；接地后 frontier 仍领先。
4. **分数绑定协议**：骨干模型、检索阈值、辩论轮次、难度加权、是否允许工具——缺一则榜不可比（接 [[评测与排行榜可靠性]]）。

### 8.2 开放问题（文内已点名）

- TTPDetect：函数级标注成本高；真实样本有专家报告者稀少；指南对近邻 TTP（如 T1547 vs T1053）区分仍不足。
- SLM 编排：exact-match ≠ 运营精确率/召回；多选格式 ≠ 开放 triage；检索可被诱饵关键词/事件洪水扰动（文未评）；sandbox 逃避导致报告残缺时任何模型不可解。
- 跨题迁移：静态二进制 TTP agent 与报告问答编排 **尚未**在同一协议下统一评测。

### 8.3 跟读坑

- 勿把 Dataset II「新发现 TTP」写成攻击能力展示——记为 **分析覆盖增益 + 人工验证 TP**。
- 勿把 35.30% 读成「可替代 SOC」——文自己写不足自治。
- 勿把 [[网络防御基准]] 的 Coverage Score / 50 SQL 预算套到本篇。
- 案例附录中的技术名仅作 **失败模式索引**；笔记 **不**展开复制步骤。
