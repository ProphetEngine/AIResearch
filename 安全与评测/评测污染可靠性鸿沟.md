# 评测污染下一刀：检测可靠性鸿沟 + 抗污染基准设计（≠ 15）

> **定位**：**评测字段**——在 **[[训练数据污染检测]]** 已立「怎么测污染」（Quiz / n-gram / 方法局限地图）与 **[[评测与排行榜可靠性]]** 已立榜单可靠性通史之后，本卡转问两刀**下游**：
> - **Reliability Gap**（*The Reliability Gap in Benchmark Auditing*）：统计检测在**分布偏移**与**基准规模**下为何失效；LLM DI / Post-Hoc DI / CoDeC 的失败模式。
> - **Contamination-Resistant**（*LLM Benchmark Datasets Should Be Contamination-Resistant*）：基准发布应如何**先天抗污染**（CRD：不可学但可推理）。
> **攻坚线**：**评测字段 / 方法局限（主）** + **发布规范建议（辅）**。
> **硬划界（开篇钉死）**：
> - **≠ [[训练数据污染检测]]**：不重跑 **DCQ** 算法教程（五选一扰动、BDQ→BCQ、WPQ 轴地图）；不重写 n-gram / Min-K% / canary / Token Completion 通史。本卡只在「检测之后为何仍不可证」处交叉引用。
> - **≠ [[评测与排行榜可靠性]]**：不重写污染概念三分、Claude/o1 System Card 个案、thinking/路由/scaffold 可比性清单。
> - **≠ [[Inspect评测Harness]]**：不写 Inspect Task=Dataset+Solver+Scorer、sandbox、日志闭环。
> - **≠ [[NemotronCC数据策展]]**：不写 Nemotron-CC 语料清洗管线、分类器质量档、合成改写。
> **禁止编造**：主张与表数字一律锚定官方 PDF（2026-09-22 CST）。

## 三、Reliability Gap：野外审计为何失真（主文 A）

### 3.1 问题立轴与总账

Abstract / Fig.1：现有成员/数据集推断工具几乎只在**大而同质的预训练语料 + 透明单阶段管线**上验证过；作者锁定两个欠研究失败模式：

1. **Distribution shift**：suspect 与 validation **违反 IID**；
2. **Scale constraints**：基准比预训练语料小**若干数量级**。

系统评测三范式——**LLM Dataset Inference (LLM DI)**、**Post-Hoc Dataset Inference (Post-Hoc DI)**、**CoDeC**——覆盖 Pythia / OLMo 2 / 医疗 LLM / 波兰 PLLuM 等共 **25** 个模型（开源侧至 **27B**），并延伸到工业模型族。**335** 次评测中仅 **201** 次正确（约 **60%**）。

### 3.2 三方法操作要点（只录接口，不重做通史）

| 方法 | 核心检验 | 判决习惯（文内） | 关键假设 / 脆弱点 |
|---|---|---|---|
| **LLM DI** | 在 suspect vs 未见 validation 上聚合弱 MIA 特征 → 单侧 t 检验 | $p < 0.1$ → 判「训过」 | validation 须**未见且与 suspect 近似 IID**；split 难度/风格差 → **假阳性** |
| **Post-Hoc DI** | 用小生成器造合成 suffix 作 validation；比「纯文本分类」与「文本+MIA」是否可分 | $p < 0.1$（相对文本基线） | 基准规模下生成器弱 → 真实/合成**分布伪影**淹没记忆信号 |
| **CoDeC** | 同数据集 in-context 样例是否**降低**下一 token 置信；分数 = $\Delta(x)<0$ 的样本比例 | $>0.8$ 强污染；$<0.6$ 无；中间不确定 | 适合**粗粒度 provenance**；近 IID 的 train/test **难分** |

配置锚点（§4.1，跟读用）：LLM DI 用每侧约 250 训分类器、至少约 1,000 文做 t 检验；Post-Hoc 子样 2,000、Llama-3.1-8B LoRA 生成 128-token suffix、GPT-2 文本分类器；CoDeC 严格用 **1** 个随机上下文样例、自第 **10** token 起均 log-prob。

### 3.3 四任务结果压缩（只锚定文内 Corr./Tot.）

**Task 1 · 有限参考数据（Pile 子样 n=2,000，Pythia）：**
受控且可给真 IID validation 时，LLM DI 在 Hacker News / Stack Exchange 网格可达 **16/16**，Pile CC/Europarl 网格 **12/16**；Post-Hoc 多在 **4–8/16**；CoDeC 常对 train/test **同给高分**（**8/16** 量级）——高分可来自「见过 train」或「两 split 分布过近」，**不是**精确成员证。

**Task 2 · OLMo 2 split 级（GSM8K train 已知进入 post-train；MMLU/DROP train 未进）：**
LLM DI **12/18**，但对 **未训**的 MMLU/DROP train 仍出假阳性——作者解释：同基准 train/test 看似 IID 代理，仍可因难度/构造差驱动检验。Post-Hoc **13/18**（GSM8K test 过小标 n/a）。CoDeC **9/18**；GSM8K 分数偏高符合已知暴露，但 DROP/MMLU 仅略低，且分数随模型变大**下降**（Fig.2），**不足以**证 split 成员。

**Task 3 · 专科后训练（医疗 QA + PLLuM SFT/Alignment）：**
信号更不稳。例：MedQA-USMLE 上 LLM DI **漏检全部** train；MedMCQA 多数可检但仍漏部分模型。PLLuM 小 split（Automatic ≈1,600 / Manual ≈1,150）下 LLM DI 对 Auto/Manual SFT **反复假阴性**，Alignment 上又有假阳性；CoDeC 跨家族方差大。

**Task 4 · 工业模型比较（无真值成员）：**
对 Gemma-3 / Qwen-3 / Llama-3.2 等只做**族间比较**：多数族在 GSM8K/MMLU/DROP 上 CoDeC 偏高且 LLM DI 常旗标；**Gemma-3** 是例外——CoDeC 更低，且为唯一在 GSM8K train 上**未被 LLM DI 旗标**的系列；作者据此**推断**其不大可能训过 GSM8K train（**比较性**，非铁证）。

### 3.4 作者四条总判（Introduction 编号结论）

1. 当前方法**尚不足以**稳定核验基准暴露。
2. 小规模下**仅 LLM DI**在有真未见、近似 IID 参考集时可用；Post-Hoc 合不成可靠合成参考；CoDeC 对近匹配 train/test 给相似分。
3. **没有任何方法**能可靠指出「基准的哪一 split 被训过」。
4. 专科后训练与工业模型上信号更不稳；工业侧最多到**模型族级**差异。

## 四、失败模式诊断（§5.5，本卡主轴）

### 4.1 LLM DI：IID 是致命脆弱点

Task 1（可控 IID）成功 vs 后续任务（用 test 作 validation 代理）假阳性，说明检验在捕捉**split 分布差**而非训练暴露。结论句：**无验证分布对齐时，不宜把 LLM DI 当作榜完整性的唯一仲裁。**

### 4.2 Post-Hoc DI：基准规模欠功率（有对照实验）

- **基准规模（Table 5–6）：** 纯文本 Base AUC 已 **>0.78**（常 ~0.88–0.90），加 MIA 几乎不增益 → 分类被 **真实 vs 合成** 分布偏移主导；校准 p 值混乱（如 Europarl $p\approx1.000$；Hacker News Val 非成员却浮现极小 p）。正确约 **12/32**。
- **全量子集生成器（Table 7–8，作者发布 held-out）：** Base AUC 塌到约 **0.55**（分布伪影消失）；正确升至 **23/32**。
→ **失败不是方法本身「永远无效」，而是标准基准文本量训不动匹配生成器。**

### 4.3 CoDeC：粗 provenance，细 split 不够用

Fig.4（Pythia）：预训练语料分数 ≫ 仅评测基准，但**同语料 train/test 几乎同分**。Fig.5（OLMo 2）：聚合后呈 **预训练 > 后训练 > 仅评测** 粗序，相邻组重叠大。文内建议：作**比较性**指示（多模型同基准、抓离群），不作单 split **认证工具**。

### 4.4 实践建议（作者原文压缩）

| 工具 | 可用条件 | 不宜用途 |
|---|---|---|
| LLM DI | 确有未见且近似 IID 的 validation | 默认拿 test 当分，证榜完整性 |
| Post-Hoc DI | 能独立评估合成 held-out 质量，且数据量够训生成器 | 标准基准规模「开箱即用」 |
| CoDeC | 粗比较 / 族间相对信号 | 认证某一评测 split |
| **共同** | 作 **互补证据** | **替代**透明数据 provenance |

局限（§6）：共享接口默认超参、开源审计至 27B、工业无真值成员、**未提出**克服失败的新检测器——量化「能容忍多少偏移 / 多少数据」仍开放。

## 五、Contamination-Resistant：先天抗污染基准设计（主文 B）

### 5.1 立场与 CRD 定义

**Position：** 基准应以 **contamination-resistant** 形式发布——对公开释放形态 **unlearnable**，但仍 **support inference**。

**Definition 2.1（CRD）：** 相对模型 $M$ 与变换 $\phi$，公开形态 $\phi(D)$ 满足：推理效用 $M(\phi(D))$ 仍有效；且对损失 $L$ 与参数 $\theta$，在 $\phi(D)$ 上的训练步 $\nabla_\theta L(M_\theta,\phi(D))$ **无法**提升泛化表现。

三性质（§2.3）：

1. **Irreversibility**：在现实对抗能力下，从 $\phi(D)$ 恢复明文 $D$ 计算上困难或不经济；
2. **Equivalence**：$M(\phi(D)) \approx M(D)$；
3. **Interoperability**：可把 $\phi(D)$ 迁到另一模型 $M_1$ 的 $\phi_1(D)$，仍满足 (1)(2)。

明文一旦上网即「可被刮」；故文本要抗污染，须映射到**潜空间/推理专用形态**（不可整包释放明文题干）。

### 5.2 评测框架（Fig.2，三阶段）

| 阶段 | 做什么 |
|---|---|
| **Curation** | 明文基准备好后，用一至多个 **anchor 模型** 把 **test 题干** 投到潜表示；只释放推理所需形态（非完整可训练序列）；**标签 $Y$ 可明文**（无配对输入则无法把答案绑回问题）；附 datacard + 少量明文样例供互操作翻译 |
| **Discovery** | 评测方把 CRD **翻译**到目标模型；同一 anchor↔target 映射可复用到后续同锚 CRD |
| **Evaluation** | 翻译后表示喂目标模型自回归；目标**始终不见明文题干**；输出对明文 $Y$ 用 Exact Match / 语义相似度等常规打分 |

### 5.3 机制核：Transformer 训练 / 推理不对称（§3）

- **训练：** 需整段 token 算各位置各层隐状态与下一 token 损失（式 (1)）；微调亦需整序列以产生标签位隐状态。
- **推理：** 主要依赖各层 **KV cache** $\{K_{1:t}^{(l)}, V_{1:t}^{(l)}\}$ 与 **倒数第二层**末位隐状态 $h_t^{(L-1)}$（Fig.3）。

**发布格式（式 (3)）：**
$$
\big(\{K_{1:t}^{(l)}, V_{1:t}^{(l)}\}_{l=1}^{L},\; h_t^{(L-1)},\; Y\big)
$$
→ 可继续生成评测，却不提供预训练所需的原始 token 序列。

### 5.4 互操作：近程锚模型 vs 远程相对表示（§4）

| 范式 | 做法 | 文内技术锚 |
|---|---|---|
| **近程：Anchor + 子空间对齐** | 指定广泛采用的 $M_{\text{anchor}}$ 编码 KV/h；目标侧算对齐映射 | Cross-LoRA（LoRA-Align SVD + LoRA-Shift）、Trans-LoRA、LoRA-X；对齐矩阵只靠**权重**，不碰明文 → 保 irreversibility |
| **远程：相对表示** | 相对固定锚样本集，把各模型 latent 投到共享坐标 | Moschella et al. relative representations；Maiorca et al. semantic alignment；锚样本 $k$ 常 **100–500**，且**不与**受保护评测内容重叠 |

等价性风险与校准（§5）：长序列翻译可能漂移；可用蒸馏对齐、prompt tuning、自适应温度等细校准。社区可用锚模型配对评测 / 分布检验审计「编码后是否仍测同一能力」。

### 5.5 兼容边界、存储与替代路径批评（跟读必记）

**较兼容：** 单轮 QA（MMLU/SQuAD/HumanEval）、分类、多模态图文对、代码生成、摘要等「输入/输出结构可分」任务。
**较弱/需改造：** 多轮对话、高度动态 agent、自适应换题、轨迹相关金标（CoQA/WebShop/DynaBench/GAIA/MLE-bench 等）——或只对子组件用 CRD。

**存储：** 文引 LLaMA-2 7B 上 100K token KV 可至约 **50GB**；PyramidKV 等压缩可大幅降（文称可至约 **350MB/100K tokens** 量级；Fig.4 给各基准近似 MB）。跟读时以原文 Fig.4 柱值为准，本卡不另造表。

**§6 替代路径（本卡只录批评句，不升主）：**

| 路径 | 文内主要批评 |
|---|---|
| Private benchmarking（如 TRUCE） | 防泄漏但抬高独立验证门槛、吞吐与开源成本；专有模型交权难 |
| Dynamic benchmarking | 新题很快再被摄入；纵向可比性差 |
| Lexical obfuscation | 现代模型常已见过改写形态；新污染甚至更难滤 |
| Decontamination / n-gram 过滤 | 召回/精度权衡；难挡改写/翻译/蒸馏间接泄漏；语料越大越不够 |

局限：依赖 Transformer；非 Transformer（如 Mamba）不适用；注意力/位置编码族间差异影响安全与保真——文称超出范围。

**社区呼吁（§7）：** (i) 推进 CRD 方法与 stitching 等低摩擦采用；(ii) 标准化锚模型作通用编码器；(iii) 把 CRD 校验接入现有管线（文举例 Hugging Face）。

## 六、两刀合读：检测之后 / 发布之前

| 问题 | Reliability Gap 给的答案 | Contamination-Resistant 给的答案 |
|---|---|---|
| 榜分虚高怎么办？ | 统计旗标**不可单独认证**；要 provenance | 从发布形态切断「可预训练」 |
| 检测器为何吵？ | IID 破、规模小、粒度粗 | 检测再强也赶不上摄入速度 → 改数据产品形态 |
