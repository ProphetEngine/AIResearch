## 一、问题：推理模型与高算力采样如何让单一榜单误导

### 1.1 旧默认假设已失效

传统「单一分数表」隐含几条假设：

1. **同一模型名 ≈ 同一推理配置**（温度、采样次数、是否工具、是否长思维）。
2. **一次前向 ≈ 一次答卷**：分数主要反映参数与预训练质量。
3. **榜上的题对模型「新鲜」**：训练集与测试集近似独立。

推理模型（o1 系、Claude 4 hybrid / extended thinking 等）把 **test-time compute** 变成一等公民：同一权重可在「快答」与「多想」之间切换，还可再叠多采样 / 共识 / scaffold。于是：**榜上一个数字，往往对应一整套未写明的协议，而不是「模型本体」的标量。**

### 1.2 官方自己怎么拆开「配置维度」

**OpenAI o1 System Card** 明确：评测覆盖整族 o1；生产数字可能因 system prompt、最终参数等略有差异（§3 Scope）。Preparedness 侧还区分：

- **pre-mitigation vs post-mitigation**（安全训练前后）；
- **scaffold / harness**（Agentless、Kali 工具、Ranger 浏览器 harness 等）；
- **pass@k / cons@k**（多尝试 vs 多数投票）。

原文级要点（Preparedness §5.2）：即使已用 custom post-training、scaffolding、prompting 做「worst known case」elicitation，结果仍应视为风险的 **lower bound**——更长 rollout、新交互、新 scaffold 仍可能抬高能力。

对「高算力采样」的可核对例子（同一 System Card，非第三方榜）：

| 设定（官方表述） | 含义（跟读） |
|---|---|
| ML 面试 coding：`pass@128` | 单元测试在题面里 → 可筛再交；k 很大时分数≠「一次答对」 |
| ML 面试 MCQ：`cons@32` | 32 次共识；与 pass@1 不可直接横比 |
| SWE-bench Verified：Agentless + 每题 5 次候选 → 报告 `pass@1` | **无**代码执行/文件编辑原生工具；与「带终端的 agent」不是同一任务 |
| MLE-bench：`bronze pass@1` vs `pass@10` | 官方写明 pass@10 与 pass@1 差距更明显；o1-preview 与 o1 在低 n 上更接近 |

**Claude 4 System Card** 把 hybrid 推理写成产品旋钮（§1.1.2）：

- **standard thinking**：默认、更快；
- **extended thinking**：更多推理时间；用户可切换；
- 约 **5%** 过长思维会经小模型摘要；开发者可开 Developer Mode 看全文。

安全与 RSP 评测中，Anthropic **在可能时对两种模式都跑**（§1.2.2）。StrongREJECT 等表头直接拆成 *standard / extended* 四列——同一模型、同一基准，**开关一开，分数量级可变**（见第三节）。

### 1.3 「单一榜单误导」的机制（架构视角）

`
同一「模型名」
 ├─ thinking / effort 档位（关 / 开 / 最大）
 ├─ 采样：pass@1 vs pass@k vs cons@k vs best-of-n + 打分器
 ├─ 工具：无工具 / 代码执行 / 浏览 / 专用 harness
 ├─ 安全层：pre- vs post-mitigation；系统提示；路由到不同变体
 └─ 子集与评分器：Verified 子集、hard subset、auto-grader 版本
 ↓
 「一个榜上数字」← 常把上列维度压扁成一格
`

**跟读结论**：排行榜可靠的前提不是「分数高」，而是 **协议可复述**。推理模型时代，缺协议的分数更像广告截图，而不是可复现实验。

## 二、污染、数据泄漏与训练集重叠风险（概念层）

本节只引用官方/论文表述；**不**用未核对的第三方「污染率表」当下结论。

### 2.1 概念三分（避免混用）

| 概念 | 直觉 | 典型症状 |
|------|------|----------|
| **训练集重叠 / contamination** | 评测题或其近重复出现在预训练/后训练语料 | 异常高分、能「背答案」、换表述骤降 |
| **评测时泄漏（runtime leakage）** | 跑评测时可搜索文献/网页/题解，而非靠题内推理或给定工具 | 分数反映检索，而非目标能力 |
| **格式/分布污染** | 语料含与自家评测格式极相似的公开脚本（含省略 system prompt） | 幻觉出虚构设定；相关评测失效 |

### 2.2 Claude 4 System Card 中的可核对案例

**（A）Alignment Faking 公开转录本进入预训练（§4.1.4）**

- Anthropic 认为早期 checkpoint 幻觉出论文虚构设定（如 “Jones Foods”），原因是预训练混入约 **150,000** 条公开转录本，且**缺少说明虚构设定的 system prompt**。
- 缓解：定向微调 + 未来公开数据加 **machine-readable canary strings**，便于从预训练语料排除。
- 直接后果（官方原意）：**与该论文相关的评测无法再可靠用于 Claude Opus 4**（相对此前模型）。

这是「污染 → 评测失效」的教科书级官方自述：不是「分数虚高」 alone，而是 **整个评测家族不可再用**。

**（B）短时程计算生物学任务中的 data leakage（§7.2.4.9）**

官方写明：部分评测存在少量 **data leakage**——模型可通过检索文献或依赖预训练既有知识拿高分，而非经由工具使用与长程推理。该评测目标是「新病原分析」类威胁模型，**由既有知识得到的分不能准确反映关切**；并计划继续改进评测以应对泄漏。

含义：即使安全评测，也要问「分数测的是不是你声明的能力」。

**（C）Creative biology：均值 vs best-of-30（§7.2.4.8）**

官方报告均值分数，并补充：若每题取 30 次中最佳，分数会明显高于均值；但因难验证且假设对手无法挑出正确答，**他们认为均值更忠实**。

这同时打到「污染/可验证性」与「高算力采样」两根柱子：多采样抬分 ≠ 真实可用能力。

### 2.3 o1 System Card 中相关表述（非完整 decontam 附录）

o1 System Card 的主体是安全与 Preparedness，**不是**能力榜 decontamination 白皮书。仍有与「泄漏/记忆/可比性」相关的官方信号：

- **Regurgitation evaluations（§4.1.3）**：内部评测检查模型是否拒绝 regurgitate 训练数据；报告近/达 100%。这测的是「拒绝复述」，**不是**「基准题未出现在训练集」。
- **METR 外部评测（§4.4.4）**：强调 scaffold 适配前后分数差很大；约 **70%** 失败被估计为 likely-spurious（含工具用不对）；且 METR **没有**拿到工具格式等训练细节——说明外部复现分数高度依赖 harness，而非纯权重。
- **SWE-bench Verified（§5.8.2）**：先说明 Verified 子集修了原版错误打分、题面不清、过细单测等问题——即 **基准本身也会污染「能力叙事」**，不一定是训练污染。

### 2.4 概念层操作建议（写笔记/引用时）

1. 问官方有没有写 **decontamination 方法**（exact match / n-gram / canary / 人工抽查）。Claude 4 主卡对此着墨有限；后续 Opus 4.5 等卡有更系统叙述——**引用时注明是哪一版 System Card**，勿把 4.5 的方法倒灌到 Opus 4/Sonnet 4。
2. 区分 **训练污染** vs **评测时联网/检索**。Agent + 浏览基准尤其危险。
3. 公开题解、竞赛复盘、GitHub issue 讨论会持续渗入网页爬取；**静态公开榜的半衰期在缩短**。
4. Canary / 保留私有 holdout / 定期换题，是官方开始承认的工程对策（Claude 4 对 Alignment Faking 数据的 canary 计划）。

## 三、路由 / thinking / 工具开关如何改变可比性

### 3.1 Thinking / extended thinking：同一模型两套数

Claude 4 System Card 表 2.7.A（StrongREJECT，越低越好）给出清晰对照（官方数字，非第三方榜）：

| 模型 | Best score · standard | Top-3 avg · standard | Best score · extended | Top-3 avg · extended |
|------|----------------------:|---------------------:|----------------------:|---------------------:|
| Claude Opus 4 | 18.21% | 7.14% | 2.24% | 1.17% |
| Claude Sonnet 4 | 6.71% | 2.66% | 2.24% | 1.38% |
| Claude Sonnet 3.7 | 31.95% | 8.09% | 10.22% | 4.05% |

**跟读**：若排行榜或截图只写「Claude Opus 4 · StrongREJECT」而不写 thinking 模式，读者无法判断对应哪一列。Jailbreak 鲁棒性叙事会完全反转量级。

同类要求适用于能力基准：extended thinking 打开时，延迟、成本、token 预算都不同——**把「多想」分数与「快答」分数塞进同一格，是协议错误，不是「更公平」**。

### 3.2 工具与 scaffold：测的是「系统」不是「裸模型」

o1 System Card 中的硬例子：

- **SWE-bench Verified**：o1 无代码执行/文件编辑 → 用 **Agentless**；官方并写 improved scaffolding / inference-time compute / finetuning **仍可能**再抬分。
- **Cyber CTF**：Kali 工具 + 最多 60 轮工具调用 + 每题 12 次尝试。
- **METR**：baseline scaffold 下看起来弱；略改 scaffold（含逐步 6 选 1）后可达「约 2 小时人类」量级——**名次可被 harness 翻转**。

Claude 4 RSP 自主性评测同样写明：终端、代码编辑器、示例提示、self-reflection、external memory 等 elicitation（§7.3 Environment and elicitation）。METR data deduplication、SWE-bench Verified hard subset 的阈值，都绑定在该环境上。

### 3.3 路由与「同名不同货」

产品层常见（概念；具体路由策略以各厂商当期文档为准，未核对则标待核实）：

- 聊天 UI 把难题 **路由** 到 reasoning 变体，简单题走快模型；
- API 上 `thinking` / `effort` / `max_completion_tokens` 由调用方决定；
- 安全分类器拦截后换拒答策略或换模型。

**可比性崩溃点**：竞技场「匿名对战」若一边是 routing 后的系统、一边是固定 API 配置，分数混的是产品体验，不是同一推理栈。

### 3.4 元规则建议：引用分数前必填的核对清单

写文章、做内部对照或转发榜单时，建议每条分数旁至少能回答：

| 字段 | 为何必须 |
|------|----------|
| **日期** | 模型与评测集都在滚动更新；System Card 也有 changelog（Claude 4 卡曾更正 Claude Code Impossible Tasks 数字） |
| **官方 URL / 论文 ID** | 可回溯；禁止只用聚合站截图 |
| **是否 thinking / extended / maximal test-time compute** | 否则不可与快答配置横比 |
| **是否工具 / 何种 harness** | Agent 分 vs 补全分 |
| **pass@k / cons@k / temperature / n** | 采样协议 |
| **子集是否一致** | 全量 vs Verified vs hard subset（如 Claude 卡 SWE-bench Verified hard；o1 卡 Verified 500） |
| **pre/post-mitigation 或系统提示** | 安全训练可改能力与拒答 |
| **评分器版本** | 自动打分器更换会漂移 |

**一句话元规则**：没有上表，就没有「可比分数」；只有「某次演示」。

## 四、常见误区与引用

### 4.1 常见误区

1. **「榜一 = 全面最强」**
 忽略任务族（数学竞赛 ≠ 长程 agent ≠ 拒答安全）、忽略成本/延迟。o1 卡自己区分面试短题与真实数月级 ML 研究。

2. **「同名模型分数应一致」**
 thinking 开关、scaffold、mitigation、checkpoint（o1-near-final vs o1-dec5-release）都会动分数。

3. **「pass@k 高就说明一次成功率高」**
 k 增大单调不降；在可验证输出（单测可见）时尤其虚高。应优先对齐 **pass@1 / 均值**，并披露 k。

4. **「公开基准干净」**
 网页题解、论文附录、GitHub、论坛会进入爬取；Claude 4 对 Alignment Faking 数据与 bio 评测泄漏的自述说明：**官方也在追赶**。

5. **「外部复现低分 = 模型弱」**
 可能是工具格式、提示、权限、超时未对齐（METR 案例）。反之，官方自报高分也可能绑死了未公开 harness。

6. **「第三方聚合榜可直接当论据」**
 本议程硬性禁止：只作线索；定论必须回到官方页/论文协议。

7. **「安全分与能力分可混排」**
 StrongREJECT 变好与 SWE 变好没有同一量纲；extended thinking 可能同时改两者。

### 4.2 引用纪律（研究会内部）

- **优先**：System Card、官方博文、原论文、官方 eval 仓库说明。
- **数字**：只抄有出处的表/句；抄录时带上配置字段（第三节清单）。
- **禁止**：凭记忆补全「某某榜 XX.X%」；禁止把 A 模型的 scaffold 分数写到 B 模型名下。
- **changelog**：Claude 4 System Card 曾修正部分评测数字——引用时注明 PDF/页面版本或日期。
- **第三方**：可写「据某聚合站（日期）显示趋势，待与官方核对」；核对前不加粗、不作结论句。

### 4.3 跟读后可带走的架构判断

评测可靠性质疑，本质是 **观测协议** 问题，不是「大家作弊」道德剧：

- 推理模型把 **compute 分配** 从训练挪到推理，观测必须记录分配方案；
- Agent 把 **工具与环境** 并入系统边界，观测必须记录边界；
- 开放网页语料让 **独立同分布假设** 持续受损，观测必须承认污染与换题成本。

因此，架构思想线上的正确反应不是「不看榜」，而是：**把排行榜降级为线索生成器，把可复述协议升级为一等公民。**
