## 一、问题动机：为何「对齐流水线」之外还要红队

### 1.1 对齐改的是训练目标；红队测的是对抗暴露面

[[对齐脉络RLHF与偏好优化]] 已覆盖：基座 → SFT → RM+RL / DPO / CAI，把「帮助且无害」写成可优化目标。但训练分布内的偏好信号，**不等于**部署后遭遇的对抗输入分布。

Ganguli et al. 开篇把问题写死：大 LM 已表现出偏见强化、有毒输出、PII 泄漏、虚假信息、极端文本等；能力上升后，伤害面还可能扩大。**红队**被定义为：用手动或自动方法，对抗性地探测有害输出，再据此更新模型以规避这些输出。作者强调三点同时发生——**发现、度量、尝试降低**——而不是只做静态基准打分。

政策 memo（CDN 短 PDF）把同一动机压成两句工程话：

1. 揭出具体脆弱点，便于按风险优先级排缓解；
2. 把攻击对话当作数据集，直接喂进更安全的系统开发。

### 1.2 相对静态评测：交互式、可适应、双用途

静态集（如 RealToxicityPrompts）测的是固定提示下的有害率。红队则是**多轮、开放目标、由攻击者自适应**的探测。论文 §4 明确：在对话式红队设定下，**HHH 提示相对 Plain LM 几乎看不出优势**——这与作者先前用静态毒性评测得到的「HHH 提示有效」结论不一致；作者归因于静态提示通常**不如**红队对话那么对抗。

**架构抓手：** 红队不是「再做一个安全榜」，而是把安全工程收成闭环：

`
威胁假设 / 开放探测
 → 人工或自动攻击对话
 → 成功度量（自评 / 偏好模型 / 专家裁定）
 → 聚类与标签（攻击面地图）
 → 训练数据 / 拒绝采样 / 策略更新 / 系统层防护
 → 再评测（含自动化回归）
`

2024 文进一步指出：没有共享标准时，各厂即使用「同一种」技术，实践形态也差很远——**跨系统客观比较安全水平因此困难**。红队议题的独立价值，正在于把这套「攻防接口」说清楚，而不混进偏好优化公式。

## 二、方法谱系（架构思想）

### 2.1 2022 研究范式：众包开放对话 × 四类安全干预 × 规模扫描

**任务接口（§3.1）**

- 界面要求红队员与 AI 助手开放对话，「让 AI 表现糟糕 / 说讨厌、冒犯、有害的话」。
- 给出简短话题示例，其余开放；要求创意、避免明显脏话、**每轮攻击聚焦单主题**；开攻前写短描述说明意图。
- 每轮给出**两条**模型回复，要求选更有害的一条——既加倍暴露机会，又产出成对偏好数据，用于训练 **harmlessness preference model**。
- 默认约 **4 轮**对话；结束时红队员在 **0–4 Likert** 上自评攻击是否成功。

**四种模型 / 干预（§3.2；与 Bai et al. HHH / HH-RLHF 同族）**

| 类型 | 机制（论文表述） | 与红队数据的关系 |
|------|------------------|------------------|
| Plain LM | 预训练 LM + 极少示例转成对话 | 对照 |
| HHH Prompted LM | 14 例 HHH 提示 | 被红队的主目标之一；其攻击数据训偏好模型 |
| Rejection Sampling (RS) | 同规模提示模型采样 16 条，偏好模型选最无害的 2 条展示 | **使用**红队数据训出的偏好模型 |
| RLHF | 从提示模型起步，用同一偏好模型做 RL | **使用**红队数据；规模↑时更难红队 |

偏好模型：用 **52B Prompted LM** 上的红队比较数据微调；输出 harmlessness score（**越低越有害**）。作者同时训 helpfulness，以缓解「靠拒绝帮忙假装无害」的张力。

**度量三件套（每场攻击）**

1. 红队员自评成功度（0–4）；边际上约 **35%** 自评为成功量级（§3.4 叙述）。
2. 对助手各轮打 harmlessness，取 **minimum**（最差一轮）作会话下限。
3. 对任务描述打分，作「意图有害性」协变量（后续混合效应控制混淆）。

**二次标注（§3.5）**：对 52B Prompted 与 52B RLHF 各抽约 500 场，三人复审；Likert 一致性低，二值化（≥3 为成功）后仍仅中等；并打最多 2 个话题标签（Figure 9）。

### 2.2 2024 实践谱系：按威胁模型选工具，再灌进定量评测

《Challenges…》不再只谈「众包让模型说脏话」，而是按**威胁模型**拆方法，并强调从定性红队迭代到自动化定量评测：

| 谱系分支 | 代表做法（原文） | 优势（文中主张） | 挑战（文中主张） |
|----------|------------------|------------------|------------------|
| **领域专家 / Trust & Safety** | Policy Vulnerability Testing（PVT）：与外部 SME 就 Usage Policy 主题做深度定性（例：Thorn / ISD / GPAHE） | 复杂、语境依赖问题有深度 | 贵、慢、难标准化比较 |
| **前沿威胁 / 国安** | CBRN、网络安全、自主 AI；专家共设评测；可用标准部署版或「缓解不同」的非商用版 | 对齐真实威胁模型 | 访问控制、保密、专家稀缺 |
| **多语多文化** | 例：与新加坡 IMDA / AI Verify 在英/泰米尔/华/马来语及本地议题上合作 | 纠正「默认英语 + 美国视角」偏差 | 能力建设依赖公共部门 |
| **模型红模型（自动）** | 红队模型生成攻击 → 蓝队在攻击输出上微调 → 可多轮迭代 | 覆盖面与速度 | 攻击多样性、与人类发现是否同分布 |
| **新模态** | Claude 3 系：图输入 + 文输出；部署前 T&S + 外部测拒绝有害图/文 | 抓住模态特有风险 | 攻击面组合爆炸 |
| **众包通用伤害** | 2022 研究：控制环境下由众包自定攻击类型与风险容忍 | 早期缺标准时的探索 | 领域专长未知、模板刷题、代表性偏差 |
| **社区 / 公开活动** | 如 DEF CON AI Village Generative Red Teaming Challenge | 参与面广、创意多样 | 与内部威胁模型、可复现协议难对齐 |

**元架构（文中「从定性到定量」）**

`
SME 清晰威胁模型 → 临时定性探测
 → 标准化攻击手法
 → LM 批量生成变体（数百–数千）
 → 可回归的自动评测 + 缓解再测
`

作者称已在国安前沿威胁与选举完整性 PVT 上采用此环，并希望推广到更多威胁模型。

### 2.3 与「对齐训练」的接口（只标边界，不重写 [[对齐脉络RLHF与偏好优化]]）

- 2022：红队对话 → 成对偏好 → harmlessness RM → **RS / RLHF**（细节见 [[对齐脉络RLHF与偏好优化]] / Bai et al.）。
- 2024：红队发现 → 策略/分类器/系统提示/产品层防护 → 自动评测回归。
- System Card 时代：红队常直接服务 **Preparedness / RSP 档位** 与 **agentic 表面**（工具、浏览、计算机使用），而不只是「对话无害」。

## 三、规模与局限

### 3.1 2022 实验：可核对规模

| 项 | 数字 / 事实（论文） |
|----|---------------------|
| 攻击总量 | **38,961**（公开数据；GitHub `anthropics/hh-rlhf`） |
| 模型规模 | 2.7B / 13B / 52B |
| 红队员 | **324** 名美国众包（主 MTurk；复审等用 Upwork） |
| 报酬 | 每完成 5 段对话约 $7.50–$9.50；复审任务按小时 ≥$20 |
| Table 1 分布 | Prompted 52B 最多（17,739，因训 RM）；各格约 O(1K)–O(3K) |
| 相对 BAD 数据集 [60] | 攻击量约一个数量级更大；模型大约一个数量级；并含 RLHF 模型上的红队数据（作者称当时公开中独有） |

**规模行为（Figure 1，作者结论）**

1. **RLHF**：规模↑ → 显著更难红队（min harmlessness↑）。
2. **Plain / Prompted / RS**：随规模大致**平坦**。
3. **HHH Prompted ≈ Plain**：对话红队下提示干预几乎无增益（与静态毒性结论不一致）。
4. **RS**：各规模最难红队，但定性上常靠**回避 / evasive** 显得无害；52B 时 RS 与 RLHF 的 harmlessness 接近。
5. 分布右尾仍在：平均无害改善后，**仍有大量有害实例**（完美安全未达成）。

**攻击内容（Figure 2 UMAP + Figure 9 标签样本）**

- 聚类含：歧视/冒犯、暴力建议、虚假信息、动物虐待、PII 索取等；作者注部分类型（如一般暴力建议）自评成功率高于「冒犯语言」类。
- ~**916** 场偏 PII；公开数据用正则过滤，部分助手「幻觉」地址等（非真实）。
- 标签频率样本（各 500 场 Prompted/RLHF）：前五为 Discrimination & injustice、Hate speech & offensive language、Violence & incitement、Non-violent unethical behavior、Bullying & harassment；**Non-violent unethical** 成功率相对更高（更「微妙」）；Child abuse / Self-harm 等较少；**Other** 仍多 → 固定标签表难穷尽。

### 3.2 2022 自陈局限（§5.1，选型时必记）

| 局限 | 原文要点 |
|------|----------|
| 应用形态窄 | 红的是「AI 助手」开放对话，不覆盖推荐、补全、纯分类、更大社会技术系统中的 LM |
| 领域专长未知 | 如造炸弹/制毒说明的有害性，众包可能无力裁定 → 需领域组织或让攻击者声明所需专长 |
| 攻击面不完备 | 模型部分训过 Python，数据中几乎未见代码攻击（如写 DDoS）；内部另发现 **roleplay attacks**（如要求「4chan mode」），公开集未覆盖 |
| 自下而上偏差 | 先收集再聚类；或应叠 taxonomy 自上而下指派 |
| 众包质量 | 模板刷题（「以 Y 开头侮辱 X」）因计件激励出现 |
| 成功定义主观 | 复审一致性低；自评与 harmlessness 相关但方差大（Figure 11） |
| 纯人工成本 | 贵且慢；应用自动化红队 [42] 作对照是明确未来工作 |

### 3.3 2024 文补强的「生态层」局限

- **无统一标准** → 跨厂商安全不可比。
- 英语 / 美国中心默认。
- 定性发现若不能产品化为自动评测，组织内**复利价值**有限。
- 政策建议（摘要）：资助 NIST 等定技术标准；资助独立政府/非营利伙伴；培育专业红队市场与认证；便利经审查的第三方访问；把红队实践绑到清晰扩展/发布条件（如 Responsible Scaling Policy）。

### 4.2 架构增量（读卡时用）

1. **威胁模型从「冒犯输出」升级为「能力 × 工具 × 持久探测」**
 - 2022：多轮对话 elicitation。
 - GPT-5：暴力规划效用、生物武器化、连接器场景注入；High bio 假设含**周–月**持续探测。
 - Claude 4.5：间接注入藏在工具返回里；直接注入 + jailbreak 合入 ART；coding / computer / browser 分表面。

2. **度量从「单一无害分数」裂成协议族**
 - 成对专家偏好、政策 grader、pass@k 式攻击成功、拒绝率饱和表、RSP rule-out。
 - 与 [[评测与排行榜可靠性]] 同构：**缺协议的「更安全」不可横比**。

3. **红队 → 自动评测** 成为厂商标准叙事
 - 对齐 2024 文的定性→定量环；SC 中的 ART / StrongReject / Production Benchmarks 即该环的产物。
 - 反过来：只有自动集、不做 expert red-team 的发布（见 Opus 4.1 笔记「自愿自动 ASL-4 rule-out、不做 human uplift」）是**资源裁剪**，不是方法消亡。

4. **勿与 [[对齐脉络RLHF与偏好优化]] 混读**
 - SC 里的 safe-completions / CAI 式原则 / RSP 是**缓解与治理**；红队章节回答的是「怎么找洞、怎么证明洞变小」。本笔记不展开前者公式。

## 五、误区（跟读时主动避开）

1. **「RS/RLHF 难红队 = 已安全」**
 2022：RS 常靠回避；harmlessness 分布仍有长尾；内部 roleplay 攻击可绕过。2025 SC：厂商自己写「非免疫」。

2. **「HHH 提示 / 系统提示已经够」**
 对话红队下 Prompted ≈ Plain；静态毒性集上的提示增益**不能**外推到自适应攻击者。

3. **「众包红队 = 专家红队」**
 2022 明确不知众包是否具备武器/化学等专长；2024/SC 把 PVT、CBRN、防务背景专家单列——**威胁模型决定人选**。

4. **「攻击成功有客观唯一标签」**
 自评、偏好模型、复审者两两不一致；政策 grader 与「规划效用」也不是同一随机变量。

5. **「公开红队集只会被善用」**
 作者讨论：同一数据可训更安全模型，也可训更有害模型（并举 GPT-4chan 类事件为社区背景）；发布是利弊权衡，不是免费午餐。

6. **「自动红队可完全替代人类」**
 2024 定位为**补充**；SC 仍并列专家战役与 PyRIT/Shade。静态攻击集尤其会制造虚假安全感（Claude 4.5 引 Nasr et al. 自适应攻击论述）。

7. **「System Card 红队章节可以当跨厂排行榜」**
 战役设计、访问档位（helpful-only / 缓解开关）、k、表面（聊天 vs 工具）均不同；只可做**方法对照**，不可直接比 ASR。

8. **「红队笔记 = 再写一遍对齐」**
 对齐回答如何优化；红队回答如何暴露与回归。本议题禁止滑回 PPO/DPO 推导。
