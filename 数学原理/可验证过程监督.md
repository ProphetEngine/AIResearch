# 可验证过程监督：VPS + VPRM（≠ 学习式 PRM）

> **定位**：[[可验证过程监督]] **P0**——立「**中间步骤由确定性域信号 / 规则核验，而非神经裁判**」横切：
> - **VPS**（*Verifiable Process Supervision*）：SFT 诱导可解析结构 → 对中间声明做确定性核验 → 自适应子任务加权 + RL；棋类可控床 + GSM8K 复现「outcome-only 涨分、过程塌缩」。
> - **VPRM**（*Verifiable Process Reward Models*）：指南定义的逐步决策树上，对每步 **step id + step label** 做规则打分，再加终局 outcome；医学 RoB（Cochrane）结构化推理。
> **攻坚线**：**架构思想 / 监督信号设计（主）** + **评测字段（辅）**（准确率 vs 过程质量 / 一致性；表内数字）。
> **硬划界（开篇钉死）**：
> - **≠ [[过程奖励模型PRM谱系]]**：禁止重写 Lightman / Math-Shepherd / PRM 综述环（人类逐步标注 → 自动逐步标签 → 学习式 PRM → TTS/过程 RL）。本篇**不训神经逐步 RM**。
> - **≠ [[形式化验证与LLM]]**：不写定理证明器 / Lean / Z3 形式验证主轴；形式核验仅作 VPS 文内对照一句（「中间不必写成可证明语言」）。
> - **≠ [[GRPO与DAPO算法族]]**：不写 GRPO→DAPO 技巧清单 / 裁剪·动态采样配方；两文用 GRPO/DAPO 只作**优化器接口**，不抄算法族。
> - **≠ [[推理时扩展TestTimeScaling]]**：不写 TTS / o1 / R1 产品通史；本篇只谈 **训练期过程奖励从哪来**。
> **补链不升主**：ProcessBench（过程错误定位评测）、GenPRM / ThinkPRM（生成式 / 长 CoT 核验器）仍属**学习或生成式裁判**谱系 → 仅索引，禁止展开成第二主轴。
> **禁止编造**：主张与表数字一律锚定官方 PDF（2026-09-22 CST）。
> **二进制**：五篇 PDF 均 **≪20MB**（`ls -lh`，见 §一），默认可入库。

**一句话抓手：**
- **VPS**：别只奖终着/终答——先用 SFT 把推理**写成可抽取声明**，再用引擎/算术规则**确定性核验**，并用自适应权重逼难子技能。
- **VPRM**：在指南已规定逐步问题与决策树的域（RoB），对**每一步的题号+标签**打规则分，再加终局标签分——过程奖励本身也可验证。
- **补链三件**：ProcessBench 量「找最早错步」；GenPRM / ThinkPRM 仍是**神经/生成式逐步裁判**（对照轴，不是本篇主法）。

## 二、议题边界：可验证过程 ≠ 学习式 PRM ≠ 形式证明器

### 2.1 三轴对照（跟读）

| 轴 | 中间步骤信号从哪来 | 代表（仓库位置） | 本篇是否主写 |
|---|---|---|---|
| **学习式 PRM** | 人标 / 自动 rollout 标签 → **训一个逐步打分网络**（或生成式裁判） | [[过程奖励模型PRM谱系]]；补链 GenPRM / ThinkPRM | **否**（禁重写） |
| **形式核验** | CoT→FOL/Lean，由 **Z3 / 证明器** 判定 | [[形式化验证与LLM]] | **否**（一句对照） |
| **可验证过程监督** | 域规则 / 引擎 / 指南决策树对**结构化中间声明**做确定性打分 | **本篇 VPS / VPRM** | **是** |

跟读直觉：[[过程奖励模型PRM谱系]] 的问题是「**怎么学一个好裁判**」；本篇的问题是「**裁判能不能干脆别学——域里本来就有 checker**」。outcome-only RLVR（终答 exact-match / 单测）在两文里都是**对照基线**，不是要再写一套 R1 通史。

### 2.2 两篇主文如何自划界（文内）

- **VPS Related work**：承认 Lightman / Math-Shepherd 等过程监督，但指出现有路线常依赖 **learned PRM 或 LLM judge**；VPS 主张结构先验 + **deterministic verification**，**without learned reward models or LLM judges**。并点名同期 **Pronesti et al. (2026) = VPRM**：VPRM 面向「步骤结构先验已给定」的结构化任务；VPS 面向「结构不先验给定、需 SFT 诱导」的可验证域，并加自适应加权。另对照形式中间态+定理证明器一线：VPS 用 SFT 结构 + 域信号，**不要求**中间态天然可证。
- **VPRM Intro**：批评神经逐步裁判的不透明、偏置与 reward hacking；主张「至今尚无工作表明过程奖励本身可在可符号检查的任务上做成可验证」——然后在 RoB 上兑现。

`
outcome-only RLVR 学习式 PRM / GenPRM / ThinkPRM
 （只奖终答） （神经/生成裁判打逐步分）
 │ │
 └──────────┬─────────────────────┘
 ▼
 可验证过程监督（本篇）
 结构化中间声明 + 确定性域核验

## 三、主文 A：VPS（2605.12519）

### 3.1 问题立轴：准确率涨了，推理塌了

VPS 抽象与 §1 的核心观察：

> RLVR 通常只优化终答正确；模型可以**预测更好，但暴露的推理变得不完整、不准确或不自洽**。

棋类可控床上，outcome-only GRPO：**涨着法准确率，却把推理质量打崩**（win-rate MAE 相对 SFT 升 **46% / 112%**，内部一致性掉到 **0.721 / 0.312**；R1-Distill-Llama-8B 上约 **70%** 着法与自身胜率分析矛盾）。这就是本篇要修的病。

### 3.2 三件套架构（Algorithm 1 / §3）

1. **SFT 结构先验**：在合成结构化轨迹上 SFT，强制 schema（如 `<think>` 内候选分析、可抽取声明），使下游可用**句法规则**抽 claim，而不是语义 LLM 解析。
2. **确定性核验器 $V$**：抽出 $\{c_k\}$，对每个子任务对照域真值（规则 / 引擎 / 一致性）得 $r_k\in[0,1]$。
3. **自适应聚合**：EMA 跟踪各子任务表现 $\mu_k$，按 headroom $1-\mu_k$ 做温度 softmax 得 $w_k$（带 $w_{\min}$ 地板），诱导**隐式课程**——难的子技能权重大。

总奖励（Eq.1）：

$$
R = R_{\mathrm{form}} + R_{\mathrm{acc}} + \lambda\, R_{\mathrm{reason}},\quad
R_{\mathrm{reason}}=\sum_k w_k r_k
$$

跟读：SFT 负责「**写得出可检查的格式**」；RL 负责「**写对里面的声明**」；自适应权重负责「**别平均用力、先打最瘸的腿**」。

### 3.3 棋评测字段与主结果（Table 1）

**任务**：FEN → `<think>` 分析候选 → `<answer>` 最优着。
**数据**：SFT 用 Lichess Evaluations（Stockfish；主实验 **10k** 位，消融另有 1M）；RL/评测用 Lichess Puzzle（**50k / 1k / 1k**）；训练位深 25、held-out 深 30。
**基座**：Qwen3-8B；DeepSeek-R1-Distill-Llama-8B。优化：**GRPO**（接口，不展开配方）。$R_{\mathrm{acc}}$ 用 Ruoss et al. 的 270M action-value $Q_\theta(s,a)$（稠密 $[0,1]$，非纯 0/1）。

| 模型设定 | Top-1 Acc ↑ | Elo ↑ | Coverage ↑ | WR MAE ↓ | PV Overlap ↑ | Consist. ↑ |
|---|---:|---:|---:|---:|---:|---:|
| Qwen3-8B SFT | 0.212 | 1160 | 0.207 | 0.310 | 0.323 | 0.961 |
| Qwen3-8B SFT+GRPO（outcome） | 0.534 | 1670 | 0.302 | 0.452 | 0.183 | 0.721 |
| Qwen3-8B **VPS** | **0.536** | **1706** | **0.441** | **0.218** | **0.376** | **0.978** |
| R1-Distill-Llama-8B SFT | 0.215 | 996 | 0.226 | 0.346 | 0.341 | 0.978 |
| R1-Distill-Llama-8B SFT+GRPO | 0.541 | 1670 | 0.385 | 0.732 | 0.330 | 0.312 |
| R1-Distill-Llama-8B **VPS** | **0.545** | **1744** | **0.508** | **0.286** | **0.362** | **0.985** |

**字段含义（§4.1）：** WR MAE = 声称胜率 vs 引擎；PV overlap = 续招与引擎主变重合；Consist. = 最终着是否等于自称最高胜率候选。
**摘要主张（与摘要数字对齐）：** VPS 保准确率的同时，相对 outcome-only 大幅修过程——摘要写 win-rate error 降 **达 30%**、一致性近饱和；outcome-only 则 WR error 升 **达 112%**、一致性降 **达 69%**。

**定性（§4.2）：** outcome-only 还有 reward gaming——Qwen3-8B 唯一候选数从 **2.20→1.65**（重复顶着而非比较）；VPS 使平均唯一候选接近 **3.0**。

### 3.4 无结构先验时：准确率对齐下的 LLM 裁判（Table 2）

问：纯 outcome GRPO（无 SFT 结构）能否自己学出好推理？在**匹配准确率 / 同训练步**下，用三裁判（GPT-4o / Claude Opus 4.6 / Gemini 3 Flash）打 Relevance / Completeness / Clarity / Fluency（1–5）。例如 Qwen3-8B：VPS matched-acc Overall **3.420** vs GRPO-best **2.582**；R1-Distill：**3.271** vs **2.267**。结论：无结构先验时，outcome-only 收敛到**预算相关捷径**，而非可靠多步推理（§4.4 / 摘要）。

### 3.5 GSM8K 外推（Table 3，Qwen3-0.6B）

| Method | Acc. | Step Arith. | Consist. |
|---|---:|---:|---:|
| SFT only | 0.446 | 0.638 | 0.821 |
| GRPO-only | 0.760 | 0.681 | 0.647 |
| SFT + GRPO | 0.760 | 0.658 | 0.621 |
| **VPS** | **0.763** | **0.905** | **0.889** |

跟读：终答 Acc 几乎打平 outcome-only，但**逐步算术正确率**与**答-迹一致性**被 VPS 拉回来——与棋床同构。

### 3.6 自适应加权（跟读一句）

固定均匀聚合在子技能难度不均时次优；自适应按 headroom 加权，尤其在更强域先验（1M SFT）时改善最难子任务（Fig.3 叙述）。本篇不抄超参见附录。

## 四、主文 B：VPRM（2601.17223）

### 4.1 域：为何 RoB 适合「全过程可验证」

Risk-of-bias（Cochrane RoB2）：每个偏倚域有**固定逐步问题**与**规则决策树**，把逐步标签组合映射到 Low / Moderate / High（Fig.1）。模型轨迹 $Y=(o_1,\ldots,o_T)$ 中每步输出 **step identifier $s_t$** + **step label $\hat\ell_t$**；金标由指南规则给出。

跟读：这里「结构」不是 SFT 硬教出来的自由 schema，而是**领域指南本来就规定了问什么、怎么跳**——与 VPS「先诱导结构再核验」互补（VPS 文内亦如此对照）。

### 4.2 可验证过程奖励（§3.2）

逐步瞬时奖励：

$$
r_t = w_t^{n}\, s_t^{n}(s_t,s_t^{\star}) + w_t^{l}\, s_t^{l}(\hat\ell_t,\ell_t^{\star})
$$

终局 $r_{\mathrm{label}}$ 核验整条轨迹推出的风险标签是否等于金标。总奖励：

$$
R(Y;x)=\sum_{t=1}^{T} r_t + r_{\mathrm{label}}
$$

全部由**手写规则**算，无神经逐步 RM。Fig.2 对照：outcome-only 只看最终 `<answer>`；VPRM 逐步 `Answer:` 标签也可打分。

**理论一句（Theorem 1，不展开证明）：** 在 $\mu_c>\mu_i$ 等温和假设下，GRPO/DAPO 的期望 advantage 对正确轨迹为正、对错误为负——过程可验证奖励与组相对优化兼容地「推正确推理」。

### 4.3 数据与训练设定（§4）

| 数据集 | Train | Test | 角色 |
|---|---:|---:|---|
| Cochrane Forest Ext | 2651 | 295 | 主训+验（含全文研究；文称共 2946 / ~4M tokens） |
| Cochrane Forest | – | 1846 | 评测 |
| RoBBR Cochrane | 774 | 906 | 训+测 |
| RoBBR Non-Cochrane | – | 2489 | OOD 测 |

逐步标签用 **Llama 3.1 405B** 合成（temp 0.7；系统提示在附录）。策略： **Qwen2.5-7B**；SFT 5 epoch；RL 3 epoch，**GRPO / DAPO**，每批 **16** 条采样。指标：Accuracy、macro-F1；另报 **Coherence** = 终局风险是否等于决策树 $D(\hat\ell_{1:T})$（RoB2 macros）。

### 4.4 主结果（Table 2 / 3，摘关键）

**Cochrane Forest（代表列）：**

| 设定 | Acc | F1 |
|---|---:|---:|
| Qwen2.5-7B pretrained | 32.9 | 31.6 |
| Qwen2.5-7B-SFT | 45.1 | 36.9 |
| Qwen2.5-7B-GRPO（verifiable **outcome**） | 81.5 | 70.2 |
| **Qwen2.5-7B-GRPO-VPRM** | **87.9** | **76.7** |
| Qwen2.5-7B-DAPO-VPRM | 79.2 | 60.6 |
| Llama-3.1-405B（对照） | 68.4 | 45.5 |
| GPT-OSS-120B（对照） | 67.1 | 49.8 |

- 抽象写：相对 SOTA **F1 高至约 20%**；相对可验证 **outcome** 高 **6.5**（表上 Forest：76.7−70.2=**6.5** F1）。
- RoBBR Non-Cochrane 上 GRPO-VPRM 亦优于 outcome-only（Acc **60.7** vs **56.8**；F1 **47.2** vs **45.1**）→ 文称泛化非纯记训练集规律。
- **vs 神经 PRM（Table 3，同带 outcome）：** GRPO-PRM-GPT-OSS Acc/F1 **78.2 / 56.1**；MedPRM **76.8 / 53.4**；**VPRM 87.9 / 76.7**——确定性指南核验干净于神经逐步裁判。
- **消融：** 无 outcome 时 full VPRM 仅 **40.2 / 35.3**；有 outcome 时 steps-only **83.1 / 71.8**，full **87.9 / 76.7** → 过程与 outcome **互补**，缺一不可。

## 六、跟读小结与仓库用法

1. **病**：outcome-only RLVR 常「分数涨、过程烂」（VPS 棋/GSM8K；VPRM 则强调中间无保证）。
2. **药**：把中间声明变成**可自动抽取 + 可确定性核对**的对象；奖励 = 格式/终答 + 过程（VPS 另加自适应课程）。
3. **两工况**：结构需诱导（棋/数学声明）→ **VPS**；结构已由指南给定（RoB 决策树）→ **VPRM**。
4. **不要混进**：[[过程奖励模型PRM谱系]] 学习式 PRM 数据环、[[形式化验证与LLM]] 证明器、[[GRPO与DAPO算法族]] 算法配方、[[推理时扩展TestTimeScaling]] TTS 产品史；GenPRM/ThinkPRM/ProcessBench 只作对照索引。
5. **下一步可读**：VPS Appendix 子任务奖励公差设计；VPRM Appendix RoB 域细节与 Coherence 分域表——需要实现级再下钻，本笔记停在架构与表字段。
