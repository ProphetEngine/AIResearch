# MOC · 推理与基础设施

## 综述

大模型从研究走向可用，瓶颈越来越多地落在系统侧：同一套模型，训练能否在数千张加速卡上稳定扩展，推理能否在给定的延迟和成本内服务大量请求，往往决定了它能否真正落地。本 MOC 收录的笔记围绕这一问题展开，分为两条主干。

训练侧关注如何把计算、显存和通信分摊到多卡多机上。主线是数据、张量、流水线和专家等并行方式的组合；在此基础上，低精度训练压缩计算与显存开销，专用通信库支撑 MoE 的专家间数据交换，而强化学习训练因为生成与更新交替进行，又带来了异步 rollout 这类新的系统设计。

推理侧关注如何让同样的模型更快、更省。它沿着几个相对独立的方向推进：调度层面以连续批处理提高吞吐，再到预填充与解码分离、面向 MoE 的分布式服务；解码层面以投机解码用小模型或额外预测头提前起草、由大模型并行验证，减少串行步数；数值层面以权重、激活和 KV 缓存量化降低显存与带宽压力；部署层面则延伸到底层算子编写、端侧小模型和机密计算环境。推理引擎把这些技术整合为可用的服务框架，是理解各方向如何落地的汇合点。

本 MOC 讲系统如何承载模型，不讨论模型能力本身。KV 缓存保留哪些 token 的算法问题见 [[MOC_注意力与长上下文]]，推理期多投入算力换取更强能力的方法见 [[MOC_推理时计算]]。

## 训练系统

解决大模型怎样在集群上切分与通信，以及怎样做低精度训练与强化学习训练。[[分布式训练并行策略]] 是本组的前置；[[NVSHMEM与DeepEP通信]] 深入专家并行的通信底层；[[低精度训练FP8与FP4]] 和 [[RL训练系统与异步Rollout]] 都以并行策略为前置知识。

## 投机解码

解决解码阶段的加速问题，且不改变输出分布。[[投机解码原理与发展脉络]] 是组内共同前置；[[EAGLE3投机解码]] 讲草稿头怎么训练；[[EntMTP熵引导投机解码]] 在多头草稿的固定拓扑之间切换，并沿用 EAGLE-2 的 path value 作选树特征；[[AdaptiveSpec与Goose]] 以 EAGLE-3 为草稿器，在其上做运行时树形调度，与 EntMTP 同属无需训练的运行时调度。MTP 头的训练见 [[MTP训练范式]]（跨 MOC，主挂训练方法），属于延伸阅读，不是前置。
