# MOC · 智能体Harness

## 综述

智能体能否把多步工具调用做成稳定任务，往往不取决于单次生成质量，而取决于外围怎样组织：提示与技能怎样写入上下文，代码修复与桌面操作怎样接外部工具，长程状态怎样写入与调回记忆，多个智能体怎样协作，以及用什么基准衡量这些能力。本 MOC 收录的笔记围绕上述 **harness** 问题展开，即工具循环与长程任务的组织方式，而不是训练期偏好优化或可验证奖励的算法本身。

第一条主干是上下文、技能与代码 / GUI 工具链。上下文工程决定哪些指令、示例与检索结果进入窗口；代码智能体 harness 给出修补—运行—再试的外环；计算机使用与 GUI 智能体把动作空间扩到桌面与浏览器；工具集成强化学习与工具轨迹合成，则回答「会用工具」所需的训练信号与数据从哪来。

第二条主干是记忆。从长程记忆通论，到 Mem0、Zep 一类生产层写入与检索，再到用强化学习维护记忆、用规划式记忆支撑长程任务，记忆从「多轮对话里多记一点」变成可独立设计的一层。

第三条主干是多智能体协作与科研循环：辩论与编排、面向科研的生成—核验—修正、以及把智能体放进经济激励下的对齐实验。以智能体为对象的评测（代码修复、浏览深研、经营长程、工作流与 MCP 工具导航等）仍主挂本页，作为读完组织方式后的对照尺，而不是迁到通用安全或榜单页。

**本页管：** 工具使用与长程任务组织、上下文工程与技能、代码 / GUI / Computer-Use harness、记忆层（含生产 Memory）、多智能体协作与科研智能体循环、**以智能体为对象的评测基准**。

**本页不管：** 偏好优化、GRPO、RLVR、过程奖励等**算法骨架**见 [[MOC_对齐与强化学习]]；测试时搜索、Mixture-of-Agents 的推理期算力主线见 [[MOC_推理时计算]]（相关篇在本页仅副挂）；气候政策 agent、辅导教学评测等见 [[MOC_专科基础模型]]；具身 VLA 主线见 [[MOC_多模态与具身]]。

读工具集成 RL 或经济对齐之前，宜先具备对齐侧算法背景：见 [[GRPO与DAPO算法族]]（跨 MOC 前置，主挂 [[MOC_对齐与强化学习]]）——此处只点背景，不展开算法机制。
