# GLM-4.5 Technical Report 深读笔记

> **主要来源**：[GLM-4.5: Agentic, Reasoning, and Coding (ARC) Foundation Models](https://arxiv.org/abs/2508.06471)；[zai-org/GLM-4.5 README](https://github.com/zai-org/GLM-4.5)（仅用于核对型号名）；[THUDM/slime README](https://github.com/THUDM/slime)（报告 §3.5 所附框架地址）（截至 2025-08-08）。报告只有 arXiv v1；两个 README 不引事实，不计入截至，slime 的内容均取自报告。
> **研究线**：架构思想（主：「窄而深」的 MoE、专家模型迭代的后训练）；AI Infra（辅：Muon 预训练设定、slime RL 框架）
> **范围与相邻笔记**：
> - ≠ [[DeepSeekV3训练与MoE基建]]、[[KimiK2技术报告深读]]：两者是 GLM-4.5 架构对比的参照，各自的训练配方在那两篇。
> - ≠ [[优化器与训练稳定性]]：Muon 的来历与稳定性问题在那篇，本篇只记 GLM-4.5 的设定。
>
> **意义**：GLM-4.5 是智谱第一个 MoE 模型（355B 总参、32B 激活），目标是在一个开源模型里同时做好智能体、推理与编程（ARC）。它相对 DeepSeek-V3 与 Kimi K2 走「窄而深」路线，并用更多注意力头换推理表现；后训练先分别训练推理、智能体与通用对话专家，再自蒸馏成一个同时支持思考与非思考模式的模型。12 项 ARC 基准平均排名第 3，智能体类排名第 2，参数只有 DeepSeek-R1 的一半、Kimi K2 的三分之一。

## 一、问题背景

报告认为，通用模型的衡量标准是三种相互关联的能力：与外部工具和真实世界交互的智能体能力、数学与科学中的复杂推理、真实软件工程中的编程能力。o1、o3 与 Claude Sonnet 4 等闭源模型已在单项上表现突出，但一个在三方面都强的开源模型仍然缺位（§1）。

## 三、核心机制

### 3.1 架构（§2.1，Table 1）

- **MoE**：无辅助损失的负载均衡路由加 sigmoid 门控，每层 1 个共享专家。与 DeepSeek-V3、Kimi K2 不同，GLM-4.5 缩小宽度（隐层维度与路由专家数）、增加高度（层数），因为作者发现更深的模型推理能力更好。GLM-4.5 隐层 5120、160 个专家激活 8 个；GLM-4.5-Air 为 106B 总参、12B 激活。
- **注意力**：GQA 加 partial RoPE；用 2.5 倍的注意力头（隐层 5120 配 96 个头）。更多的头并不降低训练损失，但稳定提升 MMLU、BBH 等推理基准。加 QK-Norm 稳定注意力 logit 的范围。
- **MTP**：两个型号都加 1 层 MoE 作多 token 预测层，用于推理时的投机解码。

### 3.2 预训练与中训练（§2.2–§2.4）

预训练语料来自网页、社交媒体、书籍、论文与代码仓库，摘要称多阶段训练共 23T token。网页按质量分桶，最高质量桶在预训练中被使用超过 3.2 个 epoch，最低桶丢弃；在 MinHash 之外再做 SemDedup 语义去重；代码全部做 Fill-In-the-Middle 训练。预训练分通用与代码推理两段，最大序列长度 4,096。

中训练用中等规模的领域数据（含指令数据），分三段：仓库级代码（把同仓文件、相关 issue、PR 与 commit 拼进同一上下文，扩到 32K）；合成推理数据（用推理模型为数学、科学与竞赛代码题合成思考过程）；长上下文与智能体（扩到 128K，上采样长文档并加入大规模合成智能体轨迹）。中训练用 best-fit packing，避免截断推理过程或仓库级代码。

**超参**（§2.4）：词嵌入、偏置与 RMSNorm 权重之外都用 Muon（Newton–Schulz 迭代 5 步，动量 0.95，更新 RMS 缩放 0.2），作者观察到 Muon 收敛更快、能容忍更大 batch；学习率用余弦衰减而非 WSD，因为 WSD 在 SimpleQA、MMLU 上更差，显示稳定段欠拟合；batch 在前 500B token 内从 16M 增到 64M token；扩到 32K 时 RoPE base 从 10,000 调到 1,000,000；负载均衡偏置的更新率前 15T token 为 0.001、之后为 0。

### 3.3 后训练：专家模型迭代（§3）

后训练分两段：先分别训练推理、智能体与通用对话三类专家（各自冷启动 SFT 再 RL），再用自蒸馏把专家融合成一个模型，使其既能深思熟虑地推理，也能直接回答。

- **SFT**（§3.1）：整体 SFT 有数百万样本、上下文 128K，平衡有无显式思考的数据，得到混合推理模式。函数调用模板用类 XML 的特殊 token 包住键值，减少代码参数里的 JSON 转义。按回答长度去掉下半 50% 的 prompt，只用一半数据却使数学与科学提升 2%–4%；对难 prompt 每题生成四个回答，再提升 1%–2%。
- **推理 RL**（§3.2）：基于 GRPO，去掉 KL 损失项（本节曲线来自较小的实验模型）。两阶段难度课程，后期换成极难题（pass@8 为 0 且 pass@512 大于 0）；直接在 64K 输出长度上单阶段 RL，优于逐步加长；代码 RL 用按 token 加权的平均损失，比按序列平均收敛快；科学 RL 只用专家验证过的高质量选择题效果最好。
- **智能体 RL**（§3.3）：网页搜索用终答正确性作奖励，编程用带可验证测例的 SWE 数据；只对模型生成的 token 计损失，忽略环境反馈；工具调用格式出错时立即终止并给零奖励。采用迭代自蒸馏：RL 到一定步数或进入平台期后，用 RL 模型的回答替换冷启动数据得到更好的 SFT 模型，再继续 RL。
- **通用 RL**（§3.4）：融合规则、人类反馈与 AI 反馈。函数调用分为逐步规则奖励（格式正确且与标注完全一致才得 1 分）与端到端多轮 RL（任务完成才得分）；最后用一个专门挑出易触发语言混杂、重复与格式错误的 prompt 集做病理 RL，因为这些问题出现率往往不到 1%，混在普通数据里惩罚效率太低。

### 3.4 slime RL 框架（§3.5）

slime 由训练（Megatron）、rollout（SGLang 加 Router）与数据缓冲三个模块组成。数学、代码等推理 RL 用同步、训练与推理同置的模式，配合动态采样减少 GPU 空闲；SWE 等智能体任务数据生成慢，用异步、解耦的模式，借助 Ray 把推理与训练引擎放在同一或不同 GPU 上。训练用 BF16，每次策略更新后对参数做在线分块 FP8 量化再交给 rollout，以 FP8 推理加速采样。智能体任务另有高并发的 Docker 隔离环境与完全异步的训练循环。

## 五、意义

GLM-4.5 给出了与 DeepSeek-V3、Kimi K2 不同的 MoE 形态取舍：同等激活参数下减宽加深、多给注意力头，以训练损失之外的推理表现为依据。后训练的专家模型迭代把「分域专家 RL 再自蒸馏」做成固定流程，用一个模型同时覆盖思考与非思考模式；slime 的同步与异步双模式则是智能体 RL 在基础设施上的一个具体解法。

## 六、局限与待核实

1. **算力未公开**：报告没有给出预训练的 GPU 型号、卡数、总 GPU 时数、并行拓扑与训练精度。
2. **各阶段 token 量**：预训练两段与中训练三段各自的 token 数只在 Figure 3 中给出，本篇不录；正文只有摘要的 23T。
3. **实现细节**：partial RoPE 的具体维度划分、GLM-4.5-Air 不用 QK-Norm 的原因均未说明。
4. **消融对象**：推理 RL 一节的对比曲线来自较小的实验模型，不是 GLM-4.5 本身。
5. **专家阶段的超参**：三类专家各自的 RL 步数、数据量与融合细节没有完整给出。
