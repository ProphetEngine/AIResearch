# Olmo 3 全栈开放配方

> **主要来源**：[Olmo 3](https://arxiv.org/abs/2512.13961)（Team Olmo，v2，2026-04-14；首次提交 2025-12-15）（截至 2026-04-14）
> **研究线**：架构思想与开放配方接口（主：从预训练到三种后训练的整条模型流程全部公开）；评测字段（辅：Base 与旗舰 Think 的对照表）
> **范围与相邻笔记**：
> - ≠ [[Nemotron3Ultra技术报告深读]]：工业开放权重的混合架构 MoE 旗舰在那篇，本篇写数据与配方全部公开的研究型旗舰。
> - ≠ [[GPToss模型卡深读]]：OpenAI 开放权重推理模型的模型卡在那篇，本篇不涉及其格式与量化。
> - ≠ [[Gemma4技术报告深读]]：Google 开放权重模型族在那篇，本篇是 AI2 的 dense 7B 与 32B。
>
> **意义**：Olmo 3 是 AI2 的「完全开放」（fully-open）模型系列：除最终权重外，还公开每个阶段的数据、中间检查点、训练与评测代码，覆盖 7B 与 32B 两个 dense 规模、Base 加 Think、Instruct、RL-Zero 三种后训练分支。报告称旗舰 Olmo 3.1 Think 32B 是迄今最强的完全开放思考模型（摘要），并在训练 token 约少 6 倍的情况下缩小了与 Qwen 3 32B 等同规模最强开放权重模型的差距（§2.3）。

## 一、问题背景

报告区分两类开放：开放权重（open-weight）模型只发布最终检查点；完全开放模型沿整条流程发布数据与中间阶段（§1、Figure 1）。只有最终权重时，研究者无法检查或修改中间阶段，也无法判断 RL 的收益是否来自预训练数据泄漏。报告举的例子是：已有的开源 RLVR 研究大多建立在不公开预训练与中训练数据的开放权重模型上，污染与「虚假奖励」难以区分，这是 RL-Zero 分支的出发点（§6）。Olmo 3 的目标是让每个阶段、检查点、数据点与依赖都能被介入（摘要）。

## 二、脉络

| 时间 | 工作 | 关键一步 |
|---|---|---|
| 2024-02 | [OLMo](https://arxiv.org/abs/2402.00838) | AI2 首个完全开放语言模型 |

## 三、核心机制：模型流程（§2）

### 3.1 Base 三阶段

| 阶段 | 数据 | 规模 | 目标 |
|---|---|---|---|
| 预训练 | Dolma 3 Mix | 7B 为 5.93T token；32B 的余弦日程截断在 5.5T | 自然多样语料 |
| 中训练 | Dolma 3 Dolmino Mix | 100B；32B 用不同随机种子跑两次后做权重平均 | 数学、代码、问答、指令与思考痕迹，为后训练铺路 |
| 长上下文 | Dolma 3 Longmino Mix | 7B 为 50B，32B 为 100B | 扩到 65K 上下文 |

预训练的三处新做法：万亿 token 级的全局去重工具、olmOCR 处理的科学 PDF、受 token 约束的配比与质量感知的上采样（§2.1）。

### 3.2 三种后训练

| 分支 | 配方 | 用途 |
|---|---|---|
| Think | SFT → DPO（Delta Learning）→ OlmoRL（RLVR） | 先生成思考痕迹再答，旗舰 |
| Instruct | SFT（可从 Think SFT 热启动）→ DPO（含长度控制）→ RLVR | 短答、对话、函数调用，低延迟 |
| RL-Zero | 直接从 Base 做 RLVR | 研究基座数据如何影响 RL；RL 数据相对预训练与中训练数据再做去污染 |

### 3.3 成本（§2.4）

1024 张 H100 专供 Olmo 3；从开始训练到评测完 Olmo 3 Think 32B 约 56 天，其中预训练（含中训练与长上下文）约 47 天，后训练约 9 天。报告按每 H100 小时 2 美元给出 2.75M 美元的估算。初版发布后，最好的 RL 运行又在 224 张 GPU 上续训 21 天，得到 Olmo 3.1 Think 32B。配方多先在 7B 或更小规模上开发，再迁到 32B。

## 四、核心机制：架构与训练栈（§3.2、附录）

1. **Dense 解码器**：7B 与 32B，超参大体沿用 OLMo 2；预训练与中训练上下文为 8192。
2. **滑动窗口注意力**：每 4 层中有 3 层用窗口 4096 的滑动窗口注意力，最后一层始终是全注意力。
3. **分词器**：与 OLMo 2 相同，源自 OpenAI 的 cl100k。
4. **吞吐**：在 OLMo-core 上，序列长度 8192、全程 bfloat16 时，7B 每 GPU 每秒 7700 token、32B 为 1960 token，对应约 43% 与 41% 的 MFU。
5. **长上下文**（§3.6）：olmOCR 科学 PDF 中超过 8K token 的文档有 22.3M 篇以上（合计 640B token），超过 32K 的有 4.5M 篇（380B token）；Longmino Mix 为 34% 长上下文数据加 66% 从 Dolmino Mix 采样的高质量短数据。报告称 66% 长、34% 短的反向配比在 10B token 的早期实验中使 OlmoBaseEval 子集下降 2.5 分。

## 五、核心机制：后训练（§4–§6）

### 5.1 Think

1. **Delta Learning**（§4.3）：直接拿 Qwen3-32B Thinking 生成的 chosen 回答继续 SFT 会损害初始 SFT 模型；改用 DPO，让模型偏好 32B 的回答而非较弱的 Qwen3-0.6B Thinking 回答，数学与代码推理明显提升（Table 21）。Table 22 显示先做 DPO 再 RLVR 优于只做 SFT 就 RLVR，DPO 是更好的 RL 起点。
2. **OlmoRL**（§4.4）：在 GRPO 上做的改动包括过滤零梯度组、主动采样以维持批大小、token 级损失、去掉 KL 损失、clip-higher、截断重要性采样，以及优势不做标准差归一化。验证器覆盖数学、代码、指令遵循与通用对话（含 LM 评判）。报告称这些改进使 RL 训练提速 4 倍，连续批处理加飞行中权重更新使训练在一半 GPU 上快一倍。
3. **3.0 到 3.1**：Olmo 3 Think 32B 训练 750 步，续训到 2300 步得到 3.1；因算力限制停止，报告称性能尚未饱和。

### 5.2 Instruct（§5）

从 Think SFT 热启动有益；DPO 结合高对比度、关注差距的样本与 GPT 评判信号，并用长度控制换取可用性。函数调用评测包括 BFCLv3、LitQA2 与 SimpleQA。

### 5.3 RL-Zero（§6）

覆盖数学、代码、指令遵循与通用混合四个领域。单域奖励上升快，混合设置更难，各域都相对欠优化，报告把它作为多目标 RLVR 的基准位。

## 六、主要结果

1. **旗舰**（Table 1，Olmo 3.1 Think 32B 对 Qwen 3 32B）：MATH 96.2 对 95.4，AIME 2025 78.1 对 70.9，IFEval 93.8 对 86.5，IFBench 68.1 对 37.3；落后的项目有 ZebraLogic 80.1 对 88.3，LiveCodeBench v3 83.3 对 90.2，GPQA 57.5 对 67.3，AlpacaEval 2 LC 69.1 对 75.6。
2. **Base**（Table 13，32B 分阶段）：预训练后 OlmoBaseEval Math 48.4、Code 29.8；中训练后 69.7 与 39.7；长上下文阶段后 Math 回落到 61.4，Code 保持 39.7。

## 七、意义

1. **「开放」被拆成可检查的层级**：报告以完全开放与开放权重的区分组织全文，中间检查点和每阶段数据是两者的核心差别。
2. **RL 研究有了不受污染干扰的基座**：RL-Zero 的数据相对预训练与中训练数据去污染，可以反查中训练数据对 RL 的影响。
3. **偏好学习看差距而不是看答案质量**：Delta Learning 说明 chosen 回答本身已饱和时，拉大 chosen 与 rejected 之间的差距才是 DPO 的收益来源。

## 八、局限与待核实

1. **差距仍在**：报告的表述是「缩小差距」「接近」，在 ZebraLogic、LiveCodeBench、GPQA 等项目上仍落后 Qwen 3 32B。
2. **成本是估算**：2.75M 美元按每 H100 小时 2 美元换算；报告说明这只反映按最佳配方训练所用的墙钟时间，不含可能大幅拉长周期的实质修改或研究探索。
3. **图与附录未录**：数据配比、长上下文消融等主要在图与附录大表中，本篇不读图取数。
4. **版本差异**：v2（2026-04-14）相对 v1（2025-12-15）更新了对照表中 LLM360 K2-V2 的分数（改用 2026 年 1 月 22 日上传的检查点）、增补了若干代码与数据地址脚注和一段 RL 设置说明，删去了致谢中的一句。本篇按 v2。
