# Qwen3 Technical Report 深读

> **主要来源**：[Qwen3 Technical Report](https://arxiv.org/abs/2505.09388)（Qwen Team，v1，2025-05-14）（截至 2025-05-14）
> **研究线**：架构思想（主：Dense 与 MoE 模型族、同一权重内的思考与非思考模式、思考预算）；AI Infra（辅：三阶段预训练、旗舰四阶段后训练与小模型蒸馏的算力取舍）
> **范围与相邻笔记**：
> - ≠ [[开源与闭源前沿模型谱系]]：各厂代际坐标在那篇，本篇只写 Qwen3 报告本身。
> - ≠ [[推理时扩展TestTimeScaling]]：推理时扩展的通论在那篇，本篇只写 Qwen3 的思考预算如何实现。
> - ≠ [[Qwen38Next架构深读]]：后续 Next 系列的架构设计在那篇，本篇只写 Qwen3。
>
> **意义**：Qwen3 是 Qwen 系列的开放权重模型族，包括 Dense 与 MoE 两类架构，参数规模从 0.6 到 235 billion，以 Apache 2.0 发布（摘要）。它把思考模式与非思考模式放进同一套权重，用对话模板中的标志切换，并用思考预算控制推理长度；小模型不走旗舰的四阶段后训练，而是从旗舰蒸馏，报告称所需 GPU 时间只有四阶段方法的 1/10（§4）。预训练用了 36 trillion token，覆盖 119 种语言和方言（§1）。

## 一、问题背景

报告指出，此前用户要在对话优化模型（如 GPT-4o）和专用推理模型（如 QwQ-32B）之间切换（摘要、§1）。Qwen3 要在一个模型里同时提供两种行为，并允许按需分配推理算力。另一个问题是模型族里小模型很多，若每个都走完整的冷启动、推理 RL、模式融合、通用 RL 四阶段，算力代价高，报告的回答是强到弱蒸馏（§4.5）。

## 三、核心机制：模型族与架构（§2）

1. **Dense**（Table 1）：0.6B 与 1.7B 为 28 层，Q/KV 头 16 / 8，绑定嵌入，上下文 32K；4B 与 8B 为 36 层，Q/KV 头 32 / 8，上下文 128K，4B 绑定嵌入、8B 不绑定；14B 为 40 层，40 / 8；32B 为 64 层，64 / 8；14B 与 32B 上下文 128K。
2. **MoE**（Table 2）：Qwen3-30B-A3B 为 48 层，Q/KV 头 32 / 4；Qwen3-235B-A22B 为 94 层，64 / 4；两者都是 128 个专家、每 token 激活 8 个，上下文 128K。
3. **组件**：与 Qwen2.5 一样用 GQA、SwiGLU、RoPE 与 pre-norm 的 RMSNorm；去掉 QKV 偏置，引入 QK-Norm 以稳定训练；分词器为字节级 BPE，词表 151,669。
4. **MoE 的差别**：沿用细粒度专家切分，但与 Qwen2.5-MoE 不同，不使用共享专家，并采用全局批负载均衡损失。报告称同样的预训练数据下，MoE 基座只用 1/5 的激活参数就能接近 Dense 基座；相对 Qwen2.5 MoE，用不到 1/2 的激活参数和更少的总参数就能超过；用 Qwen2.5 Dense 基座 1/10 的激活参数可达到相当水平（§3.3）。

## 四、核心机制：预训练（§3）

1. **数据**：36 trillion token，119 种语言和方言。扩量手段有三：用 Qwen2.5-VL 识别大量 PDF 类文档中的文本，再用 Qwen2.5 精炼；用 Qwen2.5、Qwen2.5-Math、Qwen2.5-Coder 合成教材、问答、指令与代码等数据；增补多语数据。多语数据标注系统覆盖超过 30 trillion token，标注教育价值、领域与安全等维度，支持实例级配比。
2. **三阶段**（§3.2）：通用阶段在约 30 trillion token 上以 4,096 长度训练；推理阶段提高 STEM、代码、推理与合成数据占比，再训约 5T 更高质量 token，并加快学习率衰减；长上下文阶段用数千亿 token 以 32,768 长度训练，其中 75% 的文本长度在 16,384 到 32,768 之间、25% 在 4,096 到 16,384 之间。
3. **长度外推**：RoPE 基频用 ABF 从 10,000 提到 1,000,000，推理时叠加 YARN 与 Dual Chunk Attention，报告称序列容量提高四倍。
4. **超参**：按三个阶段拟合缩放律，为每个 Dense 与 MoE 模型预测学习率与批大小。

## 五、核心机制：后训练（§4）

### 5.1 旗舰四阶段

Qwen3-235B-A22B 与 Qwen3-32B 依次经过：

1. **长思维链冷启动**（§4.1）：题目覆盖数学、代码、逻辑与一般 STEM，带可验证答案或测试用例。用 Qwen2.5-72B-Instruct 过滤难以验证、含多个子问题或纯生成的题，并去掉不需要思维链也能答对的题；回答由 QwQ-32B 生成多个候选后严格筛选。报告强调这一阶段的样本和步数宜少，以免限制后续 RL。
2. **推理 RL**（§4.2）：3,995 个题目与验证器配对，用 GRPO 更新。大批量、每题多次 rollout、off-policy 训练，并控制熵。报告举例 Qwen3-235B-A22B 在 170 个 RL 步内 AIME'24 从 70.1 升到 85.1。
3. **思考模式融合**（§4.3）：用户在查询或系统消息中加 /think 或 /no_think 切换，非思考模式输出一个空的 think 块；多轮中以最后一个标志为准。Hugging Face 的分词器配置还可以用 enable_thinking=False 关闭思考。思考数据由第二阶段模型对第一阶段题目做拒绝采样得到。
4. **通用 RL**（§4.4）：奖励系统覆盖 20 多类任务，涉及指令遵循、格式遵循、偏好对齐、智能体与 RAG 等；奖励分三类：规则奖励、有参考答案的模型评分（Qwen2.5-72B-Instruct 打分）、无参考的偏好奖励模型。

### 5.2 思考预算

思考长度达到用户设定的阈值时，人工截断并插入一句固定的英文停止指令，模型随后基于已有思考直接给出最终答案。报告强调这一能力不是专门训练的，而是模式融合后自然出现的（§4.3）。

### 5.3 强到弱蒸馏（§4.5）

覆盖 Dense 的 0.6B、1.7B、4B、8B、14B 与 MoE 的 30B-A3B。先做 off-policy 蒸馏，学生学习教师在 /think 与 /no_think 下的输出；再做 on-policy 蒸馏，学生自采样，对齐 Qwen3-32B 或 Qwen3-235B-A22B 的 logits，最小化 KL 散度。

Table 21（Qwen3-8B，从同一 off-policy 检查点出发，只用数学与代码题）：

| 方法 | AIME'24（括号内为 pass@64） | GPU 小时 |
|---|---|---|
| Off-policy 蒸馏 | 55.0（90.0） | - |
| + 强化学习 | 67.6（90.0） | 17,920 |
| + On-policy 蒸馏 | 74.4（93.3） | 1,800 |

报告观察到，蒸馏提高了 pass@64，强化学习没有。

## 六、主要结果

1. **推理 RL**：Qwen3-235B-A22B 在 170 步内 AIME'24 从 70.1 到 85.1（§4.2）。
2. **蒸馏对比**：同为 Qwen3-8B，on-policy 蒸馏的 AIME'24 为 74.4、用 1,800 GPU 小时，RL 为 67.6、用 17,920 GPU 小时（Table 21）。
3. **长上下文**（附录 A.1.1）：RULER 评测中 YARN 的缩放因子取 4，思考模式下思考预算设为 8192 token，以免超长输入上的过度推理。

## 七、意义

1. **两种模式合进一套权重**：思考与非思考由模板标志切换，不再需要两个模型；思考预算让推理长度成为可调参数。
2. **小模型不必重走旗舰流程**：on-policy 蒸馏在 Table 21 中分数更高、GPU 小时更少，并提高了 pass@64。
3. **MoE 路线的一个分支**：不用共享专家、改用全局批负载均衡，与使用共享专家的 MoE 设计形成对照。

## 八、局限与待核实

1. **算力与并行未披露**：除 Table 21 的局部 GPU 小时外，GPU 型号、卡数、训练精度与并行策略都未给出。
2. **结构细节不全**：Dense 的隐藏维度与 FFN 宽度、MoE 的专家宽度与路由打分函数未列出。
3. **思考预算的上限**：报告称输出超过 32K 后性能预计还会继续上升，留作未来工作（Figure 2 的说明）。
4. **版本**：arXiv 上只有 v1（2025-05-14）。
