# DeepSeek-R1 推理训练专项深读（训练管线与奖励/算法）

> **主要来源**：[DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning](https://arxiv.org/abs/2501.12948)（截至 2026-01-04）。以 arXiv v2 为准，含补充材料 A–F。
> **研究线**：架构思想（主：R1-Zero 到 R1 的训练管线、奖励设计）；数学原理（辅：GRPO 相对 PPO 的取舍）
> **范围与相邻笔记**：
> - ≠ [[推理时扩展TestTimeScaling]]：推理时扩展的整体论证与 o1 对照在那篇，本篇只写 R1 的训练配方。
> - ≠ [[GRPO与DAPO算法族]]：GRPO 的目标函数与后续修正在那篇，本篇只写 R1 用 GRPO 时的设定。
>
> **意义**：R1 表明，大模型的推理能力可以只靠强化学习激发，不需要人工标注的推理轨迹。R1-Zero 在 DeepSeek-V3-Base 上直接用 GRPO 加规则奖励训练，AIME 2024 的 pass@1 从 15.6% 升到 77.9%，自我反思、验证等行为自发出现。R1 再用冷启动、拒绝采样与两段 RL 解决可读性与通用能力，并把推理能力蒸馏进开源小模型。报告的结论是：关键不在大规模人工标注，而在难题、可靠的验证器和足够的 RL 算力。

## 一、问题背景

此前提升大模型推理主要靠监督数据，例如人工写的思维链示范；OpenAI o1 显示长推理可以大幅提高数学与代码能力，但没有公开方法。R1 要回答的问题是：不给人类推理轨迹，只给可验证的结果奖励，模型能否自己学会长推理（§1）。

人工推理轨迹难以扩展，也会把人的思路偏好带进模型，限制模型探索更好的推理方式（§1、§2）。因此 R1-Zero 跳过 SFT，直接在基座上做 RL。

## 三、核心机制

### 3.1 R1-Zero：只用 RL

R1-Zero 在 DeepSeek-V3-Base 上跳过 SFT，直接用 GRPO 训练（§2）。模板只要求把推理写在 think 标签内、答案写在 answer 标签内，不注入任何解题内容上的偏好（§2.3）。

**规则奖励**（§2.2）：准确性奖励对数学等确定答案做规则比对，代码题用编译器与测例判定；格式奖励鼓励把推理放进 think 标签；两者等权相加。推理任务上不用结果或过程的神经奖励模型，理由是它在大规模 RL 中容易被奖励黑客利用，重训也贵、管线更复杂。

**训练设定**（§2.1）：学习率 3e-6，KL 系数 0.001，每题采 16 个输出；最大长度在第 8.2k 步前为 32,768，之后为 65,536，性能与回答长度都在 8.2k 步出现明显跳变；共 10,400 步，合 1.6 个 epoch；每 400 步把参考模型换成最新策略。

### 3.2 GRPO 相对 PPO 的取舍（补充材料 A.3）

1. **不训价值模型**：PPO 用 GAE 估优势，需要与策略同量级的价值模型，开销大；长思维链中模型会反思、改写前文，用部分回答预测最终奖励更加困难。GRPO 对同一问题采一组回答，用组内奖励的均值与标准差算相对优势。
2. **KL 的位置**：GRPO 把 KL 的无偏估计直接加进损失；PPO 常把逐 token 的 KL 当作稠密奖励，累计后可能隐式惩罚长度，阻碍回答变长。
3. **参考模型更新**：长程训练中策略会远离初始参考，因此定期把参考模型换成最新策略。

在 DeepSeek-Coder-V2-Lite 上的对照中，PPO 对 GAE 的 λ 很敏感：取多数开源实现的默认值 0.95 时明显弱于 GRPO，调到 1.0 才接近 GRPO。

### 3.3 R1 的多阶段管线（§3，Figure 2）

R1-Zero 的问题是可读性差、语言混杂。R1 分五步：

| 阶段 | 做法 | 目的 |
|---|---|---|
| 冷启动 SFT（R1-Dev1） | 数千条对话式、第一人称的长思维链数据，由 R1-Zero 生成后经人工示范改写、LLM 扩写与人工复核（补充材料 B.3.2） | 让输出可读 |
| 第一段 RL（R1-Dev2） | GRPO，clip ratio ε 设为 10；加语言一致性奖励，即思维链中目标语言词的比例（§3.2.1） | 在可读格式上提升推理，抑制语言混杂 |
| 拒绝采样 SFT（R1-Dev3） | 从第一段 RL 的检查点拒绝采样约 600k 条推理数据，加约 200k 条非推理数据，即补充材料 B.3.3 标题所称的 800K 监督数据 | 同时提升推理与写作等通用能力 |
| 第二段 RL（R1） | 推理数据仍用规则奖励，通用数据用奖励模型加格式奖励；共 1,700 步，偏好奖励只在最后 400 步加入；温度降到 0.7（§3.2.2） | 对齐有用性与无害性 |

偏好奖励只用于最后 400 步，是因为基于模型的偏好奖励训练过久会出现奖励黑客（补充材料 B.5）。有用性奖励模型用 66,000 对偏好数据训练，只看最终摘要；安全奖励模型用 106,000 条标注为安全或不安全的 prompt，逐条打分并评估完整回答（§3.1）。

### 3.4 蒸馏（补充材料 F、B.4.3）

用 800k 条 R1 数据对 Qwen2.5 与 Llama 基座只做 SFT，不做 RL，得到 1.5B 到 70B 的六个蒸馏模型。作者认为加 RL 还能再提升，留给社区。

## 四、主要结果

**阶段对比**（Table 3）：冷启动后指令遵循上升，但因冷启动数据量小，AIME 2024 从 R1-Zero 的 77.9 降到 59.0；第一段 RL 把推理拉回到 74.0；拒绝采样 SFT 主要提升 AlpacaEval 2.0 与 Aider-Polyglot；第二段 RL 后 R1 的 AIME 2024 为 79.8，提升主要在通用与偏好基准，AlpacaEval 2.0 提升 25%、ArenaHard 提升 17%（§4）。

**蒸馏与纯 RL**（Table 16）：同为 32B，蒸馏得到的 DeepSeek-R1-Distill-Qwen-32B 在 AIME 2024 pass@1 为 72.6，在 Qwen2.5-32B-Base 上做超过 10K 步大规模 RL 得到的 Qwen2.5-32B-Zero 为 47.0。作者的结论是：把强模型蒸馏进小模型又省又好；要推进超越人类先验的边界，仍可能需要更强的基座与更大规模的 RL（补充材料 F.1）。

## 五、意义

R1 把「可验证奖励加大规模 RL」确立为推理模型的主路线：规则奖励避开了神经奖励模型的奖励黑客问题，GRPO 省掉价值模型，使长思维链 RL 在大模型上可行。多阶段管线说明纯 RL 得到的能力需要冷启动与通用数据来变得可用；蒸馏结果则说明，推理能力可以低成本地转移给小模型，小模型自己做 RL 反而不划算。

## 六、局限与待核实

1. **版本差**：v1（2025-01-22）是正文较短的版本；v2（2026-01-04）加入补充材料 A–F，含训练成本、安全评测与 R1-Dev1 到 Dev3 的阶段结果。R1-Zero 的 AIME 2024 pass@1，v1 写 71.0%，v2 写 77.9%。本篇以 v2 为准。
2. **报告自述的局限**（§6）：结构化输出与工具调用仍弱；简单问题上仍有过度思考；主要针对中英文优化，其他语言的查询可能用英语推理；对 prompt 敏感，few-shot 会降低表现，建议 zero-shot；软件工程任务因评测耗时长，大规模 RL 覆盖不足，相对 DeepSeek-V3 提升有限。纯 RL 方法本身依赖可靠奖励，写作等难以构造规则奖励的任务仍是开放问题。
3. **数据量口径**：RL 数据表中代码为 17K，正文另写 8k 条修 bug 题；通用数据表中为 66K，正文另写 12,000 条无害性题。两处与表的合计关系未写明。
4. **冷启动规模**：冷启动数据只写「数千条」，没有确切数量。
5. **800k 数据以单轮为主**：作者指出这可能限制多轮对话能力。
