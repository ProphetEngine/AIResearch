# Kimi k1.5 Technical Report 深读

> **主要来源**：[Kimi k1.5: Scaling Reinforcement Learning with LLMs](https://arxiv.org/abs/2501.12599)（Kimi Team，v4，2025-06-03；首次提交 2025-01-22）（截至 2025-06-03）
> **研究线**：架构思想（主：长上下文作为 RL 的新缩放轴、用长思维链近似隐式规划）；数学原理（辅：在线策略镜像下降的近似目标、长度奖励）

> - ≠ [[推理时扩展TestTimeScaling]]：推理时扩展的通论在那篇，本篇只写 k1.5 把上下文拉长当作训练期的缩放手段。
>
> **意义**：Kimi k1.5 是 Kimi 系列公开的长思维链 RL 配方：把上下文扩到 128k，用在线策略镜像下降的平方残差近似加长度奖励，不使用蒙特卡洛树搜索、价值函数或过程奖励模型，并给出把长思维先验压回短思维链的 long2short。报告称其 long-CoT 在多项基准上与 o1 相当（摘要），short-CoT 在 AIME 2024、MATH 500、LiveCodeBench 上分别达到 60.8、94.6、47.3（摘要）。K2 与 K3 的策略优化与 partial rollout 都回指这篇。

## 一、问题背景

报告认为扩展预训练受高质量数据总量限制，而 RL 是新的缩放方向（§1）。此前公开工作还没有在 LLM 上做出有竞争力的 RL 结果，k1.5 要给出可复现的做法：用长上下文让模型在思维链里完成试错、纠错与回溯，而不是在推理时跑显式搜索树（§2.3.1）。报告同时处理一个反向问题：长思维链学到的能力要能压回短思维链，否则部署成本过高（§2.4）。

## 三、核心机制：训练流水线与隐式规划（§2）

### 3.1 阶段

顺序是预训练、普通 SFT、long-CoT SFT、RL，报告只展开 RL（§2）。Long-CoT 预热在精炼过的 RL 题集上用提示工程构造覆盖规划、评估、反思与探索的长推理路径，再做轻量 SFT 作为 RL 热身（§2.2）。文本与视觉联合训练和做 RL。

### 3.2 用长上下文近似隐式搜索（§2.3.1）

报告先描述显式规划：维护一棵搜索树，节点是问题与当前部分解，批评模型给反馈，再选择扩展方向。然后把搜索历史与反馈全部展平成语言 token 序列，把规划算法看成在已有 token 上预测下一步。结论是不必显式建树：用长上下文自回归去近似这种隐式搜索，token 数对应传统规划的算力预算；部署时仍是纯自回归采样。报告强调目标不只是训练集准确率，而是学到可泛化的试错与回溯策略（§2.3.2）。

### 3.3 Partial rollout（§2.6.2）

每轮固定输出 token 预算，超长轨迹截断后写入回放缓冲，下一轮从截断处续写；已完成的段落直接复用，只有当前段落需要 on-policy 计算，部分段落可以不计入损失。长短轨迹因此能在异步工作节点上混跑。系统还会检测重复片段并提前停止，可以附加惩罚。

### 3.4 Long2short（§2.4）

四种方法：long-CoT 与 short-CoT 模型做权重平均，免训练；同题采样 8 次取最短正确答案做 SFT；DPO 以最短正确答案为正样本，更长的错误答案和长度达到正样本 1.5 倍的正确答案为负样本；标准 RL 之后另开一阶段，启用长度奖励并显著减小最大 rollout 长度。报告举例，k1.5-short w/ rl 在 AIME 2024 上 Pass@1 为 60.8（8 次平均），平均只用 3,272 个 token（§3.4）。

## 四、核心机制：目标函数与奖励（§2.3）

### 4.1 目标

数据为带标准答案的题集，策略生成思维链与答案。奖励取 0 或 1：可验证题用规则（如测试用例），自由形式用奖励模型判断是否匹配。优化目标是期望奖励（式 1）。

### 4.2 在线策略镜像下降的近似（§2.3.2）

第 i 轮以当前模型为参照，最大化期望奖励减去与参照策略的 KL 散度（式 2）。闭式解是参照策略乘上奖励的指数，再归一化。报告不直接优化闭式解，而最小化一个平方残差：奖励减去归一化项与 KL 系数的对数，再减去参照与当前策略的对数比，对参照策略采到的样本取平方期望。归一化项用每题 k 条样本近似，实践中也可以用这 k 条的平均奖励作基线。得到的梯度形如带均值基线的策略梯度，外加一项对对数比的 ℓ₂ 正则；与常见策略梯度的差别在于样本采自参照策略，即 off-policy。每轮参照变了就重置优化器。

报告明确不用价值网络：除了效率，还因为逐步的优势估计会惩罚「先错后纠」的路径，而长思维链恰恰需要先探索错误再恢复。

### 4.3 长度奖励（§2.3.3）

对同题 k 条回答，按长度在最短与最长之间归一化，最短对应 0.5、最长对应 −0.5；正确答案直接用这个值，错误答案只保留非正部分。它与原奖励加权相加。训练初期先不启用，再恒定启用，避免早期拖慢。加权系数的具体数值报告未给。

### 4.4 采样与奖励侧（§2.3.4–2.3.5）

1. **课程与优先采样**：先易后难；按 1 减成功率的比例多采样失败题。难度用 SFT 模型高温回答 10 次的通过率估计。
2. **过滤**：不看思维链直接猜，8 次内猜中的题剔除，排除选择题、判断题、证明题等易假阳性类型。
3. **编程题测试用例**：用 CYaRon，每题先生成 50 个测试用例、抽 10 份参考提交，至少 7 份结果一致才算有效用例；至少 9 份提交通过全部选中用例才入训练集。报告称最终 323 道题进入训练集。
4. **数学奖励模型**：价值头式奖励模型人工抽检准确率约 84.4，思维链式奖励模型达到 98.5，RL 采用后者；两类各约 800k 数据。
5. **视觉 RL 数据**：真实世界、合成视觉推理、文本渲染三类。

## 五、预训练与 SFT 的公开骨架（§2.5、附录 B）

1. **预训练三阶段**：先纯语言再逐步多模态，视觉塔先单独训练、再解冻语言模型，最终视觉文本占比 30%；cooldown 用高质量与合成问答；长上下文激活把最大长度从 4,096 扩到 32,768 再到 131,072，用 40% 全注意力与 60% 部分注意力数据，RoPE 频率设为 1,000,000。
2. **披露边界**：附录 B.3 只说架构是 Transformer 解码器变体加多模态，称规模化实验超出本报告范围。总参数量、层数、预训练总 token 数均未给出。
3. **普通 SFT**：约 100 万文本样本，其中通用问答 500k、编程 200k、数学与科学 200k、创意写作 5k、长上下文任务 20k，另加约 100 万视觉文本。调度上先以 32k 上下文训 1 个 epoch（学习率从 2×10⁻⁵ 降到 2×10⁻⁶），再以 128k 训 1 个 epoch（重新预热到 1×10⁻⁵ 再降到 1×10⁻⁶）。
4. **开源态度**：附录 B 写明当时不开源专有模型权重，承诺公开数据处理流程与配方。

## 六、基础设施（§2.6）

1. **迭代同步 RL**：rollout、回放缓冲、训练，由中央调度。
2. **混合部署**：用 Kubernetes Sidecar 把 Megatron 训练与 vLLM 推理放在同一个 pod 共享 GPU；训练结束后权重卸载、转成 Hugging Face 格式放入共享内存，经 Mooncake 用 RDMA 传给 vLLM，结束后重启 vLLM 以释放残留状态。训练切到推理不到 1 分钟，推理切回训练约 10 秒。
3. **代码沙箱**：用 crun 替代 Docker，容器启动从 0.12 秒降到 0.04 秒；16 核机器上每秒可启动的容器数从 27 升到 120（§2.6.4 的表）。

## 七、主要结果（§3）

1. **Long-CoT**（Table 2）：MATH-500 为 96.2（o1 为 94.8），AIME 2024 Pass@1 为 77.5（o1 为 74.4），Codeforces 百分位为 94（与 o1 相同），LiveCodeBench Pass@1 为 62.5（o1 为 67.2），MathVista-Test 为 74.9（o1 为 71.0），MMMU-Val 为 70.0（o1 为 77.3），MathVision-Full 为 38.6（QVQ-72B 为 35.9）。
2. **Short-CoT**（Table 3）：MATH-500 为 94.6，AIME 2024 为 60.8，LiveCodeBench 为 47.3；MMLU、IF-Eval、CLUEWSC、C-Eval 分别为 87.4、87.2、91.7、88.3。附录 C 注明 Table 3 的 IF-Eval 来自中间检查点，将更新。
3. **消融的定性结论**（§3.5）：同数据下小模型可以靠更长思维链接近大模型，但追求上限时扩更大模型的上下文更省 token；相对 ReST（不用负梯度），本方法样本复杂度更好（Figure 10）；课程学习优于全程均匀采样（Figure 9）。曲线上的点未录。

## 八、意义

1. **把上下文长度做成 RL 的缩放轴**：k1.5 的主实验是把 rollout 上下文扩到 128k 并观察硬推理基准持续提升，partial rollout 让超长轨迹不必在一轮内跑完。
2. **用 off-policy 的平方残差替代价值网络**：目标函数显式锚定当前参照策略，并刻意不惩罚「先错后纠」。
3. **长思维链与短思维链被当成一对问题**：long2short 用合并、拒绝采样、DPO 与带长度奖励的 RL 四种方式把能力压回短输出。

## 九、局限与待核实

1. **规模未披露**：总参数量、层宽、视觉塔结构、预训练总 token 数均未给出（附录 B.3）。
2. **超参未给数值**：KL 系数、每题采样数 k、长度奖励的加权系数、RL 学习率与批大小、partial rollout 的具体 token 预算。
3. **IF-Eval**：Table 3 的该数字来自中间检查点（附录 C）。
4. **「up to +550%」**：摘要对 GPT-4o 与 Claude Sonnet 3.5 的这一说法是口号级，具体对比应回到 Table 3 的单格。
5. **版本差异**：v1（2025-01-22）与 v4（2025-06-03）的正文结论与数字一致，差异在作者名单与页眉版本号。本篇按 v4。
