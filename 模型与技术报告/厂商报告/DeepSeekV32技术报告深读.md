# DeepSeek-V3.2 Technical Report 专项深读卡

> **主要来源**：[DeepSeek-V3.2: Pushing the Frontier of Open Large Language Models](https://arxiv.org/abs/2512.02556)；[DeepSeek-V3.2-Exp 推理参考实现](https://huggingface.co/deepseek-ai/DeepSeek-V3.2-Exp/tree/main/inference)（截至 2025-12-02）。报告只有 arXiv v1；推理实现页没有更新日期，不计入时间锚点。
> **研究线**：架构思想（主：DeepSeek Sparse Attention 与两阶段继续预训练）；AI Infra（辅：GRPO 的稳定化技巧、工具调用中的思考上下文管理）
> **范围与相邻笔记**：
> - ≠ [[DeepSeekV3训练与MoE基建]]：基座的 MoE、MLA 与训练配方在那篇，V3.2 报告没有重述这些数字。
> - ≠ [[DeepSeekR1推理训练深读]]：GRPO 加规则奖励的推理 RL 起点在那篇，本篇只写 V3.2 对 GRPO 的扩展。
>
> **意义**：报告认为开源模型落后闭源有三个原因：普通注意力在长序列上效率低、后训练算力投入不足、智能体场景的泛化与指令遵循差。V3.2 对应给出三项改动：在 V3.1-Terminus 上继续训练引入稀疏注意力 DSA，这是相对前代唯一的架构改动；把后训练算力提到超过预训练成本的 10%，并为此加了四项 GRPO 稳定化技巧；合成 1,800 多个环境与 85,000 条复杂 prompt 做智能体 RL。推理基准上与 GPT-5 相当，加长思考的 Speciale 变体在 IMO、IOI、ICPC、CMO 2025 达到金牌水平。

## 一、问题背景

推理模型出现后，大模型能力快速提升，但闭源模型的提升速度明显快于开源，差距在拉大。报告归纳了开源模型的三处不足（§1）：

1. **架构**：依赖普通注意力，长序列效率低，既妨碍部署也妨碍后训练。
2. **资源分配**：后训练阶段算力投入不足，难题上表现受限。
3. **智能体**：泛化与指令遵循明显落后于闭源模型。

## 三、核心机制

### 3.1 DeepSeek Sparse Attention（§2.1）

DSA 由两部分组成：

1. **Lightning indexer**：对每个 query token 与其前面的 token 计算索引分数，用少量 indexer 头、ReLU 激活，可用 FP8 实现，计算很省。
2. **细粒度 token 选择**：按索引分数只取 top-k 个 KV 条目，再对这一子集做注意力。

为了能从 V3.1-Terminus 继续训练，DSA 基于 MLA 的 MQA 模式实现：每个 latent KV 条目被该 token 的所有 query 头共享。V3.1-Terminus 训练与 prefill 用 MHA 模式、解码用 MQA 模式（附录 A）。

这样主模型核心注意力的复杂度由 O(L²) 降到 O(Lk)，k 为选中的 token 数、远小于 L；indexer 本身仍是 O(L²)，但计算量远小于 V3.1-Terminus 的 MLA（§2.3）。

### 3.2 两阶段继续预训练（§2.1.1）

起点是上下文已扩到 128K 的 V3.1-Terminus，两阶段数据分布都与 Terminus 的 128K 长上下文扩展数据一致。

| 阶段 | 做法 | 规模 |
|---|---|---|
| 稠密预热 | 保持稠密注意力，冻结 indexer 以外的全部参数；把各注意力头的分数求和并做 L1 归一化，作为目标分布，用 KL 损失训练 indexer；学习率 10⁻³ | 1000 步，每步 16 条 128K 序列，共 2.1B token |
| 稀疏训练 | 引入 top-k 选择，全模型适应稀疏模式；indexer 只在选中集合上继续对齐注意力分布，其输入从计算图中分离，主模型只用语言建模损失；学习率 7.3 × 10⁻⁶，每个 query 选 2048 个 KV token | 15000 步，每步 480 条 128K 序列，共 943.7B token |

### 3.3 后训练与 GRPO 稳定化（§3）

后训练沿用 V3.2-Exp 的管线，同样使用稀疏注意力：

- **专家蒸馏**：从同一 V3.2 基座分别训练写作与通用问答，以及数学、编程、通用逻辑推理、通用智能体、智能体编程、智能体搜索六个领域的专家，均支持思考与非思考模式，各自经大规模 RL 后为最终模型生成数据。蒸馏后的模型只略低于专家，差距可由后续 RL 消除。
- **混合 RL**：仍用 GRPO，把推理、智能体与人类对齐合并为一个 RL 阶段，以避免多阶段训练的灾难性遗忘。推理与智能体任务用规则结果奖励、长度惩罚与语言一致性奖励；通用任务用生成式奖励模型，每个 prompt 有各自的评分细则。

为了扩大 RL 算力，报告加了四项稳定化技巧（§3.1）：

1. **无偏 KL 估计**：用当前策略与旧策略的重要性比校正 K3 估计，使梯度无偏；数学等领域可用很弱的 KL 甚至去掉。
2. **离策略序列遮蔽**：大批 rollout 拆成多个 mini-batch 更新，加上训练与推理框架的实现差异，会产生离策略偏差；对优势为负、且旧策略与当前策略 KL 超过阈值的序列置零。
3. **Keep Routing**：MoE 在推理与训练框架中即使输入相同也可能路由到不同专家，导致激活参数子空间突变；把采样时的专家路由路径在训练时强制复用。报告称自 DeepSeek-V3-0324 起就在 RL 中采用。
4. **Keep Sampling Mask**：top-p、top-k 截断使旧策略与当前策略的动作空间不一致，违背重要性采样的前提；把采样时的截断掩码同样施加到训练中的策略上，并发现这有助于保持语言一致性。

**V3.2 与 Speciale**：V3.2 用专家蒸馏的数据继续 RL 数千步；Speciale 只用推理数据、减轻长度惩罚，并加入 DeepSeekMath-V2 的数据与奖励方法以增强数学证明。

### 3.4 工具调用中的思考（§3.2）

照搬 R1 在第二轮消息到来时丢弃推理内容的做法，会迫使模型每次调用工具都重新推理，浪费 token。V3.2 改为：只有新的用户消息到来时才丢弃历史推理；如果只追加工具输出，推理内容一直保留；即使丢弃推理，工具调用及其结果的历史仍保留。Roo Code、Terminus 等用用户消息模拟工具交互的框架享受不到这一保留，报告建议这类框架用非思考模式。

冷启动阶段用系统提示把推理与工具调用写进同一条轨迹，再交给 RL。随后用环境合成智能体自动合成 1,827 个任务导向的环境，这些任务难解但易验证（§3.2.3）。

## 四、主要结果

| 维度 | 报告数字 | 出处 |
|---|---|---|
| 推理 | 推理任务整体与 GPT-5-High 相当、略逊于 Gemini-3.0-Pro；思考模式 AIME 2025 为 93.1 | §4.1 |
| 代码智能体 | SWE-bench Verified 73.1；Terminal Bench 2.0 用 Claude Code 框架为 46.4，用 Terminus 框架加非思考模式为 39.3 | §4.1 |
| 搜索智能体 | 约 20% 以上的 BrowseComp 用例超过 128K 上下文；不做上下文管理为 51.4，用 Discard-all 策略为 67.6 | §4.1、§4.4 |
| Speciale | IMO 2025 得 35/42、CMO 2025 得 102/126、IOI 2025 得 492/600、ICPC WF 2025 解出 10/12，均为金牌 | §4.2 |
| 合成任务难度 | 随机抽 50 个合成的通用智能体任务，V3.2-Exp 准确率只有 12%，闭源前沿模型最多 62% | §4.3 |

## 五、意义

V3.2 的增量几乎都不在 MoE 主结构上：DSA 通过继续训练接入现有基座，把主模型核心注意力的复杂度从 O(L²) 降到 O(Lk)，又不损失长上下文表现；四项稳定化技巧针对的是大规模 RL 中训练与推理不一致带来的离策略问题，其中 Keep Routing 专门处理 MoE 的路由漂移；思考上下文管理与环境合成则把 R1 式推理接入了工具调用。报告也表明，后训练算力占比是开源模型追赶闭源的一个可调杠杆。

## 六、局限与待核实

1. **报告自述的局限**（§5）：相对 Gemini-3.0-Pro，总训练 FLOPs 更少，世界知识的广度落后；需要更长的生成轨迹才能达到同等质量，token 效率仍是问题；复杂任务求解仍不及前沿模型。
2. **算力口径**：「后训练算力超过预训练成本的 10%」没有给出分母与绝对 GPU 时数。
3. **合成规模口径**：引言写 1,800 多个环境与 85,000 条复杂 prompt，§3.2.3 写 1,827 个环境，两处与 Table 1 各类任务计数的包含关系未写明。
4. **前代模型的数字**：V3.1-Terminus 与 V3.2-Exp 的层数、参数量等未在报告中重述，不应默认等同于 V3。
5. **图中数字**：推理成本曲线（Figure 3）只在图中给出，本篇不录。
