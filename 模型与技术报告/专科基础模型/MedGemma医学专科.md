# MedGemma 1.5：医学专科多模态模型

> **主要来源**：[MedGemma 1.5 Technical Report](https://arxiv.org/abs/2604.05081)（Google Research 与 Google DeepMind，arXiv v2，2026-05-01；v1 2026-04-06）；[MedGemma | Health AI Developer Foundations](https://developers.google.com/health-ai-developer-foundations/medgemma)（产品概述，Last updated 2026-01-13）；[MedGemma 1.5 model card](https://developers.google.com/health-ai-developer-foundations/medgemma/model-card)（Last updated 2026-04-21）（截至 2026-05-01）
> **研究线**：架构思想（主）+ 评测字段与预期用途边界（辅）
> **范围与相邻笔记**：
> - ≠ [[多模态架构脉络]]：本篇不写 CLIP、Flamingo、LLaVA 等通用多模态史线，只以「生成式图文接口已经成立」为前提。
> - ≠ [[法律专科模型]]：本篇不写法律领域的专科模型。
> - ≠ [[生物学基础模型]]：本篇只写医学影像与临床文本这一侧。
> - 专家数、训练 token 总量、临床部署效果、监管批准状态，技术报告与模型卡未写的，本篇不补。
>
> **意义**：MedGemma 1.5 说明，不换骨干、不引入新的跨模态算子，只靠预处理把 3D 体数据和全切片病理图变成 2D token 序列，再配合专科教师蒸馏与强化学习，一个 4B 开放权重模型就能把 CT/MRI、病理、纵向胸片、解剖定位和化验单抽取收进同一生成式接口。它的定位是供开发者验证和微调的起点模型，官方明确不是临床级、不能直接用于诊疗。

## 一、问题背景

通用多模态模型已能看图说话，但医学影像有几处不同：CT 和 MRI 是三维体数据，病理全切片图（WSI）分辨率极高，胸片诊断常要对比前后两次检查，临床文档以化验单 PDF 与电子病历（EHR）为主；而常用的视觉编码器只接受 2D RGB 图像。数据多为去标识的内部或授权数据，输出错误的代价也远高于一般助手。MedGemma 1 已提供医学专科的开放权重模型，1.5 要回答的是：在不更换架构的前提下，怎样把这些高维模态与文档理解加进同一个 4B 模型（摘要、§2）。

1.5 只更新 4B 多模态模型，MedGemma 1 的 4B 多模态模型是它的对照基线；MedGemma 1 的 27B 纯文本与多模态模型本报告不更新，需要复杂临床知识与推理的场景，报告仍指向 27B（Figure 1）。同一集合里的 MedSigLIP（0.4B）是图像编码器组件，模型卡建议不需要文本生成的医学图像分类与检索任务直接使用 MedSigLIP。

## 三、核心机制

### 3.1 骨干与训练

- 与 MedGemma 1 一样基于 Gemma 3，同一架构；视觉编码器为 400M 参数的 MedSigLIP（在去标识医学数据上预训练的 SigLIP 编码器，模型卡），训练 1.5 时冻结，只对语言解码器做额外预训练（§2、§2.1）。
- 后训练沿用 Gemma 3 的蒸馏加强化学习配方，两边都加入医学数据；1.5 的增量是在改进的大型指令教师之外，另在 CT、MRI 与内部病理数据上训练补充的专科教师（§2.2）。
- 文档理解靠蒸馏由 Synthea 合成病历构成的 EHRQA 与多套化验单数据获得（§2.2）。
- 模型卡字段：图像规范化到 896×896、每张编码为 256 个 token；输入总长 128K tokens，输出至多 8192 tokens；只输出文本。

### 3.2 高维影像怎样进入 2D 编码器

这是本篇的架构要点：不换成 3D 骨干，而是序列化加 token 预算加领域预处理（§2.3）。

- **CT/MRI 体数据**：切成轴向 2D 切片序列，每例最多 85 片（合 21,760 个视觉 token），连同报告文本控制在 32K tokens 以内；超出时沿 z 轴等距抽片。CT 用三组 HU 窗分别映射到 R、G、B 三个通道；MRI 没有生理窗，按体做 min-max 归一化后三通道取同值。
- **病理全切片**：先在 5 倍下分割组织区域，再随机选一个倍率切 896×896 的不重叠 patch，每张切片最多 126 个 patch（合 32256 个视觉 token），并保留 patch 的原始空间顺序。病理配图的文本更短，所以上限高于 CT 的 85 片。
- **推理成本**：在 CT-RATE 这类多病种任务上，每例要按 18 个病种逐一查询，查询量是专用 CT 分类器一次前向的 18 倍，形成推理成本瓶颈（附录 A）。

## 四、评测要点

- **新能力（相对 MedGemma 1 4B，摘要）**：3D MRI 病种分类准确率提升 11%，3D CT 提升 3%（绝对值）；胸片解剖定位 IoU 提升 35%；纵向胸片宏准确率提升 4%；MedQA 提升 5%，EHRQA 提升 22%；4 个化验单信息抽取数据集上的宏 F1 平均 18%。
- **代表数字（Table 4）**：MRI Dataset 1 准确率 51.3 到 64.7；胸片解剖定位 Mean IoU 3.1 到 38.0；病理切片报告生成 ROUGE-L 2.2 到 49.4，与外部最好结果 PolyPath 的 49.8 接近。
- **口径注意**：摘要把病理增益写作「47% macro F1 gain」，而 Table 4 的病理指标是 ROUGE-L，两者名称不一致，本篇并列保留，不作换算。
- **代价**：通用知识推理 MMLU Pro 从 39.1 降到 33.8（Table 6）；SLAKE、VQA-RAD 等旧榜有小幅回退（§4 Limitations）。
- **与同尺寸模型对比**：Qwen3 VL 4B 在 MedQA 等通用生物医学文本知识上更强，MedGemma 1.5 在所有视觉任务上更高，作者归因于专科后训练与蒸馏（§4）。
- **协议**：所有评测都用与训练完全隔离的数据或划分；1.5 的提示词相对 1 有更新（§3、附录 B）。

## 五、预期用途与安全评测（模型卡与产品页）

- **预期用途**：使用受 Health AI Developer Foundations 使用条款约束（模型卡）。它是面向医疗与生命科学开发者的起点模型，开发者须针对具体用途训练、适配或做有意义的修改后再用。产品页写明 MedGemma 尚非临床级，通常还需微调；适配途径包括提示工程、微调（含 LoRA 示例）、强化学习示例与智能体编排，且任何适配都需同等验证。
- **限制**：未经验证与适配不得使用；输出不用于直接指导临床诊断、患者管理或治疗建议。多模态能力主要在单图任务上评测，未评测多图理解；未针对多轮对话优化或评测；对提示词可能比 Gemma 3 更敏感；适配时要注意验证集偏差与数据污染。
- **安全评测**：类别包括儿童安全、内容安全、表征伤害与一般医疗伤害；模型卡称前三类相对此前 Gemma 模型达到安全水平；评测主要用英文提示。技术报告未附各类别分数。

## 六、局限与待核实

1. **专科化的代价**：通用推理（MMLU Pro）与 SLAKE、VQA-RAD 等旧榜回退；作者认为旧榜依赖 token 重叠、标准答案不统一，窄任务可用定向微调补回（§4 Limitations）。
2. **非临床决策**：报告称开箱功能是「基础数据处理工具」，区别于自动化临床决策或行医；模型「不应在没有必要的临床微调时部署」（§4、Figure 2 说明）。
3. **多图与多轮**：1.5 可以输入多张切片，但模型卡仍写「未评测多图理解」；能输入多片不等于已完成多图场景评测。
4. **未公开项**：预训练 token 总量与学习率表、MedSigLIP 解冻与原生 3D 编码器的对比、27B 的 1.5 更新、监管批准与临床试验，报告与模型卡均未给出。
5. **数字口径**：摘要「47% macro F1」与 Table 4 的 ROUGE-L 名称不一致；模型卡与报告个别数字因四舍五入略有差异，本篇以报告表格为准。
6. **版本**：报告只有 arXiv 版本（v2，2026-05-01），无正式刊；模型卡为活页，以 2026-04-21 版为准。
