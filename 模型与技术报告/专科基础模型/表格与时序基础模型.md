# 非文本基础模型：TabPFN-3.5 + TimesFM / Chronos 对照

> **主要来源**：[TabPFN-3.5: Technical Report](https://arxiv.org/abs/2609.17895)（Prior Labs Team，v2，2026-09-22；首次提交 2026-09-15）；谱系锚：[A decoder-only foundation model for time-series forecasting](https://arxiv.org/abs/2310.10688)（TimesFM，v4，2024-04-17）；[Chronos: Learning the Language of Time Series](https://arxiv.org/abs/2403.07815)（v3，2024-11-04；TMLR 2024-10）（截至 2026-09-22）
> **研究线**：架构思想（主：表格 vs 时序上「foundation」各指什么、输入如何变成可训序列）
> **范围与相邻笔记**：
> - ≠ [[生物学基础模型]]、[[天气气候基础模型]]：同属非文本 / 科学 foundation 横切；本篇对象是表细胞与一维实值序列，不是分子或球上 3D 场。
> - 不写成 forecasting 工程手册；TimesFM / Chronos 只作谱系锚点。TabPFN 附录 fev-bench 上的 TimesFM-3 / Chronos-2 是后续产品代，不是本篇两篇锚点论文的同名模型。
>
> **意义**：表格与时序是文本之外最常见的数据形态。本篇三篇工作说明「foundation」在这里不共享一套 tokenizer：TabPFN 用合成 prior 预训练、对新表做 in-context 预测；TimesFM 与 Chronos 对未见序列做零样本预报，前者走连续 patch 加 MSE，后者把数值分箱后当语言做交叉熵。

## 一、问题背景

文本 LLM 之外，另一条 foundation 叙事落在表格与时序：能否在大规模预训练后，对新表做少/零梯度更新的 in-context 预测，或对未见序列做零样本预报。三类工作共享口号，但对象几何完全不同——TabPFN 吃表（行×列细胞），TimesFM / Chronos 吃一维实值序列；后两者内部又分叉为连续 patch + 回归头 vs 离散化后当「语言」做交叉熵。

## 三、三条路线的「序列化」

核心问题：实值结构如何变成 Transformer 吞得下的东西？

1. **TabPFN-3.5**：表细胞 → Fourier + ECDF 等 per-cell 编码 → 行内/上下文 Transformer（任务类型作输入；分类与回归共享骨干）。
2. **TimesFM**：实值序列 → 连续 patch（ResidualBlock）→ causal decoder → 更长 output patch（MSE）。
3. **Chronos**：实值序列 → mean scale + 均匀分箱 → 有限词表 token → 现成 T5/GPT-2 → 交叉熵。

### 3.1 TabPFN-3.5（相对 TabPFN-3 的增量，§3）

| 组件 | 文内事实 |
|---|---|
| Per-cell 编码 | 新增可学习 Fourier 与 in-context ECDF（列内 midrank → [0,1] 再展成低频 sin/cos）；标准化数值仍旁路保留 |
| 多任务 | 同一 checkpoint 联合训分类+回归；任务类型作输入 |
| 容量 | in-context transformer 宽 512→1024（每行 8 个 CLS 聚合 token，原 4）；头数 8→16；测试行 grouped-query，KV cache 规模相对 TabPFN-3 基本不变 |
| 规模 | 推荐上限 1M 行 × 6k 特征（Figure 1 图注） |
| 速度句（两句并存） | 摘要：Fast 相对 TabPFN-3 至多 3×；引言：Fast 相对 3.5 至多 6×——引用时带比较基 |

推理：训练行处理一次并缓存，测试行再打分。开源权重 TabPFN-3.5 / Fast；API 侧 Plus 与 Thinking（额外 inference-time compute；声明只靠 TabPFN-3.5 本身，不用 LLM、真实数据、联网搜索或其他模型）。许可证：代码 Apache 2.0；权重 TABPFN-3.5 License v1.0（学术较松，禁止商用生产等，全文见 HF LICENSE）。

### 3.2 TimesFM（锚点论文）

设计原则（§4）：输入非重叠 patch；decoder-only 见前缀预测后续；output_patch_len > input_patch_len，减少自回归步数；随机遮住首 patch 前缀以覆盖多种历史长度。

主模型超参（Appendix Table 6，200M）：num_layers=20，model_dims=1280，input_patch_len=32，output_patch_len=128，num_heads=16，dropout 0.2。同文另训 17M / 70M。损失主文聚焦点预测 MSE。数据：约 80% 实 + 20% 合成；总时间点规模 O(100B)；最大上下文常 512。主张：相对直接把大 LM 当零样本预报器，专训时序、体量小得多（200M 参数、O(100B) 时间点）的模型可明显更好（§1）。

### 3.3 Chronos（锚点论文）

先 mean scaling，再均匀量化到有限 bin，得到词表，然后几乎原样训 T5（及一次 GPT-2 试验）；故意忽略日历特征（§1 / §3）。

| 项 | 文内设定 |
|---|---|
| 骨干 | T5：Mini 20M / Small 46M / Base 200M / Large 710M；另 GPT-2 base 90M |
| 词表 | 4096（含 PAD、EOS）；bin 落在 [-15, +15] |
| 目标 | 交叉熵——regression via classification |
| 上下文 / 预测长 | context 512，训练预测长 64 |
| 数据增强 | TSMixup + KernelSynth；增广:合成 ≈ 9:1 |
| 推理 | 自回归采样 token → dequantize → 反缩放；天然概率多轨迹 |

与 TimesFM 同代对照：Chronos 自称 minimalist——固定词表 + 现成 LM，无时序专用结构。

## 四、三路对照

| 维度 | TabPFN-3.5 | TimesFM（锚点论文） | Chronos（锚点论文） |
|---|---|---|---|
| 对象 | 表格 | 单变量实值序列预报 | 同左 |
| Token | 细胞 / 特征组嵌入（连续） | 连续 patch 向量 | 离散 bin id |
| 骨干 | 表结构 in-context Transformer | 自研 causal stack + residual I/O | 现成 T5（改词表大小） |
| 预训练数据 | 合成 prior | 大规模真实 web 时序 + 合成 | 公开时序集 + TSMixup + GP 合成 |
| 损失 | 多任务 clf / 回归分布 | MSE 点预测 | CE 分类式回归 |
| 参数量锚 | 正文未给 | 主 200M（另 17/70M） | 20M–710M T5 族 |
| 开源入口 | PriorLabs/TabPFN；权重定制许可 | Google Research 预训练形态（本篇不跟后续渠道） | amazon-science/chronos-forecasting |

## 五、评测（只取架构含义）

1. **TabPFN-3.5（Table 1）：** 在 TabArena / BeyondArena / STRABLE / MulTaBench / RelArena-α / TALENT / ScoringBench 等上，最佳成员相对最强其他 TFM / 非 TFM 均报领先（mean win rate 文给 78% / 89%）。增量目标是把优势推到 grouped / temporal / 宽表 / 高基数等。
2. **TimesFM（§6）：** 在预训练未见的 Monash / Darts / ETT 等上，单模型零样本可贴近或超过为各集单独训练的强基线；消融显示加长 output_patch_len 单调改善 ETT 长视野平均 MAE。
3. **Chronos（§5.5）：** Benchmark I（训练语料内）更大 T5 优于本地统计与任务专模；Benchmark II（零样本）相对专为该集训练的方法可比、偶有更优。图注精确聚合数字因部分不可读，本篇只留正文定性句。
4. **交叉一句（TabPFN §C.6）：** TabPFN-TS-3.5（通用 3.5 权重、无时序微调）在 fev-bench 29 个方法中排第 6，比 TabPFN-TS-3 高 1.1 分、速度为其 2.4 倍，排在 TimesFM-3、两个 Chronos-2 变体、TiRex-2 与 Toto-2.0 之后——名称带代际后缀，超出本篇 TimesFM v4 / Chronos TMLR 论文范围。

## 六、可迁移的架构教训

1. Foundation ≠ 同一套 tokenizer。表格要解决列异质与行交换；时序要解决尺度、粒度与可变视界。
2. 「像语言一样训」可以是策略而非必然：Chronos 走 CE + 有限词表；TimesFM 走不对称 patch + MSE。
3. 合成数据角色不同但都关键：TabPFN 的合成 prior 即主训料；TimesFM 约 20% 合成；Chronos 用 GP KernelSynth + Mixup。
4. 推理时计算已出现在表格 FM（Thinking）；与 LLM 侧 test-time scaling 同构口号、不同算子。
5. 跨模态排行勿混代际：读附录看到 TimesFM-3 / Chronos-2 时，应回到本篇两篇锚点论文的 200M / T5-710M 设定。

## 七、局限与待核实
