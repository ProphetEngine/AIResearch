# 非文本基础模型：TabPFN-3.5（近月）+ TimesFM / Chronos 对照

> **定位**：表格与时序基础模型主题轴——在 LLM 主轴之外，用 **一张近月表格基础模型 TR** + **两条时序 foundation 谱系锚点**，收窄「非文本 tabular / time-series foundation」叙事；**勿另开时序通史**。
> **攻坚线**：**架构思想（主）**——「foundation」在表格 vs 时序上分别指什么、输入如何变成可训序列、损失与推理形态。
> **硬划界**：
> - **禁止写成 forecasting 工程手册**（不写管道部署、特征工程清单、调参 playbook、生产 SLA）。
> - **禁止**把 AutoARIMA / Prophet / 各家监督长序列模型做成对照表灌水；TimesFM / Chronos 只作 **谱系锚点**，评测只取文内主结果与 TabPFN 附录交叉一句。
> - TabPFN 文中 fev-bench 榜上的 **TimesFM-3 / Chronos-2** 是 **后续产品代**，**不是**本卡两篇锚点 PDF 的同名模型——交叉处显式标注。
> **禁止编造**：参数、分箱、patch 长度、基准名次与 skill 分一律取自官方 PDF（2026-09-22 CST）。

**一句话抓手：** 三类「非文本 foundation」共享「大规模预训练 → 对新任务少/零梯度更新」的口号，但 **对象几何完全不同**——TabPFN 吃的是 **表（行×列细胞）**，TimesFM/Chronos 吃的是 **一维实值序列**；后两者内部又分叉为 **连续 patch + 回归头（TimesFM）** vs **离散化后当「语言」做 CE（Chronos）**。

## 二、议题边界：何谓「非文本 foundation」

### 2.1 相对 LLM 的平行轴（本卡只立这一条）

| 轴 | 典型输入 | 预训练目标（本卡三文） | 下游默认形态 |
|---|---|---|---|
| **文本 LLM**（对照，不展开） | token 序列 | 下一 token / 掩码等 | 生成 / 指令 |
| **表格 FM（TabPFN 族）** | 表格细胞 + 标签列 | 在 **合成表先验** 上拟合成「上下文预测器」 | 对新表 **in-context** 分类/回归（训练行一次编码、测试行快速打分） |
| **时序 FM（TimesFM / Chronos）** | 历史窗口 → 未来窗口 | 在 **真实+合成序列语料** 上预训练 | **零样本**（或少量微调）预报 |

议程原话压缩：表格/时序 FM 是 LLM 之外另一条 foundation 叙事；本主题用 TabPFN-3.5 提供近月一手，TimesFM/Chronos 作谱系锚，**收窄**而非通史。

### 2.2 刻意不写什么

- 特征商店、日历特征工程、多变量协变量接入清单。
- 各监督长序列模型（Informer / Autoformer / PatchTST 监督版等）的完整排行史——仅在文内作为基线族点名。
- TabPFN-Plus / Thinking 的专有实现细节（报告明确 **intentionally not described**）。
- Chronos / TimesFM 之后的 **v2/v3 产品线** 架构（除非 TabPFN 附录引用时标明「榜上代际 ≠ 本 PDF」）。

## 三、三条路线的「序列化」对照（架构思想主轴）

> 核心问题：**实值结构如何变成 Transformer 吞得下的东西？** 三文给出三种答案。

`
TabPFN-3.5 表细胞 ──► Fourier + ECDF 等 per-cell 编码 ──► 行内/上下文 Transformer
 （任务类型作输入；clf/reg 共享骨干）

TimesFM 实值序列 ──► 连续 patch（ResidualBlock）──► causal decoder ──► 更长 output patch（MSE）

Chronos 实值序列 ──► mean scale + 均匀分箱 ──► 有限词表 token ──► 现成 T5/GPT2 ──► CE
`

### 3.1 TabPFN-3.5：表几何 + 合成先验（近月增量）

**相对 TabPFN-3 的显式改动（§3）：**

| 组件 | 文内事实 |
|---|---|
| **Per-cell 编码** | 继承缺失/无穷指示与 feature grouping；新增 **可学习 Fourier**（相对 TabFM 启发）与 **in-context ECDF**（列内 midrank → $u\in[0,1]$ 再展成低频 sin/cos）；标准化数值仍旁路保留 |
| **多任务** | **同一 checkpoint** 联合训分类+回归；任务类型作输入；仅标签编码器与输出头任务相关；分类用对 one-hot 训练标签的 attention，回归用固定 bin 上的预测分布 |
| **容量** | in-context transformer 宽 **512→1024**（每行 **8** 个 CLS 聚合 token，原 4）；头数 **8→16**，per-head dim 仍 64；测试行 **grouped-query**，KV cache 规模相对 TabPFN-3 **基本不变** |
| **预处理简化** | **不再**依赖 quantile / robust scaling 与 SVD 特征增强；默认 **8** estimators（Fast **4**），不同数据置换 |
| **合成 prior** | 管线贴近 TabPFN-3，并参考 TabICLv2；强调 **高基数类别、宽表、grouped train/test** |
| **规模（Figure 1a）** | TabPFN-3.5：**220 M**（统一）；TabPFN-3.5-Fast：**84 M**；推荐上限 **1M 行 × 6k 特征**（相对 TabPFN-3 的 1M×2k） |

**推理形态（引言 / §2.6）：** 训练行处理一次并缓存，测试行再打分「well under a second」；开源权重 **TabPFN-3.5 / Fast**；API 侧 **Plus**（多模态文本/日期 + FP8 等）与 **Thinking**（额外 inference-time compute；**不**用 LLM / 真数据检索）。

**许可证要点（§4，跟读即可）：** 代码 Apache 2.0；权重 **TABPFN-3.5 License v1.0**——学术/研究/评估较松，**禁止**商用生产与「采购决策用的竞品对标」等（全文见 HF LICENSE 链接）。

### 3.2 TimesFM：时序专用 decoder-only + patch 不对称

**设计原则（§4）：**

1. **Patching**：输入切成非重叠 patch，类比 NLP token；减 token 数、提速。
2. **Decoder-only**：见前缀 patch 预测后续；平行于 LLM 因果训练，天然适应可变历史长度。
3. **更长 output patch**：相对「逐步一 token」的 LLM，长视野预报常受益于一次吐出更长未来；文取折中——**output_patch_len > input_patch_len**，减少自回归步数，又避免 output 过长压不住月/年短序列。
4. **Patch masking**：随机遮住首 patch 前缀，覆盖从 1 到最大上下文的多种历史长度。

**主模型超参（Appendix A.6 Table 6，200M）：** `num_layers=20`，`model_dims=1280`，`input_patch_len=32`，`output_patch_len=128`，`num_heads=16`，dropout 0.2。同文还训了 **17M / 70M** 做缩放曲线。

**损失：** 主文聚焦 **点预测 MSE**（式 5）；文中提及可改 quantile 多头或参数分布 MLE，但主实验是点预测。

**数据（§5 / Table 1）：** Google Trends + Wiki Pageviews 为主，加 M4 / Electricity / Traffic / Weather 等；混合 **约 80% 实 + 20% 合成**；总时间点规模文称 **O(100B)**；最大上下文常 **512**（周/月粒度更短）。

**可跟读主张（§1）：** 相对直接把 GPT-3 / LLaMA-2 当零样本预报器，**专训时序、体量小两个数量级** 可明显更好。

### 3.3 Chronos：「时间序列的语言」——最小改 LM

**哲学（§1 / §3）：** 质疑「时序是否必须特制架构」——先 **scale（mean scaling）**，再 **均匀量化** 到有限 bin，得到词表 $\mathcal{V}_{ts}$，然后 **几乎原样** 训 T5（及一次 GPT-2 试验）；**故意忽略** day-of-week 等日历特征，「把时间序列当纯序列」。

**关键数字（§5.2）：**

| 项 | 文内设定 |
|---|---|
| 骨干 | T5：**Mini 20M / Small 46M / Base 200M / Large 710M**；另 GPT-2 base **90M** |
| 词表 | $\lvert\mathcal{V}_{ts}\rvert=$ **4096**（含 PAD、EOS）；bin 落在 $[c_1,c_B]=[-15,+15]$ |
| 目标 | **交叉熵**（式 2）——文称此为 **regression via classification**，非距离感知损失 |
| 上下文 / 预测长 | context **512**，训练预测长 **64** |
| 数据增强 | **TSMixup**（多序列凸组合）+ **KernelSynth**（GP 核组合合成）；训练采样增广:合成 ≈ **9:1** |
| 推理 | 自回归采样 token → dequantize → 反缩放；天然 **概率多轨迹** |

**与 TimesFM 的同代对照（Chronos §1）：** 点名 Das et al. 2023 等「时序专用设计预训练」为并发路线；Chronos 自称 **minimalist**——固定词表 + 现成 LM，**无**时序专用结构。

## 四、三路对照表（跟读用）

| 维度 | TabPFN-3.5 | TimesFM（本 PDF） | Chronos（本 PDF） |
|---|---|---|---|
| **对象** | 表格（异质列、缺失、高基数等） | 单变量实值序列预报 | 同左（框架可挂 encoder-decoder / decoder-only） |
| **「Token」** | 细胞 / 特征组嵌入（连续） | 连续 patch 向量 | **离散 bin id** |
| **骨干叙事** | 表结构 in-context Transformer（宽加倍、GQA 保 cache） | 自研 causal stack + residual I/O | **现成 T5**（改词表大小） |
| **预训练数据** | **合成 prior**（强调真实难分布） | 大规模真实 web 时序 + 合成 | 公开时序集 + TSMixup + GP 合成 |
| **损失** | 多任务 clf / 回归分布（实现细节见 §3.1） | **MSE** 点预测 | **CE** 分类式回归 |
| **不确定性** | 单次前向校准预测分布（引言）；ScoringBench 评完整分布 | 主文点预测；文内提可扩 quantile | **原生概率**（采样路径） |
| **下游接口** | 新表 ICL；缓存训练行 | 零样本 / 可选微调 I/O 块 | 零样本；文内亦谈微调 |
| **参数量锚** | 220M / Fast 84M | 主 **200M**（另 17/70M） | 20M–710M T5 族 |
| **开源入口** | PriorLabs/TabPFN；权重定制许可 | 文为 Google Research 预训练形态（本卡不跟后续发布渠道） | `amazon-science/chronos-forecasting` |

## 五、评测只取「架构含义」层（非工程手册）

### 5.1 TabPFN-3.5：表格主战场（Table 1 / §2）

文首 Table 1：在 TabArena / BeyondArena / STRABLE / MulTaBench / RelArena-α / TALENT / ScoringBench 等上，**最佳 TabPFN-3.5 成员**相对「最强其他 TFM / 非 TFM」均报领先（mean win rate 文给 **78% / 89%**——细节见 §C.8）。架构含义：增量编码 + 加宽 + 联合任务 + prior 重调，目标是把 TFM 优势从「干净 IID」推到 **grouped / temporal / 宽表 / 高基数 / 字符串与多模态列**（BeyondArena / STRABLE / MulTaBench）。

### 5.2 TimesFM：零样本逼近监督专模（§6）

持出 Monash / Darts / ETT 等 **预训练未见** 集：文称单模型零样本可贴近或超过为各集单独训练/调参的强基线；与 **llmtime**（大 LM 当预报器）对比时强调 **更小更准**。消融（§6.2）：加长 `output_patch_len` 单调改善 ETT 长视野平均 MAE；`input_patch_len` 过长有害。

### 5.3 Chronos：域内显著、零样本可比专模（§5.5）

- **Benchmark I**（训练语料内数据集）：更大 T5（Base/Large）在聚合相对 WQL/MASE 上优于本地统计、任务专模及其他预训练模。
- **Benchmark II**（零样本）：文称相对「专为该集训练」的方法，Chronos **可比、偶有更优**。

## 六、可迁移的架构教训（给跟读者）

1. **Foundation ≠ 同一套 tokenizer。** 表格要解决的是 **列异质与行交换结构**；时序要解决的是 **尺度、粒度与可变视界**。硬套文本 BPE 不是唯一答案（Chronos 走离散化；TimesFM 走连续 patch；TabPFN 走细胞编码）。
2. **「像语言一样训」可以是策略而非必然。** Chronos 证明 CE + 有限词表 + 现成 T5 足够强；TimesFM 证明 **不对称 patch + MSE** 也足够强——二者在同代叙事上是 **最小主义 vs 时序专用归纳偏置** 的分叉。
3. **合成数据角色不同但都关键。** TabPFN：合成 prior 即主训料；TimesFM：约 20% 合成补模式；Chronos：GP KernelSynth + Mixup 补多样性。
4. **推理时计算已经出现在表格 FM。** TabPFN-3.5-Thinking = 更强底座 + 更多 inference-time compute（且声明不用 LLM）；与 LLM 侧 test-time scaling **同构口号、不同算子**——细节专有，本卡只立接口。
5. **跨模态排行勿混代际。** 读 TabPFN 附录时看到 TimesFM-3 / Chronos-2，应回到本卡两篇锚点 PDF 的 **200M / T5-710M** 设定，避免把 2026 榜当面 2024 论文结果。
