# 地球系统基础模型 ESFM：异构数据统一框架

> **主要来源**：[Earth System Foundation Model (ESFM): A unified framework for heterogeneous data integration and forecasting](https://arxiv.org/abs/2605.00850)（Ozdemir 等，arXiv v1，2026-04-20）；[swiss-ai/ESFM README](https://github.com/swiss-ai/ESFM)（论文给出的开源代码仓库）（截至 2026-04-20）
> **研究线**：架构思想与数据接口（主）+ 文内预报字段（辅）
> **范围与相邻笔记**：
> - ≠ [[天气气候基础模型]]：本篇不写 Aurora 的骨干结构、参数规模与多域微调结果，只写 ESFM 在 Aurora 骨干之上新增的数据接口。
> - ≠ [[气候科学Agent]]：本篇不写大模型智能体的编排与报告流程；ESFM 是格点与站点场的预报模型，不是智能体。
> - ≠ [[SkySense遥感基础模型]]：本篇不写遥感影像解译；ESFM 的输入是大气与地表物理变量场和站点序列。
> - ≠ [[表格与时序基础模型]]：本篇不写通用表格与时序基础模型；站点实验只是 ESFM 统一骨干下的点数据接口。
>
> **意义**：既有地球系统基础模型大多假设输入是通道齐全、网格完整的稠密场；ESFM 把逐变量编码、可学习缺失标记和多分辨率编码放进同一骨干，使卫星稀疏观测、不规则站点和缺层、缺变量的数据也能直接用于预训练与微调，并以很低成本把确定性模型扩成集合预报。代价是在稠密数据上的误差略有上升。

## 一、问题背景

数据驱动的天气与气候模型已能与数值预报竞争，部分被视为基础模型：先在海量数据上学习物理变量之间的统计关系，再微调到下游任务，而不是为单一任务训练专用模型（摘要、§1）。但原始观测天然稀疏：卫星有轨道与云遮挡造成的缺口，站点分布不规则，不同 CMIP6 气候模式的网格、变量与缺失情况也不一致。既有模型通常假设所有通道齐全、时空网格完整，遇到缺失只能插值补齐，或为每一套变量重新训练编码器与解码器。ESFM 的主张是在同一骨干内直接处理这些异构、缺失的数据（§1.4）。

## 二、脉络

| 时间 | 工作 | 关键一步 |
|---|---|---|
| 2023-01 | ClimaX 预印本 | 天气与气候基础模型的早期尝试，用可学习向量做跨变量聚合（ESFM 文内对照） |
| 2024-05 | Aurora 预印本 | 地球系统基础模型，ESFM 所复用的 3D Swin UNet 骨干出自此处 |
| 2026-04 | ESFM | 复用 Aurora 骨干，扩展逐变量编码、缺失标记、多分辨率与站点接口、集合预报 |

ESFM 文内明说建立在 Aurora 的 3D Swin UNet 骨干之上，并用小号 Aurora 做知识蒸馏初始化，因此它是 Aurora 路线上的接口扩展，而不是另起一套骨干（摘要、§3.1）；代码仓库 README 也写明代码库基于 Aurora 模型栈扩展。

## 三、核心机制

文内列出六项贡献（§1.4），可归为四组机制：

1. **逐变量编码与跨变量注意力**：大气与地表变量各自做 patch 嵌入，而不是像 RGB 图像那样把所有变量拼成通道；随后在变量维上做轴向注意力（axial attention），捕捉温度、气压、湿度等变量之间的依赖；再由 Perceiver 把变量压到固定数量的潜变量，并沿用 Aurora 的气压层 Perceiver 沿层聚合（§2）。逐变量编码也使训练时可以随意打乱、增删变量集合，方便为新任务加变量。
2. **可学习缺失标记**：一个 patch 内部分或全部缺失时，用可学习的 NaN token 替换该 patch 的嵌入。文内对比 Aurora 为部分缺失变量额外加「密度通道」的做法：那种做法每加一个变量就要使输入输出通道数翻倍，扩展性差，也不适合整个变量缺失的情形（§2.1）。
3. **多分辨率与站点接口**：按水平分辨率把数据流分到六个离散档位，从 1.5° 以上的粗网格到极细卫星产品，另设站点档（每个站点作为单像素 patch）；站点经贪心映射排到不规则经纬网格上，使窗口注意力的邻居仍近似地理邻居，无需改动 Aurora 骨干（§2.2）。
4. **低成本集合预报**：在骨干输出的潜表示上用 AdaLN-Zero 按集合成员编号做缩放与平移调制；参数零初始化，因此扩展初期各成员与确定性输出相同，扩展过程稳定。训练时只需采样部分成员，成员数可以扩到上千而只线性增加 AdaLN 参数；损失为 almost fair CRPS 与集合均值 MAE 等权相加（§2.3）。

**训练协议**：比较实验统一用约 110M 参数的小号配置 ESFM_s（对应小号 Aurora）。预训练比较了随机初始化、八个 CMIP6 数据集预训练、以 Aurora 为教师的知识蒸馏三种起点，蒸馏起点最好；训练中随机遮掩整变量、整气压层和连续空间区域，作为真实数据缺口的代理（§3）。

## 四、主要结果（文内结论）

- **预训练起点**：知识蒸馏初始化相对随机初始化，按变量不同带来 12% 到 40% 的 MAE 收益，并节省预训练算力（§6）。
- **稠密 6 小时预报**：地表变量上 ESFM_s 与 AIFS、小号 Aurora 相当，优于 GraphCast、SFNO 与 IFS 控制预报；大号 Aurora 领先（§4、Table 1）。灵活性换来的是 MAE、RMSE 等指标上的小幅代价（§6）。
- **集合预报**：作者称地表变量的 CRPS 优于 AIFS-CRPS 与 FourCastNet 3；高空变量上 FourCastNet 3 常居前，但差距很小（§4.3、Table 2）。
- **缺失与稀疏数据**：瑞士、欧洲、美国本土等区域在初始场中整体遮掩后，区内仍能做出有技巧的预报；整层 500 hPa 从初始场中拿掉时，预测的温湿联合分布仍基本落在饱和曲线以下、零以上，即不产生过饱和或负湿度状态（§5.1）。整层气压层的变量全部遮掩时性能下降，模型需从其他气压层推断（§6、Table 6）。稀疏的 MODIS 可降水量产品微调后，预报场与 MODIS 的吻合度高于与 ERA5 的吻合度（§5.2）。
- **站点与未见数据**：在 ECMWF 约 11k 站点数据上可直接训练，并能泛化到训练时留出的站点、外推到新坐标（§5.3.1）；在 Weather-5K 上只用单步历史输入，24 小时内与站点专用模型相当（§5.3.2）；对预训练时留出的 CNRM-CM6-1-HR 气候模式，含 CMIP6 的预训练优于只用 ERA5 或不预训练，并能学习未见的海温、海冰等变量（§5.4）。
- **个例**：超强台风杜苏芮（2023-07）与 2023/24 年平流层突然增温事件中，位置与强度估计较准；后者用竖直遮掩策略把气压层从 13 层扩到 16 层（§4.4、§4.5）。
- **多年代稳定性**：多年代自回归推演保持稳定、保留季节循环，无需对质量或全球能量收支另加约束（§4.6）。

## 五、局限与待核实

1. **稠密数据上的代价**：作者承认灵活性带来误差指标的小幅下降；ESFM 能否放大到大号 Aurora 量级并追上其精度，文内只是主张，尚无实验。
2. **气压层 Perceiver 瓶颈**：从 WeatherBench2 的 37 层中随机抽 13 层训练时，6 小时 MAE 相对固定 13 层恶化 85.4% 到 500%；作者怀疑是气压层 Perceiver 的聚合能力所限，列为未来工作（附录 A.2）。
3. **MODIS 偏差**：预报场更贴近 MODIS 不等于更接近真实大气状态，模型也会学到 MODIS 检索本身的特征与偏差（§5.2）。
4. **平流层可预报性**：对流层影响的结果「令人鼓舞」，但需在十天以上的时效上用更准的预报确认（§6）。
5. **台风强度**：数据驱动模型普遍能抓住气旋位置但低估强度，部分源于训练数据分辨率（§4.4）。
6. **站点外推中的气压**：在未见站点的泛化与外推测试里，气压的误差上升最明显；作者认为微调时加入地表位势等静态变量可能缓解（§6）。
7. **版本**：只有 arXiv v1（2026-04-20），无正式刊；集合预报的离散度与技巧匹配等细节本篇未展开。
