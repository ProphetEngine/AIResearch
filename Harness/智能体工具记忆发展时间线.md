# 时间线 · 智能体 · 工具 · 记忆

> 本时间线梳理智能体的四条主线：工具使用、长程记忆、计算机与代码操作、多智能体协作，评测基准随各自出现的时间并入。读完可以看清智能体怎样从「推理时顺带调用工具」演进为「在工具环里连续工作数小时、跨会话记事、由多个代理分工」的系统，也能看到评测怎样从静态打分走向长程、防作弊与可隔离测量。主题地图见 [[MOC_智能体Harness]]。日期口径：论文取 arXiv 首版（v1）日期，官方发布按 UTC 日期，系统卡取封面日期。

## 一、奠基：推理与行动合流（2022–2023）

语言模型此前只在文本里回答问题。这一阶段的工作证明，模型可以边推理边调用外部工具，并开始用外存弥补上下文窗口的限制。

- **2022-10** · ReAct 让模型交替输出推理和动作，「想一步、做一步、看结果」从此成为多数智能体控制环的默认骨架（[arXiv:2210.03629](https://arxiv.org/abs/2210.03629)） · [[智能体工具与长程任务]] · [[代码智能体Harness史线]]
- **2023-02** · Toolformer 让模型自行标注何时调用哪个 API 并用这些数据微调，开启了「为工具调用合成训练数据」的路线（[arXiv:2302.04761](https://arxiv.org/abs/2302.04761)） · [[ToolLoop工具数据合成]]
- **2023-04** · ChemCrow 把化学专家工具接入 ReAct 环，表明通用模型配上领域工具就能完成专业科研任务（[arXiv:2304.05376](https://arxiv.org/abs/2304.05376)） · [[科研智能体]]
- **2023-05** · 多智能体辩论（Du 等）让多个模型实例互相质询再收敛答案，提出用多代理交互改善事实性与推理（[arXiv:2305.14325](https://arxiv.org/abs/2305.14325)） · [[多智能体辩论]]
- **2023-09** · ToolEmu 用语言模型模拟工具执行和环境状态，让高风险工具场景也能低成本、可重复地做安全评测（[arXiv:2309.15817](https://arxiv.org/abs/2309.15817)） · [[合成用户仿真]]
- **2023-10** · MemGPT 把上下文窗口当作内存、外部存储当作磁盘，由模型自己调函数换页，提出「虚拟上下文管理」的记忆范式（[arXiv:2310.08560](https://arxiv.org/abs/2310.08560)） · [[智能体长程记忆]]

## 二、接口、协议与评测成形（2024）

模型能调用工具之后，问题转到接口设计：给模型什么样的操作面、用什么协议接外部系统、怎样测量多步任务。

- **2024-05** · SWE-agent 提出「智能体—计算机接口」（ACI），证明为模型专门设计的命令与观测格式能显著提高仓库级修复率（[arXiv:2405.15793](https://arxiv.org/abs/2405.15793)） · [[代码智能体Harness史线]]
- **2024-06** · Mixture-of-Agents 让多层异构模型逐层参考彼此的回答再综合，把「多模型协作」变成一种推理时扩展手段（[arXiv:2406.04692](https://arxiv.org/abs/2406.04692)） · [[MixtureOfAgents与TUMIX]]
- **2024-06** · τ-bench 用模型模拟用户、配真实数据库与业务政策，并以 pass^k 衡量多次运行的一致性，补上「人—智能体—工具」三方交互评测（[arXiv:2406.12045](https://arxiv.org/abs/2406.12045)） · [[合成用户仿真]]
- **2024-08** · The AI Scientist 把「提出想法、做实验、写论文、自动评审」串成端到端闭环，科研智能体从单步工具调用走向全流程自动化（[arXiv:2408.06292](https://arxiv.org/abs/2408.06292)） · [[科研智能体]]
- **2024-10** · WorfBench 把任务分解建成带依赖的有向无环图来评测，发现模型做图规划明显难于线性规划（[arXiv:2410.07869](https://arxiv.org/abs/2410.07869)） · [[WorfBench工作流基准]]
- **2024-11** · Anthropic 开源 Model Context Protocol（MCP），用统一的客户端—服务器协议替代逐个定制的工具与数据接入（[官方博文](https://www.anthropic.com/news/model-context-protocol)） · [[MCP协议与大规模工具导航评测]]

## 三、产品化：计算机使用、记忆层与工具强化学习（2025）

2025 年，旗舰模型的卖点从答题分数转向「能否在工具环里把多步真实工作做完」。计算机使用、生产级记忆、工具集成 RL 和推理时搜索同时推进，评测也开始针对长程连贯与真实网站。

- **2025-01** · OpenAI 发布 Operator 与系统卡，模型通过截图和键鼠直接操作浏览器，计算机使用智能体进入面向用户的产品阶段（[官方博文](https://openai.com/index/introducing-operator/)） · [[计算机使用智能体]]
- **2025-01** · Zep 以时序知识图谱组织对话与业务事实，把智能体记忆做成可部署的服务（[arXiv:2501.13956](https://arxiv.org/abs/2501.13956)） · [[Mem0与Zep生产级记忆]]
- **2025-02** · A-Mem 借鉴卡片盒笔记法，让模型自己为记忆建链接、随新信息演化，提供了分页之外的另一种记忆组织方式（[arXiv:2502.12110](https://arxiv.org/abs/2502.12110)） · [[智能体长程记忆]]
- **2025-02** · Vending-Bench 用子任务简单、时程极长的经营仿真单独测「长程连贯」，发现模型平均表现不差，最差的运行仍会彻底失控（[arXiv:2502.15840](https://arxiv.org/abs/2502.15840)） · [[VendingBench经营长程评测]]
- **2025-03** · AB-MCTS 在推理时由搜索树自适应决定「再采一个新答案」还是「改进已有答案」，统一了只扩宽与只加深两种扩展方式（[arXiv:2503.04412](https://arxiv.org/abs/2503.04412)） · [[推理时树搜索ABMCTS]]
- **2025-03** · ToRL 从基座模型直接做工具集成强化学习，表明工具调用策略可以靠 RL 探索习得，不必先模仿人工轨迹（[arXiv:2503.23383](https://arxiv.org/abs/2503.23383)） · [[ToRL工具集成强化学习]]
- **2025-04** · Online-Mind2Web 在真实网站上配人工标注重测网页智能体，指出此前自报的高分存在明显水分（[arXiv:2504.01382](https://arxiv.org/abs/2504.01382)） · [[浏览与深研Agent基准]]
- **2025-04** · BrowseComp 用「难找、易验」的短答案问题考深度浏览，成为深研类智能体的通用标尺（[arXiv:2504.12516](https://arxiv.org/abs/2504.12516)） · [[浏览与深研Agent基准]]
- **2025-04** · Mem0 把记忆拆成「抽取、更新、检索」三步并提供图变体，成为生产记忆层的主流参照（[arXiv:2504.19413](https://arxiv.org/abs/2504.19413)） · [[Mem0与Zep生产级记忆]]
- **2025-05** · Anthropic 发布 Claude 4，推出扩展思考中调用工具、并行工具与 Claude Code 正式版，把「数小时级工具环上的稳定性」写成旗舰模型的核心卖点（[官方博文](https://www.anthropic.com/news/claude-4)） · [[智能体工具与长程任务]]
- **2025-05** · Darwin Gödel Machine 让编码智能体改写自身代码，以基准实测代替形式证明来筛选改动，并用档案保留多样的中间版本（[arXiv:2505.22954](https://arxiv.org/abs/2505.22954)） · [[开端性与发现基础模型]]
- **2025-08** · OpenAI 发布 GPT-5，用路由统一快答与深度思考，API 侧定位为编码与智能体任务的主力模型（[官方博文](https://openai.com/index/introducing-gpt-5/)） · [[智能体工具与长程任务]]
- **2025-08** · LiveMCPBench 让智能体在数十个服务器、数百个 MCP 工具中检索并组合工具，评测重心从「会用给定工具」转向「在工具海里找对工具」（[arXiv:2508.01780](https://arxiv.org/abs/2508.01780)） · [[MCP协议与大规模工具导航评测]]
- **2025-08** · Memory-R1 用下游答对与否作奖励，让模型通过 RL 学会何时增加、修改、删除记忆，记忆维护从人写规则变为可学习策略（[arXiv:2508.19828](https://arxiv.org/abs/2508.19828)） · [[MemoryR1强化学习记忆维护]]
- **2025-09** · SWE-Bench Pro 以企业级仓库、长程任务和抗污染设计重建代码修复评测，拉开了与已趋饱和的旧基准的差距（[arXiv:2509.16941](https://arxiv.org/abs/2509.16941)） · [[SWEBenchPro代码修复评测]]
- **2025-09** · TUMIX 在同一底座上并行运行多种工具使用策略的代理并共享中间答案，把工具策略混合变成推理时扩展手段（[arXiv:2510.01279](https://arxiv.org/abs/2510.01279)） · [[MixtureOfAgents与TUMIX]]
- **2025-09** · Anthropic 发文系统阐述上下文工程，把压缩、结构化笔记与子代理隔离并列为长程任务管理上下文的基本手段（[官方博文](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)） · [[上下文工程与智能体技能]]
- **2025-10** · Anthropic 推出 Agent Skills，把指令、脚本与资源打包成文件夹，模型只在任务相关时加载所需的最少内容，上下文从一次性写入转向按需加载（[官方博文](https://www.anthropic.com/news/skills)） · [[上下文工程与智能体技能]]
- **2025-11** · OpenHands Software Agent SDK 把代码智能体拆成可组合的包，并让本地与远程沙箱共用同一接口，研究原型由此走向生产级框架（[arXiv:2511.03690](https://arxiv.org/abs/2511.03690)） · [[代码智能体Harness史线]]

## 四、长程、多智能体与可信评测（2026）

近一年的工作集中在三处：计算机使用评测拉到真实长程工作流，多智能体研究从「堆代理」转向诊断协作本身，评测开始系统性地防范奖励作弊和数据泄漏。

- **2026-01** · DynaDebate 与《Demystifying Multi-Agent Debate》等工作确认原始辩论的收益大体等同多数投票，研究转向多样性初始化、置信度调制与动态辩论路径（[arXiv:2601.05746](https://arxiv.org/abs/2601.05746)；[ACL Anthology](https://aclanthology.org/2026.findings-acl.1694/)） · [[多智能体辩论]]
- **2026-05** · Agent Bazaar 在多代理市场里复现砍价螺旋与柠檬市场，说明单个代理理性也可能拖垮整个系统，并提出经济对齐评分（[arXiv:2605.17698](https://arxiv.org/abs/2605.17698)） · [[AgentBazaar经济对齐]]
- **2026-06** · OSWorld 2.0 用 108 个长程真实工作流重建桌面评测，计算机使用的考核从短任务转向完整的长程工作流（[arXiv:2606.29537](https://arxiv.org/abs/2606.29537)） · [[计算机使用智能体]]
- **2026-07** · StateAct 让智能体优先读取程序状态而非截图像素，在同一底座上提升长程计算机任务的完成率（[arXiv:2607.22798](https://arxiv.org/abs/2607.22798)） · [[计算机使用智能体]]
- **2026-07** · OrchBench 用确定性仿真单独评估多智能体的编排计划，只花真实执行约 1.3% 的 token，就得到与之高度相关（r=0.816）的分数（[arXiv:2607.25656](https://arxiv.org/abs/2607.25656)） · [[OrchBench多智能体编排评测]]
- **2026-09** · CHIME 先把任务成败归因到「计划」还是「执行」再分库写入记忆，把信用分配引入自演化记忆（[arXiv:2609.02074](https://arxiv.org/abs/2609.02074)） · [[CHIME长程规划记忆]]
- **2026-09** · ToolLoop 把工具数据合成从「先生成后过滤」改为分阶段「生成—校验—修正」闭环，用约 1.1 万条合成样本把 4B 模型的 BFCL 成绩推到 86.40%（[arXiv:2609.09072](https://arxiv.org/abs/2609.09072)） · [[ToolLoop工具数据合成]]
- **2026-09** · SWE-Bench Pro Verified 给公共集加上防奖励作弊的执行环境并校正有问题的题目，表明代码基准本身也需要「验真」（[arXiv:2609.08149](https://arxiv.org/abs/2609.08149)） · [[SWEBenchPro代码修复评测]]
- **2026-09** · Discovery Foundation Models 主张模型应参与知识生产过程本身，提出发现智能所需的七种能力与可修订的研究状态（[arXiv:2609.15973](https://arxiv.org/abs/2609.15973)） · [[开端性与发现基础模型]]
