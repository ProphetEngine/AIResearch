# Mixture-of-Agents + TUMIX：异构聚合与工具策略混合的测试时扩展

> **主要来源**：[Mixture-of-Agents Enhances Large Language Model Capabilities（Wang et al., 2024-06）](https://arxiv.org/abs/2406.04692)；[TUMIX: Multi-Agent Test-Time Scaling with Tool-Use Mixture（Chen et al., Google, 2025-09）](https://arxiv.org/abs/2510.01279)；[Google Research 论文页](https://research.google/pubs/tumix-augmenting-llm-reasoning-with-a-dynamic-tool-use-mixture/)（截至 2026-09-22）
> **研究线**：架构思想（主）——测试时把多路输出组合成一个更好的答案；评测字段（辅）——对话质量与可验证推理上的成本—质量曲线。
> **范围与相邻笔记**：
> - ≠ [[推理时扩展TestTimeScaling]]：本篇不写 o1/R1 的训练轴与 ToT、自一致性、Best-of-N 的通史。
> - ≠ [[多智能体辩论]]：本篇不写辩论协议及其退化诊断。
> - ≠ [[ToRL工具集成强化学习]]：本篇不写在训练期用 RL 学习工具策略。
>
> **意义**：MoA 与 TUMIX 代表测试时多路组合的两种路线——MoA 用多个不同模型逐层合成（层间聚合），TUMIX 用同一模型的多种工具策略并行再共享精炼（工具策略混合）；两者共同说明，测试时扩展的收益来自**候选的多样性**加上**好的聚合与停止规则**，而不只是采样次数。

**一句话**：MoA 让 6 个开源模型先各自作答，再由下一层模型读全部答案合成新答案，3 层后开源组合在 AlpacaEval 2.0 LC 上以 65.1% 超过 GPT-4o 的 57.5%；TUMIX 让同一个 Gemini 以 15 种文本、代码、搜索策略并行作答、逐轮互相参考精炼，并由 LLM 判断何时停止，在近等成本下平均比最强基线高约 3.55%。

## 一、问题背景

测试时多花算力可以提升答案质量，最直接的做法是对同一模型多次采样再投票或挑选（见 [[推理时扩展TestTimeScaling]]）。但这种做法有两个限制：

1. **候选同质**：同一模型的多次采样容易犯同样的错，投票只能放大多数意见，覆盖不到模型本身不会的解法。
2. **只选不合**：投票或打分只能从候选中挑一条，无法把多个部分正确的答案合成一个更好的答案。

MoA 的出发点是：不同模型擅长不同方面，能否让它们互相参考、合成更好的回答？TUMIX 的出发点是：文本推理擅长语义与常识，弱于精确计算与新知识，代码执行和搜索可以补上，但题目很少写明该用哪种工具——能否让多种工具策略并行，再互相参考？

## 二、脉络

| 时间 | 方法 | 候选来源 | 组合方式 | 主评测 |
|---|---|---|---|---|
| MoA 之前 | 自一致性、Best-of-N（见 [[推理时扩展TestTimeScaling]]） | 同一模型多次采样 | 多数票或打分挑选 | — |
| 并行路线 | 多智能体辩论（见 [[多智能体辩论]]） | 多个 agent 互相反驳 | 多轮辩论后投票 | — |
| 2024-06 | MoA | 多个不同 LLM | 下一层模型读全部输出后合成生成 | AlpacaEval、MT-Bench、FLASK |
| 2025 | Self-MoA 等 | 最强单模型重复采样 | 聚合 | 论文称「换成最强模型重复采样更好」 |
| 2025-09 | TUMIX | 同一 LLM 的 15 种工具策略 | 每轮各自参考上轮全部答案再答，LLM 判断何时停 | HLE、GPQA、AIME |

TUMIX 明确把自己与 Self-MoA 对照：在**工具增强**的设定下，多样化的 agent 组优于重复采样单一最强 agent（TUMIX §1）。需要注意的是，TUMIX 反驳的是 Self-MoA，而不是 2024 年的 MoA 原文。

## 三、MoA：层间聚合

### 3.1 现象：collaborativeness

MoA 论文观察到，LLM 在看到其他模型的输出后，倾向生成更好的回答，即使那些辅助答案比它自己独立生成的还差（MoA §1、Fig. 1）。

由此分出两种角色（MoA §2.1、Table 4）：

- **Proposer**：提供多样参考，自身分数不必最高。WizardLM-8x22B 作 proposer 很强（63.8%），作 aggregator 较弱（52.9%）。
- **Aggregator**：把多路输出合成一条高质量回答。Qwen1.5-110B-Chat 是好的 aggregator。

### 3.2 机制

MoA 有 l 层，每层 n 个模型。第一层各自回答原题；之后每一层把上一层的全部输出和原题一起，用一段 **Aggregate-and-Synthesize 提示**（要求批判性综合、不要简单复制）交给本层模型；最后一层由一个模型输出终答。整个过程只靠提示，不需要微调。论文把它类比为把激活级的混合专家（[[混合专家架构]]）提到整模型级别，门控与专家角色都由 LLM 读提示来承担。

默认配置：3 层，每层 6 个开源模型（Qwen1.5-110B / 72B、WizardLM-8x22B、LLaMA-3-70B、Mixtral-8x22B、dbrx），末层由 Qwen1.5-110B 聚合。

### 3.3 结果与消融

| 变体 | 结构 | AlpacaEval 2.0 LC |
|---|---|---:|
| MoA w/ GPT-4o | 末层聚合换成 GPT-4o | 65.7% |
| MoA | 3 层 × 6 开源模型 | 65.1% |
| MoA-Lite | 2 层，末层 Qwen1.5-72B | 59.3% |
| GPT-4 Omni (05/13) | 单模型对照 | 57.5% |

（MoA Table 2）

- **合成胜过挑选**：同一个 aggregator 改成只做排序挑一条，效果明显变差，说明它在综合而不是挑赢家（Fig. 4a）。
- **异构胜过同质**：2 层、6 个槽位时，用 6 个不同模型得 61.3%，用同一模型温度采样 6 次得 56.7%（Table 3）。
- **成本**：MoA-Lite 在 GPT-4o 量级的成本下质量更高；同层 proposer 可并行（§3.4）。
- **局限**：必须等最后一层才能出首 token，首 token 延迟高；论文建议减少层数（第一轮聚合增益最大）。

## 四、TUMIX：工具策略混合

### 4.1 机制

- **15 个 agent，同一个底座**：在 Gemini-2.5-Pro 或 Flash 上设计 15 种策略——直接回答、CoT、写代码的 CoT、只用搜索、只用代码解释器、代码加搜索、带引导的双工具等（TUMIX Table 1）。
- **共享精炼**：每轮把原题与上一轮全部 agent 的答案一起交给每个 agent，各自再答一次。
- **LLM 判断停止**：由 LLM 判断是否已收敛，至少跑 2 轮以免过早自信；终答取多数票。

### 4.2 关键发现：精炼既涨分又杀多样性

- **覆盖率单调下降**：「组内至少一人答对」的比例随轮次单调下降，正确答案会被多数意见带偏而丢失；平均准确率先升后平台，GPQA 上甚至会回落（§3.2）。
- **所以必须管停止**：LLM 判断停止能以约 **49%** 的推理成本达到接近峰值的准确率（§3.3）。
- **瓶颈在识别而非生成**：HLE 上覆盖率可达 65% 以上，准确率却停在约 34%——正确答案常常已经在候选里，难的是认出它（§1）。

### 4.3 结果（Table 2，近等成本）

| 方法（Gemini-2.5-Pro） | HLE | GPQA | AIME 24&25 | 归一化均值 |
|---|---:|---:|---:|---:|
| 无测试时扩展 | 21.6 | 84.6 | 87.3 | 64.5 |
| 最强基线（Symbolic-MoE） | 29.5 | 86.7 | 94.7 | 70.3 |
| TUMIX | 32.3 | 87.9 | 96.7 | 72.3 |
| TUMIX+（更高算力） | 34.1 | 88.3 | 96.7 | 73.0 |

- 摘要称近等成本下相对最强基线平均约 **+3.55%**；Gemini-2.5-Flash 上 TUMIX 归一化均值 **60.6**。
- **多样性与工具互补**：同样数量下，代码加搜索的混合组优于只用一种工具的组（§5）。
- **让 LLM 设计 agent**：用 Gemini-2.5-Pro 生成新 agent 并与人工 agent 混选，再提升约 **1.2%**，成本不增（§5.3）。
- **agent 数饱和**：约 12 个以内增益明显，之后可忽略（Fig. 10）。

## 五、两种机制的对照

| 维度 | MoA（层间聚合） | TUMIX（工具策略混合） |
|---|---|---|
| 多样性来源 | 多个不同模型 | 同一模型的不同工具与提示策略 |
| 外部工具 | 无 | 代码解释器 + 搜索 |
| 轮间通信 | 下一层合成一条新答案 | 每个 agent 参考全部答案后各自再答 |
| 深度控制 | 固定层数（2 或 3） | LLM 判断停止，最少 2 轮 |
| 终答 | 末层聚合器生成 | 多数票 |
| 主评测任务 | 开放式对话与指令遵循 | 有标准答案的可验证推理 |
| 主要风险 | 首 token 延迟高、回答偏长 | 精炼过度导致正确答案丢失 |

两者共同的旋钮是多样性、聚合方式、层数或轮数与预算。分歧在于：MoA 的多样性要靠多家模型，TUMIX 证明在单一模型上用工具策略也能制造足够多样性；MoA 主张「合成优于挑选」，TUMIX 的终答却回到投票，因为可验证任务的瓶颈在识别正确答案。

## 七、局限与待核实

1. **MoA 引言与表格不一致**：引言写 65.8%，Table 2 为 65.1% 与 65.7%，以 Table 2 三次运行均值为准。
2. **TUMIX 部分 HLE 数字不是纯测试**：标星号的结果用 Pro 的 HLE 表现做过 agent 选择。
3. **基线未逐一读原文**：Self-MoA、Symbolic-MoE、DEI、SciMaster、GSA 的数字均来自 TUMIX 的复现；论文自承 SciMaster 的增益低于原作者报告，可能源于工具实现差异。
4. **摘要与正文口径**：TUMIX 摘要的 +3.55% 是跨模型平均，正文另写 Pro +2.0%、Flash +5.9%（§4.2），两者并列，不应合并。
5. **成本与定价会变**：MoA 的成本分析基于 2024-05 的 API 定价，GPT-4 的 tflops 用的是社区传闻值，不能作当前依据。
