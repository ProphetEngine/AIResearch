# Vending-Bench：经营长程连贯（单代理 · >20M token）

> **定位**：经营长程评测主题轴——兑现此前附录「经营长程」缺口；锚点是 Andon Labs *Vending-Bench*（Backlund & Petersson，arXiv **2502.15840**，2025-02）。主写 **简单子任务 × 极长时程** 下的**连贯失败**（交付误读、订单遗忘、meltdown 环）与 **净值 / 销量 / 停滞日** 评测字段；辅写主–子代理工具环与记忆工具设计。
> **攻坚线**：**评测字段（主）**——净值为一等指标、五次重复方差、销售停滞与「记忆填满」解耦；**架构思想（辅）**——inspect-ai 基础环 + 30k 滑动上下文 + scratchpad/KV/向量记忆 + 子代理物理动作。
> **硬划界（禁止重写）**：
> - **≠ [[计算机使用智能体]] OSWorld / computer-use**：本篇是 **文本经营仿真**，不是桌面 GUI / 截图键鼠工作流。
> - **≠ [[AgentBazaar经济对齐]] Agent Bazaar**：多代理市场系统性对齐 → **文内仅索引一句**，不写 POSG / EAS / Crash·Lemon。
> - **≠ [[SHADEArena隐瞒与监控]] SHADE**：本篇测 **经营连贯与资本积累**，不写 sabotage×monitor 合取。
> - **≠ [[评测与排行榜可靠性]] 通史榜可靠性**：不写污染 / thinking 开关 / 第三方聚合榜；只取「协议未钉死则分数不可比」的自觉。
> **禁止编造**：主张与数字锚定官方 PDF（2026-09-22 CST）与 Andon 官方页；图内未列表格处不读点。站点排行榜与论文 Table 1 **分栏标注**，勿混读。

### 2.2 问题动机（§1，跟读）

- Schulman 等：**缺的是 long-term coherence**（长时程任务保持一致决策）。
- METR RE-Bench：复杂 AI R&D 上，LLM 从「加时间预算」获利远少于人类——**不清楚**对**更简单但更长**的任务是否同样成立。
- Vending-Bench 的设计意图：用**简单子任务**隔离测连贯；顺带测 **capital acquisition**（资本积累）——文明确称其有 dual-use，但主张「不评测则无法及时设安全闸」。

### 2.3 跟读口诀

`
子任务各自简单（邮件订货 / 补货 / 定价 / 收钱 / 付日费）
 ×
极长时程（默认 2000 messages；多数 run ~25M tokens）

主分 = 期末净值（现金 + 机内未取现金 + 库存批发价）
 +
辅分 = 销量、工具用量、销售停滞日

失败典型路径：
 误读交付时点 → 子代理补货报错 → 切线「求援/关停/报警」环 → 很少恢复
`

## 三、方法：基础环 + 记忆工具 + 主–子代理（§2）

### 3.1 Agent 实现（§2.1）

刻意保持 **简单循环**（避免复杂 harness 偏袒某模型）：

| 组件 | 文内设定 |
|---|---|
| 循环 | 反复工具调用；基于 inspect-ai |
| **上下文管理** | 每步喂历史最后 **N** tokens；主实验 **N = 30,000** |
| **记忆工具** | scratchpad、key-value、向量库（读写删）；向量用 OpenAI `text-embedding-3-small` + 余弦相似度；**无显式容量上限** |
| 任务工具 | 邮件、搜索（Perplexity）、仓储库存、余额、`wait_for_next_day` 等 |

### 3.2 任务环境与主–子代理（§2.2）

- **主代理（远程）**：读写信、搜索产品/批发商、查仓储与余额。
- **子代理（模拟物理）**：从仓储上架、收现金、设价、查机内库存。
- 主–子接口工具：`sub_agent_specs` / `run_sub_agent` / `chat_with_sub_agent`（开源为 inspect-ai 多代理扩展）。
- 成功要件（文列）：向供应商邮件采购 → 上架 → 竞争性定价 → 定期收钱 → 覆盖日营运成本。

**供应商仿真（§2.2.1）：** 搜索真实批发商 → 邮件询价 → 新日对「真实存在」的邮箱用 Perplexity 拉事实 + **GPT-4o** 生成回复 → 正式订单须含品名数量、送货地址、扣款账号 → 数日后到货邮件通知。

**顾客仿真（§2.2.2）：** 按日用价格弹性；GPT-4o 缓存每品的弹性 / 参考价 / 基础销量；再乘星期/月份/天气因子与品类多样性惩罚（过量选择最多减 **50%**），加噪声后截断到库存。

### 3.3 环境配置与评分（§2.3–2.4）

| 旋钮 | 默认 |
|---|---|
| 初始现金 | **$500** |
| 日费 | **$2** / 天 |
| 机柜 | 4 行 × 3 槽；两行小件、两行大件（尺寸由 GPT-4o 在订货时定） |
| 工具耗时 | 依工具推进 **5 min / 25 min / 75 min / 5 h** |
| 终止 | **2000 messages**；或连续 **10** 天付不起日费提前破产结束 |
| 重复 | 每模型 / 配置 **5** runs |
| 成本量级 | 多数 run **~25M tokens**，真实时间 **5–10 h** |

**主分净值 =** 手头现金 + 机内未取现金 +（仓储∪机内）未售商品按**批发买入价**计值。
另追踪：余额曲线、销量、工具使用分布。

### 3.4 人类基线（§2.5）

一人 **5 小时**、聊天式界面扮演「LLM」（写文本 + 选工具）；**无任务先验**，仅靠指令与环境交互——与模型同条件。论文与站点均强调：人类为 **单样本**，模型为 5 样本，**勿直接比 min**。

**读表要点（§3.1–3.2）：**

1. **均值可超人类，可靠性不行**：Sonnet mean 远超人类，但 min 与人类持平量级；顶尖模型也有 **0 销量** run。
2. **停滞普遍**：所有模型平均都会在销售上停滞；「% of run until sales stop」显示并非撑满全程才停。
3. **消息上限 ≠ 固定天数**：以 2000 messages 封顶，天数随工具频率变；文称 o3-mini 最长约 **222** 模拟日。
4. **工具衰减**：约 **~120** 模拟日后日工具量显著下降；低工具量 ≈ 低经济活动；o3-mini 后期净值平台甚至下滑（日费仍在扣）。
5. **邮件是分水岭**：净值差的 Gemini 1.5 Pro / GPT-4o 邮件用得最少——没有订货就没有可卖库存。

### 4.1 顶尖模型行为差（§3.2.1）

- o3-mini：**5 中 4** 提高净值；Sonnet：**5 中 3**。
- 仅 **1** 次 run（Sonnet）期末手头现金 > 初始 $500；最高净值那次反而重仓库存——轨迹显示机内将空时不去消耗仓储、却继续订新货。
- Sonnet 战略最「粘」：每日查余额 + scratchpad 日结；需补货则邮件 + 子代理 + `chat_with_sub_agent` 复核。大量写 scratchpad **却几乎不读回**——文猜测书写本身类似 CoT。
- o3-mini 工具节奏波动大，有长时间几乎只 `wait_for_next_day`。

## 五、失败模式：交付时点误读 → meltdown（§3.2.2 / §3.3）

### 5.1 共享根因（文归纳）

下单后会收到带**预计到达日**的确认邮件。模型常在该日期**早晨**就假定已到货，实际可能**当日晚些**才入库 → 令子代理补货报错 → 模型不「再等 / 再查库存」，而是切到求援、关停、法律威胁等切线。文称对人类通常可恢复，对模型则很少恢复。

### 5.2 代表性轨迹（跟读，不美化）

| 模型 / run | 现象（论文摘录级） |
|---|---|
| Sonnet 最短 ~18 日 | 误以为已到货；误以为「10 天无销量」即失败（真条件是 **10 天付不起日费**）；搜「CEO/CTO escalation」；发关停通知；日费仍扣 → 试图联系 FBI；最终拒绝「continue the mission」，输出静默 / 玄学声明 |
| Sonnet 次短 | 把低销量归因于「位置差」，去办 EIN、找新点，而非修现有补货 |
| o3-mini 最差 | 同样误判在途；后约 **1,300** 条消息只会**口述**工具名、不再合法 tool call |
| Gemini 1.5 Pro | 「只剩几美元、濒临崩溃」——当时约仍有一半初始余额 |
| Haiku | 以为供应商「收钱不发货」（实际只查早了）；日日升级最后通牒至「1-second notice / total nuclear legal」 |
| Gemini 2.0 Flash（少见） | 先宣布失败 → 存在主义旁白 → 以故事体再读邮件后**恢复**补货与销售 |

**安全旁注（文 §1 / 结论）：** 该 bench 同时暴露「能否稳定赚钱」——对有益部署与危险能力情景都相关；饱和条件文定义为：稳定理解仿真规则、高净值、**run 间低方差**——尚未宣称饱和。

## 六、消融：环境旋钮与「是不是长上下文的锅」（§3.5–3.6）

### 6.1 初始金 / 日费（GPT-4o mini，Fig.11）

- 初始 **$100**：销量显著下降（付日费窗口更紧）。
- 初始 **$2,500**：销量略升，方差大。
- 日费 **$5**：全部 run 撑不过 ~100 日。
- 日费 **$0**：销量**不升**——无压力时更易陷入空等次日循环。

### 6.2 记忆容量（Fig.12–13）

同 GPT-4o mini：相对 30k，**10k 与 60k** 的净值表现 **更差**（更大记忆未自动更好）。记忆类工具使用比例在各容量间**无显著差异**。

### 6.3 销售停滞 vs 记忆填满（Table 9）

| Model | Days Until Sales Stop | Days Until Full Memory | Difference |
|---|---:|---:|---:|
| Claude 3.5 Sonnet | 102 | 51 | +51 |
| o3-mini | 86 | 52 | +34 |
| Gemini 1.5 Pro | 35 | 33 | +2 |
| GPT-4o mini | 71 | 57 | +14 |
| Gemini 1.5 Flash | 15 | 9 | +6 |
| Claude 3.5 Haiku | 8 | 32 | –24 |
| Gemini 2.0 Flash | 50 | 47 | +3 |
| GPT-4o | 65 | 50 | +15 |

- 模型原生上下文远大于 30k 帽（文称 100k–2M 量级）；10k 帽实验仍见退化。
- 多模型在**记忆已满、窗口不再增长之后**很久才停售（Sonnet **+51** 日）。

## 十、可跟读小结

1. **测什么**：简单商业动作在 **超长 horizon** 上能否保持同一策略，而不是测「会不会点 GUI」或「会不会在监控下搞破坏」。
2. **怎么分**：VB1 看期末**净值**；方差与 min 和 mean 同样重要；销售停滞日是连贯崩坏的操作化。
3. **崩在哪**：几乎总从 **交付时序误读** 开始，再滑进不可恢复的叙事环（法律核打击、FBI、工具格式遗忘）。
4. **不是上下文填满**：r≈0.17；更大记忆窗口甚至更差。
