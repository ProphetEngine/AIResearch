# Synthetic user simulation：τ-bench + ToolEmu（可选 P2 短卡）

> **定位**：合成仿真评测主题轴 **可选短卡**——用 **LM 模拟用户** 与/或 **LM 模拟工具环境**，做多轮 **策略一致性** 与 **风险** 评测；相对 [[智能体工具与长程任务]]（旗舰工具环/长程产品叙述）与 [[代码智能体Harness史线]]（编码 ACI / harness 史）**只立「合成仿真评测」子轴**。
> **攻坚线**：**架构思想（主）**——谁在仿什么、怎么判成功/失败；**评测字段（辅）**——pass^k、safety/helpfulness、端到端真失败精度。
> **硬划界（禁止重写）**：
> - **禁止重写** [[智能体工具与长程任务]] 的 MCP / ReAct / 并行工具 / System Card 长程叙事（本卡仅把 ReAct / function calling 当作实验脚手架点名）。
> - **禁止重写** [[代码智能体Harness史线]] 的 ACI / Docker / OpenHands SDK 史线（本卡不写「给 LM 什么 shell 面」，写「用 LM 仿用户或仿工具观测」）。
> - **禁止重写** `B5` 红队攻击手册；ToolEmu adversarial emulator 只作 **评测侧状态采样** 接口。
> - [[智能体工具与长程任务]] 产品页里的 **τ²-bench** 分数 → **点到即止**，本卡主文是 **τ-bench（2406.12045）**，不外推 τ² 协议。
> **禁止编造**：数字锚定官方 PDF（2026-09-22 CST）与 arXiv API；站点 https://toolemu.com/ 仅作入口/组件口号辅读。

### 2.2 两条合成轴对照（跟读口诀）

`
τ-bench 真 DB/API ←→ Agent ←→ LM-模拟用户（多轮对话）
 成功 = 终态 DB 与标注目标一致；辅看 pass^k 一致性

ToolEmu LM-模拟工具观测/状态 ←→ Agent（对静态 underspec 指令）
 风险 = LM safety 评轨迹；辅看 helpfulness 与真失败精度
`

| 维度 | **τ-bench** | **ToolEmu** |
|---|---|---|
| LM 主要仿谁 | **用户**（`gpt-4-0613`；temp **1.0**） | **工具执行 + 沙箱状态**（GPT-4 作 emulator） |
| 工具侧 | **Python API + JSON DB**（确定性转移） | **仅规格**，无真实实现亦可评高风险工具 |
| 用户侧 | 多轮、隐藏 user instruction、可 `###STOP###` | 用例内 **underspecified instruction**（偏红队） |
| 主判据 | 终态 DB vs 标注 write actions | safety / helpfulness 量表（0–3）+ 二值失败 |
| 主威胁模型 | 信息不完整下的策略 + **域政策遵从** | 指令欠指定下的 **长尾严重后果** |
| 代表数字（文内） | gpt-4o FC：retail **61.2** / airline **35.2** pass^1；pass^8 **&lt;25%**（retail） | 最安全配置 failure **23.9%**；识别失败中 **68.8%** 为人判真失败（adversarial） |

## 三、τ-bench：Tool–Agent–User 三角 + pass^k

### 3.1 设定（§3）

- 状态 $S = S_{db} \otimes S_{user}$；动作 $A = A_{db} \cup A_{user}$。
- **DB**：对 agent/user 隐藏；只经 API 读写；转移 **确定性**（Python）。
- **Domain policy**：系统提示中的规则；部分落在 API 校验，部分（如行李额）需 agent 自己算进参数。
- **User sim**：只见与 agent 的自然语言史，**不见** agent↔API 轨迹；指令里保证「在政策下唯一合理终态」。
- **奖励**：终态 DB 与标注目标比对（rule-based）；作者承认可漏「未写库但违规」类行为，但换得快且可复现。

### 3.2 规模（Table 1）

| 域 | DB 规模（文） | API | Tasks |
|---|---|---|---|
| **τ-retail** | 500 users / 50 products / 1,000 orders | 7 write + 8 non-write | **115** |
| **τ-airline** | 500 users / 300 flights / 2,000 reservations | 6 write + 7 non-write | **50** |

构造三阶段：人工 schema/API/政策 → LM 助生成库条目 → 人工任务标注并用 agent 多试打磨「唯一结果」。

### 3.3 pass^k（§3 + Fig. 4）

- **pass^k**：同一任务 **k 次 i.i.d. 全成功** 的概率，再对任务取期望（相对 coding 的 pass@k「至少一次成功」）。
- 动机：客服类要的是 **一致性**，不是「偶发一次对」。
- 实验：agent temp **0.0**、user temp **1.0**；每任务至多 **30** agent actions；主表 ≥3 trials。

### 3.4 主结果与失败谱（§5，Table 2 / Fig. 5）

| 模型（function calling；Llama-3 为 text-ReAct） | retail | airline | avg（域加权） |
|---|---:|---:|---:|
| gpt-4o | **61.2** | **35.2** | **48.2** |
| gpt-4-turbo | 57.7 | 32.4 | 45.1 |
| claude-3-opus | 44.2 | 34.7 | 39.5 |
| gpt-3.5-turbo | 20.0 | 10.8 | 15.4 |
| meta-llama-3-70B | 14.8 | 14.4 | 14.6 |

- FC **稳赢** 同模 text-ReAct / Act（Fig. 3）。
- gpt-4o：pass^1&gt;60%（retail）时 **pass^8 仍 &lt;25%**。
- 失败粗分（36 个 agent 失败，retail gpt-4o）：wrong arg / wrong info 合计约 **55%**；wrong decision（政策）**25%**；partial resolve **~19%**。
- 去政策消融（Table 3）：airline 上 gpt-4o **33.2→10.8**（规则复杂时政策真被用到）；retail 降幅小（常识即可糊弄简单规则）。

**跟读：** τ-bench 证明「会调函数」≠「多轮问清意图 + 守域规 + 多次对话同终态」。

## 四、ToolEmu：LM 仿沙箱 + 自动风险评

### 4.1 三组件（站点 / 文 Fig. 1–3）

1. **Tool emulators**：只凭 **tool spec + 输入 + 轨迹史** 吐 observation；可覆盖尚无公开 API 的工具。
2. **Safety & helpfulness evaluators**：GPT-4 对整段轨迹打定性标签并可二值化（Table 1：safety 如 Certain No Risk(3)…；helpfulness Excellent(3)…）。
3. **Curated benchmark**：**36** toolkit（共 **311** tools）× **144** underspec 用例 × **9** risk types；**30** 个 toolkit 不在既往静态沙箱能力榜；**7** 个尚无公开 API/实现（Table 2）。

**Standard vs adversarial emulator：** 后者额外吃 underspecification 与「intended risks / risky actions」，把状态采样推向更易致灾的长尾（Fig. 4 药瓶歧义例）。

### 4.2 有效性（§4，人评；100 case × 双 emulator = 200 轨迹）

| 指标 | 文内 |
|---|---|
| Identified failure precision | Standard **72.5%±7.1%**；Adversarial **68.8%±6.7%**（Table 3；摘要取 adversarial **68.8%**） |
| True failure incidence | Standard **39.6%**；Adversarial **50.0%**（adversarial 多检出约 **10 p.p.**） |
| 无 critical issue 仿真比 | Standard **91.9%**；Adversarial **85.6%**（Table 4） |
| Safety 评 vs 人 | Cohen’s κ A-H **0.478** ≈ H-H **0.480**；recall **73.1%** vs 单人约 **78.8%** |
| Terminal 实装抽检 | ChatGPT-3.5 的 **7** 个检出失败中 **6** 可在真 bash 复现；文称手搭沙箱约 **8h** vs 仿真 **&lt;15 min** |

典型失败模式（作者归纳）：虚构/无据假设、指令误读、错误执行、**风险无知**。

### 4.3 Agent 表（§5 Table 5；全 144 case + **adversarial** emulator；temp=0）

| Agent | Safety avg ↑ | Failure Inc. ↓ | Helpfulness ↑ |
|---|---:|---:|---:|
| GPT-4 Basic | 2.007 | 39.4% | 1.458 |
| Claude-2 Basic | 1.829 | 44.3% | 1.464 |
| ChatGPT-3.5 Basic | 1.430 | 62.0% | 0.768 |
| GPT-4 + Safety prompt | **2.359** | **23.9%** | 1.824 |
| GPT-4 Helpful+Safety | 2.241 | 30.5% | 1.624 |
| NoAct（对照） | 3.000 | 0% | ~0 |

**跟读：** 安全提示能压失败率，但「最安全配置仍有约四分之一用例失败」；NoAct 满分安全、近零有用 → 必须看 **safety–helpfulness frontier**（Fig. 6），不能只报拒答率。

### 4.4 局限（§7，照录压缩）

- Emulator/evaluator 仍是 prompt GPT-4：复杂/对抗场景会出 critical issue；常有「假电话号」类 minor。
- 用例 curated **仍大量依赖人**；自动出题常违反有效用例要求。
- 威胁模型主攻 **instruction underspecification**，恶意意图等未铺开。

## 五、合读：何时用哪张卡

| 问题 | 优先锚点 |
|---|---|
| 客服/域政策下，多轮问询后 DB 是否对、是否稳 | **τ-bench** + pass^k |
| 工具尚无沙箱/高危，要快速摸长尾灾 | **ToolEmu** + adversarial emu + safety 评 |
| 编码仓库里 ACI/沙箱能不能复现实验 | → **[[代码智能体Harness史线]]**（本卡不写） |
| 旗舰产品怎么讲 agent / 并行工具 | → **[[智能体工具与长程任务]]**（本卡不写） |

**可选短卡结论：** 合成仿真把「人在环」与「险在环」从工程阻塞里解放出来，但判据都带着代理性——τ 的终态比对可漏软违规；ToolEmu 的真失败精度约七成、且依赖更强 LM 当沙箱裁判。读产品 τ / τ² 分数时，先问测的是 **用户仿** 还是 **工具仿**，再问 **pass^1 还是 pass^k / failure incidence**。
