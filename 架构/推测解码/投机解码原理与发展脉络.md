# 投机解码原理与发展脉络

> **主要来源**：[Fast Inference from Transformers via Speculative Decoding](https://arxiv.org/abs/2211.17192)（Leviathan、Kalman、Matias，v2）；[Accelerating Large Language Model Decoding with Speculative Sampling](https://arxiv.org/abs/2302.01318)（Chen 等，DeepMind）；[Medusa](https://arxiv.org/abs/2401.10774)（v3）；[EAGLE](https://arxiv.org/abs/2401.15077)（v3）；[TensorRT LLM 投机解码文档](https://nvidia.github.io/TensorRT-LLM/features/speculative-decoding.html)（页面标 Last updated 2026-09-26）（截至 2026-09-28）。其余来源见第九节。
> **研究线**：架构思想（草稿—校验的并行解码）· AI Infra（decode 访存墙、batch 与部署取舍）· 数学原理（保分布的拒绝采样与期望加速比）
> **范围与相邻笔记**：
> - 本篇是投机解码的共用背景：瓶颈、保分布校验、草稿来源与树形校验的分类，以及 2018 年至 2026 年 9 月的脉络。各方法的细节在各自的笔记里，本篇只给一两句定位。
> - ≠ [[推理引擎生态]]：本篇不写 vLLM / SGLang / TensorRT-LLM 的选型地图，只在 4.4 节记引擎文档里投机解码的落点。
> - ≠ [[MTP训练范式]]：多 token 预测（MTP）作为训练目标怎么训，看那篇；本篇只写 MTP 模块被拿来当草稿的那一面。
>
> **意义**：投机解码把「大模型每步只出一个 token、却要搬一遍全部权重」的 decode 访存墙，换成「便宜地猜一段、目标模型一次并行校验」。在严格的接受规则下输出分布与原模型相同，所以它是少有的不改目标模型、不损质量就能降延迟的手段。2024 年以后，草稿从外挂小模型逐步内置进目标模型的预训练（MTP 头、EAGLE 式草稿层），投机解码由此从推理期技巧变成模型报告里的标准部署字段。

## 一、问题背景

- **decode 受内存带宽束缚**：自回归每步通常只产出 1 个 token，却要把全部参数从 HBM 搬进计算单元（Medusa 摘要）；Chen 等人在引言里也说明，大模型上的采样受内存带宽限制。Lookahead 摘要的表述是 decode「memory bandwidth bounded」，加速器的并行算力大量闲置。
- **并行打分几乎不比单步贵**：Chen 等人观察到，目标模型对一段短续写并行打分的延迟，与采样一个 token 相当（摘要）。闲置算力因此可以拿来一次校验多个候选 token。
- **约束**：不能改目标模型，最好也不能改输出。Leviathan 等人的目标是「without any changes to the outputs」，现成模型不重训、不改架构即可加速（摘要）。

## 三、核心思想

### 3.1 草稿—校验

用便宜的草稿串行猜 γ 个 token，目标模型一次前向并行算出这 γ+1 个位置的分布，从左到右逐个决定接受；遇到第一个拒绝就停下，并从校正分布补一个 token。所以每轮至少产出 1 个 token，最坏情况不比原解码少产出。

### 3.2 保分布的接受规则

记目标分布为 p，草稿分布为 q（Leviathan 的记号；Chen 等人的论文里 p、q 的含义正好相反，读原文时注意）：

- 草稿 x 来自 q。若 q(x) ≤ p(x) 直接接受；若 q(x) > p(x)，以概率 1 − p(x)/q(x) 拒绝。
- 拒绝后从 norm(max(0, p(x) − q(x))) 重新采样。
- 可以证明这样得到的 x 服从 p（Leviathan §2.3 与附录 A.1；Chen 定理 1，「within hardware numerics」）。贪心解码时规则退化为「草稿 token 与目标 argmax 相同才接受」。

### 3.3 期望加速比

Leviathan 等人假设每个位置的接受概率独立同分布，均值记为 α（衡量草稿逼近目标的程度），草稿单步成本与目标单步成本之比记为 c：

- 每轮期望产出 token 数 = (1 − α^(γ+1)) / (1 − α)（式 1）。
- 墙钟期望加速比 = (1 − α^(γ+1)) / ((1 − α)(γc + 1))（定理 3.8）。
- 只要 α > c，就存在能带来加速的 γ，加速比至少为 (1 + α)/(1 + c)（推论 3.9）。论文实验里草稿比目标小一两个数量级，c 都小于 0.05。
- 算术运算总量会上升（被拒绝的草稿白算），但目标模型权重与 KV 缓存每轮只读一次，内存访问按式 1 的倍数下降（§3.4）。这正是 decode 受带宽束缚时投机解码有效的原因。

三条推论：α 由草稿与任务决定，是第一位的；c 由硬件和实现决定；γ 不是越长越好，α 低时拉长 γ 只会增加白算（§3.5 按 α、c 数值求最优 γ）。

## 四、关键机制

### 4.1 草稿从哪来

| 草稿来源 | 代表 | 要点 | 代价 |
| --- | --- | --- | --- |
| 独立小模型 | Leviathan、Chen | 现成小模型直接用 | 词表要与目标一致（TensorRT LLM 文档：分词器不同则接受率极低、反而变慢）；要单独维护权重；接受率随领域漂移 |
| 目标模型上的轻量头 | Medusa（彼此独立的头）、Hydra（依赖已猜 token 的头） | 草稿内置进目标，运维面小 | 要训头；头的质量决定 α |
| 特征级草稿层 | EAGLE、EAGLE-2、EAGLE-3 | 复用目标模型的隐层特征起草；EAGLE-3 改为多层特征融合、直接预测 token | 要为每个目标模型训练草稿层 |
| 预训练自带的 MTP 模块 | DeepSeek-V3、GLM-4.5、Nemotron 3 Ultra、Gemma 4、Kimi K3、Qwen3.8-Next | 训练期作为辅助目标，推理期挪作草稿或丢弃 | 与骨干同训，改动在模型侧；K3 另把 MTP 层微调成 EAGLE-3 式草稿 |
| 预训练后单独训练的草稿 | DeepSeek-V4.1-Flash DSpark | 冻结骨干单独训，后训练继续训但不把草稿损失回传骨干；一次前向并行出多个草稿位 | 多一套训练流程 |
| 免模型检索 | Lookahead（Jacobi + n-gram 池）、Prompt Lookup（从上下文复制）、Goose | 不训练、不加权重 | 加速幅度通常更保守，依赖文本里的重复 |

### 4.2 一条链还是一棵树

- **链**：一次校验一条长度 γ 的续写，第一处拒绝之后的草稿全部作废。
- **树**：SpecInfer 把多个候选排成 token 树，Medusa 用树注意力一次校验多条续写。在同样的校验预算下，深度（每步可接受的 token 数）与宽度（某一位置被拒绝后的备选）此消彼长。
- **从静态树到动态树**：Medusa、Hydra、EAGLE 用固定拓扑；EAGLE-2 按草稿置信度在每个上下文里重建树；EntMTP 按生成熵在几棵预设树之间切换；AdaptiveSpec 逐步调整深度、宽度与节点数；Goose 按 token 来源的可靠程度把树拉成「深脊柱 + 宽枝」。共同的判断是：接受率随上下文变化，固定树形在可预测的片段猜得太保守，在难预测的片段又白白浪费校验算力。

### 4.3 接受规则：无损与有损

- **无损**：3.2 节的拒绝采样，或贪心下的精确匹配。Leviathan、Chen、SpecInfer、Lookahead、EAGLE 系、Goose 都声明输出分布不变。
- **有损**：Medusa 的 typical acceptance 放宽接受条件以提高接受率，同时维持生成质量；AdaptiveSpec 的 margin 规则在目标模型对草稿 token 的概率与其 top-1 概率之比超过阈值时，接受不匹配的草稿；TensorRT LLM 的 MTP 配置有「思考阶段放宽接受」的开关。这些都离开了严格同分布，论文报告的是「准确率保留多少」而不是「输出相同」。

### 4.4 与 batch、调度和引擎的关系

- **batch 越大收益越小**：投机解码用闲置算力换串行步数；batch 增大后 decode 从带宽受限转向算力受限，闲置算力变少。AdaptiveSpec v2 的 batch 扫描里，加速比从 3.20× 降到 1.67×（GSM8K）；EAGLE-3 在 SGLang 上 batch 64 仍有 1.38× 吞吐，是「大 batch 下全无用」的反例。Nemotron 3 Ultra 报告说大 batch 时可能关掉 MTP 更划算。TensorRT LLM 文档写明：开启投机后每个请求都生成一条长 max_draft_len 的草稿，目前无法动态关闭，因此只在小 batch 下能看到加速。
- **与连续批处理正交**：连续批处理决定一步里拼哪些请求，投机解码减少每个请求的串行步数，接受与拒绝仍在步进循环里发生。
- **与 PD 分离叠乘**：投机只加速 decode；prefill 偏算力。分池后把投机放在 decode 池更自然，是否默认开启属部署配置。
- **与量化、MLA、分页正交**：投机降的是串行步数，量化与 MLA 降的是每步搬移量与 KV 体积，分页降的是碎片，几项可以相乘，不能互相替代。
- **引擎落点**（TensorRT LLM 文档，Last updated 2026-09-26）：支持 Draft/Target、EAGLE 3（默认一条链，可选动态树）、NGram（Prompt Lookup Decoding 的实现）、MTP（DeepSeek 系及 Qwen3.8 MoE、Qwen3.5 MoE、Step-3.x 等自带 MTP 模块的架构）、PARD、DFlash、用户自定义草稿，以及可与 MTP、EAGLE 3 叠加的免模型后缀自动机（SA）增强。SGLang 的项目 README 在生态表里列有 SpecForge，用于训练投机草稿并部署到 SGLang。

### 4.5 训练侧

- **MTP 先是训练目标**：Gloeckle 等人提出 MTP 是为了提升样本效率与下游能力，推理加速是附带收益；V3 的 MTP 也是先作为训练目标，再挪作草稿。MTP 怎么训看 [[MTP训练范式]]。
- **草稿的训练目标向接受率靠拢**：EAGLE-3 用 training-time test 让草稿在训练时就面对自己的预测；Kimi K3 直接优化接受率的负对数；Nemotron 3 Ultra 用只训头的 KL 对齐草稿。
- **草稿与骨干的耦合度**：从联合预训练（V3、Gemma 4），到冻结骨干后单独训（Medusa-1、DSpark），再到完全免训练（Lookahead、Goose、EntMTP、AdaptiveSpec），是一条「质量与运维成本」的取舍轴。

## 五、常见误区

1. **「投机解码一定无损」**：Leviathan、Chen 路线保证同分布（在数值误差内）；typical acceptance、margin 规则、思考阶段放宽接受等都会离开严格同分布。引用加速比前要先看论文声明的是 lossless，还是「质量可接受」。
2. **「接受率低也能靠拉长草稿硬加速」**：草稿过长而 α 低时，校验浪费上升，甚至减速（Leviathan §3.5 的 γ–α–c 取舍；Lookahead 论文对草稿失败的讨论）。生产上要按领域实测接受率，不能把论文的 2–3× 当 SLA。
3. **「MTP 就是投机解码」**：MTP 是训练目标，投机解码是推理算法；MTP 模块可以当草稿，但训练收益（样本效率、下游能力）与推理收益要分开看。
4. **「各论文的加速比可以横比」**：硬件、温度、目标模型、batch、是否用树都不同。本篇脉络表里的倍率只说明各方法在自身设定下的量级，不构成排名。
5. **「大 batch 下投机解码无用」**：收益确实随 batch 下降，但 EAGLE-3 在 SGLang batch 64 仍有 1.38×；是否开启要按负载实测，Nemotron 3 Ultra 也只说大 batch 时「可能」关掉更划算。

## 六、意义

- **把访存墙变成可调的并行轴**：在不改目标模型、不改输出分布的前提下降低 decode 延迟。这是 [[推理引擎生态]] 所说「serving 效率」之外独立的一个因子。
- **草稿从部署期外挂变成模型设计的一部分**：V3 之后，MTP 头、drafter 规格、接受率成为技术报告的常规字段（GLM-4.5、Nemotron 3 Ultra、Gemma 4、Kimi K3、Qwen3.8-Next、DeepSeek-V4.1-Flash）。
- **研究焦点转向自适应**：2024 年后的进展主要不在「草稿更准」，而在「按上下文决定猜多少、怎么校验」（EAGLE-2、EntMTP、AdaptiveSpec、Goose）。

## 七、局限与待核实

- **Medusa-2 加速比**：本篇按 v3 全文摘要与结论取 2.3–2.8×；arXiv abs 页摘要与 v1 全文为 2.3–3.6×，版本间口径不一。
- **版本差异**：EAGLE v1 摘要写的是相对 vanilla 约 3×、比 Lookahead 快 2×、比 Medusa 快 1.6×，v3 改为 LLaMA2-Chat 70B 上 2.7×–3.5×；Hydra v1 写 Hydra++ 相对自回归 2.71×，v2 为 2.70×；AdaptiveSpec 的 v1 与 v2 数字不同，见 [[AdaptiveSpec与Goose]]。本篇一律取最新版。
- **加速比不可横比**：脉络表里的倍率来自各自摘要，硬件、模型、温度与 batch 各不相同。
- **i.i.d. 假设**：3.3 节的公式假设各位置接受概率独立同分布；EAGLE-2 已发现接受率依赖上下文，公式只能作量级估计。
- **未覆盖**：自回归之外的模型（扩散语言模型、线性注意力层）上的投机解码；SGLang、vLLM 中各投机方法的默认配置与版本差异；PARD、DFlash 两种方法本篇只记引擎落点，不展开其方法。
- **引擎文档是活页**：TensorRT LLM 支持的方法列表随版本变化，本篇以页面标注的 2026-09-26 版本为准。
