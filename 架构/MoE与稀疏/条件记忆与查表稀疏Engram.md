# 条件记忆与查表稀疏Engram

> **主要来源**：[Conditional Memory via Scalable Lookup: A New Axis of Sparsity for Large Language Models](https://arxiv.org/abs/2601.07372)（简称 Engram 论文，Cheng 等，官方仓库 [deepseek-ai/Engram](https://github.com/deepseek-ai/Engram)）；[Scaling Embeddings Outperforms Scaling Experts in Language Models](https://arxiv.org/abs/2601.21204)（简称 Liu 等）；[On the Design of Qwen3.8-Next Architecture](https://arxiv.org/abs/2608.30320)（简称 Qwen3.8-Next 报告）；[DeepSeek-V4.1-Flash](https://arxiv.org/abs/2609.19969)（简称 V4.1-Flash 报告）；[FactorEngram](https://arxiv.org/abs/2609.35578)（截至 2026-09-28）。其余来源见第十三节。
> **研究线**：架构思想（在 MoE 的「条件计算」之外，用按输入确定地址的大表查表做「条件记忆」：怎样寻址、怎样融合、参数在专家与表之间怎样分）· AI Infra（地址只取决于输入 token，表可以放在加速器之外并提前取回）
> **范围与相邻笔记**：
> - ≠ [[MoE路由与负载均衡]]：本篇不写专家路由、负载均衡与专家并行通信，只写与专家并列的另一条稀疏轴。
> - ≠ [[检索增强与知识外挂]]：本篇不写从外部文档库检索内容的做法。
> - ≠ [[检索式注意力]]：本篇不写在长上下文里检索内容的注意力做法。
> - ≠ [[智能体长程记忆]]：本篇不写智能体跨会话的记忆管理。
> - ≠ [[线性注意力与状态空间模型谱系]]：本篇不写把历史压缩进循环状态的「记忆」。
> - ≠ [[测试时记忆Titans与嵌套学习]]：本篇不写推理时按梯度写入权重的神经记忆。
> - ≠ [[分词器与数据配比]]：本篇不写分词器设计，只写查表模块对分词器的依赖。
> - ≠ [[端侧小模型]]：本篇不写端侧的逐层嵌入部署细节。
>
> **意义**：MoE 用「只激活一部分专家」把参数量与每 token 计算量解耦，但专家要靠隐状态路由，取哪个专家要算到那一层才知道。条件记忆换了一种稀疏：用前几个 token 组成的 n-gram 直接算出表的地址，取回一行向量加进残差流。地址在前向开始前就已确定，表可以放在主机内存并提前取回。Engram 论文把这一思路作为与 MoE 互补的稀疏轴系统化，2026 年起 DeepSeek-V4.1-Flash、Qwen3.8-Next、LongCat-Flash-Lite 相继采用，但对「拿专家参数换查表参数是否划算」，各家给出的结论并不一致。

## 一、问题背景

### 1.1 先区分四种「记忆」

「记忆」一词在本库里至少有四种用法，本篇只写最后一种。

| 含义 | 记的是什么 | 怎样取回 | 何时写入 | 所在笔记 |
|---|---|---|---|---|
| 检索增强与检索式注意力 | 外部文档或长上下文中的原文片段 | 按查询向量做相似度检索 | 推理时随文档库或上下文变化 | [[检索增强与知识外挂]]、[[检索式注意力]] |
| 智能体记忆 | 智能体跨步骤、跨会话积累的事实与经验 | 由智能体读写外部存储 | 运行时持续写入 | [[智能体长程记忆]] |
| 线性注意力与状态空间模型的状态 | 把已读序列压缩成的固定大小状态 | 每步由循环更新带出 | 推理时逐 token 更新 | [[线性注意力与状态空间模型谱系]] |
| 参数化查表记忆（本篇） | 训练得到的大型嵌入表或键值表 | 按输入 n-gram 的哈希或按隐状态的近邻搜索选出少数行 | 只在训练时更新，推理时只读 | 本篇 |

前三种记忆的内容在推理时会变；本篇的「条件记忆」是模型参数的一部分，推理时只读，它与 MoE 专家同属「参数多、每 token 只用一小部分」的稀疏结构。

### 1.2 为什么需要另一条稀疏轴

Engram 论文的出发点是：语言建模包含组合推理与知识检索两类性质不同的子任务，其中命名实体、固定搭配这类文本局部、静态、高度程式化；标准 Transformer 没有原生的查表原语，只能用多层注意力与前馈网络「算出」这些模式，论文称这相当于在运行时重建一张静态查找表，浪费了本可用于高层推理的深度（Engram 论文第 1 节）。

论文据此提出两类稀疏的区分：条件计算按需激活参数来处理动态逻辑，条件记忆用稀疏查表取回固定知识的静态嵌入（Engram 论文第 1 节）。Liu 等从另一侧给出动机：MoE 随规模与稀疏度提高，边际收益递减，并受通信开销与显存带宽等系统瓶颈约束，因而需要在前馈网络之外寻找正交的稀疏扩展维度（Liu 等第 1 节）。

## 三、两条前史：按隐状态寻址与按输入寻址

Engram 论文在相关工作中把两类前作分开：一类是把大规模稀疏键值存储直接集成进模型层的参数化记忆（PKM、PEER、Memory+、UltraMem 等），一类是把 n-gram 结构接入表示空间的嵌入扩展（N-Grammer、SCONE、OverEncoding 等）（Engram 论文第 7 节）。两类的关键差别在于「地址从哪里来」。本篇把它概括为按隐状态寻址与按输入寻址，这是本篇的整理口径，不是某篇论文的原话。

### 3.1 键值记忆层：地址由隐状态决定

- **Lample 等**：层的输入先经查询网络得到查询向量，再与键比较；键与值不是输入 token 而是自由的嵌入向量，且值的数量非常大（Lample 等第 2 节、第 3.1 节）。乘积键把一组键拆成两组子键，使近邻搜索快速且精确；论文称记忆层能把容量扩大最多十亿参数而计算开销可以忽略，带记忆的 12 层模型优于 24 层基线，推理速度是后者的两倍（Lample 等摘要）。
- **PEER**：把乘积键技术用于从超过一百万个微型专家的池子里稀疏检索，论文称其在性能与计算的权衡上优于稠密前馈层和粗粒度 MoE（PEER 摘要）。
- **UltraMem**：引入大规模超稀疏记忆层，针对 MoE 推理时访存成本高的问题；论文称训练的最大 UltraMem 有 2000 万个记忆槽（UltraMem 摘要）。
- **Berges 等**：记忆层用可训练的键值查找在不增加 FLOPs 的情况下增加参数；论文给出最多 128B 记忆参数、预训练到 1 万亿 token 的缩放结果，称其优于算力预算超过两倍的稠密模型，以及算力与参数都匹配的 MoE，事实类任务上增益尤其明显（Berges 等摘要）。

这一支的共同点是：查询来自隐状态，选哪一行要在该层算出查询后才知道，与 MoE 路由同属「运行时决定」。

### 3.2 n-gram 嵌入：地址由输入决定

- **N-Grammer**：把输入的单元组嵌入用乘积量化聚类成离散隐表示，在其上计算二元组 ID，经哈希查二元组嵌入表，再与输入嵌入合并（N-Grammer 第 3 节）。它的地址来自聚类后的离散码，介于两支之间。
- **Huang 等（Over-Tokenized Transformer）**：解耦输入词表与输出词表，把输入词表扩大到多元组 token；论文称输入词表大小与训练损失呈对数线性关系，大输入词表可在不增加成本的情况下达到两倍规模基线的水平（Huang 等摘要）。Engram 论文以 OverEncoding 指称这一做法，把 n-gram 嵌入与词表嵌入取平均（Engram 论文第 3.2 节）。
- **SCONE**：保留原词表，为一组高频 n-gram 引入嵌入，嵌入由单独模型在训练时学习；训练后预先计算并放在加速器之外的内存，推理时查表对延迟影响很小（SCONE 摘要）。

这一支的地址只取决于输入 token，为后来「表放在加速器外、提前取回」埋下了伏笔。Engram 论文对这一支的批评有两点：一是此前做法多把 n-gram 嵌入当作外加增强，没有在严格公平的对比下验证效率；二是它们都把嵌入放在输入层（第 0 层），访存与计算只能串行（Engram 论文第 7 节）。

## 四、Engram 的结构

本节只写结构，不写公式。按 Engram 论文第 2 节，模块对每个位置分「检索」与「融合」两个阶段，并且只插在骨干的个别层，标准的输入嵌入与输出层保持不变（Engram 论文第 2.1 节、图 1）。

### 4.1 检索：压缩后的后缀 n-gram 与多头哈希

1. **分词器压缩**：子词分词器为无损还原，常把语义等价的词分到不同 ID（如 Apple 与带前导空格的 apple）。论文预先计算一个满射，按 NFKC、小写化等归一化后的文本等价关系把原始 ID 合并成规范 ID；对 128k 词表，有效词表缩小 23%（Engram 论文第 2.2 节）。
2. **后缀 n-gram**：对每个位置取以该 token 结尾、由规范 ID 组成的后缀 n-gram（Engram 论文第 2.2 节）。
3. **多头哈希**：直接为所有 n-gram 组合建表不可行，论文沿用哈希做法；为缓解冲突，每个 n-gram 阶各用多个哈希头，每个头把上下文映射到一张大小为素数的嵌入表，哈希函数是轻量的乘法与异或；各阶各头取回的向量拼接成记忆向量（Engram 论文第 2.2 节）。

### 4.2 融合：上下文门控、短卷积与残差

1. **上下文门控**：取回的嵌入与上下文无关，可能受哈希冲突或多义带来的噪声影响。论文以当前隐状态作查询、以记忆向量投影出键与值，归一化后算出一个标量门；若取回内容与上下文矛盾，门趋近于零，噪声被压掉（Engram 论文第 2.3 节）。
2. **短卷积**：门控后的值再经一个短的逐通道因果卷积，核大小为 4，膨胀取最大 n-gram 阶（Engram 论文第 2.3 节）。
3. **残差接入**：输出经残差连接加回该层隐状态，其后照常是注意力与 MoE（Engram 论文第 2.3 节）。
4. **多分支骨干**：论文默认骨干是把残差流扩成多条并行分支的结构；各分支共享同一张稀疏嵌入表与值投影，各用一个键投影以得到分支专属的门，这些线性投影可以融合成一次 FP8 矩阵乘（Engram 论文第 2.4 节）。

### 4.3 训练设置

Engram-27B 的表参数用 Adam 更新，学习率放大 5 倍、不用权重衰减；卷积参数初始化为零，使训练开始时模块严格保持恒等映射（Engram 论文第 4.1 节）。

### 4.4 与两种「看起来相似」的设计的区别

- **按 token ID 的哈希路由**：DeepSeek-V4 在前 3 个 MoE 层使用哈希路由，按输入 token ID 用预定义的哈希函数决定目标专家（DeepSeek-V4 报告第 2.1 节、第 4.2.1 节）。它与 Engram 一样由输入确定地址，但选中的是专家（一段计算），不是表中的一行向量；地址只看当前 token，不看前文。
- **逐层嵌入**：Engram 论文把逐层嵌入（Per-Layer Embeddings）等列为「用大表扩容」的嵌入扩展做法，与把 n-gram 组合结构接入表示空间的一支区分开（Engram 论文第 7 节）。逐层嵌入的端侧部署见 [[Gemma4技术报告深读]] 与 [[端侧小模型]]，本篇不展开。

## 五、稀疏分配：U 形律与「何时拿专家换表」

### 5.1 Engram 论文：固定总参数下的 U 形

论文把问题表述为「稀疏分配」：总参数与每 token 激活参数都固定时，未激活的参数预算该怎样在 MoE 专家与 Engram 表之间分。它定义分配比为分给专家的比例，比例为 1 即纯 MoE（Engram 论文第 3.1 节）。

在两个算力预算下，验证损失随分配比呈一致的 U 形：纯 MoE 并非最优，把约 20%–25% 的稀疏参数预算转给 Engram 效果最好；最优点在两档规模下都位于约 75%–80%；专家比例降到约 40% 时，仍与纯 MoE 基线相当（Engram 论文第 3.1 节）。论文对 U 形两端的解释是：偏 MoE 时模型缺少专门存放静态模式的记忆，只能用深度与计算去重建；偏 Engram 时模型失去条件计算能力，记忆替代不了计算（Engram 论文第 3.1 节）。

论文还在固定 MoE 骨干上单独加大 Engram 表，称验证损失随记忆槽数呈幂律（对数空间中线性），并且在同样的记忆预算下比 OverEncoding 的取平均做法扩展潜力更大（Engram 论文第 3.2 节）。

这条律在缩放研究脉络中的位置见 [[缩放定律的扩展形态]]：那篇把它作为缩放律在稀疏结构上的一种扩展来对照，本篇写它背后的模块设计与工程条件。

### 5.2 Liu 等：先把专家加到「甜点」以上

Liu 等在 LongCat-Flash 架构上比较扩嵌入与扩专家，用总参数与激活参数之比作为稀疏度的代理（Liu 等第 3 节）。论文称：

- MoE 的缩放曲线呈严格的对数线性；低比值区间多加专家就能明显降损失，此时引入 n-gram 嵌入的优势比不上直接加专家；高稀疏度时 n-gram 嵌入的收益明显得多。论文的总结是：专家数超过其「甜点」后再引入 n-gram 嵌入（Liu 等第 3.1 节）。
- 嵌入参数占比过高后又会被同参数的 MoE 反超；论文认为这与 Engram 的 U 形结论一致，并给出原则：分给 n-gram 嵌入的参数不超过总参数预算的 50%（Liu 等第 3.2.1 节）。
- 宽度越大，n-gram 嵌入的优势越大；深度越大，相对优势越小（Liu 等第 3.3 节）。

Liu 等的 n-gram 嵌入是加在输入嵌入上的（与原 token 嵌入一起取平均），这一点与 Engram 插在中间层不同（Liu 等第 2 节）。

### 5.3 Qwen3.8-Next：固定总参数下看不到下游收益

Qwen3.8-Next 报告做了同样的「减专家、加 n-gram 表」实验：损失随词表大小非单调变化，在 10 倍（25%）处最低，与前人报告的分配甜点一致；但域外的困惑度在各预算间变化很小，下游基准相对纯 MoE 基线没有明显提升（Qwen3.8-Next 报告第 2.3.2 节）。报告由此认为 n-gram 嵌入与 MoE 专家在扩容中扮演不同角色，转而在保持 MoE 参数不变的前提下另加 n-gram 表：词表从 20V 扩到 200V，损失单调下降，下游表现却不跟随，部分基准饱和或波动，中文基准随词表增大持续改善（Qwen3.8-Next 报告第 2.3.2 节）。

### 5.4 三种结论怎样并读

| 来源 | 设定 | 结论 |
|---|---|---|
| Engram 论文 | 总参数与激活参数固定，按验证损失与下游基准 | 拿一部分专家预算换表更好，U 形 |
| Liu 等 | 按稀疏度分区间，按训练与验证损失 | 专家已多时换表才划算，表参数不宜过半 |
| Qwen3.8-Next 报告 | 总参数固定，同时看损失与下游 | 损失有甜点，下游看不到收益；改为额外加表 |

三者在「损失有分配甜点」上并不矛盾，分歧在于损失上的收益能否转化为下游指标。三者的骨干、训练 token 数、表的插入位置与评测集都不相同，本篇不判断谁对，只记录各自的设定。

## 六、效果与机制（论文称）

本节均为 Engram 论文自述的结果，尚无独立复现。

- **同参数、同 FLOPs 对比**：Engram-27B 由 MoE-27B 派生，把路由专家从 72 个减到 55 个，空出的参数给 5.7B 参数的嵌入模块，总规模保持 26.7B（Engram 论文第 4.1 节）。论文称它在知识类之外，通用推理与代码数学上的提升更明显，例如 CMMLU +4.0、BBH +5.0、HumanEval +3.0、MATH +2.4（Engram 论文第 4.2 节）。
- **等效加深**：论文用 LogitLens 与 CKA 分析，称 Engram 模型早期层的预测更快接近最终输出，Engram-27B 第 5 层的表示与 MoE 基线约第 12 层最相似，即 Engram 相当于增加了有效深度（Engram 论文第 6.1 节）。
- **插入位置**：单个模块插在第 2 层最好，越深越差；把同样预算拆成两个模块放在第 2 层与第 6 层更好。论文的解释是：越早插入越能替骨干承担局部模式重建，但越早的隐状态越缺少上下文，门控越不准；经过一轮注意力已足以给门控提供有意义的上下文（Engram 论文第 6.2 节）。
- **哪些组件重要**：多分支下的分支专属融合、上下文门控、分词器压缩三者移除后损失退化最大；去掉短卷积只有轻微影响（Engram 论文第 6.2 节）。
- **关掉记忆后**：推理时完全屏蔽 Engram 输出，事实知识类基准只保留原性能的 29–44%，阅读理解类保留 81–93%；论文据此称 Engram 是参数化知识的主要存放处，而依赖上下文的任务主要靠骨干的注意力（Engram 论文第 6.3 节）。
- **长上下文**：论文称把局部依赖交给查表后，注意力能更多处理全局上下文；在预训练损失对齐的设定下，Multi-Query NIAH 为 97.0 对 84.2（Engram 论文第 5.2 节）。

## 七、系统侧：确定性寻址带来的工程空间

### 7.1 推理：主机内存与提前取回

MoE 要靠运行时隐状态路由，Engram 的地址只取决于输入 token ID，前向开始前就已知；推理时系统可经 PCIe 从主机内存异步取回嵌入，并把模块放在骨干的特定层，用前面几层的计算掩盖传输延迟（Engram 论文第 2.5 节）。

这带来一组硬件与算法的共同约束：放得越深，掩盖延迟的计算窗口越长；但建模上越早插入越好，因此位置要同时满足两边（Engram 论文第 2.5 节）。论文还提出，n-gram 访问服从齐普夫分布，可以按访问频率把表分层放在 HBM、主机内存与 NVMe SSD 上（Engram 论文第 2.5 节）。

论文的吞吐实验把一个 100B 参数的 Engram 层插在第二个块、整张表放在主机内存，用第一个块的计算掩盖传输；在 H800 上，吞吐损失在 8B 骨干上最高为 2.8%（Engram 论文第 6.4 节）。论文强调这是保守的基线：实验强制所有查表都走 PCIe，没有用频率分层缓存（Engram 论文第 6.4 节）。

### 7.2 训练：按行切分与全互连

训练时把大表按模型并行切到各卡上，前向用全互连通信收集被激活的行，反向把梯度发回，总记忆容量随加速器数线性扩展（Engram 论文第 2.5 节）。V4.1-Flash 报告给出了生产实现：表按行划分到专门的 Engram 并行进程组，组大小权衡单卡显存与查表通信范围；由于查表下标只取决于输入序列，每个训练步在流水线阶段处理微批之前就为整个本地批次发起预取；梯度在反向时缓冲，骨干反向结束后再送回所属的卡（V4.1-Flash 报告第 3.1.3 节）。

### 7.3 通信库：DeepEP 的 EngramBuffer

DeepEP 仓库的说明（[deepseek-ai/DeepEP](https://github.com/deepseek-ai/DeepEP)）称其为 Engram 提供实验性的远程内存访问原语：EngramBuffer 支持 GPU 与 CPU 存储和经 RDMA 的多层取回（DeepEP 仓库 README）。DeepEP 整体的通信设计见 [[NVSHMEM与DeepEP通信]]；本篇只记录查表稀疏在通信库里有了专门的缓冲接口，不展开专家并行通信。仓库说明是活页，没有可核实的发布日期，本篇不把它作为时间节点。

### 7.4 表的优化器

查表参数每步只有少数行被更新，三份来源对它的优化器各有处理：

| 来源 | 表的优化器 | 其他相关设置 |
|---|---|---|
| Engram 论文 | Adam，学习率放大 5 倍，不用权重衰减 | 卷积参数零初始化 |
| Qwen3.8-Next 报告 | Adam，关闭权重衰减 | n-gram 层的键值投影用 Muon |
| V4.1-Flash 报告 | 动量更新后接 Sinkhorn 平衡，替代 Adam 以省下优化器状态显存 | Engram 学习率放大 5 倍；投影层用 Muon |

出处：Engram 论文第 4.1 节；Qwen3.8-Next 报告第 3.1 节；V4.1-Flash 报告第 2.5 节与第 4.2.2 节。

更广的软硬件共同设计视角见 [[硬件软件协同部署]]；本篇的「表放主机内存、按确定地址提前取回」是那篇所述思路在查表稀疏上的一个具体实例。

## 八、2026 年的改进方向

本节各篇的实验规模都远小于第九节的工业模型，这里只写思路，不把它们的数字与工业模型并列。

- **哈希冲突是不是瓶颈**：Lin 等用最小完美哈希为最高频的 n-gram 建一层无冲突的热表，其余仍走原多头哈希；在严格同参数下，无冲突设计并不稳定地改善验证损失。论文观察到训练中高频位置先领先、后被低频位置反超，而无冲突配置反超得更早，因此认为冲突起了隐式正则的作用；论文还指出门控在反超后仍偏向高频位置，主要限制可能在门控的功劳分配而非下标精度（Lin 等摘要）。
- **分解与共享**：TN-gram 指出 Over-Tokenized Transformer 与 Engram 都为每个阶单独建哈希表，既带来冲突，也让嵌套的 n-gram 无法共享结构；它用 CP 形式的共享因子表示各阶 n-gram 嵌入，论文称以少得多的参数达到或超过 Engram 式模块（TN-gram 摘要）。FactorEngram 指出 Engram 把每个取回的嵌入当作整体、只用一个标量门调节，参数只通过与语义无关的哈希冲突共享；它改为在共享的基向量字典上取回稀疏系数，并用同一字典逐基做上下文门控（FactorEngram 摘要）。
- **摆脱分词器**：Lim 等指出 Engram 依赖 token 级 n-gram 哈希，换分词器就得从头训练嵌入；它把异或哈希换成字节级多项式哈希、各阶共用嵌入空间，使字节相同的 token 序列哈希相同，论文称性能相当（Lim 等摘要）。Lngram 走得更远：从隐状态学离散符号，在符号序列上做 n-gram 查表，去掉对分词器 ID 的依赖，并可扩展到非文本模态（Lngram 摘要）；Lngram v2 把路由数、记忆维度与骨干宽度解耦，以便独立扩大记忆容量（Lngram v2 摘要）。

## 九、工业采用

### 9.1 DeepSeek-V4.1-Flash

V4.1-Flash 有 552B 骨干参数与 196B Engram 参数（V4.1-Flash 报告第 2.1 节）。报告称沿用 Engram 的原设计（分词器压缩、多头哈希、上下文门控、多分支接入），改动两处：去掉短卷积，因为其收益抵不上推理栈中增加的复杂度；表改用动量更新加 Sinkhorn 平衡（V4.1-Flash 报告第 2.4.2 节）。

配置上，196B Engram 参数均分在两个模块，每个模块用 {2,3,4} 三个 n-gram 阶、8 个哈希头，每阶总嵌入维度 2048；每个头索引一张约 16M 项的表，表大小取互不相同的素数；嵌入表与键值投影都用 FP8；两个模块放在第 1 层与第 14 层（从零计数），以平衡各流水线阶段的显存；推理时经后台 RDMA 从主机内存预取，第一个模块的预取与第一个块的计算重叠（V4.1-Flash 报告第 2.4.2 节）。RL 采样期间，Engram 表常驻 GPU 显存（V4.1-Flash 报告第 3.1.3 节）。该模型其余架构见 [[DeepSeekV41Flash深读]]。

### 9.2 Qwen3.8-Next

报告摘要称 Qwen3.8-Flash-Next 为 125B 参数、每 token 激活 6B 的稀疏 MoE，另有 51B 参数的 n-gram 嵌入表放在加速器之外（Qwen3.8-Next 报告摘要）。n-gram 部分用多头哈希查表，经 Engram 式的上下文门控注入残差流（Qwen3.8-Next 报告第 2.3 节）。消融显示没有哪个深度始终占优，多层分布同样预算也没有稳定收益，单层即可；最终放在第 2 层，使主机内存预取与第 1 层计算重叠（Qwen3.8-Next 报告第 2.3.1 节）。报告还尝试了 Engram 式的 token 归一化压缩词表、各阶非均匀分配、按频率划分槽位等提效手段，在其训练配方中都没有看到一致的收益（Qwen3.8-Next 报告第 2.3.2 节）。该模型其余架构见 [[Qwen38Next架构深读]]。

### 9.3 LongCat-Flash-Lite

LongCat-Flash-Lite 总参 68.5B、激活约 3B，其中超过 30B 参数分给嵌入，论文称它超过了参数量相当的 MoE 基线（Liu 等摘要）。正文给出的激活参数随上下文为 2.9B 到 4.5B（Liu 等第 1 节）。论文为推理侧设计了仿照 KV cache 的 N-gram Cache，用定制 CUDA 核在设备上管理 n-gram ID（Liu 等第 4.2 节）。

### 9.4 从三家实现看共同点与未公开之处

- 三家都利用确定性寻址做预取或缓存；V4.1-Flash 与 Qwen3.8-Next 明确写了主机内存预取与前面层计算的重叠，LongCat-Flash-Lite 则在设备上缓存 n-gram ID。
- V4.1-Flash 公开了阶数、哈希头数、表大小与精度；Qwen3.8-Next 报告第 2.3 节没有给出 n-gram 阶数与哈希头数，51B 参数也没有按阶或按头拆分。
- 三家的表都绑定各自的分词器 ID；Engram 的分词器压缩还依赖文本归一化规则。换分词器即需重训表，这正是第八节 Lim 等与 Lngram 想解决的问题。

## 十、意义

1. **稀疏不止一种**：MoE 把「算什么」稀疏化，条件记忆把「记什么」稀疏化。Engram 论文把后者表述为与前者互补的一条轴，并用 U 形分配律把两者放进同一个预算问题里。
2. **地址提前已知是系统红利**：地址只取决于输入，表可以离开 HBM，参数规模的上限从加速器显存转到主机内存，这是专家并行做不到的。
3. **损失与下游之间的落差**：三份来源都看到损失上的分配甜点，但 Qwen3.8-Next 报告在下游上没有看到同样的收益。查表记忆究竟主要帮了哪些能力，仍是开放问题。
4. **门控是关键部件**：Engram 论文的消融与 Lin 等的分析都把注意力引向门控，说明问题可能不在「查得准不准」，而在「取回的内容何时该用」。

## 十一、局限与待核实

1. **单篇结论**：U 形分配律、等效加深与长上下文收益都只来自 Engram 论文自身，尚无独立复现；Liu 等与 Qwen3.8-Next 报告只在损失甜点上与其一致。
2. **Engram 论文内部数字不一致**：MMLU 的增量在摘要与引言写 +3.4，第 4.2 节正文写 +3.0，表 1 中 MoE-27B 与 Engram-27B 的 MMLU 为 57.4 与 60.4；本篇不引 MMLU 增量。
3. **作者与机构**：Engram 论文只写「Cheng 等」与官方仓库，作者机构未核实。V4.1-Flash 报告把 Engram 称作「我们之前的工作」，但本篇不据此推断机构。
4. **版本**：Engram 论文当前为 v2，本篇按 v2 引用；v1 的表述与数字可能不同，未逐项对照。
5. **未公开的配置**：Qwen3.8-Next 的 n-gram 阶数、哈希头数与 51B 的拆分未见公开；LongCat-Flash-Lite 的 n-gram 阶数与子表数未在本篇核对。
6. **DeepEP EngramBuffer**：只见于仓库说明；README 是活页，内容可能随项目变化，没有可核实的发布日期，不计入截至，也不作时间节点；它与 V4.1-Flash 生产实现的对应关系未核实。
7. **2026 年改进论文**：Lin 等、TN-gram、Lim 等、Lngram、FactorEngram 的实验规模都远小于工业模型，本篇只引摘要中的思路，是否能在大规模上成立未知。
