# MoE / 稀疏激活：从 Switch 到当代大规模 MoE

## 一、稀疏激活动机：总参 vs 激活参

稠密 Transformer 对每个 token 复用同一套参数；算力与参数量大体同向增长。Mixture-of-Experts（MoE）改成「按输入选择不同参数子集」：模型可以有**很大的总参数量（capacity）**，但每个 token 只走少数专家，因而**每 token 的激活参数量与 FLOPs 可近似保持常数**。

这一分离直接改写了缩放叙事：

- **总参**：决定可存储的容量与知识广度，常随专家数近似线性增加。
- **激活参 / 每 token FLOPs**：决定训练与推理的算力与延迟预算；路由只激活一部分专家时，这部分可远小于总参。

Switch Transformers（Fedus et al., 2021/2022）把这一思路说得很清楚：在固定每 token FLOPs 的前提下，增加专家数仍能改善预训练困惑度，并相对 T5 基线给出显著的步数/墙钟加速。Mixtral 与 DeepSeek-V3 的公开叙事同样建立在「总参大、激活参可控」之上——例如 Mixtral 官方给出约 46.7B 总参、约 12.9B 每 token 激活参；DeepSeek-V3 技术报告给出 671B 总参、每 token 激活 37B。

跟读提示：读论文或产品文案时，先问两句——「总参是多少？」「每个 token 实际激活多少？」二者差得越大，稀疏收益叙事越强，但也越依赖路由、通信与负载均衡是否真正落地。

## 二、架构思想：Switch → Mixtral → DeepSeek-V3

### 2.1 Switch Transformers：把 MoE 简化到可训、可扩展

**位置**：用稀疏 Switch FFN 替换 Transformer 中的稠密 FFN（通常每隔一层或按设定频率插入），注意力侧仍多为稠密计算。

**路由（Switch routing）**：经典 MoE（如 Shazeer et al., 2017）常用 top-$k$（$k>1$）。Switch 简化为 **$k=1$**：路由器对专家做 softmax，token 只送往概率最高的一个专家；输出再乘以该门控值以保证可微。公开宣称的好处包括：路由计算更轻、专家容量可更低、实现与通信更简单。

**专家容量与丢弃**：在 TPU 等需要静态形状的设定下，每个专家有固定容量

$$
\text{expert capacity} = \left(\frac{\text{tokens per batch}}{\text{number of experts}}\right) \times \text{capacity factor}.
$$

容量因子 $>1$ 留缓冲；若某专家溢出，溢出 token 可经残差旁路不经该层专家计算（dropped tokens）。容量因子过大则空槽浪费算力与通信。

**负载均衡损失（思想）**：鼓励批次内各专家接收大致均匀的 token。Switch 采用可微辅助损失（与早期分离的 load / importance 设计相比有所简化），形式为 $\alpha \cdot N \sum_i f_i P_i$，其中 $f_i$ 是实际被路由到专家 $i$ 的 token 比例，$P_i$ 是路由器概率质量分配到专家 $i$ 的比例；文中常用 $\alpha=10^{-2}$。均匀路由时该项被压低。

**训练稳定性技巧（公开要点）**：路由局部用 float32 的 **selective precision**；减小初始化尺度；微调时对专家层加大 dropout（expert dropout）。规模上，文中报告了结合数据/模型/专家并行、可达千亿至约万亿参量级的 Switch 变体，并相对 FLOPs 对齐的 T5 给出预训练加速（文中有「约 7×」等量级的对比表述，具体配置见表与图）。

**跟读抓手**：Switch 的「主线贡献」不是发明 MoE，而是证明 **top-1 + 容量因子 + 辅助均衡损失 + 训练技巧** 可以把稀疏模型训稳，并把「参数轴」从 FLOPs 轴中拆出来。

### 2.2 Mixtral：开源叙事把稀疏 MoE 推到可下载、可部署

来源以 Mistral 官方博文为主（2023-12-11）；更细的论文为 arXiv:2401.04088（本笔记未强制归档其 PDF）。

公开要点（已核实）：

- **结构**：decoder-only；每层 FFN 侧有 **8 组专家参数**；对每个 token，路由器选 **2 个专家**，输出相加合并（sparse MoE / SMoE）。
- **总参 vs 激活参（官方数字）**：**46.7B 总参数**，**每 token 仅使用 12.9B 参数**；因此推理成本被叙述为「接近 12.9B 稠密模型」。
- **能力叙事**：32k 上下文；英/法/意/德/西；代码生成较强；Instruct 版经 SFT + DPO，MT-Bench **8.3**。
- **对比叙事**：多数基准上优于或匹敌 Llama 2 70B，推理约 **6× 更快**；相对 GPT-3.5 多数基准持平或更好；Apache 2.0 开放权重。
- **生态**：向 vLLM 等提交集成（含 Megablocks 等高效推理内核相关改动），强调「可实际跑起来」的开源栈。

相对 Switch 的思想跳跃：路由从 top-1 回到 **top-2**（更接近经典 MoE 的多专家组合），并把叙事重心从「超算上的万亿参预训练」转到「社区可下载的高质量开源权重 + 成本/性能权衡」。名称「8x7B」容易被误读成「八个 7B 相加 = 56B」——官方总参是 46.7B，因为注意力、嵌入等共享骨干不按专家数倍增。

### 2.3 DeepSeek-V3：细粒度 MoE + 推理相关结构，接上当代

来源：DeepSeek-V3 Technical Report（arXiv:2412.19437）。公开规模：**671B 总参，每 token 激活 37B**；预训练约 **14.8T** token；全流程约 **2.788M H800 GPU hours**（报告给出分阶段数字）。

**DeepSeekMoE（相对「传统粗粒度 MoE」）**：

- 除前几层外，FFN 换为 MoE；每层含 **1 个共享专家 + 256 个路由专家**；每个专家中间维 **2048**。
- 每个 token **激活 8 个路由专家**（共享专家始终参与）；亲和度用 **sigmoid**，再对选中专家做归一化得到门控。
- **Node-limited routing**：每个 token 最多发往 **$M=4$** 个节点，以限制跨节点通信。
- 报告称因均衡策略有效，**训练与推理均不丢弃 token（no token-dropping）**。

**负载均衡：auxiliary-loss-free（当代关键创新点）**：

- 为每个专家维护偏置 $b_i$，用 $s_{i,t}+b_i$ 做 top-$K$ 选专家；真正乘到专家输出上的门控仍来自原始亲和度 $s_{i,t}$。
- 按训练步监测整批负载：过载则减小 $b_i$，欠载则增大（步长 $\gamma$）。
- 另保留极小系数的 **序列级** 互补均衡损失，避免单条序列内极端不均（报告中 $\alpha=0.0001$ 量级）。
- 动机：过大的辅助损失会伤主任务；无辅助损失主路径旨在减少「为均衡而牺牲质量」。

**MLA（Multi-head Latent Attention）与推理**：

- 对 KV（及 query）做低秩联合压缩；推理时主要缓存压缩后的潜向量与解耦的 RoPE key，从而 **显著减小 KV cache**，同时力图保持接近标准 MHA 的效果。
- 这与 MoE 正交但同属「当代可服务化大模型」：MoE 管 FFN 容量/算力，MLA 管长上下文下的记忆与带宽。

**MTP（Multi-Token Prediction）**：

- 训练时额外预测后续 token（报告配置深度 $D=1$ 等）；可稠密化训练信号，并可用于推测解码加速；推理时可丢弃 MTP 模块，主模型独立运行。

**如何「接上当代」**：Switch 证明稀疏可扩展；Mixtral 证明开源 top-2 MoE 可赢稠密大模型的成本曲线；DeepSeek-V3 则把 **更细专家粒度、共享专家、无辅助损失主均衡、跨节点通信约束、FP8/通信重叠基础设施，以及 MLA 推理结构** 组合成「总参极大、激活受控、可训可服」的当代模板。读当代 MoE 时，应同时看路由算法与 **通信拓扑约束**，而不是只数专家个数。

## 三、AI Infra 辅线：专家并行、通信与负载失衡

### 3.1 专家并行（Expert Parallelism, EP）

稀疏层的专家权重通常切分到不同设备：同一批次的不同 token 经 all-to-all（或等价 collective）送到持有目标专家的设备，计算后再 combine 回来。Switch 文中在 Mesh TensorFlow 语境下描述了专家与数据并行的组合；DeepSeek-V3 报告训练侧使用例如 **64-way EP（跨 8 节点）**、Pipeline Parallel、ZeRO-1 数据并行等组合，并强调可在无昂贵 Tensor Parallel 的情况下撑起训练内存。

### 3.2 通信为何成为瓶颈

- MoE 的额外成本不只在「多算一点路由」，而在 **跨设备搬运激活**：dispatch / combine 的带宽与延迟随专家数、节点数、top-$k$、序列长度上升。
- DeepSeek-V3 写明：跨节点 EP 曾使计算:通信比恶化到约 **1:1**；其 DualPipe 等设计试图用计算-通信重叠把 all-to-all 与流水线通信藏进计算气泡，并定制跨节点内核以同时吃满 IB 与 NVLink。
- **Node-limited / device-limited routing** 本质是用路由约束换通信可重叠性：每个 token 不可任意打到全集群任意专家。

### 3.3 负载失衡为何同时伤质量与吞吐

- **质量**：路由塌缩（少数专家吃掉几乎全部 token）浪费容量，等价于「名义总参很大、有效专家很少」。
- **吞吐**：静态容量下，热专家溢出 → token drop 或排队；冷专家空转 → SM/带宽浪费。推理侧 DeepSeek-V3 还讨论冗余专家、周期性根据在线统计调整部署等，以维持服务 SLO。
- Switch 用辅助损失 + 容量因子；DeepSeek-V3 转向 **偏置动态调节为主、极弱序列损失为辅**，并宣称可做到不丢 token——这是同一 Infra 问题在算法上的不同解。

跟读提示：谈「MoE 更省」时，省的是 **激活 FLOPs**；账单上还要加上 **路由、all-to-all、负载不均造成的气泡与空槽**。Pareto 优势只在系统把这三项压住之后才成立。

## 四、常见误区

1. **把总参当成激活参**
 例如把 Mixtral「8x7B」读成 56B 激活，或把 DeepSeek-V3 的 671B 当成每 token 都算一遍。正确对比推理成本应对齐 **激活参 / 每 token FLOPs**。

2. **以为专家越多一定越好**
 Switch 已指出专家数存在收益递减；且专家增多往往加剧路由难度、通信与均衡压力。当代系统常用「更细更多专家 + 限制每 token 触及的节点/设备数」来换组合多样性，而不是无约束地堆专家。

3. **把 Switch 的 top-1 当成唯一正统**
 Mixtral 用 top-2；DeepSeek-V3 激活 8 个路由专家加共享专家。$k$ 是质量、算力、梯度与通信的折中，不是教条。

4. **忽略容量因子与 token drop**
 论文数字很好看时，若训练大量 drop，有效计算与声称 FLOPs 不对齐。DeepSeek-V3 强调 no token-dropping，本身说明这是关键工程指标。

5. **只谈架构、不谈通信与精度**
 大规模 MoE 的可行性常取决于 EP 拓扑、重叠调度、以及路由/门控等对低精度敏感模块的处理（Switch 的 selective float32；DeepSeek-V3 的 FP8 混合精度与门控保持高精度等）。

6. **误读「稀疏」为注意力稀疏**
 本议题的稀疏主要指 **权重/专家激活稀疏**（FFN 侧条件计算），与 Longformer 等 **注意力模式稀疏** 互补但不是同一件事。

7. **开源叙事中的基准与许可**
 Mixtral 博文中的「最强 / 优于 GPT-3.5」等表述是当时官方宣传口径，复现时应回到具体基准表与评测设定；许可（Apache 2.0）与权重可用性是工程选型的另一轴，不宜与质量分数混为一谈。
