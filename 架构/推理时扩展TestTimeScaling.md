# 推理时计算 / test-time scaling / 链式推理前沿

> **主要来源**：[Learning to reason with LLMs](https://openai.com/index/learning-to-reason-with-llms/)（OpenAI，2024-09-12）；[Introducing OpenAI o1-preview](https://openai.com/index/introducing-openai-o1-preview/)（OpenAI，2024-09-12）；[OpenAI o1-mini](https://openai.com/index/openai-o1-mini-advancing-cost-efficient-reasoning/)（OpenAI，2024-09-12）；[OpenAI o1 System Card](https://arxiv.org/abs/2412.16720)（v2）；[DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning](https://arxiv.org/abs/2501.12948)（v2）（截至 2026-04-30）。
> **研究线**：架构思想（训练期 RL + 长思维链 + 推理期算力，主）· 数学原理（推理算力与准确率的权衡，辅）· AI Infra（思考 token 的成本与延迟，辅）
> **范围与相邻笔记**：
> - ≠ [[DeepSeekR1推理训练深读]]：本篇不写 R1 各阶段的数据、超参与消融，只取它对推理时扩展的论证。
> - ≠ [[GRPO与DAPO算法族]]：本篇不写 RL 目标函数及其变体。
> - ≠ [[推理时树搜索ABMCTS]]、[[自适应测试时算力]]：本篇不写具体的外层搜索与按难度分配预算的方法，那些是本篇主线下的方法切片。
>
> **意义**：o1 与 R1 把「推理期多花算力换准确率」从提示技巧变成训练目标和产品形态，让扩展从只看预训练规模变成训练期、推理期两条轴；这也改变了成本结构、产品分层与安全监控的对象。

**一句话**：同一模型在推理期生成更长的思维链、或对多个候选投票与重排，准确率可以继续平滑上升；o1 公开了这条轴，DeepSeek-R1 用可复述的配方说明它主要来自「难题 + 可靠验证 + 大规模 RL」，并可蒸馏到小模型。

## 一、问题背景

2020–2023 年的主叙事是训练时扩展：更大参数、更多 token、更多预训练算力（Kaplan、Chinchilla 等，见 [[规模定律与预训练范式]]）。模型训完后单次前向的能力大致固定，想再涨分主要靠更大的预训练或更多对齐数据。

2024 年 9 月 OpenAI 发布 o1-preview，并公布了开发中的 o1 的评测；原文称 o1 的表现「随更多强化学习（训练期算力）和更多思考时间（推理期算力）持续提升」，并且这种扩展的约束「与预训练明显不同」（*Learning to reason*）。此后「多想一会儿」成为主叙事，原因大致有三：预训练的边际收益变贵；竞赛数学、编程这类可验证任务正好能用结果奖励训出长思维；思考深度天然可以做成延迟、成本与质量之间的产品旋钮。

## 三、核心机制

### 3.1 共同骨架

o1 公开叙述与 R1 论文收敛到同一结构：预训练底座 → 大规模强化学习鼓励「先想后答」 → 推理时生成可含自我纠正、换策略、验证的长思维链 → 可选的多采样、共识或打分重排。o1 System Card（§1–2）称 o1 系列用大规模强化学习训练、会在回答前生成长思维链，并在上下文中推理安全规范（deliberative alignment）。

### 3.2 o1：公开了什么、没公开什么

公开的：训练范式是大规模 RL + 思维链；原始思维链对用户隐藏，产品展示模型生成的摘要，理由包括监控潜力、用户体验与竞争因素，且不宜把合规要求训进原始思维链，以免破坏可监控性（*Learning to reason*「Hiding the Chains of Thought」；System Card §4.3.2）；评测默认用最大推理算力设定。

未公开的：具体 RL 算法、奖励模型结构、训练算力；底座与架构细节；原始思维链是否忠实反映内部计算（System Card 称这仍是开放问题）。

### 3.3 DeepSeek-R1：可复述的配方

- **R1-Zero**（§2）：在 DeepSeek-V3-Base 上跳过 SFT 直接做 GRPO（组内相对优势，不训价值模型）；奖励只用规则化的准确率与格式，明确不用神经奖励模型，以防大规模 RL 中的 reward hacking。AIME 2024 pass@1 从 15.6% 升到 77.9%，自洽解码可达 86.7%；训练中平均回复长度持续上升，并出现反思、换路的「aha moment」。代价是可读性差、语言混杂。
- **R1**（§3）：冷启动 SFT（可读的长思维链）→ 加语言一致性奖励的 RL → 拒绝采样得到约 800k 条 SFT 数据（约 600k 推理、200k 非推理）→ 结合规则奖励与模型奖励的第二阶段 RL。最终 AIME 2024 pass@1 79.8%、MATH-500 97.3%、Codeforces 2029 分（96.3 百分位）。
- **蒸馏**：用约 800k 条轨迹对 Qwen、Llama 系小模型做 SFT，长思维链能力不必每家从零跑大规模 RL。

## 四、评测直觉：推理算力与准确率

AIME 2024 是最清楚的公开权衡链（*Learning to reason*）：GPT-4o 平均 12%；o1 单样本 74%，64 样本共识 83%，对 1000 个样本用学习到的打分函数重排 93%。每向右一步，都是用更多推理算力或更强的选择器换准确率。IOI 上的选择策略同理：按公开测例、模型生成测例和打分函数挑 50 份提交得 213 分，随机提交约 156 分。发布页另称，在 IMO 资格考中 GPT-4o 只解出 13% 的题，开发中的推理模型（o1）为 83%（*Introducing OpenAI o1-preview*）。

R1 论文（附录 E）给出另一面：
- 2024 年竞赛数学题上，R1 平均用 8,793 个思考 token 达到 61.8% Pass@1，难题想得多、易题想得少；GPT-4o 只输出平均 711 个 token，解题率 24.7%。
- 对非推理模型做多数投票补不上差距：AIME 2024 上 GPT-4o 的 64 票多数投票只从 9.3% 升到 13.4%，远低于 R1 的 79.8% 和 o1 的 79.2%。独立采样不会像长思维链那样在一条轨迹内回退和自纠。
- 两者可以叠加：R1 的 Pass@64 为 90.0%，高于 Pass@1 的 79.8%，多数投票、MCTS 这类传统推理时方法仍可补充长思维链。

可以把一次请求的推理算力粗记为「思维链长度 × 候选数 × 验证成本」（非论文公式）。公开结果共同暗示：在可验证域，先把思维链长度训厚、再适度加候选数，往往比「短答案 × 大量独立投票」更省 token。跨论文数字不能直接横比，除非对齐采样数、温度、工具与是否隐藏思维链。

## 五、成本、产品与安全

- **成本结构**：推理模型多出一类思考 token，占用上下文、通常按输出单价计费，API 不一定返回原文。贵的往往是中间的几万个思考 token，延迟也从秒级变成数秒到数分钟。
- **产品旋钮**：选模型、调 effort 或最大 token 数、按问题路由到快模型或推理模型；思考深度成为显式的服务等级。o1-mini 是同期推出的低价推理型号，官方称其 API 价格比 o1-preview 低 80%（*OpenAI o1-mini* 发布页）。最大输出设得太小，可能在写出可见答案前就因思考耗尽而中断。
- **服务侧**：KV 缓存随思维链变长线性增长，吞吐与尾延迟成为新瓶颈；R1 的路线则是把大模型 RL 得到的能力蒸馏回小模型权重。R1 附录给出训练成本约 147K H800 GPU 小时（按每小时 2 美元约 29.4 万美元）。
- **安全**：o1 System Card 称推理与推理期算力带来能力跃迁，CBRN 与说服维持 Medium 评级并加强缓解；监控对象从最终答案扩展到思维链摘要与行为模式（§4.3、§5.3）。

## 六、意义

推理时扩展让「模型能力」不再只由预训练规模决定：同一模型可以按请求花不同的算力，训练目标也从模仿答案变成学会怎样想。它引出了一串后续方向——RL 算法（GRPO 及其变体）、过程奖励与验证器、外层搜索、按难度分配预算、潜空间推理——也让成本模型、产品分层和思维链监控成为架构层面的问题。

## 七、局限与待核实

- o1 内部是否使用显式搜索、过程奖励模型或特定搜索宽度，未公开。
- 训练期与推理期算力的可兑换定量关系，OpenAI 只有定性图，没有可引用的系数。
- 各厂商按思考深度计费的最新价格与是否对思考 token 打折，以官方定价页为准。
- R1 蒸馏小模型在数学、代码以外领域的泛化与安全对齐，论文未充分评估。
- o1 System Card 引 v2、R1 引 v2；两者 v2 与本篇所用数字一致（o1 v2 只改了贡献者名单）。
