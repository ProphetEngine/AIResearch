# 时间线 · 长上下文与注意力效率

> 本时间线梳理长上下文与注意力效率的关键转折。长上下文其实是两个问题：位置编码能否外推到更长的序列（能不能读），注意力的二次计算和随长度线性增长的 KV 缓存是否付得起（读不读得起）。各节点依次覆盖位置编码与分页显存、KV 头共享与低秩压缩、推理期检索与驱逐、可训练稀疏注意力、线性注意力与混合架构，最后是压缩带来的系统性盲点。这一主题的共用背景集中写在本页，专题笔记只写各自的方法增量。日期口径：论文取 arXiv 首版（v1）日期，官方发布按 UTC 日期，系统卡取封面日期。

## 一、能读多长，读不读得起（2019—2023）

注意力计算随序列长度平方增长，解码时 KV 缓存又随长度线性占用显存和带宽。这一阶段，位置编码、注意力头结构、算子与服务端显存管理各自给出了第一代解法。

- **2019-11** · MQA 让所有查询头共享一组 K/V，解码时的 KV 缓存和显存读写成倍减少，代价是质量略有下降（[arXiv:1911.02150](https://arxiv.org/abs/1911.02150)） · [[注意力效率族MQA到MLA]]
- **2020-06** · 「Transformers are RNNs」用核特征映射替代 softmax，借矩阵乘的结合律把注意力复杂度从二次降到线性，并揭示了它的循环形式，线性注意力路线由此开端（[arXiv:2006.16236](https://arxiv.org/abs/2006.16236)） · [[线性注意力与状态空间模型谱系]]
- **2021-04** · RoPE 用旋转矩阵把相对位置写进 Q 与 K 的点积，成为此后开放模型的主流位置编码，也是后来各种上下文扩展方法的共同起点（[arXiv:2104.09864](https://arxiv.org/abs/2104.09864)） · [[长上下文位置编码与系统侧]]
- **2022-05** · FlashAttention 按 GPU 存储层级分块计算精确注意力，结果不变，显存读写大幅减少，长序列的算子瓶颈得到缓解（[arXiv:2205.14135](https://arxiv.org/abs/2205.14135)） · [[AI基础设施总览]]
- **2022-09** · Snell 等人提出上下文蒸馏：教师带着长提示生成，学生不带提示学习复现，把上下文带来的行为写进参数。这是「不把内容放进上下文」的另一条路（[arXiv:2209.15189](https://arxiv.org/abs/2209.15189)） · [[上下文蒸馏]]
- **2023-05** · GQA 让每组查询头共享一组 K/V，在 MHA 与 MQA 之间折中，而且可以从 MHA 检查点少量续训得到，此后成为开放模型的默认配置（[arXiv:2305.13245](https://arxiv.org/abs/2305.13245)） · [[注意力效率族MQA到MLA]]
- **2023-08** · YaRN 对 RoPE 的不同频段分别插值，只需少量续训就能把上下文窗口扩展到原来的数倍（[arXiv:2309.00071](https://arxiv.org/abs/2309.00071)） · [[长上下文位置编码与系统侧]]
- **2023-09** · vLLM 的 PagedAttention 把 KV 缓存按块分页管理，消除显存碎片，服务端能同时容纳更多、更长的请求（[arXiv:2309.06180](https://arxiv.org/abs/2309.06180)） · [[长上下文位置编码与系统侧]]
- **2023-11** · Prompt Cache 把提示中可复用的模块预先算好注意力状态，长前缀不必每次重算（[arXiv:2311.04934](https://arxiv.org/abs/2311.04934)） · [[Prompt前缀缓存]]
- **2023-12** · SGLang 的 RadixAttention 用前缀树自动复用请求之间相同前缀的 KV，前缀缓存从此成为推理引擎的默认能力（[arXiv:2312.07104](https://arxiv.org/abs/2312.07104)） · [[Prompt前缀缓存]]
- **2023-12** · Mamba 让状态空间模型的参数随输入变化（选择性），用固定大小的状态做线性时间序列建模，成为注意力之外最主要的骨干候选（[arXiv:2312.00752](https://arxiv.org/abs/2312.00752)） · [[线性注意力与状态空间模型谱系]]

## 二、压缩 KV（2024）

上下文窗口进入 128K 到 1M 量级后，KV 缓存成了推理成本的主体。2024 年的工作分别从低比特量化、混合骨干、架构内低秩压缩、推理期检索和按头分工几个方向削减 KV。

- **2024-01** · KVQuant 与次月的 KIVI 发现 Key 适合按通道量化、Value 适合按 token 量化，KV 缓存可以压到 2—4 比特，精度损失可控（[arXiv:2401.18079](https://arxiv.org/abs/2401.18079)；[arXiv:2402.02750](https://arxiv.org/abs/2402.02750)） · [[KV缓存量化与压缩]]
- **2024-03** · Jamba 按 1:7 交错注意力层与 Mamba 层并加入 MoE，混合骨干在大规模模型上落地，支持 256K 上下文（[arXiv:2403.19887](https://arxiv.org/abs/2403.19887)） · [[混合Mamba与注意力架构设计菜谱]] · [[线性注意力与状态空间模型谱系]]
- **2024-05** · DeepSeek-V2 提出 MLA，把 K/V 压成低秩潜向量后再缓存，KV 显存远低于 GQA，原文称质量不降（[arXiv:2405.04434](https://arxiv.org/abs/2405.04434)） · [[注意力效率族MQA到MLA]]
- **2024-09** · RetrievalAttention 在解码时用向量检索只取与当前查询最相关的 KV，长上下文推理不必遍历全部 KV（[arXiv:2409.10516](https://arxiv.org/abs/2409.10516)） · [[检索式注意力]]
- **2024-10** · DuoAttention 发现只有少数「检索头」需要完整 KV，其余「流式头」只保留注意力汇点和近窗即可，KV 压缩开始按头分工（[arXiv:2410.10819](https://arxiv.org/abs/2410.10819)） · [[DuoAttention与KVzip]]

## 三、可训练稀疏、混合架构与压缩的盲点（2025—2026）

推理模型和智能体任务把上下文推到百万 token。研究重心从推理期近似转向把稀疏与压缩写进预训练，线性注意力与全注意力的混合进入旗舰，同时人们开始测量压缩带来的系统性盲点。

- **2025-02** · NSA 把压缩、选块、滑窗三路稀疏注意力写进预训练计算图，并按 GPU 内存访问方式设计内核。稀疏注意力从推理期近似变成可以端到端训练的原生结构（[arXiv:2502.11089](https://arxiv.org/abs/2502.11089)） · [[原生稀疏注意力NSA]]
- **2025-02** · InfiniRetri 利用模型自身的注意力分数按句检索并重填窗口，不依赖外部向量库就能处理超长输入（[arXiv:2502.12962](https://arxiv.org/abs/2502.12962)） · [[检索式注意力]]
- **2025-05** · KVzip 以「能否用缓存重构原文」作为驱逐准则，做与查询无关的 KV 压缩，压缩后的缓存可以在多次不同提问之间复用（[arXiv:2505.23416](https://arxiv.org/abs/2505.23416)） · [[DuoAttention与KVzip]]
- **2025-10** · Meta 等系统比较层间与层内两种混合方式，给出注意力与 Mamba 怎么混、比例与位置怎么定的设计建议；同月，Kimi Linear 以线性注意力与 MLA 按 3:1 混合，官方称首次在公平对比下超过全注意力（[arXiv:2510.04800](https://arxiv.org/abs/2510.04800)；[arXiv:2510.26692](https://arxiv.org/abs/2510.26692)） · [[混合Mamba与注意力架构设计菜谱]]
- **2025-12** · DeepSeek-V3.2 从 128K 的 V3.1-Terminus 继续训练，架构上唯一的改动是引入细粒度稀疏注意力 DSA，可训练稀疏注意力进入开放权重旗舰（[arXiv:2512.02556](https://arxiv.org/abs/2512.02556)） · [[DeepSeekV32技术报告深读]]
- **2026-02** · OPCD 与 DiSC 把同策略采样、反向 KL 等新目标用于上下文蒸馏，系统提示、经验知识和新文档可以持续写进参数，同时保住后训练能力（[arXiv:2602.12275](https://arxiv.org/abs/2602.12275)；[arXiv:2602.16093](https://arxiv.org/abs/2602.16093)） · [[上下文蒸馏]]
- **2026-04** · DeepSeek-V4 预览版混合 CSA（压缩后的稀疏注意力）与 HCA（更重压缩的稠密注意力），原生支持 1M 上下文，分块 KV 压缩成为旗舰架构的核心部件（[arXiv:2606.19348](https://arxiv.org/abs/2606.19348)） · [[DeepSeekV4技术报告深读]]
- **2026-06** · Nemotron 3 Ultra 以 Mamba 与注意力混合加 LatentMoE 做开放旗舰，并扩展到 1M 上下文，混合骨干在开放旗舰上落地（[arXiv:2606.15007](https://arxiv.org/abs/2606.15007)） · [[Nemotron3Ultra技术报告深读]]
- **2026-08** · Qwen3.8-Next 采用 Gated DeltaNet 与全局注意力混合，并在继续预训练阶段换用稀疏的 QSA 控制长文注意力开销，线性注意力混合成为主流厂商的世代架构（[arXiv:2608.30320](https://arxiv.org/abs/2608.30320)） · [[Qwen38Next架构深读]]
- **2026-09** · DeepSeek-V4.1-Flash 从 64K 起直接从零训练稀疏注意力、不做稠密预热，再扩到 1M，并把主 KV 压到 FP4，KV 压缩推到新的极限（[arXiv:2609.19969](https://arxiv.org/abs/2609.19969)） · [[DeepSeekV41Flash深读]]
- **2026-09** · Periodic Weak Spots 发现分块 KV 压缩会让检索准确率随 token 位置对块长取余的值（相位）周期起伏：DeepSeek-V4 base 在 128K 大海捞针测试中，不同相位最多相差 40.2 个百分点，而平均分看不出来。长上下文评测需要把相位纳入测量（[arXiv:2609.36322](https://arxiv.org/abs/2609.36322)） · [[分块KV压缩的相位敏感性]]
