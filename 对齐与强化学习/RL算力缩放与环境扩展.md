# RL算力缩放与环境扩展

> **主要来源**：[The Art of Scaling Reinforcement Learning Compute for LLMs](https://arxiv.org/abs/2510.13786)（简称 ScaleRL）；[RLVE: Scaling Up Reinforcement Learning for Language Models with Adaptive Verifiable Environments](https://arxiv.org/abs/2511.07317)；[Environment Scaling for Interactive Agentic Experience Collection: A Survey](https://arxiv.org/abs/2511.09586)（简称环境扩展综述）；[Generate, Filter, Control, Replay: A Comprehensive Survey of Rollout Strategies for LLM Reinforcement Learning](https://arxiv.org/abs/2605.02913)（简称 GFCR 综述）（截至 2026-10-08）。其余来源见第九节。
> **研究线**：架构思想（RL 后训练的算力与表现如何用一条可外推的曲线刻画，环境如何从固定数据集变成可批量生产、难度可调的训练对象）· AI Infra（异步 rollout、沙箱与环境服务在算力账中的位置）
> **范围与相邻笔记**：
> - ≠ [[GRPO与DAPO算法族]]：不推导策略梯度目标，只引用 ScaleRL 消融对各设计选择的结论。
> - ≠ [[AgenticRL景观与能力模块]]：不重画能力模块地图，本篇展开其中「环境与训练算力」一格。
> - ≠ [[ToolLoop工具数据合成]]：不写离线合成工具轨迹用于 SFT，只讨论在线 RL 需要的可交互、可验证环境。
> - ≠ [[规模定律与预训练范式]]：不写预训练的参数—数据—算力幂律，只拿它与 RL 的饱和曲线对照。
> **意义**：RL 后训练的算力已从预训练的零头涨到一成量级，ScaleRL 给出一套能从小规模外推的曲线语言，环境扩展回答「这些算力该花在什么任务上」；两者合起来，让 RL 从逐个配方试错走向可以事先做预算的规模工程。

**一句话**：RL 能否像预训练那样「加算力就涨」，取决于两件事。一是配方：它决定表现曲线的上限和爬升速度，而许多常见的工程细节只改速度、不改上限。二是环境：静态题集很快会被做穿或卡在太难的题上，只有能持续出题、难度随策略调整、可以自动判对错的环境，才能让曲线继续向右延伸。

## 一、问题背景：算力上来了，预测工具没跟上

1. **RL 算力的占比在上升**。DeepSeek-V3.2 称其 RL 预算已超过预训练成本的 10%（DeepSeek-V3.2 §1、§4.1，见 [[DeepSeekV32技术报告深读]]）；MiMo-V2.6-Pro 一次智能体 RL 的成本拆分为：rollout 43.8%、训练 43.5%、评分器 12.7%（MiMo-V2.6 §4.1，见 [[MiMoV26智能体强化学习短报]]）。算力一旦到这个量级，「先跑一次大的看看」就太贵了。
2. **缺少类似预训练的预测方法**。预训练有幂律，可以从小规模外推（见 [[规模定律与预训练范式]]）。ScaleRL 开篇指出，RL 领域缺乏可比的预测方法，也没有原则性的办法判断一项算法改进在加大算力后是否仍然有效（ScaleRL 摘要）。各家配方多以单次大跑报告结果，难以分辨谁的上限更高、谁只是起步更快。
3. **静态数据会让学习信号消失**。题目太容易，组内采样全对；太难，全错。两种情况下组相对优势都为零（这正是 [[GRPO与DAPO算法族]] 中动态采样要过滤的样本）。RLVE 把这一点作为动机：固定的数据分布随训练推进必然失配（RLVE 摘要）。BroRL 也指出，ProRL 式拉长训练步数在数千步后进入平台期（BroRL 摘要）。

## 三、RL 算力缩放：从单次大跑到可外推曲线

### 3.1 饱和曲线与三个参数

ScaleRL 用一条 sigmoid 型曲线拟合验证集通过率与训练算力的关系（ScaleRL §2.1）：

$$R_C - R_0 = \frac{A - R_0}{1 + (C_{\text{mid}}/C)^{B}}$$

- $A$ 是渐近通过率，即这套配方在无限算力下能到的上限；
- $B$ 是缩放指数，决定曲线有多陡，即算力效率；
- $C_{\text{mid}}$ 是收益达到一半时的算力。

为什么不用预训练式的幂律：通过率有上界，饱和形状更贴近实际；论文称在其设定下 sigmoid 拟合比幂律更稳健（ScaleRL §2.1、附录 A.4）。拟合在保留的同分布验证集上做：从训练题集中留出 1,000 道题，每 100 步测一次平均通过率（ScaleRL §2）。

外推是这条曲线的用处所在。论文称在 8B 稠密模型上用前 50k GPU 小时拟合，外推到 100k GPU 小时，后续实测点落在曲线上；Llama-4 Scout（17B×16 MoE）的 50k GPU 小时运行同样如此（ScaleRL 图 1）。整项研究耗用超过 40 万 GPU 小时（ScaleRL 摘要）。

### 3.2 上限与效率要分开看

论文的核心观察有两条（ScaleRL 摘要）：

1. **不同配方的上限并不相同**。把 DeepSeek（GRPO）、DAPO、Magistral、MiniMax-M1 等常用配方放在同一设定下拟合，$A$ 有明显差异（ScaleRL 图 2）。
2. **许多细节只改效率**。损失聚合方式、优势归一化、课程、离策略算法等选择，主要改变 $B$，几乎不移动 $A$。

推论很直接：在小算力下比较「谁涨得快」，可能选中一个起步快但上限低的配方。比较配方时应拟合整条曲线，分别报告 $A$ 和 $B$。

### 3.3 ScaleRL 配方

论文把消融中表现最好的选择合成一套配方（ScaleRL §3、§4），要点如下：

- **异步离策略**：采用 PipelineRL 式流水线，生成与训练并行，并限制最大离策程度；论文称它相对常见的离策设置主要提高效率 $B$，大算力下上限也略高（§3.1）。
- **损失**：采用 CISPO，即裁剪重要性采样权重而非裁剪更新（来源见 [[MiniMaxM1技术报告深读]]）；损失在 prompt 级平均，优势在 batch 级归一化。
- **数值精度**：语言模型头的 logits 用 FP32 计算，论文称这一项把 $A$ 从 0.52 提到 0.61（§3.2）。
- **数据侧**：过滤组内零方差的 prompt；通过率达到 0.9 及以上的题不再采样（No-Positive-Resampling）；对过长生成强制截断。
- **留一消融**：组合后逐项去掉一个选择，各跑 16,000 GPU 小时，论文称每一项的贡献都由此得到确认（§4）。

### 3.4 哪些轴值得加算力

ScaleRL §5 比较了几条加算力的路径（结论均为论文称）：

| 轴 | 现象 |
|---|---|
| 模型规模 | Scout MoE 的上限明显高于 8B 稠密模型，只用后者约 1/6 的 RL 算力就超过其表现 |
| 生成长度 | 从 14k 加到 32k token，早期更慢（$B$ 降、$C_{\text{mid}}$ 升），但上限更高 |
| batch 大小 | 更大的 batch 起步慢，上限更高，训练也更稳 |
| 每题生成数 | 固定总 batch 时在 8 到 32 之间调整，影响是次要的 |
| 多任务 | 数学与代码联合训练时，两个领域各自呈现平行的可预测趋势（初步结果） |

**宽度与长度**。ProRL 通过拉长训练步数扩展 RL，并称长训练能找到基座模型采样不到的推理策略（ProRL 摘要）。BroRL 则把每题 rollout 加到数百条，论文称能让 ProRL 训练 3K 步后饱和的模型恢复增长（BroRL 摘要）。注意口径：BroRL 增加的是总 rollout 量，ScaleRL 的「每题生成数影响次要」是在固定总 batch 下的分配问题，两者并不矛盾。

## 四、环境扩展：让曲线有地方延伸

### 4.1 生成—执行—反馈的分析框架

环境扩展综述把智能体与环境的交互拆成三段，每段有各自的扩展维度（环境扩展综述 §2 至 §4）：

| 阶段 | 扩展维度 | 含义 |
|---|---|---|
| 任务生成 | 复杂度、动态性、多样性 | 题目能否越来越难、随策略变化、覆盖更多类型 |
| 任务执行 | 交互性、真实度 | 环境是否支持多轮交互，与真实部署有多接近 |
| 反馈 | 密度、粒度、自动化、客观性、鲁棒性 | 奖励多久给一次、细到哪一步、是否需要人、能否被钻空子 |

综述附录 A.2 强调生成器与验证器的不对称：许多任务验证远比求解容易，这是可验证环境能够自动扩展的前提。

### 4.2 程序化可验证环境

- **Reasoning Gym** 提供百余个题目生成器与验证器，覆盖代数、逻辑、图论、游戏等领域，复杂度可调，能生成几乎无限的训练数据（Reasoning Gym 摘要）。
- **RLVE** 在程序化生成之上加入自适应难度：每个环境维护一个难度区间，策略在当前最高难度上的准确率达到阈值（论文设为 90%）后，难度上调一级（RLVE §2.2）。环境要么像排序那样可以直接比对答案，要么像数独那样利用「验证比求解容易」来判分。RLVE-Gym 收录 400 个人工设计的环境。论文称在 400 个环境上联合训练，从一个很强的 1.5B 推理模型出发，六个推理基准平均绝对提升 3.37%；继续原有 RL 训练、用三倍以上算力只提升 0.49%（RLVE 摘要、§5）。论文还称，环境数量越多，泛化提升越稳定（§4.2）。

这条线的价值在于把「数据」换成「数据生成器加难度调度」，正面回应第一节第 3 条的信号消失问题。

### 4.3 软件工程环境：从仓库到可执行沙箱

软件工程任务天然可验证（测试通过与否），难点在于为每个任务配好可运行的依赖环境。

- **SWE-Gym**：2,438 个真实 Python 实例，每个带可执行运行时与单元测试（SWE-Gym 摘要）。
- **R2E-Gym**：用 SYNGEN 从提交历史生成测试并反向翻译出问题描述，不依赖人写的 issue，得到 8.7K 以上的任务；论文称 32B 模型在 SWE-bench Verified 上达到 34.4%，结合执行式与非执行式验证器后达到 51%（R2E-Gym 摘要）。
- **SWE-smith**：对任意 Python 仓库先建执行环境，再自动合成让既有测试失败的任务，从 128 个仓库得到 5 万个实例；论文称据此训练的 32B 模型在 SWE-bench Verified 上达到 40.2%（SWE-smith 摘要）。
- **工业规模**：Qwen3-Coder-Next 以 SWE-smith 等开源集为基座注入 bug，要求「让既有测试失败且回退可修」才保留，得到约 80 万个可验证实例，覆盖 9 种以上语言（Qwen3-Coder-Next §2.1，见 [[Qwen3CoderNext技术报告深读]]）。可复现执行环境的 harness 设计见 [[代码智能体Harness史线]]。

### 4.4 工具与通用智能体环境

- **全模拟**：AgentScaler 自动构建全模拟的异构函数调用环境，先学通用智能体能力、再做领域专精，在 τ-bench、τ²-Bench 与 ACEBench 上评测（AgentScaler 摘要）。
- **真实加合成**：Kimi K2 汇集 3000 多个真实 MCP 工具与两万多个合成工具来合成智能体轨迹（用于 SFT）；RL 侧用统一的 Gym 式接口承载环境，长尾轨迹以 partial rollout 推迟到下一轮继续（见 [[KimiK2技术报告深读]]）。
- **合成后用 RL 自身筛选**：DeepSeek-V3.2 自动合成环境后，只保留 pass@100 大于 0 的任务，得到 1,827 个环境、4,417 个任务；消融显示只在合成的通用智能体任务上做 RL，也能提升 Tau2、MCP-Mark、MCP-Universe 等基准（DeepSeek-V3.2 §3.2.3、§4.3，见 [[DeepSeekV32技术报告深读]]）。
- **环境作为开源资产**：MiMo-V2.6 开源约 7k 个可验证环境（见 [[MiMoV26智能体强化学习短报]]）；Nemotron 3 Ultra 的报告称一并开源 RL 环境（含 NeMo Gym 等，见 [[Nemotron3Ultra技术报告深读]]）。
- **沙箱基础设施**：Kimi K3 的 AgentENV 基于 microVM，支持暂停、分叉与快照，报告称累计创建 51,219,741 个沙箱（见 [[KimiK3技术报告]]）；GLM-4.5 的 slime 框架把训练、rollout 与数据缓冲拆成独立模块，智能体任务在高并发 Docker 环境中运行（见 [[GLM45技术报告深读]]）。

解释器、搜索等工具接入 RL 环境的具体做法见 [[ToRL工具集成强化学习]]。

### 4.5 自提题与开放式环境

Absolute Zero 让同一个模型既出题又解题，用代码执行器同时校验题目是否合法、答案是否正确，论文称完全不用外部数据也在代码与数学推理上达到同类最优（Absolute Zero 摘要）。环境扩展综述把生成器与验证器协同进化、开放式多智能体环境列为未来方向（环境扩展综述 §6）。这条路把「环境扩展」推向极端：出题本身也交给模型。

## 五、rollout：算力花在哪些轨迹上

第一节的成本拆分显示，rollout 与训练几乎各占一半算力，因此「生成哪些轨迹、留下哪些」是缩放问题的另一面。GFCR 综述把 rollout 策略统一为四个模块，并以可靠性、覆盖度、成本三项标准评价（GFCR 综述 §3）：

| 模块 | 回答的问题 | 本篇已出现的例子 |
|---|---|---|
| 生成（§4） | 轨迹怎么产生：单条、组、树、多轮工具交互 | 组采样；多轮工具环境 |
| 过滤（§5） | 哪些轨迹能变成学习信号 | 零方差过滤；pass@100 筛选环境 |
| 控制（§6） | 在哪些题上、花多少、以多长、同策还是离策 | RLVE 难度调度；No-Positive-Resampling；PipelineRL 异步；Kimi K2 的 partial rollout |
| 回放（§7） | 旧轨迹与旧题如何复用，课程如何自演化 | Absolute Zero 的自提题课程 |

把各家配方放进这张表，能看出很多「新技巧」其实是同一模块里不同的旋钮。

## 七、意义

- **RL 可以做预算了**：先在小算力上拟合曲线，再决定一次大跑值不值，这是预训练早已习惯、RL 刚开始具备的能力。
- **评价配方换成两维**：上限 $A$ 与效率 $B$ 分开报告，能区分「真的更好」和「只是起步快」。
- **环境成为一等生产对象**：环境的数量、难度可调性与验证可靠性，开始像预训练语料一样被统计、筛选和开源；环境工程是 RL 时代的数据工程。

## 八、局限与待核实

1. **曲线的适用范围有限**：ScaleRL 的实验主要在数学（Polaris-53K）上做，多任务只有初步结果；拟合对象是同分布验证集的通过率，下游基准的趋势只在 AIME-24 等少数集合上展示。智能体长程任务、奖励来自评分模型的任务是否同样遵循饱和曲线，尚无同等规模的证据。
2. **曲线描述的是固定模型与数据**：公式成立的前提是模型与训练数据不变，换数据、换环境集合后要重新拟合；它不是跨模型规模、跨预训练算力的统一定律，论文也把这类定律列为下一步工作。
3. **环境数量不等于质量**：合成环境可能存在可被钻空子的验证器，这会带来奖励黑客，甚至泛化为更广的失对齐（见 [[奖励黑客与涌现失对齐]]）；模拟环境与真实部署之间有差距；RLVE 的环境是人工设计的，自动生成环境的质量控制仍靠 pass@k 一类的经验筛选。
4. **工业数字口径不一**：DeepSeek-V3.2 的「超过预训练成本 10%」未给分母；MiMo-V2.6 的成本拆分来自 Pro 版的单次运行；各家的「环境数」统计口径不同，不宜横向比较。
5. **未覆盖的方向**：奖励模型与评分器自身的缩放、多智能体自博弈环境、RL 训练框架的系统实现。
