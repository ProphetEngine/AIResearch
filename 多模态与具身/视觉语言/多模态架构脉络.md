## 一、为何多模态成为产品默认

产品侧的「默认多模态」不是某一篇论文突然宣布的，而是几条能力需求叠在同一接口上：

1. **用户输入不再只是纯文本。** 截图、文档页、UI、视频帧、代码仓库截图、手写公式——真实任务里视觉与语言天然交织。若模型只能吃文本，产品就要外挂 OCR / 检测 / 检索流水线，体验碎片化。
2. **输出侧需要语言生成，而不只是相似度打分。** CLIP 一类对比模型能做开放词表分类与检索，但摘要里明确：它解决的是「用自然语言引用视觉概念、做 zero-shot 迁移」。开放式问答、看图对话、按指令编辑描述，需要**条件语言生成**（Flamingo / LLaVA 路线）。
3. **助手形态要求「同一模型、同一对话接口」。** 与 Decoder-only LLM 产品化同构：用户用自然语言下指令，模型在同一会话里看见图 / 音 / 视频与文本。Gemini 2.5 博客把这一点写成产品主张：在「原生多模态 + 长上下文」之上再叠 thinking。
4. **数据与监督形态变了。** CLIP 证明互联网图文对可规模化；Flamingo 证明交错网页（M3W）可练 in-context few-shot；LLaVA 证明「视觉指令数据」可把聊天形态对齐到用户意图。产品默认多模态，实质是**默认同一条生成式接口承接多种模态输入**。

需要区分三种能力：**「能对齐语义」≠「能生成回答」≠「端到端原生训练」**。后文脉络正是沿这三条能力逐步补齐。

## 二、脉络：对比对齐（CLIP）→ 交叉注意力 / 感知器（Flamingo）→ 视觉指令微调叙事 → 原生多模态（Gemini 2.5 公开主张）

### 2.1 CLIP：对比对齐——双塔共享嵌入空间

**论文主张（摘要）：** 用「预测哪条 caption 配哪张图」这一简单预训练任务，在约 **4 亿**（image, text）对上从零学习 SOTA 级图像表示；预训练后用自然语言指称视觉概念，实现下游 **zero-shot** 迁移。在 ImageNet 上，zero-shot CLIP 可匹配原始 ResNet-50 精度，且**不使用**其 128 万条标注训练样本。

**架构思想（§2）：**

| 组件 | 做法 |
|------|------|
| 图像编码器 | ResNet（含 attention pooling）或 ViT |
| 文本编码器 | Transformer（BPE，最长 76 token；取 `[EOS]` 表示） |
| 目标 | 在 batch 内学多模态嵌入：最大化 $N$ 个真实配对的余弦相似度，最小化 $N^2-N$ 个错误配对；对称交叉熵（InfoNCE / multi-class N-pair 族） |
| 投影 | 各编码器表示经**线性投影**进入共享空间（论文称未采用当时自监督里流行的非线性 projection head） |
| 数据 | WIT（WebImageText），约 4 亿对；batch 极大（文中 32,768） |

**相对「预测完整 caption」的效率论点（§2.3，Figure 2）：** 直接做 caption 生成（类 VirTex）在 ImageNet zero-shot 上学习慢；换成 bag-of-words 预测再换成**对比目标**，效率再提升约 4×。直觉：不必拟合文本的每一个词，只需判断「整段文本是否配这张图」。

**产品接口含义：**

- 测试时：文本编码器把类别名 / 描述嵌成「零样本线性分类器权重」；图像编码器提特征，按余弦相似度分类。
- **能做：** 开放词表分类、检索、作为后续系统的视觉骨干。
- **不能直接做：** 开放式看图说话、多轮视觉对话（对比模型输出的是相似度，不是自回归 token）。

**要点：** CLIP 把监督从「固定 $K$ 类标签」换成「自然语言」；架构上是**双塔对齐**，不是统一自回归骨干。

### 2.2 Flamingo：冻结视觉 + 冻结 LM + Perceiver Resampler + gated cross-attention

**论文主张（摘要 / §1）：** Flamingo 是 Visual Language Model（VLM）族，强调**少样本快速适应**：只需在提示里放入少量图文示范，即可覆盖 caption、VQA、多选等。16 项任务上刷新 few-shot SOTA；其中 6 项在仅 32 条任务样本、不更新权重时超过大量标注上微调的 SOTA。

**三大架构创新（摘要明确列出）：**

1. **桥接强大的视觉-only 与语言-only 预训练模型**（冻结二者，插新层连接）；
2. **处理任意交错的视觉与文本序列**；
3. **无缝接受图像或视频**。

**模块拆解（§2，Figure 3–4）：**

1. **Vision Encoder（冻结）**
 - NFNet-F6；对比目标预训练（文中写采用 Radford et al. CLIP 式两项对比损失）。
 - 图像 → 2D 特征网格展平为 1D；视频按 1 FPS 逐帧编码，加时间嵌入后再展平。

2. **Perceiver Resampler（可训）**
 - 把可变长度、高分辨率的视觉特征压成**固定数量视觉 token**（文中为 **64**）。
 - 学一组 latent query，对视觉特征做 cross-attend（类 Perceiver / DETR）。
 - 作用：控制后续视觉–文本 cross-attention 的计算量，并统一图 / 视频接口。

3. **Gated xattn-dense（可训，插入冻结 LM）**
 - 在预训练 LM（Chinchilla 1.4B / 7B / 70B → Flamingo-3B / 9B / 80B）层间插入新的 cross-attention + dense。
 - K/V 来自视觉 token，Q 来自语言。
 - **$\tanh(\alpha)$ 门控**，$\alpha$ 初始化为 0：初始化时输出与原 LM 一致，稳定训练并减轻灾难性遗忘。
 - 消融（Table 3）：去掉 tanh gating、解冻 LM、去掉交错数据 M3W，整体得分明显下降。

4. **交错建模与注意力掩码（§2.3）**
 - 似然：$p(y\mid x)=\prod_\ell p(y_\ell\mid y_{<\ell}, x_{\le\ell})$。
 - 每个文本 token **只直接 cross-attend 到「紧邻其前」的那一张图 / 视频**的视觉 token；对更早图像的依赖经 LM 自注意力间接传递。
 - 训练时交错数据最多约 5 张图，评测时可扩到 32 shots——体现掩码设计带来的外推。

**数据混合（§2.4）：** M3W（约 4300 万网页的交错图文）+ ALIGN 类图文对 + LTIP + VTP 视频–句子对。消融强调：**去掉 M3W 对 few-shot 伤害最大**。

**相对 CLIP 的思想跃迁：**

| | CLIP | Flamingo |
|--|------|----------|
| 输出 | 相似度 / 嵌入 | **自回归文本** |
| 视觉–语言耦合 | 共享嵌入空间（双塔） | **LM 内 cross-attention** |
| 适应新任务 | 改类别文本 / 线性探针 | **In-context few-shot 提示** |
| 训练时 LM | 文本塔从零或独立训 | **大 LM 冻结**，防遗忘 |

Flamingo 自己也写明局限（§5）：分类上仍落后最强对比模型；in-context 对示范敏感、随 shot 数扩展成本高。这为下一段「指令微调」留下产品缺口。

### 2.3 视觉指令微调叙事（LLaVA 等）：把「助手对话」接到外挂视觉编码器上

**为何需要这一跳（公开叙事，非 Flamingo 原文）：**
Flamingo 证明了「冻结大 LM + 视觉条件」的 few-shot 生成力，但落地产品更常要的是：**多轮聊天、遵循用户意图、开源可复现配方**，而不是只靠精心构造的 in-context 示范。LLaVA（Liu et al., 2023）把 NLP 里的 instruction tuning 搬到视觉–语言，并自称「multimodal 领域的 GPT-3 时刻」叙事上承接 Flamingo。

**架构要点（LLaVA §4.1，据 arXiv 正文）：**

- 视觉：冻结 **CLIP ViT-L/14**；
- 连接：简单**线性投影** $H_v = W\cdot Z_v$，把视觉特征映到 LLM 词嵌入维；
- 语言：Vicuna；端到端在指令数据上更新投影 + LLM（视觉编码器仍冻结）；
- 两阶段：① 大量图文对上只训 $W$ 做特征对齐；② 在约 **158K** 视觉指令数据上微调对话能力。

作者明确对比：更复杂的连接可以是 Flamingo 的 gated cross-attention 或 BLIP-2 的 Q-Former；LLaVA 故意选轻量投影以快速做数据中心实验。

**数据思想：** 用 GPT-4（纯文本）根据 caption / box 等符号表示生成 conversation、详细描述、复杂推理三类指令数据——把「对齐好的图文对」改造成「用户指令 → 助手回答」。

**产品含义：**
开源多模态助手的主流工程模板一度是：

> **预训练视觉编码器（常 CLIP 系）+ 投影 / 少量适配器 + 指令微调后的 LLM**

这与 Flamingo「重 cross-attn、重交错预训练」不同，更接近「外挂视觉 tokenizer + 对话对齐」。宜把它定位为**脉络中的产品化中间态**，而不是唯一学术最优。

### 2.4 Gemini 2.5 公开主张：原生多模态 + 长上下文 + thinking

**来源边界：** 以下仅据 Google DeepMind 官方博客（2025-03-25；文内标注 last updated March 26），**不是**同行评审论文；不推断未公开的层数、融合算子或训练配方。

**博客明确写下的主张：**

1. **Gemini 2.5 是 thinking model**：回答前先「推理自己的想法」，以提升表现与准确性；建立在 2.0 Flash Thinking 等探索之上，并结合更强 base model 与改进的 post-training。
2. **继承 Gemini 系列长项：native multimodality（原生多模态）与 long context。**
 - 2.5 Pro：**100 万 token** 上下文（并称 200 万即将到来）；
 - 可理解来自文本、音频、图像、视频乃至**整个代码仓库**等不同信息源的复杂问题。
3. 评测叙事偏重推理 / 代码 / 人类偏好榜（LMArena #1 等），多模态细节以「原生 + 长上下文吃多源信息」为主，**未在该文展开**与 CLIP/Flamingo 同级的模块图。

**架构思想层面的「可读信息」：**
在公开产品叙事里，「原生多模态」被用来对照早期「LLM + 外挂视觉编码器 / 晚融合」印象——即视觉（及其他模态）不是事后插件，而是模型能力的一等公民，并与超长上下文一起服务智能体与多源理解。
**但：** 博客没有给出可复核的训练图或「从第几层融合」的定义；因此笔记中把它标为**公开主张 / 产品定位**，与 CLIP、Flamingo 的可证伪架构描述区分开。

### 2.6 2025–2026：原生多模态的几个库内节点

2.4 只依据博客；库内后续笔记能补上的节点如下。

- **Gemini 2.x / 3**：Gemini 2.5 技术报告（arXiv:2507.06261）确认 sparse MoE + native multimodal 的 text / vision / audio 输入，并给出视频每帧 66 / 258 token、causal 音频表示等专项，但仍没有 CLIP / Flamingo 级的模块图，是否保留独立视觉编码器未说明（[[Gemini25技术报告深读]]）；Gemini 3 Pro 模型卡沿用「稀疏 MoE + 原生多模态」口径（[[Gemini3Pro模型卡深读]]）。
- **开放权重原生多模态**：Llama 4（2025-04）以 early fusion 把文本与视觉 token 送入统一骨干，视觉编码器基于 MetaCLIP 思路并与冻结 Llama 联合适配（[[LLaMA开源生态里程碑]]、[[开源与闭源前沿模型谱系]]）。
- **理解与生成统一**：BAGEL 用 MoT 把理解专家与生成专家放进同一共享自注意力序列，在交错多模态数据上预训练，报告编辑、世界建模等能力随规模依次涌现（[[BAGEL统一多模态生成]]）。
- **全模态入、语音出**：Qwen3-Omni 到 Qwen3.5-Omni 用 Thinker–Talker 端到端统一文本、图像、音频、视频并流式合成语音（[[QwenOmni音视频原生]]）；Step-Audio 2 走音频入、音文交织 token 出的端到端语音路线（[[StepAudio2语音旗舰]]）；开源侧另有面向长视频音视联合理解的 AV-Flamingo（[[音视频联合Flamingo]]）。

这些节点的共同方向，是从「外挂编码器接到 LLM、只出文本」走向同一模型内多模态入、多模态出。但它们大多仍带编码器：Llama 4 的视觉编码器沿 MetaCLIP 思路，BAGEL 用 SigLIP2 + FLUX VAE 双编码器，Qwen3-Omni 用自训的 AuT 音频编码器。可见「原生」不等于取消编码器，3.2 的判别问题仍适用。

## 三、常见混淆：外挂视觉编码器 vs 端到端多模态

### 3.1 「外挂视觉编码器」通常指什么

工程上常指：

1. 有一个**独立预训练**的视觉骨干（CLIP / NFNet 对比模型 / SigLIP 等）；
2. 通过投影、Q-Former、Perceiver、cross-attn 等把视觉特征注入 LLM；
3. 训练时视觉骨干**冻结或很少更新**，主要学连接器与（可选）LLM。

**Flamingo、LLaVA 都属广义「外挂 / 桥接」家族**，差别在桥的复杂度与数据：

- Flamingo：重桥（Perceiver + 多层 gated xattn）+ 大规模交错预训练 + **推理时 few-shot**；
- LLaVA：轻桥（线性层）+ **指令微调**让对话形态对齐。

二者都**不是**「从像素到语言随机初始化端到端一把梭」；它们刻意复用单模态预训练，避免灾难性遗忘（Flamingo Table 3 行 viii 直接对比了解冻 LM 的掉点）。

### 3.2 「端到端 / 原生多模态」在公开话语里的多层含义（易混）

| 说法 | 常被用来指 | 注意 |
|------|------------|------------|
| 端到端训练 | 从输入到任务损失一条梯度链（如 LLaVA stage 2 更新投影+LLM） | 仍可能冻结视觉编码器 |
| 端到端多模态模型 | 单一网络同时处理多模态输入输出 | 不一定公开是否分阶段预训练 |
| 原生多模态（Gemini 博客用语） | 产品主张：多模态是模型内建能力，而非事后插件 | **无模块图**；不可直接等同「取消了视觉编码器」或「无对比预训练」 |

**实用判别问题（比标签重要）：**

1. 视觉塔是否独立对比 / 分类预训练？
2. 融合是共享嵌入、离散视觉 token、还是 LM 内 cross-attn / 早期拼接？
3. 适应新任务靠改提示、指令微调，还是深度全参视觉–语言联训？
4. 输出是相似度，还是 token 生成？

CLIP 答「1 是、2 共享嵌入、3 改文本/探针、4 相似度」。
Flamingo 答「1 是、2 cross-attn、3 in-context、4 生成」。
LLaVA 答「1 是、2 投影拼接进词嵌入、3 指令微调、4 生成」。
Gemini 2.5 博客只明确「原生多模态 + 长上下文 + thinking」，**1–3 的实现级答案待官方技术报告核实**。

### 3.3 为何产品仍大量使用「外挂」

- **复用**：视觉对比模型与 LLM 各自已有海量算力沉淀；
- **稳定**：冻结 LM（Flamingo）或先对齐再指令微调（LLaVA）降低遗忘与调参成本；
- **迭代速度**：换视觉骨干或换 LLM 底座比重训原生融合模型快。

「原生」叙事的吸引力在于：减少模态缝隙、统一长上下文里的多源推理、服务形态更干净——但这是**目标函数与系统定位**，不等于公开可复现的单一架构图。

## 四、常见误区与引用

### 4.1 误区

1. **「CLIP 已经是多模态 GPT」**
 CLIP 是对比双塔，主接口是嵌入与 zero-shot 分类，不是开放式生成助手。

2. **「Flamingo = 把图 CNN 特征直接拼进 GPT」**
 关键是 Perceiver 压成固定视觉 token + **带门控的 cross-attention 插入冻结 LM**，以及交错掩码；不是简单 concat。

3. **「有视觉编码器就一定是外挂、性能一定差于原生」**
 Flamingo / LLaVA 证明桥接路线可以很强；「原生」优势需看任务、数据与是否公开可复核，不能靠标签判胜负。

4. **「视觉指令微调 = 再训一个 CLIP」**
 LLaVA 的关键增量是**指令数据与对话目标**；CLIP 权重常作冻结视觉前端。

5. **「Gemini 2.5 博客 = 可引用的融合架构论文」**
 该文是产品与评测叙事（thinking、榜单、1M context、native multimodality），**无**给出与 CLIP §2 / Flamingo §2 同级的层间接线证明。引用时应写「官方主张」，并单列待核实项。
