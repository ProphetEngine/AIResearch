# 视频生成模型脉络

> **主要来源**：[Sora 2 is here](https://openai.com/index/sora-2/)（OpenAI 博文，2025-09-30）与 [Sora 2 System Card](https://openai.com/index/sora-2-system-card/)；[What to know about the Sora discontinuation](https://help.openai.com/en/articles/20001152-what-to-know-about-the-sora-discontinuation)（OpenAI 帮助中心）；[Video models are zero-shot learners and reasoners](https://arxiv.org/abs/2509.20328)（Wiedemer 等，Google DeepMind，v2）；[Matrix-Game 3.0](https://arxiv.org/abs/2604.08995)（v3）（截至 2026-09-29）。各开放模型的技术报告见第九节。
> **研究线**：架构思想（视频扩散从像素到潜空间、从 U-Net 到时空 Transformer、从离线整段到自回归流式）· 评测字段（视频模型的零样本能力怎么测、闭源旗舰缺少哪些可核材料）
> **范围与相邻笔记**：
> - ≠ [[扩散生成式视觉与LLM]]：图像潜扩散、LDM、DiT 的原理在那篇，本篇只写它们怎样被搬到时间维上。
> - ≠ [[DiffusionForcing族]]、[[MatrixGame与Cosmos]]：自回归视频扩散与交互式世界模型的方法细节在那两篇，本篇只给脉络定位。
> - 闭源旗舰没有架构与训练层面的技术报告，本篇不写其参数量、训练算力、潜空间压缩比、采样步数，也不用第三方「架构解说」或评测站代替官方材料。
>
> **意义**：视频生成在四年里从像素空间的视频扩散走到带同步音频、可实时交互的世界模型，开放模型（Movie Gen、HunyuanVideo、Wan、Cosmos）留下了完整的技术报告，闭源旗舰（Sora、Sora 2、Veo 3、Genie 3）则只有博文与安全文档。最醒目的一个转折是：**As of April 26, 2026, the Sora product is no longer available.**（[Sora 2 博文页](https://openai.com/index/sora-2/)顶部说明）——曾被定位为「通向世界模拟器」的旗舰产品在发布约七个月后下线，而它的架构从未以技术报告形式公开。

## 一、问题背景

- **视频比图像多一个时间维**：每段视频是几十到上百帧，既要逐帧逼真，又要跨帧连贯（物体恒存、运动合理、镜头切换一致）。直接把图像扩散按帧堆叠，算力与显存随帧数线性以上增长。
- **成对数据少**：文本—视频配对数据远少于文本—图像配对，早期工作要么从图像模型迁移，要么靠无标注视频学运动。
- **可核材料不对称**：学术与开放模型发表技术报告；闭源旗舰多以博文、产品页和系统卡发布，系统卡写安全与部署，不写架构与训练配方。这决定了本篇能写到多细：开放模型写到机制，闭源旗舰只写官方声明。

## 三、核心思想

### 3.1 从图像扩散继承

视频生成几乎都建立在图像扩散之上：去噪目标、无分类器引导、潜空间压缩与 DiT 骨干都直接沿用（原理见 [[扩散生成式视觉与LLM]]）。早期工作的共同做法是在图像模型里插入时间层，或把 2D 卷积、注意力分解为空间与时间两部分（Video Diffusion Models、Make-A-Video、Video LDM）。

### 3.2 三个压缩方向

- **级联**：先生成低分辨率、低帧率视频，再用空间与时间超分模型逐级放大（Imagen Video、Make-A-Video）。
- **潜空间**：用视频 VAE 把帧压进低维潜空间，在潜空间里扩散（Video LDM、Stable Video Diffusion，此后成为主流；Wan 报告的贡献之一就是新的 VAE）。
- **时空图块**：把潜视频切成时空图块当 token，用 Transformer 统一处理不同时长、分辨率和画幅（Sora 研究短报的表述；Movie Gen 用 73K 视频 token 的上下文生成 16 秒视频）。

### 3.3 数据与规模

Stable Video Diffusion 把「数据怎么筛」写成三阶段训练的核心；Wan 报告称 14B 模型显示出视频生成在数据与模型规模上的缩放规律；HunyuanVideo 与 Wan 都把数据管线、渐进式扩展与基础设施写进报告。

### 3.4 从整段生成到流式生成

整段（双向）扩散一次生成固定长度的视频，无法边生成边交互。Diffusion Forcing → Self Forcing → Causal Forcing 这一支把扩散改成按帧（或按块）自回归，并处理训练—推理分布差与蒸馏方式，使实时流式生成成为可能；Matrix-Game 3.0 在此之上加长程记忆、做成可部署的交互世界模型。

## 四、关键机制与可核材料

### 4.1 音频进入视频生成

Movie Gen（2024-10）在开放报告中给出带同步音频的视频生成；Veo 3（2025-05）官方称首次能生成带音频的视频；Sora 2（2025-09）把「同步对白与音效」作为定位。音频从后期配乐变成与画面联合生成的模态。

### 4.3 视频模型的零样本评测（Wiedemer 等）

- **对象**：Veo 3（Vertex API，model ID `veo-3.0-generate-preview`），对照 Veo 2；输入是首帧图像加文本指令，输出 720p、24 帧每秒、8 秒视频。
- **规模**：62 项定性任务与 7 项定量任务，共分析 18,384 段生成视频。
- **方法本质**：黑盒提示评测，不是 Veo 的训练配方报告。Vertex API 会用 LLM 改写提示（prompt rewriter），部分题目的解可能来自改写器；作者把「改写器 + 生成器」当一个整体，并对关键推理题用独立 LLM（Gemini 2.5 Pro）对照，确认它单独解不了。
- **读数方式**：定量题报 pass@k，并区分 best frame（任一帧最好）与 last frame（只看最后一帧）。专用模型（如 SAMv2）仍常更强，作者把现状类比为早期 GPT-3「通才未精专」。
- **项目页**：[video-zero-shot.github.io](https://video-zero-shot.github.io/)。

## 五、常见误区

1. **「Sora 2 的架构可以从博文或第三方解说里读出来」**：官方只有博文与系统卡，系统卡不含架构与训练配方。
2. **「系统卡就是技术报告」**：系统卡写安全栈、红队、政策与溯源，是部署文档。
3. **「Veo 3 零样本评测的成功样例等于 Sora 2 的能力」**：Wiedemer 等只测 Veo 3 与 Veo 2，结论不能移到别的模型上。
4. **「视频生成的 chain-of-frames 与视频理解的 Chain-of-Frames 是一回事」**：前者是 Wiedemer 等对「逐帧生成即逐步推理」的类比；后者是 [[SiLVR与ChainOfFrames]] 里在推理链中引用帧号的视频理解方法，二者只是同名。
5. **「下线等于技术失败」**：官方材料只写了产品停止的时间与数据导出安排，没有给出原因；本篇不推断原因。

## 六、意义

- **技术路线收敛**：潜空间 + 时空 Transformer + 大规模数据筛选成为通用配方，开放模型的报告（Movie Gen、HunyuanVideo、Wan）让这套配方可复现。
- **视频模型被重新定位**：一是作为通用视觉零样本学习者（Wiedemer 等），二是作为可交互的世界模型（Genie 3、Matrix-Game 3.0、Cosmos），视频生成从内容工具变成通向物理世界建模的一条路线。
- **闭源旗舰的可核缺口与产品风险**：Sora 从 2024-02 的「世界模拟器」研究短报、2025-09 的 Sora 2，到 2026-04-26 产品下线，始终没有架构与训练技术报告。产品下线后，可依据的仍只有博文与系统卡；以闭源产品为依据的结论，随时可能失去可复核的对象。

## 七、局限与待核实

- **API 停止日期**：帮助中心写的是「will be discontinued on September 24, 2026」，页面未标具体更新日期；API 是否已按期停止，待核实。
- **系统卡正文**：系统卡以 OpenAI 落地页为准，4.2 节「系统卡覆盖」一行概括的是系统卡全文的章节，未逐节摘录原文。
- **Wiedemer 等的读数**：以 v2 为准；评测含提示改写器，部分题目的能力来源不完全可分。
- **未覆盖**：可灵、Runway、Pika、Luma 等商业模型（没有可核的技术报告，HunyuanVideo 报告里的对比只作为其自报）；视频生成的评测基准（如 VBench）；视频生成的安全与溯源（水印、C2PA）。
- **年月口径**：arXiv 节点按首版年月，括注的版本号是本篇所据版本；Matrix-Game 3.0 以 v3（2026-09-29）为准，摘要与 v2 一致。
