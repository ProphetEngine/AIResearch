# On-device SLM：MobileLLM / Phi-4（及与 Gemma 4 小尺寸对照）

> **主要来源**：[MobileLLM（Liu 等，Meta，ICML 2024）](https://arxiv.org/abs/2402.14905)；[Phi-4 Technical Report（Abdin 等，Microsoft Research）](https://arxiv.org/abs/2412.08905)；对照用 [Gemma 4 Technical Report](https://arxiv.org/abs/2607.02770)（截至 2026-09-22）
> **研究线**：架构思想（主）——小模型的能力从哪里来；AI Infra（辅）——端侧内存层级与量化
> **范围与相邻笔记**：
> - ≠ [[Gemma4技术报告深读]]：本篇不重写 Gemma 4，E2B/E4B 只作第三个对照点。
> - ≠ [[合成数据与教科书式数据]]：本篇不写合成数据与 textbook 数据的通史，Phi-4 只记本报告的数据配方。
> - ≠ [[MobileLLM端侧增量]]：本篇不写 2024 之后的 MobileLLM-Pro / Flash。
>
> **意义**：小模型有两条走法——MobileLLM 在不足 1B 参数、手机内存层级的硬约束下，靠架构（更深更瘦、权重复用）挤出能力；Phi-4 在 14B 档几乎不动架构，靠合成数据与后训练把推理榜推过教师模型。两路解决的约束不同，不能混成一张排行榜。

**一句话**：同样叫「小模型」，MobileLLM 回答的是「手机装得下、跑得动时架构怎么排」，Phi-4 回答的是「参数固定时数据怎么喂」。

---

## 一、问题背景：端侧与小模型的约束

**手机的内存层级**（MobileLLM §1、Figure 2）：

| 层级 | 量级（文中举例） | 含义 |
|---|---|---|
| SoC SRAM / LLC | **~8–32 MB** | 通常只够放一个 transformer block |
| DRAM | 约 6–12 GB | 权重与 KV 工作集的上限 |
| Flash | 约 100 GB | 存储充裕，但带宽远低于 DRAM，不适合作工作集 |

MobileLLM 的动机测算：手机上 350M 8-bit 模型约 0.035 J/token；125M 模型标称约 50 tok/s，对照 iPhone 上 MLC Chat 跑 LLaMA 7B 的 3–6 tok/s。由此把目标定为「参数不足 1B，优先准确率与存储、带宽」，而不是追云侧的规模曲线。

**Phi-4 的「小」是另一档**：14B decoder-only，默认 4K、中段训练后 16K 上下文。对手机 DRAM 偏大，对前沿模型属小模型。它要回答的是：同参数下能否靠数据把推理能力推上去。

## 三、两路对照：架构优先 vs 数据优先

| 维度 | 架构优先：MobileLLM | 数据优先：Phi-4 |
|---|---|---|
| 核心命题 | 不足 1B 时，架构比再堆数据或参数更关键 | 参数与架构基本固定，数据质量与课程决定上限 |
| 尺寸 | 125M–1.5B dense | 14B dense |
| 约束来源 | SRAM 只够一块、DRAM 带宽有限 | 推理成本与同参对手 |
| 主要旋钮 | 深而瘦、词嵌入共享、GQA、相邻块权重共享 | 40% 合成数据、种子过滤、PTS 与 judge 两段 DPO |
| 数据 | 标准 next-token，1T tokens | 约 10T tokens，合成数据多轮重复 |
| 量化 | W8A8 训练后量化掉点不足 0.5 | 报告主轴不涉及手机量化 |
| 评测焦点 | 零样本常识、chat、API 调用、iPhone 延迟 | MMLU / GPQA / MATH、安全红队 |
| 一句话 | 「手机 SRAM 只够一块 → 深而共享」 | 「合成数据 + 关键 token 偏好把 14B 推过教师」 |

## 四、架构优先：MobileLLM 的四项技术与层共享

### 4.1 四项技术（MobileLLM §2.2）

在约 125M / 350M 上扫描深宽并叠加四项技术：

1. **SwiGLU FFN**：相对 ReLU FFN，125M 零样本均分 42.6→43.9。
2. **深而瘦**：同参数下更深更瘦更好，与「宽度更重要」的直觉相反；既往 125M 多为 12 层，MobileLLM 用到约 30 层。
3. **输入输出嵌入共享**：小模型里词嵌入占比高（125M 时超过 20%，LLaMA-7B 约 3.7%），共享后把预算挪给深度。
4. **GQA**：kv 头 16→4，125M 精度基本持平、350M 仅 −0.2，体积约 −10%。

### 4.2 相邻块权重共享（MobileLLM §2.3）

深度有益，但端侧不能为深度无限加参数。做法是让相邻 block 共用权重、立即连算两次（MobileLLM-LS）：共享权重留在 SRAM 里，避免 DRAM 往返。

| 共享策略 | 精度（Table 2 均分，125M / 350M） | 硬件读法 |
|---|---|---|
| 相邻块立即共享 | 45.0 / 50.2 | 对缓存友好，被选用 |
| 全体重复一遍 | 45.2 / 50.7，略高 | 对缓存不友好 |

iPhone 13 上（Table 7，125M 配置），执行时间：30 层基线 15.6 ms，LS 版 16.0 ms，60 层不共享版 29.0 ms——LS 几乎不增延迟与体积。

### 4.3 关键结果

- **零样本常识均分（Table 3，1T tokens，32×A100）**：125M 46.3、LS 47.0；350M 51.3、LS 52.1。摘要口径：比此前同档最好结果高 2.7% / 4.3%，LS 再加 0.7% / 0.8%。更大档：600M 54.3、1B 57.3、1.5B 59.4（Appendix Table 8）。
- **端侧任务**：LS-350M 的 MT-Bench 3.16、AlpacaEval 胜率 48.20%；API 调用上 350M 的意图 / 结构精确匹配 65.3 / 48.8，对照 LLaMA-v2 7B 的 62.8 / 50.9。
- **蒸馏负结果（§3.5）**：以 LLaMA-v2 7B 为教师蒸馏，训练慢 2.6–3.2×，精度持平或更差，所以主路径仍是从零训练。

## 五、数据优先：Phi-4 的配方

### 5.1 架构几乎不动（Phi-4 §3）

紧随 phi-3-medium：tiktoken 词表，预训练改为 4K 全注意力，中段训练扩到 16K（RoPE base 250K），预训练约 10T tokens。报告未给完整层配置表。

### 5.2 预训练数据（Table 5 与 §3.1–3.2）

| 来源 | 占比 | 重复轮数 |
|---|---:|---:|
| 合成数据 | 40% | 13.8 |
| 网页 | 15% | 1.2 |
| 网页改写 | 15% | 5.2 |
| 代码 | 20% | 2.4 |
| 采购数据 | 10% | 1.7 |

报告的消融主张：同 token 预算下，多轮重复合成数据往往优于加新的网页数据；但纯合成在知识类榜单（如 TriviaQA）明显吃亏，所以保留网页与采购数据。合成数据从高质量种子出发，报告强调种子不干净会严重污染衍生的合成数据。

### 5.3 后训练（Phi-4 §4）

- **SFT**：约 8B tokens。
- **PTS-DPO**：在可自动判对错的任务上估计前缀成功率，找出让成功率剧变的「关键 token」，只对该 token 构造偏好对，降低全长 DPO 的噪声。
- **Judge-DPO**：约 85 万对，由 GPT-4o 打标。

Table 9：PTS 对 GPQA、MATH 帮助更大，judge-DPO 对 ArenaHard 帮助更大；IFEval 反而从 66.2 降到 63.0。

### 5.4 关键结果（Table 1 与 §7–8）

- MMLU 84.8；GPQA 56.1（GPT-4o 50.6）；MATH 80.4（GPT-4o 74.6）。
- 短板：SimpleQA 3.0、IFEval 63.0，明显落后大模型。
- 安全：AIRT 红队两周；在 phi-3-medium 上生成的 GCG 后缀没有迁移到 phi-4。
- 报告自列弱点：事实幻觉、严格格式指令弱、偶发小数比较错误（9.9 vs 9.11）、简单题也冗长。

## 六、第三个对照点：Gemma 4 E2B/E4B

E2B / E4B 有效参数 2.3B / 4.5B（含逐层嵌入后总参数 5B / 8B），多模态，配 mobile QAT；E2B 量化后约 0.8 Gb（Gemma 4 Table 3）。它介于两路之间：既用架构手段（PLE 让有效参数远小于总参数），也走产品化量化。细节见 [[Gemma4技术报告深读]]。

## 七、意义

- **端侧约束首先是内存层级**：MobileLLM 把瓶颈定位在 SRAM/DRAM 层级，层共享之所以划算，是因为权重能留在 SRAM 里；这是数据中心模型设计里不会出现的取舍。
- **数据可以替代一部分规模**：Phi-4 显示 14B 在 STEM 推理上可超过教师模型，但知识类与指令跟随仍受参数量限制。

## 九、局限与待核实

- **数据卡缺失**：MobileLLM 未给预训练语料配比；Phi-4 未给完整层配置表。
- **跨模型分数不可比**：三份报告的评测协议、温度、是否开启推理模式都不同，对照表只对齐设计取舍，不排名次。
- **「端侧」含义不同**：MobileLLM 是真实手机约束；Phi-4 是小模型推理成本档；Gemma E2B/E4B 是开源端侧产品，引用时要标明是哪一档。
- **Phi-4 超过教师只限 STEM**：GPQA、MATH 高于 GPT-4o，知识与指令类仍落后。
