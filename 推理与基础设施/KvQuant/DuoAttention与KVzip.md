# KV 新方法：DuoAttention（头分工）+ KVzip（query-agnostic 压缩）

> **主要来源**：[DuoAttention（Xiao, Tang, Zuo, Guo, Yang, Tang, Fu, Han；MIT / 清华 / 交大 / Edinburgh / NVIDIA）](https://arxiv.org/abs/2410.10819)，v1 2024-10-14；[KVzip（Kim, Kim, Kwon, Lee, Yun, Song；SNU / NAVER AI Lab 等，NeurIPS 2025）](https://arxiv.org/abs/2505.23416)，v2 2025-09-30（截至 2026-09-22）
> **研究线**：架构思想（主）——哪些 KV 必须全留、哪些可以只留近窗或按分数驱逐；显存、延迟与精度字段（辅）
> **范围与相邻笔记**：
> - ≠ [[KV缓存量化与压缩]]：本篇不写 KV 低比特量化，只记「两文都可与量化叠加」。
> - ≠ [[检索式注意力]]：本篇不写 decode 期的向量检索近似。
> - ≠ [[长上下文位置编码与系统侧]]：本篇不写位置外推与分页调度。
> - SnapKV、PyramidKV、H2O、StreamingLLM、TOVA、FastGen 只作基线，不展开方法。
>
> **意义**：两篇都在回答「长上下文的 KV 里哪些可以不留」：DuoAttention 发现只有少数注意力头需要完整 KV，其余头只看开头与近窗即可，于是同时压低 prefill 与 decode 的显存；KVzip 按「能否复述原文」给 KV 打分，压缩结果不依赖具体问题，可以压缩一次、回答多个问题，契合文档与会话 KV 预计算后复用的场景。

**一句话**：DuoAttention 是「少数头全记住，多数头只看开头与近窗」；KVzip 是「不问之后问什么，先按能否复述上下文来裁剪 KV」。

---

## 一、问题背景

据 DuoAttention §1 与 KVzip §1–2：

1. **KV 随长度线性增长**：Llama-3-8B、FP16、100 万 token 的 KV 至少约 137 GB，超过单卡 80GB；prefill 延迟随长度平方增长，decode 随 KV 线性增长。
2. **统一剪 KV 伤长上下文**：H2O、StreamingLLM、TOVA、FastGen 等在大海捞针（NIAH）上容易丢 needle；StreamingLLM 式常数窗省显存，但有效记忆困在开头与近窗。
3. **query-aware 驱逐不可复用**：SnapKV、PyramidKV 用当前问题尾部的注意力打分，单问题时效果好；把第一次压缩后的缓存拿去回答后续问题，效果大幅下降（KVzip Fig.2）。而企业场景常常是文档 KV 预计算后反复查询。

## 二、脉络

| 节点 | 做法 | 局限 | 来源 |
|---|---|---|---|
| StreamingLLM | 只留开头的 sink token 与近窗，常数显存 | 中间信息丢失 | DuoAttention §1；[[检索式注意力]] |
| H2O / TOVA / FastGen | 按注意力统计统一驱逐或按头配置 | NIAH 上易失败；FastGen 超长时 OOM | DuoAttention §1、Fig.6 |
| SnapKV / PyramidKV | 按当前问题打分驱逐 | 不能跨问题复用 | KVzip §1–2 |
| DuoAttention（2024-10） | 头级二分：检索头全 KV，流式头常数窗 | 需要一次门控优化 | DuoAttention |
| KVzip（2025） | 按上下文复述打分，与问题无关 | 每个上下文要多付一次打分开销 | KVzip |

## 三、DuoAttention：检索头与流式头

### 3.1 核心观察

少数检索头（Retrieval Heads）会跨长距离对准相关 token；多数流式头（Streaming Heads）主要看开头的 sink 与近邻。剪掉流式头的中间 KV 对 passkey 几乎无伤，剪掉检索头则崩（Fig.1）。

### 3.2 怎样找出检索头（§2）

- 给每个 KV 头设一个可训练门控 α（模型权重冻结），前向时输出为 α × 全注意力 + (1−α) × 流式注意力。
- 在合成数据（长文中嵌入多条随机 passkey，末尾要求全部召回）上，对末层隐状态做相对全注意力的蒸馏损失，加 α 的 L1 稀疏项；约 2000 步，可训参数只有「层数 × 头数」量级。
- 部署时按阈值二值化：α 大的头保留全 KV，其余只留 sink + 近窗。
- 与「看注意力图找检索头」的区别：直接衡量「只留近窗时输出是否显著改变」，消融称更优（Fig.13）。

### 3.3 部署行为（§2.3）

- decode：检索头追加全部新 KV，流式头只保留 sink + 滑动窗，显存为常数。
- 分块 prefill：流式头每算完一块就剪到 sink + 近窗，可直接用 FlashAttention-2，不需特制核。
- 常用比例：Llama-2-7B（MHA）检索头 25%；Llama-3-8B（GQA）50%，GQA 更难压。

### 3.4 结果（§3）

| 项 | 结果（论文口径） |
|---|---|
| LongBench 均分（附录 Table 3/4） | Llama-3-8B-1048K：Full 40.08，Duo（50%）40.21；Llama-2-7B-32K：Full 37.52，Duo（25%）34.49 |
| 短上下文（Llama-3-70B，50%） | MMLU 79.35%、MBPP 47.09%、MT-Bench 9.14，接近 Full 的 79.38 / 47.85 / 8.93 |
| 效率（单卡 A100，MHA / GQA） | decode 显存最多降 2.55× / 1.67×；decode 延迟最多 2.18× / 1.50×；prefill 延迟 1.73× / 1.63×；prefill 显存降 2.38× / 1.53× |
| 与量化叠加（Fig.12） | 加 8-bit 权重与 4-bit KV 后，Llama-3-8B 在单卡 A100-80G 上可到约 330 万 token 上下文，约为 Full BF16 的 6.4× |

## 四、KVzip：按上下文复述打分

### 4.1 核心思想（§3.1–3.2）

目标是找一个 KV 子集，使模型对任意未来问题的输出都与使用完整 KV 时接近。直觉：把模型看作「上下文 → KV」的编码器，裁剪后的 KV 若仍能让模型按提示复述原文，信息就是充分的。

实际做法不必真的重建：构造「Repeat 提示 + 原文」做一次 teacher-forced 前向，取每个 KV 对在这次复述中获得的最大交叉注意力作为分数，驱逐低分者。论文称这一分数比 prefill 自注意力更稀疏，且与 QA、摘要、推理等任务的高分 KV 重叠，而两道不同 QA 之间的高分 KV 各不相同（Fig.5–6），以此支撑与问题无关的设计。

### 4.2 分块打分（§3.4）

对整段直接取最大值与 FlashAttention 的分块计算不兼容。做法是把上下文切成固定 2K 块，每块与复述提示拼接前向，复杂度从 O(n²) 降到 O(m·n)。代价：压缩期约多付一次 prefill 量级的注意力计算（论文称约 2 倍 prefill 注意力开销），每个上下文只需一次。

### 4.3 两种部署形态

- **依赖上下文**：每个上下文 prefill 后打分、按比例驱逐，适合同一文档被多次查询时摊销。
- **不依赖上下文**：用一篇样例书聚合出静态的头分数，再套 DuoAttention 式头级驱逐，部署后零压缩开销，压缩率较保守。

### 4.4 结果（§4）

- **任务泛化（Fig.9，Qwen2.5-7B-1M，多问题复用设定）**：检索密集任务在约 30% 预算下接近满血，而 SnapKV / PyramidKV / H2O 在保留 90% 时已明显下降；语境理解任务约 30% 近无损；高冗余任务可到约 10%。
- **与量化叠加**：LLaMA3-8B 在 124K 上下文，16-bit KV 约 16.3 GB；4-bit 加 70% 驱逐后约 1.2 GB，论文称掉点可忽略。
- **与 DuoAttention 头分数比较（Fig.11）**：KVzip 的头分数只需数次前向（约 1 分钟级），DuoAttention 的门控优化为数小时、8 GPU 级，12 个数据集平均表现 KVzip 更优。
- **效率宣称**：decode 侧注意力延迟约 2× 改善；摘要另写 KV 可压缩至约 394×，正文主叙事是驱逐约 70% 近无损。
- **安全现象（Table 1）**：DecodingTrust 隐私例中，满 KV 拒绝给出电话号码，压缩 40% 后却给出了；论文归因于优先保留可复述的 KV、丢掉了与对齐相关的 KV。

## 五、两篇对照

| 问题 | DuoAttention | KVzip |
|---|---|---|
| 裁什么 | 整个头二选一 | token × 头的 KV 对，也可聚合成头级 |
| 信息准则 | 合成 passkey 上的输出蒸馏 + L1 | 复述原文时的最大交叉注意力 |
| 一次性成本 | 门控优化（数小时） | 每个上下文约一次 prefill 量级的打分，或模型级一次 |
| 多问题复用 | 流式头天然与问题无关，检索头全留 | 设计目标即跨问题复用 |
| 互相关系 | — | 可替换 DuoAttention 的头分数 |

两者可叠（头级 + KV 对级），但属于不同层面的方法。

## 六、意义

- **头不匀是可利用的结构**：DuoAttention 说明长上下文能力集中在少数头上，按头分配 KV 预算比统一剪裁更能保住大海捞针与 LongBench。
- **可缓存的压缩**：KVzip 把「压缩后的 KV」变成可以复用的资产，这与前缀缓存、文档 KV 预计算的需求一致；query-aware 方法在这类场景下会失效。

## 八、局限与待核实

- **合成数据依赖**：DuoAttention 的检索头识别只在合成 passkey 数据上优化，换到其他任务分布是否稳定，论文只用消融支持。
- **GQA 收益较小**：GQA 模型需要保留 50% 检索头，效率倍数明显低于 MHA，不能把 MHA 的倍数直接套到 GQA 服务。
- **KVzip 的压缩开销**：每个上下文多付约一次 prefill 量级的计算，只有在多次查询时才摊得回来。
- **394× 不可外推**：摘要中的 394× 不代表任意任务；正文主结论是约 70% 驱逐近无损。
- **对齐行为可能被破坏**：压缩后出现原本会拒绝的隐私泄露，说明驱逐可能丢掉与安全对齐相关的 KV，部署前需单独评估。
- **未复现**：本篇未复现实验，未读图估算未列表的曲线点。
