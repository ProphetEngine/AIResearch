# Quantization-aware training：ZeroQAT（端侧 QAT @ 推理成本级）

> **主要来源**：[End-to-End On-Device Quantization-Aware Training for LLMs at Inference Cost](https://arxiv.org/abs/2509.00031)（Tan、Song 等，佐治亚大学、北得克萨斯大学、东北大学等，v2 2025-09-29，以下简称 ZeroQAT）（截至 2026-08-14）。
> **研究线**：架构思想（主：用零阶梯度估计代替反向传播，让量化感知训练绕开直通估计器，端到端联合训练模型与量化参数）；评测字段（辅：W2A16、W4A4 等设定下的困惑度与下游准确率，A100 与手机上的内存和时延）
> **范围与相邻笔记**：
> - ≠ [[SpinQuant与ARCQuant量化]]：那篇冻结权重做训练后量化，本篇在训练中更新权重与量化参数。
> - ≠ [[KV缓存量化与压缩]]：本篇量化权重与激活，不涉及解码期 KV 缓存的压缩。
> - ≠ [[端侧小模型]]：本篇只取「端侧能不能跑量化感知训练」这一效率问题，不写端侧模型谱系。
>
> **意义**：量化感知训练（QAT）比训练后量化（PTQ）更能保住低比特精度，但要存激活、反传梯度和优化器状态，作者举例说微调 LLaMA-7B 就可能需要数百 GB 显存，所以实际部署几乎都用 PTQ。ZeroQAT 只做前向，用两次扰动前向的损失差估计梯度，内存降到接近推理，同时把可学习的激活平滑与权重裁剪放进同一个端到端训练环。Llama2-7B 的 W4A4 微调准确率达到 55.7，而 SmoothQuant 与 OmniQuant 只有 32.9 与 38.8；OnePlus 12 手机上能微调 6.7B 的 OPT 模型，而 FP16 微调会内存溢出。它说明低比特部署不必在「便宜但掉点的 PTQ」和「准但训不起的 QAT」之间二选一。

## 一、问题背景

ZeroQAT 把 PTQ 分成两类并指出各自的问题（§3.1）。基于范围的 PTQ（如 SmoothQuant）只缩放或裁剪数值范围，中等比特下表现不错，Llama2-7B 的 W6A6 困惑度 6.20、接近全精度的 5.47，但 W4A4 时恶化到 83.12。基于近似的 PTQ（如 OmniQuant）逐层最小化重建误差，有两个毛病：一是误差累积，浅层重建改善明显、深层收益递减，因为每层都在已被前层量化噪声扰动的输入上优化；二是目标不一致，逐层重建损失下降时整体困惑度并不一定下降。微调过的模型对量化噪声更敏感，问题更明显。

一阶 QAT 原理上能解决这些问题，但内存不可承受；QLoRA、EfficientQAT 这类参数高效 QAT 降低了开销，在权重与激活联合量化（W4A4）时仍表现不佳（Table 2）。零阶（ZO）优化早已被 MeZO 用于全精度微调，但已有的零阶加量化工作大多只量化权重。作者称 ZeroQAT 是第一个在极低比特下同时量化权重与激活、内存接近推理的端到端 QAT（§3.2），这是作者的说法。

## 二、脉络

| 时间 | 工作 | 关键一步 |
|---|---|---|
| 2019-02 | [LSQ](https://arxiv.org/abs/1902.08153) | 按任务损失的梯度学习量化器步长，与权重一起训练 |
| 2023-05 | [QLoRA](https://arxiv.org/abs/2305.14314) | 冻结 4 比特量化的基座，只把梯度反传进 LoRA，单张 48GB 卡微调 65B 模型 |
| 2023-05 | [MeZO](https://arxiv.org/abs/2305.17333) | 原地执行的零阶 SGD，微调内存与推理相同，单张 A100 80GB 可训练 30B 模型 |
| 2023-05 | [LLM-QAT](https://arxiv.org/abs/2305.17888) | 用模型自己的生成做无数据蒸馏，量化权重、激活与 KV 缓存 |
| 2023-08 | [OmniQuant](https://arxiv.org/abs/2308.13137) | 逐层学习权重裁剪与等价变换的 PTQ |
| 2024-07 | [EfficientQAT](https://arxiv.org/abs/2407.11062) | 先逐块训练全部参数，再端到端只训练量化参数 |
| 2025-08 | ZeroQAT | 用零阶梯度做端到端 QAT，同时量化权重与激活，大幅降低训练内存 |
| 2026-08 | [QUASAR](https://arxiv.org/abs/2608.13966) | 在 QAT 训练环里每步做轻量的损失感知重建，覆盖 INT2 至 INT4 与 NVFP4；它仍用反向传播与 STE、只量化权重，本篇则绕开 STE；两文没有互相对照 |

## 三、方法（§4）

- **零阶 QAT**：对权重加随机扰动，用正负两次扰动后的量化前向损失之差乘扰动方向，平均若干次得到梯度估计，再按普通 SGD 更新；前向用量化权重，后台仍维护全精度权重。梯度直接由有限差分估计，因此不需要直通估计器（STE）。作者认为 STE 是人为设计的有偏代理梯度，低比特时真实的平滑梯度已经很小而 STE 仍给出大更新，容易不稳定，形式分析见附录 G。不存激活与典型的优化器状态，内存接近推理。
- **可学习的激活平滑**：借鉴 SmoothQuant 与 Outlier Suppression+，用逐通道的缩放与平移把激活的量化难度迁移到权重，但这两个参数与模型参数一起由零阶优化端到端更新，而不是逐层离线标定。
- **可学习的权重量化器**：步长、零点与上下裁剪比例都可学习（LSQ 一脉），平滑后部分通道的权重分布变偏，需要非对称裁剪。只量化权重时去掉平滑、只留裁剪（§5.1）。
- **轻量变体（仅微调）**：零阶下内存主要来自正在更新的参数，于是冻结并预量化大部分参数，只让注意力的 Q、V 矩阵保持全精度并更新。只更新 Q、V 时内存降到全参数的 27%–38%，准确率接近全参数；只更新 Q 则明显下降（附录 D.4）。该变体用于量化预训练会明显掉点，Llama2-7B 的 W2A16 困惑度从 29.61 升到 41.05（附录 D.3）。
- **初始化与协议**：平滑参数先用 OmniQuant 式的重建训练少量轮次初始化（W4A4 两轮、W2A16 四轮），再进入零阶优化；量化预训练用 WikiText2 与 C4 混合的 128 段、每段 2048 token；结果为三次运行的平均（附录 C）。

## 四、结果

**Llama2-7B 主对照（Table 2；量化预训练报困惑度，量化微调报准确率）：**

| 方法 | 类别 | 预训练 W6A6 / W2A16 / W4A4 | 微调 W6A6 / W2A16g128 / W4A4 |
|---|---|---|---|
| SmoothQuant | 基于范围的 PTQ | 6.20 / 100.23 / 83.12 | 57.2 / 27.7 / 32.9 |
| OmniQuant | 基于近似的 PTQ | 5.87 / 37.37 / 14.26 | 63.9 / 40.6 / 38.8 |
| EfficientQAT | QAT | 5.60 / 33.40 / 76.32 | 66.4 / 45.4 / 28.6 |
| ZeroQAT | QAT | 5.76 / 29.61 / 12.95 | 65.3 / 54.1 / 55.7 |

全精度零阶微调的准确率为 66.0。部分格子作者标注为「该方法本质上不适合此设定」，列出只为说明局限。W6A6 时各方法与全精度相差多不到 1 个困惑度，差别集中在低比特。

- **零样本**（Table 4，Llama-1-7B 五项均值）：W2A16 时 ZeroQAT 51.75、EfficientQAT 47.65；W4A4 时 ZeroQAT 53.11、OmniQuant 52.15；全精度 65.26。
- **微调**（Table 6，Llama-1 在五个数据集上的均值）：W2A16 时 7B / 13B 为 53.9 / 55.7，比 EfficientQAT 高 4.8 / 3.6 点；W4A4 时为 54.8 / 57.4。OPT 的 W4A4 微调在 SST-2 上约 88%，基线约 60%（Table 5）。
- **服务器内存**（Table 7，W2A16g128）：量化预训练相对 LLM-QAT 内存降 89%–92%，且不随批量增长；量化微调时 OPT-13B 只需 6.8GB，OPT-1.3B 相对 EfficientQAT 内存从 5.9GB 降到 0.8GB，单步时间从 0.69 秒降到 0.31 秒。
- **手机**（Table 8，OnePlus 12，骁龙 8 Gen 3、16GB 内存，W4A4）：微调的运行内存 OPT-1.3B 从 3.5GB 降到 1.2GB，OPT-2.7B 从 8.1GB 降到 2.6GB；OPT-6.7B 的 FP16 微调内存溢出，ZeroQAT 用 6.4GB、微调时延 29.1 秒。推理吞吐提高 1.41–1.52 倍。

## 五、意义

ZeroQAT 把 QAT 的主要门槛从「训不起」改成「收敛慢一些」：零阶估计噪声大，作者观察到它更依赖迭代次数而非数据量，样本数从 32 到 512 段变化时困惑度波动多在 0.5 以内（附录 D.5、Table D.6）。它也把平滑、裁剪这些原本属于 PTQ 的手段收进端到端目标，绕开了逐层重建的误差累积与目标错位。对端侧来说，这意味着设备上可以对已量化模型做个性化微调，而不必先在服务器上用全精度训练再量化。

## 六、局限与待核实

- **版本差异**：v1（2025-08-21）题为 *ZeroQAT: Your Quantization-aware Training but Efficient*，还没有轻量变体和手机实验；v2 改为现标题，补了轻量变体、端侧实验与附录 G 的理论分析。本篇按 v2。
- **内存优势有条件**：Table 7 中批量为 1 的量化预训练，OPT-6.7B 与 OPT-13B 上 ZeroQAT 的内存（14.2GB、26.6GB）高于 OmniQuant（12.3GB、16.8GB），批量为 4 时才反超；「近推理内存」主要体现在量化微调和大批量。
- **依赖 PTQ 初始化**：平滑参数先用 OmniQuant 式重建初始化，0 轮初始化时性能明显下降（§5.3、Table D.5），方法并非纯零阶。
- **口径**：§1 称 2 比特仅权重量化时五项零样本平均提升 5.1%，Table 4 中 7B 相对 EfficientQAT 的差为 4.1 点，正文没有说明 5.1% 的计算口径。
- **覆盖面**：模型限于 OPT 与 Llama-1/2 的 13B 以内，手机实验只到 OPT-6.7B、单一 SoC；与 Gemma 4 等较新的开源 QAT 权重没有对照。文中没有给出代码入口。
