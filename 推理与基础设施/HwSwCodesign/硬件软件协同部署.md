## 三、NVIDIA Blackwell（数据中心主线）

### 3.1 代际：双 die 统一 GPU → Grace Blackwell → NVL72

据 *Technical Brief* V2.1（§「A New Class of AI GPU」等）：

- **晶体管 / 工艺**：约 **2080 亿**晶体管；TSMC **4NP**（NVIDIA 定制）。文称相对 Hopper **>2.5×** 晶体管，并称单芯片算力叙事上可达 **20 petaFLOPS**（营销口径，跟读时与具体精度列分开记）。
- **双 die**：两个接近光罩极限的 GPU die，经 **NV-HBI** 以 **10 TB/s** 片间带宽连成**单一相干 GPU**。
- **Grace Blackwell Superchip（产品页 / datasheet）**：1× Grace CPU + 2× Blackwell GPU，经 **NVLink-C2C** 组成 Superchip（产品页叙述 Grace–GPU 相干链路约 **900 GB/s** 双向；勿与第 5 代 NVLink「每向 900 GB/s、合计 1.8 TB/s」混淆）；GB200 NVL72 = **36 Grace + 72 Blackwell** 液冷机架，**72-GPU NVLink 域**「像一块大 GPU」。
- **Blackwell Ultra / GB300 NVL72**：Brief 称相对 GB200 NVL72 约 **1.5×** AI 性能，并给出相对 Hopper 体系的多组「AI factory / reasoning」倍率（50× / 35× / 30× / 25× 等——**均为厂商投影图叙事，跟读时标注「projected / subject to change」口径，不外推为第三方实测**）。

**架构思想一句：** 代际跃迁不只是「单卡 FLOPS↑」，而是把 **双 die 相干 + CPU–GPU C2C + 72 卡 NVLink 域** 做成可卖的**机架级原子**，让模型并行尽量停在高带宽域内。

### 3.2 精度：第 5 代 Tensor Core 与第二代 Transformer Engine（FP8 / FP4）

**Brief Table 1（支持数据类型）**：FP64、FP32、TF32、FP16、BF16、**FP8**、INT8、**FP6**、**FP4**。文称第五代 Tensor Core 支持含 **社区定义 microscaling（OCP）** 在内的 FP4 等格式。

**第二代 Transformer Engine（Brief）：**

- 与 Dynamo / TensorRT-LLM / NeMo 等**协同**（本篇不展开软件）；硬件侧主张用 **micro-tensor scaling（细粒度缩放）** 做动态范围管理，以 **启用 FP4 AI**。
- 文称由此 **加倍 FP4 Tensor Core 性能**、**加倍通向 HBM 的参数带宽**、**加倍单卡可支撑的模型规模**（相对其 FP4 基线表述；勿与 Hopper FP8 跨代随意换算）。
- **Attention**：Blackwell Ultra 相对 Blackwell GPU，文称 attention 层计算约 **2×**（长序列指令增强）——服务「reasoning / 长上下文」硬件叙事。

**RTX 白皮书对照（同代精度族，不同产品线）：**

- 第 5 代 Tensor Core：在 Hopper FP8 Transformer Engine 能力之上，增加 **FP4 / FP6**；并带第二代 FP8 TE（文称与数据中心 Blackwell **相似**）。
- 图注口径：**FP4 吞吐约为 FP8 的 2×**（Figure 8：「double throughput of FP8」）。
- 应用例（生成式图像）：相对 FP16，FP4 显著降显存（FLUX.dev 例：FP16 **>23 GB** → FP4 **<10 GB**）——说明**精度轴直接改写「哪些模型能本地跑」**，但数字绑定具体模型与量化链路，不外推到 LLM serving。

**产品页 / Ultra datasheet（跟读锚点，非独立实测）：**

- Ultra datasheet 开篇称 Blackwell Ultra GPU 可达约 **20 petaFLOPS FP4 sparse** 推理性能量级（与 Brief 单芯片 20 PFLOPS 营销同族）。
- Architecture datasheet：第二代 TE **启用 FP4**；规格表出现 **Total NVFP4 Tensor Core** 列（与 Brief Table 2 的 FP4 dense/sparse 列同读；命名以各 PDF 原文为准）。

### 3.3 互联：第 5 代 NVLink / NVLink Switch → NVL72；机架外 IB / Ethernet

据 Brief §「Fifth-Generation NVLink and NVLink Switch」：

| 项 | 白皮书数字 |
|---|---|
| 每 GPU NVLink | **18** 条链路；合计约 **1.8 TB/s** 双向（每向 900 GB/s）；相对 PCIe Gen5 约 **>14×** |
| 单链路有效带宽 | 每向约 **50 GB/s**（相对 Hopper 第 4 代「每链路加倍」叙事） |
| 域规模 | 文称可 scale 至 **576** GPU（Switch 支撑）；**NVL72** 单域 **72** GPU |
| 域内聚合 | **130 TB/s** GPU 带宽（72-GPU 域） |
| SHARP | 新一代 SHARP **FP8**，文称约 **4×** 带宽效率 |
| 相对 8-GPU 箱 | 文称 GB300 NVL72 可支持约 **9×** 于单 8-GPU 系统的 GPU 吞吐（通信与算力共扩） |

**机架规格（Brief Table 2，dense/sparse）：**

| | **GB300 NVL72** | **GB200 NVL72** |
|---|---|---|
| 配置 | 72 Ultra GPU + 36 Grace；18 compute tray + 9 NVLink Switch tray | 72 Blackwell GPU + 36 Grace；同结构 |
| FP4 Tensor | **1080 / 1440** PFLOPS | **720 / 1440** PFLOPS |
| FP8/FP6 Tensor | **360 / 720** PFLOPS | **360 / 720** PFLOPS |
| HBM | HBM3e；**20 TB**（机架合计） | HBM3e；**13.5 TB** |
| HBM 带宽 | **576 TB/s** | Up to **576 TB/s** |
| Fast memory | **37 TB** | Up to **31 TB** |
| NVLink 域带宽 | **130 TB/s** 双向 | **130 TB/s** 双向 |

**机架外（产品页落盘 PDF，只作索引）：**

- **Quantum-X800** InfiniBand、**Spectrum-X800** Ethernet：GB200 页附带的 AI 规模组网平台 datasheet（2024 春 CreationDate）——对应 **跨机架 / 多租户云** 的 scale-out，与域内 NVLink **正交**。
- **Line Card**：选型导览，非架构深读。

### 3.4 与软件栈的「协同」边界（只点一句）

Brief / 产品页反复出现 Dynamo、TensorRT-LLM、NeMo、SHARP、Confidential Computing（TEE-I/O、NVLink 在线保护）等——含义是：**精度与互联的硬件能力，要靠编译器/运行时/集合通信才变成 tokens/s**。实现与引擎选型 → **B7 / [[AI基础设施总览]]**；本篇只保留「硬件已为 FP4 + 72 卡域 + SHARP FP8 预留钩子」这一层。

## 四、Google Cloud TPU（官方 HTML 线）

### 4.1 何时用 TPU（intro 文档口径）

*Introduction to Cloud TPU*：TPU 为矩阵运算 ASIC，片上 **HBM**；以 **slice** 扩展；图须经 **XLA** 编译。适合：矩阵主导、主循环无大量自定义 CPU op、大 batch、长时间训练、超大 embedding（SparseCore 叙事）。不适合：频繁分支/元素级代数、需高精度算术、主循环大量自定义 op。

### 4.2 系统抽象（architecture 文档）

- **Chip / TensorCore**：MXU（脉动阵列）+ vector + scalar；较新代 MXU 为 **256×256**（v6e、TPU7x），更早多为 **128×128**；乘用 **bfloat16** 输入、累加 **FP32**（文档通述）。
- **Pod / Slice / Topology**：Pod 内专用网；slice 用 **ICI**；2D 或 3D 拓扑；**Multislice** 用 DCN 跨 slice。
- **SparseCore**：稀疏/embedding 加速（v5p、TPU7x 每芯片 4；v6e 每芯片 2）。

### 4.3 代际对照表（文档表直接摘录）

| 规格 | **v5p** | **v6e (Trillium)** | **TPU7x (Ironwood)** |
|---|---|---|---|
| Chips / Pod | 8960 | 256 | **9216** |
| Peak / chip **BF16** | 459 TFLOPs | 918 TFLOPs | **2307** TFLOPs |
| Peak / chip **FP8** | 459 TFLOPs | 918 TFLOPs | **4614** TFLOPs |
| HBM / chip | 95 GiB | 32 GiB | **192** GiB |
| HBM BW / chip | 2765 GBps | 1638 GBps | **7380** GBps |
| TensorCores / chip | 2 | 1 | 2 |
| SparseCores / chip | 4 | 2 | 4 |
| ICI 双向 / chip | 1200 GBps | 800 GBps | **1200** GBps |
| DCN / chip | 50 Gbps | 100 Gbps | 100 Gbps |
| 互联拓扑（文） | （见 v5p 专页） | **2D torus** | **3D torus**（可至 9216；cube=4×4×4） |

**Ironwood 双 chiplet（TPU7x 页）：**

- 每 chiplet：1 TensorCore + 2 SparseCore + **96 GB** HBM；两 chiplet 经 **D2D**（文称约 **6×** 于 1D ICI 链路）。
- 编程模型：JAX 等将每芯片暴露为 **两个 device**（第四维区分 chiplet）；相对 v4/v5p 的 MegaCore 统一内存是代际变化。
- 框架注记：TPU7x 支持 **JAX / PyTorch**；**TensorFlow 不支持**（文档 Note）。

**v6e 补充：** 每芯片 1 TensorCore、2 MXU；ICI **4 ports**；Pod **256** chips；推理友好配置含单 VM 挂 **8** chips（`v6e-8`）等。

**精度跟读：** 官方表突出 **BF16 / FP8**（及 v6e 的 Int8 TOPs）；**未见与 NVIDIA 同款的「FP4 Tensor 峰值」列**——若业务对比 FP4，需另寻 Google 量化/训练文档，**本篇不编造 TPU FP4 峰值**。

**Ironwood 独立 PDF：** 检索窗内以 cloud.google.com HTML / Blog 为主 → **「待核实」**（无与 Blackwell Technical Brief 对等的单一 PDF 白皮书落盘）。

## 五、对照：部署侧「三轴」一张表

| 轴 | **NVIDIA Blackwell 线** | **Google TPU 线** |
|---|---|---|
| **代际原子** | 双 die GPU → Grace+GPU Superchip → **NVL72 机架** | Chip → Host(4/8 chip VM) → **Slice / Pod**（至 9k+ chips） |
| **低精度** | **FP8 / FP6 / FP4** + micro-tensor scaling；TE 第二代 | 表列 **BF16 / FP8**（TPU7x FP8=2×BF16）；MXU bf16×→fp32 acc |
| **高带宽域** | 第 5 代 **NVLink** 1.8 TB/s/GPU；域内 **130 TB/s** @72 | **ICI**（TPU7x 1200 GBps/chip 双向）；3D torus / Multislice+DCN |
| **内存** | 机架级 HBM3e **13.5–20 TB** + Fast memory **31–37 TB**（Table 2） | 单芯片 HBM 至 **192 GiB**（TPU7x）；另有 VMEM / Host 分层 |
| **软件钩子（仅索引）** | CUDA-X / Dynamo / TRT-LLM / NeMo / SHARP | **XLA** + JAX/PyTorch；Pallas 等（Blog 线，本篇不展开） |
| **一手形态** | Technical Brief + Datasheet **PDF 已落盘** | **HTML 一手**；Ironwood PDF **待核实** |

**跟读抓手：** 两边都在卖「把通信留在专用高带宽域、把精度降到硬件原生支持的最低有效位、用机架/Pod 卖规模」；差异在 **域的几何（NVLink Switch 域 vs ICI torus）** 与 **公开精度表是否下探到 FP4**。
