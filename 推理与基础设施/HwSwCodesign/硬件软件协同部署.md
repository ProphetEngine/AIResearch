# Hardware–Software codesign：NVIDIA Blackwell / Google TPU 部署侧白皮书线

> **主要来源**：[NVIDIA Blackwell 架构页](https://www.nvidia.com/en-us/data-center/technologies/blackwell-architecture/)；[NVIDIA GB200 NVL72 产品页](https://www.nvidia.com/en-us/data-center/gb200-nvl72/)；[NVIDIA GB300 NVL72 产品页](https://www.nvidia.com/en-us/data-center/gb300-nvl72/)；[NVIDIA NVLink 页](https://www.nvidia.com/en-us/data-center/nvlink/)；[Introduction to Cloud TPU](https://cloud.google.com/tpu/docs/intro-to-tpu)；[TPU 系统架构](https://cloud.google.com/tpu/docs/system-architecture-tpu-vm)；[TPU7x（Ironwood）](https://cloud.google.com/tpu/docs/tpu7x)（截至 2026-10-07）
> **研究线**：AI Infra——部署成本的硬件侧底座
> **范围与相邻笔记**：
> - ≠ [[AI基础设施总览]]：本篇不写训练并行、FlashAttention、PagedAttention。
> - ≠ [[推理引擎生态]]：本篇不写引擎选型与投机解码；Dynamo、TensorRT-LLM 等只作白皮书措辞的索引。
>
> **意义**：大模型推理的单位成本主要由三件事决定——每代芯片的显存带宽与容量、硬件原生支持的最低精度、能把多卡连成统一高带宽域的互联；Blackwell 与 TPU 两条产品线都在这三条轴上同时加码，读懂这三轴才能解释白皮书数字为何会落到每 token 成本上。

**一句话**：代际决定每卡搬多少字节，精度决定每个参数占多少字节，互联决定多卡之间搬字节的代价；三者相乘，才是部署成本。

---

## 一、问题背景：为什么硬件规格会变成成本

以下为综合 [[推理引擎生态]] §3.1、[[PrefillDecode分离与统一服务]]、[[NVSHMEM与DeepEP通信]] 与 NVIDIA Blackwell 架构页、NVIDIA NVLink Fusion 技术博客、TPU 系统架构文档的归纳，未做实测。decode 逐 token 生成时，每一步都要把权重和 KV 缓存从 HBM 读一遍，算得少、搬得多（[[推理引擎生态]] §3.1；[[PrefillDecode分离与统一服务]] 也把 decode 定性为 memory-bound），所以单卡产出 token 的速度首先看 HBM 带宽。精度一侧，[Blackwell 架构页](https://www.nvidia.com/en-us/data-center/technologies/blackwell-architecture/)称 micro-tensor scaling 让 FP4 可用，并使显存所能支撑的模型性能与规模加倍：每个参数占的字节更少，同样的容量装得下更大的模型，同样的带宽每秒读得更多参数。互联一侧，专家并行每层都要按路由结果做跨卡 all-to-all（[[NVSHMEM与DeepEP通信]]），通信留在 NVLink 或 TPU ICI 这类高带宽域内，代价远低于跨域网络：[NVIDIA 技术博客](https://developer.nvidia.com/blog/integrating-custom-compute-into-rack-scale-architecture-with-nvidia-nvlink-fusion/)称第五代 NVLink 每 GPU 双向 1.8 TB/s，是 PCIe Gen5 的 14 倍；TPU 一侧 slice 内走 ICI、跨 slice 走带宽低得多的 DCN（TPU 系统架构文档；数字见第四节表）。

因此「代际 × 精度 × 互联」是同一笔账：每 token 要搬的字节数，除以每秒能搬的字节数。

## 二、脉络

| 节点 | 内容 | 来源 |
|---|---|---|
| Hopper → Blackwell | 晶体管增至约 2080 亿（相对 Hopper 超过 2.5×），双 die 合成一块 GPU；精度下探到 FP6 / FP4 | Blackwell 架构页（2080 亿、双 die、FP4）；[CUDA 12.8 技术博客](https://developer.nvidia.com/blog/cuda-toolkit-12-8-delivers-nvidia-blackwell-support/)（超过 2.5×）；GB200 NVL72 产品页规格表（FP8/FP6 Tensor Core 行） |
| 单卡 → Superchip → 机架 | Grace CPU + 2 块 GPU 组成 Superchip，36 个 Superchip 组成 GB200 NVL72，72 卡一个 NVLink 域 | GB200 NVL72 产品页 |
| Blackwell → Blackwell Ultra | 架构页称 Blackwell Ultra Tensor Core 的 AI 算力 FLOPS 为 Blackwell GPU 的 1.5×、attention 层加速为 2×；GB300 NVL72 产品页写作稠密 FP4 Tensor Core FLOPS 为 Blackwell 的 1.5× | 架构页；GB300 NVL72 产品页 |
| TPU v5p → v6e → TPU7x | 单芯片 BF16 从 459 到 2307 TFLOPs，HBM 带宽从 2765 到 7380 GBps，Pod 最大 9216 芯片 | TPU7x 文档 |

## 三、NVIDIA Blackwell 的三条轴（架构页、NVL72 产品页、NVLink 页）

### 3.1 代际：双 die 与机架级单元

- 两个接近光罩极限的 die 以 10 TB/s 的芯片间互联连成单一 GPU（架构页）。
- 算力口径：GB200 NVL72 产品页规格表按整机与 Superchip 两列给出 NVFP4 Tensor Core 算力，每个 GB200 Superchip（1 个 Grace CPU + 2 块 Blackwell GPU）稀疏 40、稠密 20 PFLOPS，整机 72 卡稀疏 1,440、稠密 720 PFLOPS；按 72 卡折算，每块 GPU 约为稀疏 20、稠密 10 PFLOPS（本篇推算）。
- Grace 与 GPU 之间经 NVLink-C2C 互联（GB200 NVL72 产品页），架构页称这条高速链路双向 900 GB/s。
- 设计含义：卖的不是一块卡，而是让模型并行尽量停在 72 卡高带宽域内的机架级单元。

### 3.2 精度：FP8 / FP6 / FP4 与细粒度缩放

- Blackwell Tensor Core 新增精度，包括社区定义的 microscaling 格式（架构页）；GB200 NVL72 规格表列出从 FP64 到 NVFP4 的各档 Tensor Core 算力。
- 第二代 Transformer Engine 用 micro-tensor scaling 做细粒度动态范围管理，让 FP4 可用于推理；收益见第一节。
- 架构页称 Blackwell Ultra Tensor Core 的 attention 层加速为 Blackwell 的 2×，服务长序列推理。
- 同为 Blackwell 架构的 GeForce RTX 50 系列也原生支持 FP4。NVIDIA 博客称，相对 FP16，FP4 占用的显存不到一半（[CES 2025 博客](https://blogs.nvidia.com/blog/generative-ai-studio-ces-geforce-rtx-50-series/)），模型体积最多缩小 60%、性能提高一倍以上（[RTX AI Garage 博客](https://blogs.nvidia.com/blog/rtx-ai-garage-blackwell-nim-blueprints-pc/)）；两篇博客都举 FLUX.1 [dev] 为例：FP16 需要 23 GB 以上显存，FP4 不到 10 GB，因而能在更多 GeForce RTX 卡上本地运行。这说明精度轴直接改写「哪些模型能本地跑」，但数字绑定具体模型与量化链路，不外推到 LLM 服务。

### 3.3 互联：第五代 NVLink

| 项 | 数字与出处 |
|---|---|
| 每 GPU | 最多 18 条链路，合计 1,800 GB/s（NVLink 页）；NVLink Fusion 技术博客称双向 1.8 TB/s，是 PCIe Gen5 的 14 倍 |
| 域规模 | 第五代 NVLink 最多可扩展到 576 GPU；NVL72 单域 72 GPU，NVLink Switch 芯片提供域内 130 TB/s（架构页） |
| 集合加速 | 架构页称 NVLink Switch 芯片借支持 FP8 的 SHARP 带来 4× 带宽效率 |
| 机架外 | GB300 NVL72 产品页写明配 Quantum-X800 InfiniBand 或 Spectrum-X 以太网，每 GPU 经 ConnectX-8 SuperNIC 获得 800 Gb/s 网络连接，负责跨机架扩展，与域内 NVLink 分工 |

### 3.4 机架规格（NVL72 产品页规格表，稀疏 / 稠密）

| | [GB300 NVL72](https://www.nvidia.com/en-us/data-center/gb300-nvl72/) | [GB200 NVL72](https://www.nvidia.com/en-us/data-center/gb200-nvl72/) |
|---|---|---|
| FP4 Tensor | 1,440 / 1,080 PFLOPS | 1,440 / 720 PFLOPS（NVFP4） |
| FP8/FP6 Tensor | 720 PFLOPS（页面只列稀疏） | 720 / 360 PFLOPS（页面注明稠密为稀疏的一半） |
| GPU 显存（HBM3E） | 20 TB | 13.4 TB |
| GPU 显存带宽 | 最高 576 TB/s | 576 TB/s |
| Fast Memory | 37 TB | 页面未列 |

## 四、Google TPU 的三条轴（Cloud TPU 文档）

### 4.1 系统抽象

- TPU 是矩阵运算专用芯片，计算图须经 XLA 编译；适合矩阵主导、大 batch、长时间训练，不适合频繁分支与大量自定义算子（Introduction 文档）。
- MXU 为脉动阵列，v6e 与 TPU7x 是 256×256，bfloat16 输入、FP32 累加；slice 内芯片经 ICI 互联，跨 slice 经 DCN（Multislice）；SparseCore 加速 embedding（系统架构文档）。

### 4.2 代际对照（TPU7x 文档表）

| 规格 | v5p | v6e | TPU7x |
|---|---|---|---|
| 每 Pod 芯片数 | 8960 | 256 | 9216 |
| 每芯片 BF16 | 459 TFLOPs | 918 TFLOPs | 2307 TFLOPs |
| 每芯片 FP8 | 459 TFLOPs | 918 TFLOPs | 4614 TFLOPs |
| 每芯片 HBM | 95 GiB | 32 GiB | 192 GiB |
| HBM 带宽 | 2765 GBps | 1638 GBps | 7380 GBps |
| ICI 双向 | 1200 GBps | 800 GBps | 1200 GBps |
| DCN | 50 Gbps | 100 Gbps | 100 Gbps |

TPU7x 用 3D torus 拓扑（单元为 4×4×4 立方），每芯片两个 chiplet、各 96 GB HBM，chiplet 间 D2D 带宽约为单条 ICI 链路的 6 倍；JAX 等框架把每芯片暴露为两个设备；不支持 TensorFlow。

## 五、两条线对照

| 轴 | NVIDIA Blackwell | Google TPU |
|---|---|---|
| 代际单元 | 双 die GPU → Superchip → NVL72 机架 | 芯片 → slice → Pod（最多 9216 芯片） |
| 低精度 | FP8 / FP6 / FP4 + 细粒度缩放 | 文档表只列到 BF16 / FP8（TPU7x 的 FP8 为 BF16 的 2×），未见 FP4 列 |
| 高带宽域 | NVLink 1.8 TB/s 每 GPU，72 卡域 130 TB/s | ICI 每芯片 1200 GBps，3D torus |
| 内存 | 机架 HBM 13.4–20 TB | 单芯片 HBM 最高 192 GiB |

共同点：都把通信留在专用高带宽域、把精度降到硬件原生支持的最低有效位、按机架或 Pod 卖规模。差异在域的几何（NVLink Switch 全互联 vs ICI torus）与公开精度表是否下探到 FP4。

## 六、意义

- **读规格的方法**：看推理成本时，先看 HBM 带宽与容量（决定 decode 速度与能放多大模型），再看原生最低精度（决定每参数字节数），最后看高带宽域的大小（决定并行能否不出域）。
- **软件要跟上才兑现**：架构页提到的 Dynamo、TensorRT-LLM、SHARP 等说明，精度与互联能力要靠编译器、运行时、集合通信才变成 tokens/s。

## 七、局限与待核实

- **Ironwood 白皮书**：2026-09-22 未找到 TPU7x 的单一架构白皮书，TPU 数字以 HTML 文档为准，待核实。
- **营销口径**：产品页的峰值 PFLOPS、Blackwell Ultra 相对 Blackwell 的 1.5× 与 2×，以及架构页、产品页中多组相对 Hopper 的倍数，都是厂商口径或投影，不是独立实测；每 GPU 算力是本篇按整机 72 卡折算的。
- **NVFP4 / OCP microscaling 的位级定义**：本篇不展开，以独立规范为准。
- **跨厂商比较**：两家公开精度列不对齐（TPU 表无 FP4），不宜直接比峰值。
- **Vera Rubin**：NVIDIA 已有下一代 Rubin 平台页，本篇不展开。
