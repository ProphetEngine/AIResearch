# Privacy-preserving inference：GPU/CPU TEE 机密计算（信任边界 × CC tax）

> **主要来源**：[Benchmarking Confidential Computing Performance on NVIDIA Blackwell GPUs](https://arxiv.org/abs/2608.26575)（Asad、Grunseid，Confidential.ai，v2 2026-09-01，以下简称 Blackwell 文）；[EnclaveX: End-to-End Confidential AI with CPU/GPU TEEs](https://arxiv.org/abs/2606.31408)（Schambach、Le、Arnautov、Fetzer，德累斯顿工业大学、STACKIT、Scontain，v1 2026-06-30）（截至 2026-09-01）。
> **研究线**：架构思想（主：CPU 可信执行环境、GPU 机密计算模式与应用层之间的信任边界，以及远程证明链）；评测字段（辅：机密计算带来的吞吐与时延开销、证明延迟）
> **范围与相邻笔记**：
> - ≠ [[隐私与机器遗忘]]：那篇事后从权重里去除知识，本篇在运行时用硬件隔离保护数据，不写遗忘算法。
> - ≠ [[端侧小模型]]：「数据不出设备」是另一条路线，本篇写公有云与多租户上的机密虚拟机加机密 GPU。
> - 两文都把侧信道排除在威胁模型之外；本篇只记防御配置与开销，不写任何攻击方法。
>
> **意义**：在别人的基础设施上跑模型，提示词、生成结果、KV 缓存和模型权重在主机内存与互连上都是明文，虚拟机监控器、宿主机系统、其他租户或能物理接触机器的人都可能读到。机密计算用硬件加密与远程证明把运营方移出可读范围，长期的顾虑是代价。Blackwell 文在 8 张 B200 上做成对对照，发现配置正确时机密推理的吞吐开销只有约 1%–3%，常见的 30%–40% 来自可避免的软件配置；开销集中在主机与 GPU、GPU 与 GPU 的加密边界上，而非 GPU 计算本身。EnclaveX 补上另一半：仅有机密虚拟机还不够，Kubernetes 管理员仍能进入虚拟机读取数据，它在应用通过证明之后才下发密钥，额外证明延迟约 1.3%。两文合看，机密推理的成本主要是工程问题，安全边界则要一直画到应用层。

## 一、问题背景

可信执行环境（TEE）为上层提供三项性质（Blackwell 文 §2.1）：机密性，客户机内存由硬件加密，宿主机系统与虚拟机监控器拿不到密钥；完整性，对内存的重放、篡改或重映射会被硬件发现；远程证明，硬件对启动时装载的软件做签名度量，链到厂商的根信任，远端先验证再信任。两文的栈都是 Intel TDX 机密虚拟机加 NVIDIA 机密计算（CC）模式：GPU 机密启动，PCIe 与多卡 NVLink 上的流量加密，TDX 报告与 GPU 证明报告都验证通过后 GPU 才释放会话密钥。

已有的 Hopper 测量把开销主要归于 CPU 与 GPU 之间经 PCIe 的数据传输。Blackwell 文要回答的是：在多卡、生产级推理栈上，开销具体落在哪条加密边界、能否靠软件消除。EnclaveX 要回答的是：机密虚拟机加机密 GPU 之后，谁仍在可信计算基（TCB）里。

## 三、信任边界与开销机制

### 3.1 四条加密边界（Blackwell 文 §2.2、§5.1）

| 边界 | 机制 | 对推理的含义 |
|---|---|---|
| PCIe 批量传输 | 主机与设备之间经驱动的回弹缓冲区做 AES-GCM | 加载权重与回读采样结果按字节付费；热路径上权重与 KV 应常驻 GPU |
| 命令通道 | 每次提交内核都走加密的 GSP-RPC | 每次提交固定多付约 12 µs，逐个提交内核时被放大 |
| NVLink 加密（NVLE） | 跨卡集合通信加密 | 按字节付费，通信占比大时不随批量摊薄 |
| 能力损失 | NVSwitch 多播被禁用 | 依赖多播的融合核要换成无多播路径 |

单核 AES-256-GCM 上限约 13.9 GB/s，实测机密 PCIe 路径约 10 GB/s；每张 GPU 的安全会话在当前实现里是单线程、绑定单核，所以扩展靠加 GPU，加宿主线程没用。

### 3.2 两轴开销模型（Blackwell 文 §4）

1. **按主机操作计**：机密模式下每次内核提交与主机设备同步都更贵，是每个解码步的固定成本，随批量增大而摊薄，可用完整的 CUDA graph 与框架补丁消除。
2. **按 NVLink 流量计**：加密的跨卡流量按近似恒定的每字节费率计费，端到端成本取决于跨卡通信占每步时间的比例；比例大时不随批量摊薄，是软件去不掉的硬件下限。

哪一轴占主导，取决于负载形状与软件版本，所以开销不是一个常数。

### 3.3 EnclaveX：证明通过后才下发密钥（§1、§3）

仅用机密容器或机密虚拟机加 H200 机密 GPU 时，Kubernetes 管理员仍可 `kubectl exec` 进入机密虚拟机，相当于 enclave 内的 root。EnclaveX 的组件：

- Intel TDX 提供虚拟机级的内存隔离，NVIDIA H200 机密 GPU 由虚拟机内的驱动保护 IO；
- SCONE 运行时提供进程级的屏蔽执行，目标是更小的 TCB；
- 配置与证明服务（CAS）本身运行在 TEE 中，管理策略、验证证明，通过后才供给密钥；
- 客户机内核模块在运行时度量 ML 应用，并关闭客户机内的内存转储。

流程是先证明 CAS，再证明虚拟机与 GPU，再证明运行中的应用，最后才下发配置与解密密钥，应用代码不用修改。威胁模型假设攻击者可控制系统软件与虚拟机监控器、物理探测内存、拥有 Kubernetes 全部 API 权限并能篡改网络，侧信道与拒绝服务不在范围内。

## 四、结果

**Blackwell 文头条数字**（Table 2、§4；均为配置正确时相对非机密的开销）：

| 负载 | 开销 |
|---|---|
| MoE 服务，4 卡张量并行，偏解码 | 约 1.5% |
| MoE 服务，8 卡张量并行，偏解码 | 约 3%（两轮五次重复的中位数为 2.8% 与 3.6%） |
| 单卡，完整 CUDA graph 加框架补丁 | 低于 1% |
| 8 卡训练（bf16） | 10%–13% |

- **提交税**（§5.2）：单次内核提交从 3.45 µs 增至 15.7 µs，单纯同步几乎不变。合成解码每步约 181 次提交，逐个提交时机密模式慢 2.41 倍，整步捕获成一个 graph 后只慢 1.04 倍。vLLM 0.22 在单张 B200 上运行 Qwen3.5-9B，解码 1179 对 1772 token/s，倒推每步多 2.28 ms，约等于按注意力层切分的 graph 所需的 185 次提交乘 12 µs；加解密本身在解码中只占 0.5% 的 CPU 时间。
- **NVLink 下限**（§5.3）：拷贝引擎带宽约降 11%，基于 SM 的拷贝约降 18%，NCCL 集合通信约降 10%；PCIe 主机到设备的带宽为 3.5 对 51.6 GB/s，但只影响加载阶段。
- **单卡**（§6）：关闭调度重叠时开销约 2%；打开重叠的原版 SGLang 运行 Qwen3-8B 时开销 34%–39%，原因是机密模式强制每步的 token 回读同步，GPU 利用率从约 74% 降到约 57%；把回读移到异步线程的补丁加完整 graph 后低于 1%，不同输入输出形状下中位数 1.2%、最差 6.5%。
- **多卡 MoE**（§7，MiniMax-M2.7，约 2290 亿参数的 MoE）：输出从 256 增至 2048 token 时开销从 14.4% 降到 1.1%，并发增大时平台在约 5.4%；4 卡的吞吐约为 8 卡的 94%。有注意力张量并行时输入越长开销越高，没有张量并行（数据并行注意力加专家并行）时输入越长开销越低，3970 亿参数模型在 32k 上下文约 2%。
- **训练与资源**（§8、§10）：8 卡 dense 张量并行约 13%，调优后的 MoE 专家并行约 11%，全部来自加密集合通信；FP8 训练在机密模式下损失更多，作者建议默认 bf16。机密模式在 B200 上固定预留 **700 MB** 显存，能耗不受影响，部分情况下更低，因为变慢时 GPU 更多处于空闲。

**EnclaveX**（§5，H200 NVL 141GB，Triton 25.01 加 TensorRT-LLM 0.17.0，Llama-3.1-8B-Instruct FP8）：

| 对比 | 指标 | 结果 |
|---|---|---|
| SCONE 对机密虚拟机 | 吞吐、token 间隔、首 token 时延 | 无显著开销（SIM 模式依赖虚拟机的内存保护，不再二次加密） |
| 机密虚拟机对非机密 | 吞吐 | 35.0%–62.8%，随批量增大而下降 |
| | token 间隔 | 35.2%–73.9%，随批量增大而下降 |
| | 首 token 时延 | 11.2%–38.3%，随输入变长而下降 |
| 证明 | TDX 加机密 GPU 原生证明 | 平均 1.1611 秒 |
| | 加应用层证明 | 再加 0.0147 秒，合计约 1.1758 秒，约多 1.27% |

作者把机密虚拟机的开销归于 CVM 与机密 GPU 之间经回弹缓冲区的加密 IO，计算占比上升时开销下降；TDX Connect 等可信设备 IO 方案 NVIDIA 机密 GPU 尚不支持。

## 五、意义

Blackwell 文把「机密计算慢」拆成了可操作的部分：单卡上的高开销主要是推理框架没有为机密模式改造，属于软件问题，正在上游修复；多卡上剩下的是加密 NVLink，随跨卡流量而非算力增长。由此得到的部署要点很具体：始终用完整 CUDA graph，用带机密补丁的框架，权重与 KV 常驻 GPU，张量并行宽度按需取、长上下文优先数据并行注意力加专家并行，偏解码的负载开销最低，GPU 侧的性能剖析在机密模式下被关闭，观测改在宿主侧做（§11）。EnclaveX 说明硬件 TEE 只解决了基础设施运营方的问题，云上 Kubernetes 的管理权限是另一类内部威胁，需要应用层证明加密钥托管来处理，而这一步几乎不增加延迟。

## 六、局限与待核实

- **Blackwell 文的范围**（§1.3）：只测性能，不审计任何安全性质；不测证明与机密虚拟机的启动开销；不测跨节点传输。§9 指出 GPU 机密模式下 GPUDirect RDMA 直接不可用，机密客户机也不支持锁页主机内存，跨节点 KV 传输只能绕道 CPU 并走加密回弹缓冲区，PD 分离部署因此更难，但没有给出端到端测量；TDISP 等把设备 DMA 纳入可信边界的方案只是方向。
- **Blackwell 文的数据与利益**：数据跨两个框架的多个版本、历时数周收集，作者说明跨行比较只有方向意义，行内的机密与非机密对比才是受控的。作者来自机密计算公司，单卡补丁由作者自己实现。§1.3 说局限汇总在 §10，实际的 §10 是开销汇总表，没有单独的局限节；单卡未打补丁的开销在 §4 写作 35%–39%，§6 写作 34%–39%。
- **Blackwell 文版本差异**：v2 相对 v1（2026-08-27）只去掉了一位作者，正文没有变化。
- **EnclaveX 的证明测量**：测试平台是预生产系统，Intel 的报告验证库无法验证其报告，作者跳过了这一步，也跳过了部分 H200 报告度量的验证；应用层证明的标准差（0.1508 秒）大于均值（0.0147 秒）。内核模块写的是「将开源」。
- **两文不可合并成一个数字**：两文的对照都是非机密虚拟机，但 GPU 代际（B200 与 H200）、推理栈（打补丁的 SGLang 与 Triton 加 TensorRT-LLM）和负载都不同，EnclaveX 的几十个百分点与 Blackwell 文的 1%–3% 不能直接比较。
- **与 [[硬件软件协同部署]] 的口径**：那篇引 NVIDIA 架构页，称 Blackwell 是业界首款支持 TEE-I/O 的 GPU，说的是硬件能力；EnclaveX 在 H200 平台上引 NVIDIA 2025 年的可信计算发布说明，称机密 GPU 尚不支持 TDX Connect、SEV-IO 等可信设备 IO；Blackwell 文也说 TDISP 所需的硬件与驱动支持在其 B200 测试栈上尚未提供。三者说的分别是硬件能力和当时的软件栈，并不直接矛盾；何时可用以 NVIDIA 最新文档为准。
