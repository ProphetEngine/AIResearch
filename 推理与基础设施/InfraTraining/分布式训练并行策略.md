# 分布式训练并行策略

> **主要来源**：[Megatron-LM: Training Multi-Billion Parameter Language Models Using Model Parallelism](https://arxiv.org/abs/1909.08053)；[GPipe: Efficient Training of Giant Neural Networks using Pipeline Parallelism](https://arxiv.org/abs/1811.06965)；[ZeRO: Memory Optimizations Toward Training Trillion Parameter Models](https://arxiv.org/abs/1910.02054)；[Efficient Large-Scale Language Model Training on GPU Clusters Using Megatron-LM](https://arxiv.org/abs/2104.04473)；[PyTorch FSDP: Experiences on Scaling Fully Sharded Data Parallel](https://arxiv.org/abs/2304.11277)；[Ring Attention with Blockwise Transformers for Near-Infinite Context](https://arxiv.org/abs/2310.01889)（截至 2026-10-08）。其余来源见第八节。
> **研究线**：AI Infra（五种并行各切什么、通信从哪来、怎样组合）· 架构思想（模型结构如何决定可用的切法）
> **范围与相邻笔记**：
> - ≠ [[AI基础设施总览]]：本篇不重写 Megatron 列切/行切的推导、FlashAttention 与 PagedAttention；只把该篇第二节的并行概述扩成完整的概念地图。
> - ≠ [[DeepSeekV3训练与MoE基建]]：本篇不写 DualPipe 的气泡公式与 V3 的跨节点 all-to-all 参数，只把 V3 作为组合案例引用。
> - ≠ [[NVSHMEM与DeepEP通信]]：本篇不写专家并行的通信内核实现，只写专家并行在并行组合中的位置。
> - ≠ [[混合专家架构]]：本篇不写路由与负载均衡算法。
> **意义**：并行策略把模型规模与集群规模解耦，是 MoE、长上下文与 RL 训练系统共同的前置知识；近一年的重心从「切得开」转向「把通信藏到计算背后」。

**一句话**：大模型训练要同时解决「装不下」（参数、梯度、优化器状态、激活超出单卡显存）和「算不完」（总算力需求超出单卡）两个问题；业界把模型和数据沿五个维度切开——样本（数据并行）、层内矩阵（张量并行）、层序（流水线并行）、序列（上下文并行）、专家（专家并行），再按网络带宽由内到外叠成 3D/4D 组合。每种切法都用一种通信换一种显存或算力，选型的核心是让通信落在够快的链路上、并尽量被计算盖住。

## 一、问题背景：装不下与算不完

1. **显存账**。以混合精度 Adam 为例，每个参数要存 FP16 权重与梯度各 2 字节，外加 FP32 主权重、一阶矩、二阶矩共 12 字节，合计约 16 字节/参数；ZeRO 论文以 7.5B 模型为例，仅模型状态就需约 120 GB（ZeRO §5、图 1）。激活还随批量与序列长度增长，长上下文训练时常成为最大头。
2. **算力账**。即使显存够，单卡也无法在合理时间内完成万亿 token 级的训练，必须把一步训练的计算摊到成百上千张卡上。
3. **通信账**。切开就要同步：梯度要归约，层内部分结果要合并，层间要传激活，跨卡注意力要交换 K/V，MoE 要把 token 发给远端专家。通信能否被计算重叠、能否落在节点内高速互联上，决定了扩展效率。

因此「怎么切」不是一个开关，而是在显存、通信、计算效率（以及实现复杂度）之间找平衡的组合问题。

演进主线可概括为三步：先解决「切得开」（2018–2019，流水线、张量、ZeRO 各自成形），再解决「组合得好」（2021–2022，三维组合的配置法则与激活显存优化），最后转向「长序列与稀疏」（2023 年起，上下文并行、专家并行与通信重叠成为主角）。

## 三、核心机制：五种并行各切什么

### 3.1 数据并行与 ZeRO/FSDP：切样本，再切冗余

- **朴素数据并行**：每卡一份完整模型，各算一份数据，反向后对梯度做 all-reduce。通信只在每步末尾一次、易与反向重叠，所以扩展最简单；问题是每卡都存全套模型状态，模型一大就装不下。
- **ZeRO 的观察**：数据并行的 N 份模型状态是完全冗余的，可以每卡只保管 1/N，需要时再取。三阶段依次切优化器状态（显存约降至 1/4，通信量与数据并行相同）、梯度（约 1/8，通信量仍相同）、参数（显存随卡数线性下降，通信量约为数据并行的 1.5 倍）（ZeRO §5、§7）。
- **代价在哪**：第三阶段每层前向、反向前都要 all-gather 该层参数，用完即丢，通信从「每步一次」变成「每层一次」，依赖与计算重叠和足够大的批。
- **FSDP**：PyTorch 原生的全分片实现，与张量实现、调度器、显存分配器协同设计；论文称性能与 DDP 相当，同时支持大得多的模型（摘要）。Llama 3 的用法说明了实践中的折中：分片优化器状态与梯度，但前向后不重新分片参数，以免反向时多一次 all-gather（Llama 3 §3.3.2）。

### 3.2 张量并行与序列并行：切层内矩阵

- **思想**：把一层内的大矩阵乘按列或按行切到多卡。Megatron 的关键是让非线性留在分区内——第一层按列切、第二层按行切，使每个 MLP 或注意力块前向只需一次 all-reduce（细节见 [[AI基础设施总览]] 2.2 节）。
- **代价**：每层都有同步，且处在计算关键路径上，所以张量并行几乎总被限制在节点内的 NVLink 域（Megatron 集群训练论文的经验法则一：张量并行度一般不超过单机 GPU 数）。切得太细时子矩阵乘变小，GPU 效率下降。
- **序列并行（Megatron 意义）**：张量并行没有切 LayerNorm、Dropout 等逐 token 运算，它们的激活在每卡重复保存。Korthikanti 等把这些运算沿序列维切开，把原来的 all-reduce 换成 reduce-scatter 加 all-gather；由于 ring all-reduce 本就由这两步组成，通信带宽不变（激活重计算论文 §4.2.2），配合选择性重计算，激活显存约降为 1/5，重计算开销减少九成以上（摘要）。

### 3.3 流水线并行：切层序，与气泡周旋

- **思想**：把连续若干层放在一个阶段（stage），各阶段在不同设备上，层间只传激活。通信量小、只是点对点，适合跨节点。
- **气泡**：第一个微批要走完所有阶段，后面的阶段才开始忙；一批结束时又要排空。GPipe 式调度下气泡占理想计算时间的比例为 $(p-1)/m$（$p$ 为阶段数，$m$ 为微批数）（Megatron 集群训练论文 §2.2.1）。要让气泡小就得 $m\gg p$，但同时在飞的微批越多，要暂存的激活越多。
- **1F1B**：稳态时每个阶段交替做一次前向、一次反向，尽早释放激活，把在飞微批数限制在 $p$ 以内；气泡不变，但显存大幅下降。
- **交错式 1F1B**：每卡负责 $v$ 段不相邻的层（虚拟阶段），气泡降为 $\frac{1}{v}\cdot\frac{p-1}{m}$，代价是点对点通信次数增加 $v$ 倍（Megatron 集群训练论文 §2.2.2）；论文称吞吐可提升 10% 以上（摘要）。
- **零气泡**：反向可拆为对输入求梯度（B，下游阶段在等它）和对权重求梯度（W，没人等它）。把 W 挪去填气泡，ZB-H1 在不超过 1F1B 显存峰值的前提下缩小气泡，ZB-H2 在放宽显存时可做到零气泡；论文报告相对 1F1B 吞吐最高提升 23%，放宽显存后 31%（Zero Bubble 论文摘要、§2）。DeepSeek-V3 的 DualPipe 沿用了这一拆分，并把 MoE 的 all-to-all 也塞进前向/反向块的重叠中（见 [[DeepSeekV3训练与MoE基建]] 第四节）。

### 3.4 上下文并行：切序列，处理长上下文

当序列长到单卡放不下一条样本的激活时，需要把同一条序列切到多卡。难点在注意力：每个 query 要看到此前所有 key/value。

| 路线 | 做法 | 取舍 |
|---|---|---|
| Ring Attention | 序列分块，各卡持有一块 Q 并让 K/V 块沿环传递；每收到一块就做一次分块注意力，通信与计算完全重叠；可处理长度随设备数线性增长（Ring Attention 论文摘要） | 环形步数随卡数增长；因果掩码下按顺序切块会使各卡计算量不均（Llama 3 的分块配对即为负载均衡而设） |
| DeepSpeed-Ulysses | 注意力前用 all-to-all 把「按序列切」转成「按头切」，每卡拿到完整序列的一部分头，算完再转回；序列长度与设备数同比增长时通信量恒定（Ulysses 论文摘要） | 每卡分到若干完整的头，并行度因此不能超过注意力头数 |
| all-gather 式（Llama 3） | 先 all-gather 全部 K/V，再算本地 Q 块；序列切成 $2\times\mathrm{CP}$ 块，第 $i$ 张卡取第 $i$ 与第 $2\times\mathrm{CP}-1-i$ 块以平衡负载（Llama 3 §3.3.2） | 通信暴露在关键路径上；官方称选它有两个理由：更容易支持文档掩码等多种掩码，且 GQA 下 K/V 远小于 Q、注意力是 $O(S^2)$ 而通信是 $O(S)$，暴露的延迟可忽略 |

Llama 3 405B 在 128K 长上下文阶段把 CP 开到 16（Llama 3 表 4）。上下文并行与位置编码、长上下文推理侧的分工见 [[长上下文位置编码与系统侧]]。线性注意力与 SSM 层的上下文并行传的是固定大小的状态而非 K/V，见 [[线性注意力与状态空间模型谱系]]。

### 3.5 专家并行：切专家

- **思想**：MoE 层的不同专家放在不同设备上；每个 token 经路由选中少数专家后，被 all-to-all 发往专家所在卡（dispatch），算完再 all-to-all 收回（combine）。非 MoE 部分照常用其他并行。
- **特点**：MoE 让参数量随专家数增长而每 token 计算量基本不变，专家并行是承载这些参数的自然切法；代价是每层两次 all-to-all，数据量与激活同量级，且受路由不均影响，最忙的卡决定整体速度。
- **为何成为当代主角**：细粒度专家越多、跨节点越多，通信越重。DeepSeek-V3 报告称跨节点专家并行使计算与通信之比约为 1:1，这正是 DualPipe 和定制 all-to-all 内核要解决的问题（[[DeepSeekV3训练与MoE基建]] 第一、四节）。通信内核本身见 [[NVSHMEM与DeepEP通信]]，路由与负载均衡算法见 [[MoE路由与负载均衡]]，MoE 结构的通史见 [[混合专家架构]]。

## 四、组合：3D/4D 并行与网络层级

### 4.1 对照表

| 并行 | 切什么 | 主要通信 | 通信频率 | 主要节省 | 典型放置 |
|---|---|---|---|---|---|
| 数据并行 / ZeRO / FSDP | 样本；ZeRO 再切模型状态 | 梯度 all-reduce；ZeRO-3 加逐层参数 all-gather | 每步一次（ZeRO-3 为每层） | 算力；ZeRO 省模型状态显存 | 最外层，可跨多跳网络 |
| 张量并行（含序列并行） | 层内矩阵 | 层内 all-reduce 或 reduce-scatter/all-gather | 每层多次，在关键路径上 | 权重与激活显存 | 节点内 NVLink |
| 流水线并行 | 层序 | 阶段间点对点传激活 | 每微批每阶段边界 | 权重显存 | 可跨节点 |
| 上下文并行 | 序列 | K/V 环形传递、all-gather 或 all-to-all | 每个注意力层 | 长序列激活显存 | 靠近内层 |
| 专家并行 | MoE 专家 | 两次 all-to-all | 每个 MoE 层 | 专家参数显存 | 节点内或跨少量节点 |

### 4.2 配置法则

1. **按带宽由内到外排**。Llama 3 的排序为 [TP, CP, PP, DP]：最内层要求最高带宽与最低延迟，通常限于同一台服务器；最外层可跨多跳网络，需容忍较高延迟（Llama 3 §3.3.2）。
2. **张量并行到单机为止，再用流水线扩模型，最后用数据并行扩吞吐**。这是 Megatron 集群训练论文的前两条经验法则；论文还指出不合适的 TP×PP 组合可使吞吐差到 2 倍（§1）。
3. **微批大小是隐藏的第三个旋钮**：它同时影响气泡比例、显存与单卡算子效率，最优值依模型而定（Megatron 集群训练论文经验法则三）。
4. **全局批大小有上限**：数据并行度越大，每组分到的批越小，气泡与效率都会受影响。Llama 3 从 8K 卡扩到 16K 卡时 BF16 MFU 由 43% 降到 41%，官方归因于保持全局 token 数不变时每个数据并行组的批变小（§3.3.2、表 4）。

### 4.3 三个公开配置

| 模型 | 组合 | 值得注意的取舍 | 详见 |
|---|---|---|---|
| Llama 3 405B（稠密） | TP8 × PP16 × DP（FSDP），长上下文阶段加 CP16；BF16 MFU 38%–43% | 稠密模型的标准 4D 组合；CP 用 all-gather 而非环形 | 表 4 |
| DeepSeek-V3（MoE） | PP16 × EP64（跨 8 节点）× ZeRO-1 DP，不用 TP | 以 DualPipe 重叠 all-to-all 与流水通信，代价是两份参数副本 | [[DeepSeekV3训练与MoE基建]] |
| Kimi K2（MoE） | EP16 × PP16 × ZeRO-1，交错式 1F1B | 明确不用 DualPipe：它使参数与梯度显存加倍，须加大并行度来弥补，而加大流水线并行会增加气泡、加大专家并行会抬高开销，这些额外代价对万亿参数以上的模型过高；改为增加热身微批，在交错式 1F1B 下重叠专家并行通信 | [[KimiK2技术报告深读]]；K2 报告 §2.4.2 |

三者说明：并行组合没有通用最优解，取决于稠密还是稀疏、单卡显存、互联拓扑，以及对实现复杂度的容忍度。

## 六、意义

- **把模型规模和集群规模解耦**：模型结构不变，通过换切法就能从单机扩到万卡；Megatron 与 ZeRO 让十亿到万亿参数的训练成为工程问题而非算法问题。
- **反过来塑造架构**：可切性影响结构选择。注意力头数影响 Ulysses 的并行度，GQA 让 K/V 变小、使 all-gather 式上下文并行变得划算，MoE 路由中的节点数上限（V3 每 token 最多发往 4 个节点）就是为通信设计的。架构与 Infra 的协同叙事见 [[AI基础设施总览]]。
- **近一年的重心**：从「切得开」转到「藏得住」。DualPipe、零气泡调度和计算-通信重叠的目标都是把通信藏到计算背后；低精度训练是另一条路：矩阵乘以 FP8 执行、理论算力约为 BF16 的两倍，MoE 分发前的激活也以 FP8 传输（DeepSeek-V3 的做法），细节见 [[AI基础设施总览]] 4.3 节与 [[DeepSeekV3训练与MoE基建]] 第四节。优化器层面的分布式适配（如 Distributed Muon）见 [[优化器与训练稳定性]]。

## 七、局限与待核实

1. **数字的口径**：文中吞吐、MFU、扩展效率均绑定原论文的硬件（V100、A100、H100、H800）与实现版本，不能外推为通用值。
2. **ZeRO 显存比例的前提**：4 倍、8 倍的降幅以混合精度 Adam（$K=12$）和较大的数据并行度为前提（ZeRO §5）；其他优化器或精度配置下比例不同。
3. **上下文并行的命名不统一**：Megatron 的「序列并行」（切 LayerNorm/Dropout 激活）与 Ulysses、Ring Attention 一类「序列/上下文并行」（切注意力的序列维）是两回事；不同框架对 CP 与 SP 的称呼有交叉，阅读时需看具体切的是哪部分。
4. **未覆盖的方向**：异构集群、自动并行搜索、激活卸载与 CPU/NVMe 卸载、容错与弹性训练、RL 后训练中训练与推理共置的并行问题，本篇均未展开；二维序列并行（Ring 与 Ulysses 混合）及 PyTorch 原生上下文并行的实现，本篇也未覆盖。
5. **DualPipe 的适用面**：DualPipe 需两份参数副本，DeepSeek 称在大专家并行下影响有限；Kimi K2 则称它使参数与梯度显存加倍、须加大并行度，由此增加的流水线气泡与专家并行开销对万亿参数以上的模型过高（K2 报告 §2.4.2）；两种判断依赖各自配置，本篇不作裁决。
