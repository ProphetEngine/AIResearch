## 一、选型地图：把「引擎」拆成可比较的轴

[[AI基础设施总览]] 已把 serving 的**显存脚**钉在 PagedAttention（KV 分页、近零碎片），并把 DeepSeek-V3 的 **Prefill / Decode 分阶段部署**写成报告级对照。B-7 补的是：**同一套 KV 思想之上，生产引擎在调度、前缀、结构化输出、投机与硬件栈上如何分叉**——方便按工作负载选型，而不是按「谁的博客倍率更大」。

### 1.1 一张对照表（主张均可回溯到论文摘要 / 仓库 README；非第三方榜）

| 轴 | **vLLM（论文基线）** | **SGLang（论文 + README）** | **TensorRT-LLM（README 自述）** |
|----|----------------------|-----------------------------|--------------------------------|
| **问题重心** | 高吞吐 serving 下 **KV 内存浪费与块级共享**（PagedAttention） | **多调用 LM Program**：前缀复用 + 结构化解码 + 前端语言 | **NVIDIA GPU 上的内核 + 运行时优化库**（attention / GEMM / MoE 等） |
| **KV / 前缀** | 分页块 + block table；块级共享（beam / 并行采样） | **RadixAttention**：radix tree 上自动跨请求 / 跨调用复用 KV（论文 §3） | README 列 **prefix caching** 等为特性旗标；细节见其文档/博客族（本卡不编造实现等价于 Radix） |
| **调度** | 与 **iteration-level scheduling** 共设计（vLLM 论文对照 Orca） | continuous batching、chunked prefill、zero-overhead scheduler（README 特性列表） | Prefill–Decode **disaggregation**、Wide EP、speculative decoding 等（README Overview） |
| **结构化输出** | 非论文主贡献 | **Compressed FSM** 加速正则 / JSON 等约束解码（论文摘要；博客另述 jump-forward） | Guided decoding 与 speculative 的组合见其 tech blog 目录（README 链到 blog12 等） |
| **投机解码** | 论文主文非此；生态后续集成属工程层 | README 列 speculative decoding；论文主贡献是 Radix + FSM | README 明确列 Speculative Decoding；文档 API 可见 Eagle / MTP / N-Gram 等配置名（overview 导航） |
| **硬件 / 锁定** | CUDA 中心的开源栈（论文评测） | README：NVIDIA / AMD / TPU / Ascend 等（**自述**覆盖面） | **NVIDIA GPU** 优化库；与 Triton / Dynamo 生态衔接（README） |
| **代表公开倍率（勿外推）** | 相对 FasterTransformer / Orca 等约 **2–4×** 吞吐（vLLM 摘要；[[AI基础设施总览]] 已录） | 相对当时 SOTA 引擎最高约 **6.4×** 吞吐（SGLang 摘要；任务含 agent / JSON / multi-turn 等） | README / 厂商博客含大量 tok/s 叙事——**本卡不抄未独立核验的峰值** |

### 1.2 选型启发式（思想层，非 SLA）

1. **共享前缀极强**（few-shot、多轮、同一系统提示灌大量会话、agent 反复工具调用）：优先看 **RadixAttention / 前缀缓存命中率**，而不是只比单请求 decode tok/s。SGLang 论文把「跨多次 generation call 自动复用 KV」写成相对「请求结束后丢弃 KV」的引擎缺口（§1、§3）。
2. **JSON / 正则约束解码是主路径**：看 **约束解码是否与运行时共设计**（SGLang compressed FSM）；单独套一层 Outlines 式 mask 可能吃掉 continuous batching 红利（论文把 structured output 列为运行时优化机会）。
3. **要在固定 NVIDIA 栈上压延迟 / 做 EP / PD 分离**：TensorRT-LLM README 把自己定位为「自定义内核 + 算法运行时（含 PD disagg、Wide EP、Speculative Decoding）」；选型代价是 **NVIDIA 绑定与引擎/版本演进成本**（README 另有弃用策略说明）。
4. **要可移植、跟开源模型 day-0、兼做 RL rollout 后端**：SGLang README 强调多硬件与 post-training / RL 框架集成（slime、verl 等——**采纳自述，非本卡实测**）。
5. **基线仍是「KV 布局是否分页」**：若部署仍用连续预留最大长度，先回到 [[AI基础设施总览]] / vLLM 论文的碎片叙事；引擎品牌换了也救不了 20%–38% 有效 KV 利用率那类布局病。

### 1.3 与「连续批处理 / PD 分离」的接口（相对 [[AI基础设施总览]] 的调度轴）

- **Continuous / iteration-level batching**：vLLM 论文明确与 Orca 的 iteration-level scheduling 对照，并在 PagedAttention 上共设计（[[AI基础设施总览]] §4.2 已点到；本卡不再复述分页算法）。选型含义：吞吐引擎比的是 **每步可拼进 batch 的活跃序列**，不是静态 batch=64。
- **Prefill–Decode 分离**：DeepSeek-V3 §3.4（[[AI基础设施总览]] 表）给出报告级最小部署单元；SGLang / TensorRT-LLM README 均把 **prefill-decode disaggregation** 列进当代特性。跟读抓手：prefill 算力型、decode 访存型——分池后才能独立扩缩与叠 EP；**不是**对 PagedAttention 的替代，而是调度 / 拓扑层增量。

## 三、投机解码思想（一手论文）

### 3.1 共同瓶颈：decode 受内存带宽束缚

自回归每步通常只产出 **1** 个 token，却往往要搬动近乎整模参数（Medusa 摘要；Chen et al. 引言：sampling 在大模型上 memory bandwidth bound）。投机族的共享直觉：

> **用「便宜的草稿」串行猜一段连续 token，再用目标模型一次前向并行校验；在接受率足够时，减少目标模型的串行步数——而不必改目标架构。**

### 3.2 经典框架：独立草稿模型 + 保分布校验

**Leviathan et al.（2211.17192）** 引入 *speculative decoding*：用更高效的近似模型 $M_q$ 提出前缀，目标模型 $M_p$ 并行计分；配合 *speculative sampling*，在随机设定下最大化接受概率，并保证输出分布与单独跑 $M_p$ **相同**。摘要报告：T5-XXL 上相对标准 T5X 实现约 **2×–3×** 加速，**identical outputs**；无需重训或改架构。

**Chen et al.（2302.01318，DeepMind）** 同期独立提出 *speculative sampling*：草稿长度 $K$ → 目标模型并行打分 → **modified rejection sampling** 从左到右接受子集，在硬件数值误差内保持目标分布。Chinchilla **70B**、分布式设定下约 **2–2.5×** decode 加速；强调不修改目标模型、不牺牲 sample quality。文中写明与 Leviathan et al. **并发独立**、核心思想相同。

**跟读抓手：** 加速上限由 **接受率 $\alpha$（或 $\beta$）** 与草稿成本比 $c$ 决定（Leviathan 文中有 $\gamma$、$\alpha$、$c$ 权衡）；草稿与目标分布越近，越能把「多余算力」换成更少串行步。拒绝后从校正分布重采样——这是「无损（同分布）」路线与「典型接受 / 启发式」路线的分界（见下）。

### 3.3 变体 A：多解码头（Medusa）——草稿内置进目标

**Cai et al.（2401.10774）**：认为独立草稿模型难获取、难维护、难塞进分布式目标服务。做法：在 LLM 上增加多个 decoding heads，并行预测后续多个 token；用 **tree-based attention** 构造多候选续写并一次校验。

- **Medusa-1**：骨干冻结，只训头 → 摘要称可 **lossless** 加速，实验 **>2.2×**。
- **Medusa-2**：头与骨干一起训（需特殊配方保住能力）→ 约 **2.3–2.8×**。
- 扩展：无数据时的 self-distillation；**typical acceptance** 提高接受率同时维持生成质量（相对严格同分布 rejection，属质量—速度权衡旋钮）。

**跟读抓手：** 把「草稿模型」换成「同一隐状态上的多头 + 树注意力」，降低运维面；是否严格同分布取决于接受规则（rejection vs typical）。

### 3.4 变体 B：Lookahead Decoding——无辅助模型的并行 Jacobi / n-gram

**Fu et al.（2402.02057）**：宣称 **exact**、**无需辅助模型或外部数据存储**。把自回归改写为可用 **Jacobi 迭代** 并行推进的形式；用 lookahead 分支生成 n-gram、verification 分支校验，并用 **n-gram pool** 缓存历史轨迹上的候选。摘要 / 引言：MT-Bench 上约 **1.8×**；代码补全等多卡强扩展可达约 **4×**；与 FlashAttention 等兼容。

**跟读抓手：** 用目标模型自身的并行算力换串行步数；无 draft 运维，但加速幅度通常低于「强草稿 / 多头」路线（以各论文自报区间为准，不横比作排名）。

### 3.5 与引擎生态的接口（不落到未读实现细节）

| 机制 | 引擎侧常见落点（公开自述 / 文档名） | 选型含义 |
|------|--------------------------------------|----------|
| 独立 draft + 同分布采样 | TRT-LLM Speculative Decoding；SGLang README 列 speculative decoding | 需维护草稿权重与词表对齐；接受率随领域漂移 |
| MTP / 多 token 头 | DeepSeek-V3 等报告写 MTP 可服务投机（[[MTP训练范式]] / V3 交叉）；TRT-LLM 文档见 MTPDecodingConfig 等命名 | 训练期埋头，推理期可丢弃或改作 draft |
| Medusa 式多头 | 研究原型 → 部分引擎/社区集成（本卡不断言某引擎默认开启） | 要额外训头；tree attention 与分页 KV 需共设计 |
| Lookahead / n-gram | TRT-LLM 文档可见 NGramDecodingConfig；Lookahead 论文自有实现仓库 | 低运维基线；加速预期更保守 |

**与 PD 分离叠乘：** 投机主要加速 **decode 串行步**；prefill 仍偏算力。分池后投机装在 decode 池更自然——V3 §3.4 与引擎 README 的 PD 叙事一致，但是否默认打开投机属部署配置，不写进未核验的「一定更快」。

## 四、常见误区

1. **「换引擎 = 重做一遍 PagedAttention」**
 [[AI基础设施总览]] 的分页思想已被多引擎吸收；B-7 差异更多在 **前缀树、约束解码、PD/EP、投机与硬件内核**。把选型吵成「谁发明了分页」会漏掉 Radix / FSM。

2. **「投机解码一定无损」**
 Leviathan / Chen 路线强调 **同分布 / identical outputs**（在数值误差内）。Medusa 的 **typical acceptance**、以及任何「阈值放宽」都会离开严格同分布；需分清论文声明的是 lossless 还是质量可接受加速。

3. **「接受率低也能靠拉长 $K$ 硬加速」**
 草稿过长而 $\alpha$ 低时，校验浪费上升，甚至减速（Lookahead 论文对 draft 失败的讨论；Leviathan 对 $\gamma$–$\alpha$–$c$ 权衡）。生产上要按领域测接受率，禁止抄 2–3× 当 SLA。

4. **「SGLang 论文的 6.4× 可当成任意聊天 API 的保证」**
 该数字来自论文设定下相对 Guidance / vLLM（文中版本）/ LMQL 等、在 agent、JSON、multi-turn 等 **LM program** 负载上的峰值（摘要）。Radix 红利依赖前缀重叠；无共享前缀的单轮短生成不应预期同倍率。

5. **「TensorRT-LLM README 的 tok/s 与 vLLM 论文 2–4× 可直接横比」**
 硬件世代、精度、是否投机、是否 PD、模型与 trace 全不同。本卡把 TRT 数字留在「厂商自述 / 博客」层，不写入与 arXiv 表同一列的「结论倍率」。

6. **「PD 分离替代了连续批处理」**
 二者正交：continuous batching 管 **一步内如何拼请求**；PD 分离管 **prefill 与 decode 是否同池**。V3 部署表与引擎特性列表是叠加关系。

7. **「有了投机就不需要量化 / MLA / 分页」**
 投机降的是 **串行步数**；量化与 MLA 降的是 **每步搬移与 KV 体积**；分页降的是 **碎片**。[[AI基础设施总览]] 的「势」乘法式仍然成立，投机是多一个因子，不是替换。

8. **编造未归档的「EAGLE / Spec-v2 最新倍率」**
 本卡入口止于已核实的 Leviathan / Chen / Medusa / Lookahead 与 SGLang / TRT README。更新一代投机算法须先下 PDF 再补节，禁止用二手博客填表。

## 六、一句话收束

PagedAttention 解决的是 **KV 放得下、碎得少**；SGLang 补上 **跨调用前缀复用 + 结构化解码的运行时**；TensorRT-LLM 补上 **NVIDIA 内核与 PD/EP/投机等部署武器库**；投机解码（Leviathan/Chen → Medusa → Lookahead）则在 decode 访存墙上开辟 **「草稿—校验」并行轴**。选型看工作负载的前缀重叠、约束输出、硬件锁定与是否愿意维护草稿，而不是单看某一篇摘要里的 2×–6×。
