# 合成预训练新轴：BeyondWeb

> **主要来源**：[BeyondWeb: Lessons from Scaling Synthetic Data for Trillion-scale Pretraining](https://arxiv.org/abs/2508.10975)（截至 2025-08-19）。作者为 DatologyAI 团队，首版 2025-08-14，现行 v2 2025-08-19；下文简称 BeyondWeb。
> **研究线**：架构思想（主）——合成预训练数据的两种范式，以及质量种子、风格对齐、多样性、改写器选择各自起多大作用；评测字段（辅）——1B×1T、3B/8B×180B 三档训练，14 项基准 0-shot 与 5-shot 的均值。
> **范围与相邻笔记**：
> - ≠ [[NemotronCC数据策展]]：本篇不写 Nemotron-CC 从 Common Crawl 到 6.3T 的全管线，只把其中的高质量合成子集 Nemotron-Synth 当作对照基线。
> - ≠ [[合成数据与教科书式数据]]：本篇不写 phi、Cosmopedia 一类从零生成教材的通史，Cosmopedia 只作对照。
> - ≠ [[分词器与数据配比]]：本篇不写 FineWeb、DCLM、Dolma 的正文提取与过滤通史，DCLM 只作改写种子的来源。
> - ≠ [[合成对齐数据Magpie]]：本篇写预训练阶段的改写合成，不写对齐阶段的指令与偏好数据。
>
> **意义**：高质量网页总量有限，重复训练收益递减，合成数据被寄望于突破这道「数据墙」。BeyondWeb 用一组受控消融说明，改写式合成的收益主要来自信息密度、风格与多样性的联合设计，而不是「换个大模型重写一遍」；它把合成数据在万亿 token 预算下仍能持续受益这件事做成了受控实验结论。

**一句话**：对高质量网页做多种策略的改写，在相同真实知识量下提高每个 token 的信息密度、贴近下游使用的文体，并靠多样性撑住长训；没有单一因素能单独决定效果。

---

## 一、问题背景

据 BeyondWeb §1–2：

1. **数据墙**：前沿模型的预训练预算已到数万亿 token，高质量网页不够用；重复使用同一批数据，收益会逐轮下降。
2. **生成器驱动的合成成本高、覆盖窄**：让大模型凭参数记忆从零写教材或故事，需要很强的生成器，主题覆盖受限，还有幻觉与分布塌缩的风险。
3. **改写式合成缺少系统研究**：以真实网页为条件、用中小模型改写的做法已被广泛采用（BeyondWeb §2 称 Kimi K2、Qwen2.5、Grok、GPT-5 均有报道），但哪些因素真正决定合成数据质量、规模放大后是否仍有效，此前没有受控对照。

合成数据的通用背景（Self-Instruct、phi 的教科书质量路线）见 [[合成数据与教科书式数据]]。

## 二、脉络

| 节点 | 范式 | 做法 | 留下的问题 |
|---|---|---|---|
| TinyStories（2023-05）、phi-1（2023-06） | 生成器驱动 | 大模型从零写简化故事或教科书式内容 | 依赖强生成器，覆盖受限 |
| WRAP（2024-01） | 改写式 | 把网页改写成问答等风格 | 风格单一 |
| Cosmopedia（2024-03） | 生成器驱动 | 按主题种子大规模生成教材类文本 | 总量有限，长训时只能重复 |
| Nemotron-CC 合成（2024-12） | 改写式 | 在高质量 CC 输入上做多种风格改写，得到 Nemotron-Synth | 各因素的作用未拆开 |
| BeyondWeb（2025-08） | 改写式 | 多策略改写加系统消融 | 完整生成策略未公开 |

两种范式的分界（BeyondWeb §2）：生成器驱动的知识来自生成模型的参数；改写式的知识来自已有网页，模型只负责改写成信息更密、格式更贴近任务的文本，因而覆盖更广、算力更省。

## 三、方法与实验设定

### 3.1 BeyondWeb 做什么（§3）

以真实网页为锚、以多样策略生成，种子取 DCLM 中由 DatologyAI 策展方法选出的高质量子集。论文列出的策略族有三类：格式变换（如网页改为问答）、风格修改（如加强教学语气）、内容重组（提高信息密度与可学性）。完整 prompt 与生成策略细节未公开。

### 3.2 对照与训练口径（§3、附录 A）

- **对照数据**：RedPajama（RPJ，最少策展的网页，作真实基线）；Cosmopedia-v2（约 27B token，不够时重复）；QA WRAP（源为 RPJ，改写器 Llama-3.1-8B-Instruct）；Nemotron-Synth（文称约 1.5T token，实验中随机子采样）。合成对照统一按 60% 随机 RPJ 加 40% 合成混合。
- **模型与预算**：1B（Llama-3.2 结构）训 1T token；3B（Llama-3.2）与 8B（Llama-3.1）各训 180B token。
- **只动数据**：优化器为 AdamW，batch 512、上下文 2048；除早期在 RPJ 上做过搜索外不广泛调参，目的是让增益只来自数据干预。
- **评测**：14 项任务（含 FineWeb 常用的 8 项），0-shot 与 5-shot 取均值。

## 四、主结果（Table 1、Fig.1）

**14 项均值（%）**：

| 规模 | RPJ | QA WRAP | Cosmopedia | Nemotron-Synth | BeyondWeb |
|---|---:|---:|---:|---:|---:|
| 1B（1T token） | 50.7 | 52.5 | 52.2 | 54.3 | **57.4** |
| 3B（180B token） | 53.5 | 55.3 | 55.8 | 58.8 | **60.8** |
| 8B（180B token） | 56.6 | 58.4 | 58.6 | 61.1 | **63.7** |

- **增益幅度**：相对 RPJ 为 +6.7 / +7.3 / +7.1 个百分点，相对 Nemotron-Synth 为 +3.1 / +2.0 / +2.6 个百分点；摘要称相对 Cosmopedia 最多高 5.1 个百分点。三档规模下分别在 14 项中的 13 / 12 / 13 项取最高。
- **训练加速（8B）**：BeyondWeb 追平 RPJ 训满 180B 的精度只需 23.2B token（7.7 倍），追平 Nemotron-Synth 需 66.2B token（2.7 倍）。
- **跨规模**：同为 180B token，3B 的 BeyondWeb（60.8）超过除一个以外的全部 8B 基线，明确高于 8B 的 Cosmopedia。

## 五、系统消融：七个问题（§4）

消融默认用 1B 模型训 20B token，真实高质量网页与合成数据各半；合成数据由同一份 10B 高质量种子改写而来，真实基线 RPJ-HQ 把这 10B 看两遍，以控制新知识量。注意这里是 50:50 混合，与第四节主对照的 60:40 口径不同。

| 问题 | 关键数字（14 项均值） | 结论 |
|---|---|---|
| 生成器驱动是否只等于摘要（§4.2） | RPJ-HQ 45.5；8B 简单摘要 46.7；Cosmopedia 47.1；BeyondWeb 50.4 | 简单摘要就能接近 Cosmopedia，收益大量来自信息密度；BeyondWeb 比摘要高 3.7 个百分点，说明不只是知识蒸馏 |
| 能否突破数据墙（§4.3） | 全真实上界 46.2；10B 重复两次的下界 45.5；同风格续写 46.2；BeyondWeb 50.4 | 朴素续写只到上界；有设计的合成比全真实上界高 4.2 个百分点 |
| 种子质量（§4.4） | 低质网页 + 高质网页 45.6；低质合成 + 高质网页 48.6；高质合成 + 高质网页 49.2；BeyondWeb 50.4 | 高质量数据有限时优先拿来做改写种子；只靠高质量种子仍不到最优 |
| 风格对齐（§4.5） | RPJ 样本中对话风格约 2.7%（GPT-4o 标注），按 Organize the Web 的四类对话风格统计为 3.67%；对话占比升到 50% 时 5-shot 均值从 43.2 到 44.1，超过 20% 后饱和 | 贴近部署风格有用，但不充分 |
| 规模上的多样性（§4.6） | 1B 训到约 50 倍 Chinchilla 最优 token 量时，单策略数据开始过拟合下滑，BeyondWeb 仍在改善 | 单一风格早期有效、随后进入平台期；多样性是长训不饱和的关键 |
| 改写器族（§4.7） | OLMo-2-7B 49.9、Phi-4-14B 49.5、Llama-3.1-8B 49.2、Mistral-7B-v0.3 48.9；改写器自身基准相差约 7 个百分点，下游差距不到 1 个百分点 | 改写器自身强弱不预测合成质量；选到「够用」容易，选到最优难 |
| 改写器规模（§4.8） | Llama-3 系 1B / 3B / 8B 改写器：47.3 / 48.8 / 49.2 | 1B 到 3B 提高 1.5 个百分点，3B 到 8B 只提高 0.4 个百分点，约 3B 饱和 |

## 六、三条原则（§6）

1. **质量优先于新颖**：改写高质量数据，而不是堆低质量数据。
2. **风格对齐部署用例**：训练数据的文体应接近模型实际被使用的方式。
3. **保持生成多样性**：长训时靠多样性避免收益饱和。

论文强调三者要联合优化，单因素通常只有温和收益；朴素合成可能花了算力却没有收益。

## 七、工程与落地

- **生成基础设施**（§3）：早期用 Slurm 与 AWS Hyperpod 上的 H100，后来改为 Kubernetes 上的 Ray 加 vLLM，可调度异构 GPU，并接入已有的 Ray / Spark 策展流程；论文称另文详述，未给规模数字。
- **生产落地**（§1）：BeyondWeb 属于 DatologyAI 的策展平台，用于为 Arcee AI 的 AFM-4.5B 策展 7T token 预训练语料。
- **未来方向**（§5）：合成数据自身的规模定律与内在重复度量；进一步缩小改写器；在预训练阶段对齐人类价值；扩展到非网页、多模态与专有领域。

## 八、意义

- **把「合成数据有没有用」拆成可检验的因素**：信息密度、种子质量、风格、多样性、改写器族与规模各自的贡献都有受控数字，后续工作可以逐项对照。
- **改写式合成走到预训练主体**：在 1T token 的长训中收益仍在扩大，3B 模型可以超过同预算的大多数 8B 基线，论文据此称，高质量合成数据可以用少得多的参数取得更好结果。
- **降低合成门槛**：约 3B 的改写器就接近饱和，改写器自身基准不预测合成质量，大规模合成不必依赖最强的生成模型。

## 九、局限与待核实

- **配方未公开**：具体 prompt 与生成策略没有给出，只能复述原则与消融结论，无法照方复现。
- **口径不同**：主对照为 60:40（RPJ 比合成），消融为 50:50（高质量网页比合成），两组数字不能直接比较。
- **Cosmopedia 靠重复补足**：Cosmopedia-v2 约 27B token，不够时重复使用，作者承认这是生成器驱动范式的局限。
- **续写实验有混淆**：续写模型见过远多于 20B 的语料，可能把参数知识带进合成数据（论文自述）。
- **评测范围**：14 项基准的均值，不涉及对话评测或开放式生成评测。
- **AFM-4.5B 的 token 数口径不一**：论文写 7T；Arcee AI 2025-07-29 的正式发布文写基座共训 8T token，其中通用预训练 6.5T、中期训练 1.5T。两者统计范围可能不同，完整配比不在论文中。
- **Fig.2 图注与正文不一致**：§4.2 正文写摘要 46.7%、Cosmopedia 47.1%，Fig.2 图注把两者都写作 46.8%；本篇取正文。
