# B-9：多语言与跨语种

> 攻坚线：**架构思想（主）**
> 入口：Conneau et al., *Unsupervised Cross-lingual Representation Learning at Scale*（XLM-R，arXiv:1911.02116v2，2020-04-08）；BigScience Workshop, *BLOOM: A 176B-Parameter Open-Access Multilingual Language Model*（arXiv:2211.05100v4，2023-06-27）；当代配比交叉 [[Qwen3技术报告深读]]（arXiv:2505.09388）。
> **与 B-3 划界：** B-3 回答「切词器与网页过滤/去重管线」；本卡回答「同一权重如何服务多语、跨语种迁移与语种配比如何成为架构旋钮」。数字一律取自上述 PDF / 已有 TR 笔记，不编造未核对比。

## 一、问题动机：英文默认轴之外的架构问题

早期谱系与数据叙述常以英文/代码为默认。跨语种能力至少拆成三层架构问题（均来自入口论文的问题陈述，而非后验口号）：

1. **共享表征 vs 容量稀释**：固定参数下加语种，低资源可先受益于正向迁移，过点后全体退化——XLM-R 称之为 **curse of multilinguality**（§1、§5.1）。
2. **无监督跨语种迁移 vs 生成式多语 LM**：XLM-R 走 **多语 MLM + 下游微调**（编码器式理解）；BLOOM 走 **decoder-only 因果 LM + 开源多语语料 ROOTS**（生成与 few-shot）。
3. **语种选择与字节/token 配比**：语种名单、采样指数 $\alpha$、词表份额、源级/实例级 mixing，决定「哪一门语言真正吃到梯度」；当代旗舰把「语种数」写成产品指标（如 Qwen3 **29→119**），但**公开报告往往不给逐语种百分比**——接口可读，配方常不可复现。

**架构思想主线抓手：** 多语不是「再堆一份非英文数据」，而是在 **容量分配（模型宽/词表）—采样分配（$\alpha$ / mixing）—目标形态（MLM 理解 vs 因果生成）** 三者上的联合设计。本卡按 XLM-R → BLOOM → 当代配比接口写短史。

## 二、XLM-R：规模化无监督跨语种表征

### 2.1 元信息与主张

| 字段 | 核实值 |
|------|--------|
| 标题 | Unsupervised Cross-lingual Representation Learning at Scale |
| 作者 | Conneau, Khandelwal 等（Facebook AI） |
| arXiv | **1911.02116v2** [cs.CL] **8 Apr 2020** |
| 官方 PDF | `https://arxiv.org/abs/1911.02116`（12 页；pdfTeX CreationDate 2020-04-09 CST） |
| 模型名 | **XLM-RoBERTa（XLM-R）** |
| 一句话 | 在 **100** 语、**>2 TB** 过滤 CommonCrawl 上训多语 MLM；相对 mBERT / 先前 XLM 大幅抬升跨语种理解，并首次强调可与强单语模型在 GLUE/XNLI 上竞争而不牺牲 per-language 表现（摘要、§1） |

### 2.2 相对 mBERT / XLM 的关键差分

| 维度 | 内容（据 §3、§5） |
|------|------------------|
| **目标** | 仅用单语数据的 **multilingual MLM**；**不用** TLM（作者称在改进无监督设定后，纯 MLM 已可逼近先前带 TLM 的 XNLI 水平，故聚焦无监督，§5.1） |
| **数据** | **CC-100**（CCNet 管线：语种识别 + 每语 LM 过滤；英语 1 个 dump、其余语种 12 个 dump）；相对 Wiki-100，低资源数据量常升 **数个数量级**（Fig.1、§3） |
| **语种** | **100**；消融固定含 en/fr/de/ru/zh/sw/ur 等 7 语评估核，并扩到 15/30/60/100（§3） |
| **切词** | **SentencePiece Unigram**，直接打 raw text；**不用**语言嵌入（利于 code-switching）；词表 **250K**（消融用 150K）（§3、§5.1） |
| **采样** | 按句数比例、指数平滑 $\alpha$；XLM-R 取 **$\alpha=0.3$**（§3、Fig.5） |
| **规模** | **XLM-R Base**：$L=12,H=768,A=12$，**270M**；**XLM-R**：$L=24,H=1024,A=16$，**550M**；主模型 **1.5M** updates、**500×32GB V100**、batch **8192**（§3、§5.2） |

### 2.3 架构思想核心：curse of multilinguality

固定容量下：

- **7→15 语**：正向迁移主导，低资源涨分；
- **再往上到 100 语**：干扰/稀释主导，XNLI 整体从 XLM-7 的 **71.8%** 降到 XLM-100 的 **67.7%**（Wiki 设定叙述，§5.1）；CC 上趋势同类（Fig.2）。

缓解路径（文中实证）：

1. **加宽模型**（Fig.4：XLM-30 加宽可追平 XLM-7；XLM-100 仍因词表稀释落后）；
2. **加大共享词表占比**（固定总参调窄 Transformer：32K→256K 词表，XNLI 均准 **+2.8%**；同 BERTBase 下 128K→512K **>3%**）（Fig.6、§5.1）；
3. **更大数据 + 更长训 + 更大 batch**（CC vs Wiki，Fig.3；batch 与 SPM 简化，Fig.7）；
4. **采样 $\alpha$** 在高/低资源间显式权衡（Fig.5；总体最优约 **0.3**）。

**一句话：** 多语 SOTA 不是「语种越多越好」，而是 **语种数 × 容量 × 词表 × 采样** 的帕累托面；「诅咒」可用容量缓解，但在中等算力下仍是硬约束（§1）。

### 2.4 下游数字（仅报告文中）

| 设定 | 数字（摘要 / Table 1–3 / §5.2–5.3） |
|------|-------------------------------------|
| **XNLI 跨语种迁移**（英训→15 语测，单模型） | XLM-R **80.9%** avg；相对 XLM-100 **+10.2**、mBERT **+14.6**；sw **+15.7**、ur **+11.4**（对 XLM-100） |
| **translate-train-all** | XLM-R **83.6%** avg（文称当时 XNLI 新 SOTA） |
| **MLQA**（英 SQuAD 微调→7 语） | F1/EM **70.7 / 52.7**；相对先前 SOTA **61.6 / 43.5**；相对 mBERT F1 **+13.0** |
| **NER CoNLL**（跨语种 en→） | 相对 mBERT 平均 F1 **+2.42**（跨语种）；each-lang **+1.86**；all-lang avg F1 **89.43** |
| **GLUE** | 优于 BERTLarge 均分约 **1.6%**；与 XLNetLarge 持平量级；RoBERTa 仍高约 **1.0%** avg（§5.3） |

架构结论（§5.3）：**可以做一个服务多语的大模型，同时在单语下游保持强竞争力**——前提是容量与数据足够；剩余与 RoBERTa 的缝仍归因于 curse / vocabulary dilution。

## 三、BLOOM：开源多语 decoder-only 旗舰

### 3.1 元信息与主张

| 字段 | 核实值 |
|------|--------|
| 标题 | BLOOM: A 176B-Parameter Open-Access Multilingual Language Model |
| 作者 | BigScience Workshop（数百人协作） |
| arXiv | **2211.05100v4** [cs.CL] **27 Jun 2023** |
| 官方 PDF | `https://arxiv.org/abs/2211.05100`（73 页；pdfTeX CreationDate 2023-06-28 CST） |
| 定位 | **176B** 参数、**decoder-only** Transformer；ROOTS 上训；公开权重与代码（Responsible AI / RAIL 许可叙事，摘要、§1） |
| 语种 | **46** 自然语言 + **13** 编程语言（合计 **59**）（摘要、§3.1） |

### 3.2 ROOTS：人机共策的多语语料（架构侧含义）

| 维度 | 核实值（§3.1） |
|------|----------------|
| 规模 | **1.61 TB** 文本；**498** 个 HF 数据集组件 |
| 来源结构 | 社区 Catalogue / 伪爬取 + **OSCAR 21.09（占语料 38%）** + GitHub 代码（对齐 AlphaCode 语种选择） |
| 治理取向 | 优先人类参与、本地/语言专家；源级可追溯；部分组件可公开、全量需申请（对照「纯启发式过滤 CC」） |
| 字节大头（Table 1，便于读 Fig.3） | English **~485 GB**；简中 **~261 GB**；French **~208 GB**；Spanish **~175 GB**；Programming **~175 GB** 等 |
| 配比读数 | 按 Table 1 字节求和约 **1.614 TB**，与文称 1.61 TB 一致；**English ≈ 30.0%** 字节；代码字节约 **10.8%**，与正文「ROOTS consists of around **11%** of code」（§4.5）一致 |
| 家族失衡 | Indo-European + Sino-Tibetan 合约 **1321.89 GB**；Niger-Congo 子集约 **0.4 GB**（Fig.3 图注）——「46 语」≠「均匀 46 份容量」 |

**架构含义：** BLOOM 把「多语」从 XLM-R 式 **自动爬取+α 采样** 推进到 **目录治理 + 专家入选语种 + 仍不得不混 OSCAR 以凑体积**；语种覆盖是**组织约束与算力预算的折中**，不是单纯 LID 扫全网。

### 3.3 模型与切词差分（相对 GPT-3 英词表路线）

| 设计点 | 内容（§3.2–3.3、Table 3） |
|--------|---------------------------|
| **形态** | 因果 decoder-only（消融支持：预训练后因果 decoder 强于若干 encoder-decoder 变体，§3.2） |
| **位置** | **ALiBi**（相对 learned / RoPE，文称同长度下训练更稳、下游更好） |
| **稳定** | Embedding 后额外 **LayerNorm**（104B float16 预实验；最终 176B 用 **bfloat16**） |
| **176B 骨架** | **70** 层；hidden **14336**；头 **112**；seq **2048**；GELU；词表绑定 |
| **词表** | Byte-level BPE，**250,680**（含 200 预留）；与训练数据**同语种采样比**训 tokenizer；以 **fertility** 相对单语 tokenizer 作验收（目标：各语退化不超过约 10 pp；Table 2） |
| **预分词** | 刻意避免英式空格启发式（文称曾伤 Arabic / code） |
| **训练** | Jean Zay；约 **384**×A100 80GB 量级配置；176B 预训练目标约 **366B** tokens（小模型档 **341B**；另述 ROOTS ≈341B tokens，后因修订 scaling 意见对主模型多训 25B 重复数据）（Table 3、§3.5） |
| **系列** | 560M / 1.1B / 1.7B / 3B / 7.1B / 176B（Table 3） |
| **后训练** | **BLOOMZ**：xP3 多任务 prompt 微调（83 数据集、46 语、16 任务；语种分布贴近 ROOTS，Fig.4）；约 **13B** tokens 预算（Table 3） |

### 3.4 评测侧对「多语架构」的读法（节选，不重开全表）

- **英文任务：** 零样本常落后纯英可比模型；**one-shot 后差距缩小甚至追上 OPT**——文解释为多语模型在更长上下文中更确定输入/输出语言（§4.2 SuperGLUE）。
- **代码：** ROOTS ~11% code；HumanEval 等与「Pile 系英+码」模型对照（§4.5）。
- **BLOOMZ：** 多任务 prompt 微调后零样本泛化显著强于同族预训练检查点（§4.7 叙事；与 T0 同配方族）。

**相对 XLM-R 的架构跃迁：** 从「共享编码器 + 任务微调做 XLU」变为「开源大规模因果 LM + 多语 byte-BPE + 可选指令混合」；**诅咒未消失**，但旋钮从 α/词表扩展到 **语种入选治理、OSCAR 占比、ALiBi/稳定性、xP3 语言镜像**。

## 四、当代大模型多语配比接口（交叉 Qwen3 TR，不重写）

本节只固定「读当代报告时该看哪些接口字段」，数字以已有笔记为准。

### 4.1 从 XLM-R / BLOOM 继承的接口清单

| 接口 | XLM-R | BLOOM | 当代旗舰（Qwen3 例） |
|------|-------|-------|----------------------|
| 语种覆盖宣称 | 100 | 46 自然 + 13 代码 | **119** 语言/方言（相对 Qwen2.5 的 **29**） |
| 数据量级 | >2 TB CC-100 | 1.61 TB ROOTS；~341–366B tokens | 预训练约 **36T** tokens |
| 配比粒度 | 句级采样 $\alpha=0.3$ | 源目录 + OSCAR 38% + 训 tokenizer 同采样比 | **实例级**标注配比（教育价值/领域/安全等），覆盖 **>30T** tokens 标注；小代理模型消融（相对源级/域级） |
| 词表 | SPM 250K | BBPE 250,680 | Qwen BBPE **151,669**（TR 笔记 §2.2） |
| 训练阶段与语种 | 单一 MLM 预训练 | 预训练 + xP3 多语指令 | **S1 General >30T @4K**（含 119 语）→ **S2 Reasoning ~5T**（抬 STEM/代码/推理/合成）→ 长文数百 B（TR 笔记 §3.2） |
| 跨语种评测 | XNLI / MLQA / NER | SuperGLUE、多语摘要/翻译、BLOOMZ 等 | MMMLU、MGSM、Belebele（80 支持语）等（TR 笔记 / 报告附录） |

### 4.2 Qwen3 交叉摘要（勿当本卡主文）

据 [[Qwen3技术报告深读]] 与报告 §3.1–3.2：

- **覆盖扩张：** 29→119；token 约 36T（相对 Qwen2.5 约 2× tokens、3× 语言覆盖）。
- **扩语料手段：** VL OCR 精炼 PDF、系列模型合成、**增补多语**。
- **配比主张：** 细粒度标签 → **instance-level mixture**，而非只调源/域比例。
- **报告未给出**与 BLOOM Table 1 同级的「逐语种字节/百分比」表 → 跟读时标为**接口可知、配方不可逐项复现**；勿用外部博客补百分比。

### 4.3 架构思想收束（当代）

1. **语种数是产品指标，配比才是容量分配。** XLM-R 的 curse 在 36T 时代仍可能以「长尾语梯度不足 / 词表不公」形式出现；公开卡若只写「支持 N 语」而未写采样或标注策略，信息量接近营销。
2. **切词与多语绑定。** B-3 的 SentencePiece 无损叙事 ↔ XLM-R SPM ↔ BLOOM fertility 验收 ↔ Qwen BBPE：同一 Unicode 在不同词表下的 token 长度差，会扭曲「公平语种配比」。
3. **理解线 vs 生成线。** XLM-R 优化跨语种分类/QA；BLOOM/Qwen3 优化多语生成与指令。迁移实验协议（zero-shot en→xx、translate-train-all、xP3）不可混读成同一分数。
4. **合成与标注上移。** 当代用 VL/合成/实例标注做配比，是对 BLOOM「人工目录」与 XLM-R「α 平滑」的工程替代；思想 deb 仍是 **谁决定稀有语的有效曝光**。

## 五、常见误区

1. **「语种越多，跨语种一定越强」**
 XLM-R §5.1：过点后 curse of multilinguality 使全体下降；需加容量/词表/数据。

2. **「多语模型必然牺牲英文」**
 XLM-R：GLUE 接近 RoBERTa（差约 1.0% avg）；BLOOM：one-shot 英文任务可逼近纯英大模型。牺牲与否取决于容量与配比，不是命运。

3. **「有 TLM / 平行语料才叫跨语种」**
 XLM-R 主结果是**无监督 MLM**；明确选择不训 TLM。跨语种迁移可从共享子词与多语共现中涌现（亦见相关工作对 mBERT 的分析引用）。

4. **「BLOOM 46 语 ≈ 均匀多语」**
 Fig.3 / Table 1：印欧+汉藏字节碾压；Niger-Congo 合计约 0.4 GB。覆盖名单 ≠ 有效算力份额。

5. **「当代 N 语旗舰已公开逐语种配比」**
 Qwen3 公开 119 与实例级标注叙事，**未**在 TR 中给出 BLOOM 式逐语种字节表。交叉笔记时保持「待配方级核实」。

6. **「多语 = B-3 语料工程的同义词」**
 B-3 管过滤/去重/混合质量；本卡管**语种轴上的架构权衡与迁移设定**。二者耦合（同一 HTML 的 token 数、LID 误差）但问题不同。

7. **「Byte-level BPE / 大词表自动解决低资源」**
 BLOOM 用 fertility 约束退化；XLM-R 显示词表加大有帮助但挤占 Transformer 宽度。词表是容量再分配，不是免费午餐。

8. **「指令微调（BLOOMZ / 当代 chat）等于预训练配比已公平」**
 xP3 镜像 ROOTS 分布（Fig.4）；后训练可放大预训练偏见，也可通过任务混合部分修正——二者必须分开读。
