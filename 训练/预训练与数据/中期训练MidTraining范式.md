# 中期训练（Mid-Training）范式总览

## 本文范围 / 与相关笔记分工

## 一、为何需要 Mid-Training

近几代前沿配方普遍不再把「预训练 → 后训练」写成两段硬切。综述开篇指出：仅靠网页级噪声语料继续堆 token，推理、代码与长上下文等能力常常出现**收益停滞**；因而在通用预训练之后，额外插入若干 **annealing 风格** 的中间阶段——提高数据质量、下调或分段学习率、按课程拉长上下文——以稳住收敛并抬高后期边际效用。

这一动机可与 [[规模定律与预训练范式]] 对照阅读：规模定律主要回答「给定算力，参数与 token 如何配」；Mid-Training 回答的是「在已经吃过海量通用语料之后，**剩余预算该换什么分布、什么步长、什么窗口**」。二者互补，而非互相替代。

综述还从三条理论视角概括「为何退火有效」（§II）：

1. **Gradient Noise Scale（GNS）**：更高质量数据往往带来更大的有用梯度方差；较大 GNS 有助于逃离尖锐极小、避免在低质平台上过拟合。
2. **Information Bottleneck**：学习率退火阶段可被理解为压缩噪声/冗余特征、保留对下游更可预测的结构。
3. **Curriculum Learning**：先广后精的数据课程，与「由多样噪声语料转向结构化推理样本」的调度同构。

上述三条是综述给出的**解释框架**，而非单一可证伪定理；后文配方仍以经验为主。

## 二、定义与阶段位置

**工作定义（据综述摘要与引言）。** Mid-Training 是介于大规模通用预训练与任务特定微调之间的**中间阶段**：模型已从海量网页等语料获得广覆盖表征后，再经历一轮或多轮 annealing——同时或交替地（i）上采样高质 / 合成 / 推理向数据、（ii）降低或分段调整学习率、（iii）逐步扩展上下文窗口——以提升泛化、稳定收敛并扩展能力边界。

**在流水线中的位置：**

```
通用预训练（广覆盖、噪声可容忍）
        ↓
  Mid-Training / Annealing（质量退火 · LR · 长上下文）
        ↓
后训练（SFT / 偏好优化 / RL 等）
```

实践中命名并不统一：有的技术报告写「annealing stage」「reasoning stage」「long-context stage」，有的把长上下文单列为 mid-training 之后的续训。综述的贡献在于把这些做法收成**同一范式下的三域 taxonomy**（数据分布、LR 调度、长上下文扩展），而不是某一厂商配方的别名。

**与相邻概念的边界：**

- **≠ 单纯持续预训练（continual pretraining）**：持续预训练可在任意检查点上换语料续训；mid-training 强调相对「主预训练」的**刻意退火设计**（更高质分布 + 配套 LR/窗口），见 [[持续学习]] 中的遗忘风险对照。
- **≠ 后训练对齐**：指令 / QA 风格数据可在 mid-training 提前注入，但综述明确指出其最优插入位置仍有争议；偏好优化与 RL 算法本身不属于本篇。

## 三、常见配方轴

### 3.1 数据分布：从「覆盖」转向「信号密度」

综述 §III 将 mid-training 常用数据归为若干类型（多源可并存）：

| 类型 | 角色（综述口径） | 代表来源（综述 Table I / §III-A 举例） |
| --- | --- | --- |
| 高质量过滤网页 | 相对主预训练更严的质量 / 教育价值 / 低毒过滤 | FineWeb-Edu、DCLM-Baseline、peS2o、RefinedWeb 等子集 |
| 代码与数学 | 强化符号推理与程序综合 | Stack、OpenWebMath、FineMath、Stack-Edu 等 |
| 指令 / QA 风格 | 提前塑造意图跟随与应答一致性 | UltraChat、FLAN、StackExchange QA、OpenOrca 等 |
| 合成教科书 / 知识密集 | 低资源域与结构化讲解 | Cosmopedia、各类合成数学轨迹 |
| 长文档 / 长问答 | 为窗口扩展提供自然长依赖 | 书籍、代码仓、过滤出的长网页；亦有合成长问答 |
| 推理 / CoT | 显式分解步骤，利于数学与逻辑 | 合成或过滤得到的逐步推理样本 |
| Fill-in-Middle（FIM） | 双向条件与碎片段鲁棒；提高单样本利用效率 | 代码预训练与部分通用配方中采用 |

**综述提炼的数据侧要点（§III-C，择要）：**

- 相对早期预训练，mid-training **更重质量**；过滤语料在消融中往往优于未过滤语料，且不同 HQ 源互补（如 FineWeb-Edu 偏学术基准，DCLM 偏常识推理），宜组合而非单源押注。
- 上采样教育 / 代码 / 数学，有助于推理与 STEM 基准；领域数据即便占比不高，也可带来不成比例的增益（综述援引 OLMo 2 等观察）。
- **指令风格数据**的收益与插入时机仍不一致：有报告称 mid-training 提前注入优于推迟到微调，也有报告称晚期加入指令样本的增益接近 SFT，最优位置未决。
- 长上下文能力依赖**数据来源**而非仅序列长度：纯长数据可能伤短上下文；自然长文优于机械拼接；书籍与代码仓常被标为有效长依赖源。
- 合成数据可针对欠表示域与复杂推理定制，提高后期样本效率（与 [[合成数据与教科书式数据]] 接口，不在此重写教科书通史）。
- 对高质子集的**适度重复与改写**可部分替代单纯堆量；但分布与主预训练断裂会加剧遗忘——综述援引 OpenCoder：其 mid-training 仍保留约 **84%** 来自主预训练分布，以维持连续性。
- 存在「灾难性过训练」警示：token 预算过大可能损害后续微调可塑性，需显式设定停止准则。

### 3.2 学习率：与阶段对齐的衰减，而非单一余弦叙事

综述 §IV 指出：主预训练常用「线性 warmup + cosine / linear 衰减」；引入显式 annealing 后，更多配方采用 **多阶段 / WSD（Warmup–Stable–Decay）/ 多步阶梯衰减**，以便在检查点上复用、并与数据分布切换对齐。

常见调度形态（综述 §IV-B）：

| 形态 | 要点 |
| --- | --- |
| Cosine（常衰减至峰值的约 10%） | 仍最常见；综述强调衰减长度宜与预定总步数对齐，否则易过早或过晚衰减 |
| Linear decay | 部分优化文献报告在若干设定下优于 cosine |
| WSD（MiniCPM 等） | warmup → 稳定高 LR → 末段快速衰减；综述称末段可用约 **10%** token 完成大幅掉 loss，且便于中间检查点再衰减 |
| Multi-step / 阶梯（DeepSeek 系等） | 在固定 token 比例处离散降 LR，利于跨规模复用前段 |
| Power 等扩展 | 在 WSD 与 μP 思路上寻找可迁移的 LR–token 关系（Granite 3.0 等采用） |

**LR 侧共识与未决（§IV-D）：** warmup 有助于早期稳定并支撑更高峰值 LR；衰减形态与 batch、模型尺度、优化器强耦合，**尚无统一理论**；Kaplan 与 Hoffmann 等对「schedule 形状是否重要」的经验结论并不一致——mid-training 实践仍高度启发式。优化器本身见 [[优化器与训练稳定性]]。

### 3.3 长上下文扩展：位置编码重映射 + 课程式拉长

综述 §V 将多数 RoPE 系扩展统一为对基频的重映射 $h(\theta)$，并可叠加温度 / logit 缩放（如 YaRN）与架构侧省显存手段（GQA、MLA、局部–全局交错、稀疏注意力等）。代表族包括 PI、NTK-aware、NTK-by-parts、YaRN、LongRoPE、以及实践中常见的 **ABF（Adaptive Base Frequency）** 升基频。

**实践范式（综述 §V-C / §V-D）：**

- 窗口**渐进**拉长（例如 $4\mathrm{k}\!\to\!32\mathrm{k}\!\to\!128\mathrm{k}$），而非一次跳到目标长度。
- 长/短样本混合（综述概括常见约 **30%–60%** 长样本区间，具体比例因模型而异），并辅以检索、重排、FIM 等合成长依赖任务。
- 架构改动主要**解锁 KV 预算**，不能替代频率重映射。
- 综述给出的经验默认（面向约 $\le 128\mathrm{k}$）：ABF 将 $\theta$ 提到约 $10^{6}$ 量级，并配合 YaRN 类 $\alpha(s)=0.1\ln s+1$；更长窗口则考虑分阶段 ABF 与 LongRoPE 类非均匀缩放，并注意短上下文回退。

### 3.4 目标与其它耦合旋钮

除标准下一词预测外，综述点名 **FIM**、推理 / CoT 监督信号、以及部分配方在 annealing 末段提高指令占比以**平滑过渡到 SFT**。目标选择通常与数据轴绑定，而非独立第四套完整 taxonomy；本文将其视为与数据/LR/窗口耦合的配套旋钮。

三条轴的相互依赖（综述引言）：无高质量数据则难特化；无合适调度则浪费高质 token 或失稳；无上下文扩展则下游长程任务受限。有效 mid-training 应作**联合设计**。

## 四、代表性证据（来自综述汇整）

以下数字均转述综述 Table VII 及正文对公开技术报告的汇整，用于说明「中间段」被广泛报告为有效；**不是**在同一基准、同一消融协议下的可直接横向对比排行榜。

| 来源（综述汇整） | 报告的 mid-training / annealing 相关增益 |
| --- | --- |
| Llama 3 | 退火使 **8B** 在 GSM8K 提升 **24.0%**、MATH 提升 **6.4%**；对 **405B** 提升可忽略 |
| OLMo 2 | mid-training 使 **7B / 13B** 平均分分别约 **+10.6 / +10.3**；GSM8K 约 **+43.4 / +37.8**（同表还列 ARC、MMLU、DROP 等分项） |
| SmolLM2 数据消融（综述正文） | FineMath4+ 相对 InfiMM-WebMath：GSM8K 约 **2×**、MATH 约 **6×**（强调逐步推理语料） |
| MiniCPM 系 / WSD | 综述强调稳定段后快速衰减与高质数据引入的配合；MiniCPM4 一行报告以更少 token 达到与更强对照可比的整体表现（见表 VII 定性/定量摘要） |
| 多模型共性 | 综述将增益粗分为「推理与适应性」「可扩展效率」「可靠基础（稳定、抗遗忘、补短板）」三类叙事 |

阶段 token 与数据配比的厂商差异极大（综述 Table II）：例如有的在 1T 级通用之后仅用数十 B 级退火，有的退火本身达到数 T；长上下文阶段从数十 B 到数百 B 不等。**具体配比应以各技术报告为准**；库内全栈开放配方细节见 [[OLMo3全栈开放配方]]，本文不复制其数据表。

评测上，综述指出 mid-training 阶段仍主要依赖通用套件（MMLU / MATH / HumanEval / LongBench / RULER 等，Table VI），缺少专为「中间段」设计的标准协议——这也是横断比较困难的原因之一。

## 六、开放问题

综述 §VII 将 mid-training 仍定性为「工程艺术多于原则科学」，并列出方向：

1. **动态课程**：按 loss 锐度、梯度方差或中间基准，自适应调整数据组成，而非固定采样比。
2. **有理论根据地 LR 调度**：使衰减与模型尺度、数据阶段、batch 共同演化；弥合「schedule 不重要」与「衰减形态显著影响」两类经验。
3. **长上下文两条线**：位置编码的分布外泛化；以及 KV 压缩、量化、混合注意力–SSM、检索摘要等算力路径——并需要更好的长程数据与指标，以及与长度相关的 scaling 叙述。
4. **指令数据何时注入、过训练如何判停、如何在创新分布与连续性之间折中**，仍缺少可复现的公共基准与协议。
