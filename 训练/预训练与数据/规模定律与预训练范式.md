## 一、问题背景

训练预算往往事先给定：加速器数量、墙钟与总 FLOPs。超大模型通常只能完整训练一次，开训前把参数量 N 与训练 token 数 D 配好，往往比再调半个数量级学习率更关键。规模定律问：在 FLOPs(N,D)=C 约束下，如何选 N 与 D，使预训练交叉熵（或下游可迁移能力）尽可能好。答错了，会得到欠训练的巨型模型——算力花完了，损失仍远未到该算力下的最优前沿。

## 三、Kaplan：幂律直觉

在 WebText2 上，交叉熵损失 L 随非嵌入参数 N、数据集大小 D、训练算力 C 平滑下降；当另外两个因子不构成瓶颈时，L 对其中任一个近似服从幂律，且在宽范围内对深度/宽度不敏感（摘要、§1.1）。更大模型更样本高效；固定算力、数据充足时，最优策略往往是训很大的模型并早停，而不是把小模型训到收敛。

**单因子瓶颈（§1.2）：**

1. 仅参数瓶颈、数据足够、训至收敛：L 约按 (Nc/N) 的 αN 次幂下降；文中 αN≈0.076，Nc≈8.8×10^13（非嵌入参数；式 1.1）。
2. 仅数据瓶颈、大模型、早停：L 约按 (Dc/D) 的 αD 次幂下降；αD≈0.095，Dc≈5.4×10^13（式 1.2）。
3. 仅算力瓶颈、最优模型尺寸：对最小算力 Cmin，αCmin≈0.050，Ccmin≈3.1×10^8 PF-days（式 1.3）。

联合 N 与 D 时，文中给出过拟合形式：把「参数项」与「数据项」加在同一括号内再取 αD 次幂（式 1.5）。由 αN/αD 得：增大模型时，为免过拟合，数据宜按约 N^0.74 亚线性增长（§4）。Table 2 联合拟合给出 αN=0.076、αD=0.103、Nc=6.4×10^13、Dc=1.8×10^13（与单因子拟合略有差别）。

算力最优分配的经验（§6）：N 约按 Cmin^0.73 增长，batch 约按 Cmin^0.24，步数几乎不涨（约 Cmin^0.03）。**含义：新增算力应主要换成更大模型，数据量增长相对缓慢。** 这是后续「只堆参数」范式的直接来源，也是 Chinchilla 要纠正的假设。计算估计常用 C≈6NBS（非嵌入；§2.1）。

## 四、Chinchilla：欠训练纠正

Kaplan 外推意味着算力涨 10× 时模型约涨 5.5×、token 仅约涨 1.8×（Chinchilla 引言复述；见 arXiv v1 §1，正式版未收）。实践中 GPT-3、Gopher 等多在约 300B tokens 上训练却把参数堆到百亿乃至更大。Chinchilla 论断：在给定 FLOPs 下这些模型显著欠训练——参数过大、token 过少；纠正后的经验规则是模型大小与训练 token 数应近似等比例放大（摘要）。

同一 Gopher 算力预算下，Chinchilla 用 70B 参数、并采用 4× 更多数据（摘要；正文称相对 Gopher 约小 4 倍，训在 1.4T tokens 上），在大量下游上超过 Gopher 等；MMLU 平均准确率 67.5%，相对 Gopher 有超过 7% 的改进（摘要；正文另报 5-shot 平均 67.6%）。本节数字大部分按 NeurIPS 2022 正式版正文及补充材料；10× 算力对应 5.5×/1.8×、1T 模型须约 10^26 FLOPs 两项见 arXiv v1，正式版未收。

作者在 70M–16B+ 参数、5B–500B tokens、逾 400 次训练上拟合 Nopt∝C^a、Dopt∝C^b（§3）。三种方法（训练曲线包络、IsoFLOP 剖面、参数化损失拟合）得到的 a 在 0.46–0.50、b 在 0.50–0.54，都接近 0.5，对照 Kaplan 的 0.73/0.27（Table 2）。

参数化损失（方法 3）：把理想生成过程的损失、有限容量偏差、有限数据次优写成三项之和（式 2）。补充材料 Appendix D.2 式 (9) 的拟合为 L=E+A/N^0.34+B/D^0.28，其中 E=1.69、A=406.4、B=410.7；在 FLOPs≈6ND 约束下最优前沿仍为幂律。与 Kaplan 的方法差异：Kaplan 对所有模型用固定 token 数与固定学习率日程，中间检查点会高估「更短日程本可达到的损失」，从而低估加数据的效益（§2）。

外推（补充材料 Table A3）：约 67B 参数在与 Gopher 同量级算力下对应约 1.5T tokens；175B 则需约 3.7T tokens。除非算力达到约 10^26 FLOPs，1T 参数模型通常不是最优选择（见 arXiv v1 §3.4，正式版未收）。

## 五、Infra 辅线

1. **Token 预算与数据墙**：等比例加数据把万亿级 tokens 与清洗、配比、污染检测推到台前。
2. **有效 token**：进一步放大数据集只有在高质量时才真正有益（Chinchilla §5）；子集是否多 epoch 会进入损失曲面。
3. **预训练到指令再到偏好**：底座损失密度由 L(N,D) 决定；SFT/偏好对齐不再直接服从预训练交叉熵幂律，但「拿什么底座去对齐」仍由 compute-optimal 叙事约束。更小的 compute-optimal 底座往往降低微调与推理成本（摘要）。

## 六、局限与待核实

1. **版本**：Kaplan 维持 arXiv（2020-01-23），无正式刊。Chinchilla 数字大部分按 NeurIPS 2022 正式版正文及补充材料（落地页 [proceedings.neurips.cc](https://proceedings.neurips.cc/paper_files/paper/2022/hash/c1e2faff6f588870935f114ebe04a3e5-Abstract-Conference.html)）；预印本 arXiv:2203.15556 作首发节点；「10× 算力对应模型 5.5×、token 1.8×」（arXiv v1 §1）与「不到约 10^26 FLOPs 时 1T 参数模型通常不是最优」（arXiv v1 §3.4）两项只见于 arXiv v1，正式版未收。
2. **不可无条件外推**：「模型与 token 等比例放大」的经验规则依赖数据、优化器与拟合区间；高算力处可能存在凹性（Chinchilla §5）。
3. **损失不等于下游能力**：平滑损失改进不能从指数直接推出 MMLU 等增益。
