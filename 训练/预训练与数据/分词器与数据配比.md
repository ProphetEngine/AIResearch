# B-3：Tokenizer 与预训练数据配比 / 语料工程

> 攻坚线：**AI Infra（主）** + **架构思想（辅）**

## 一、问题动机：同样算力为何差一截

预训练叙事常把「数据」压成一个标量 $D$（token 数）。工程上 $D$ 至少拆成两层：

1. **切词（Tokenizer）**：原始 Unicode 字节/字符如何映射成离散 id。词表大小、是否依赖预分词、是否可逆，直接决定「同一篇 HTML 文本变成多少个训练 token」，以及跨语言/代码/数字的压缩效率与边界 bias。

开放权重模型常公开参数却不公开语料配方（FineWeb 摘要；DCLM 引言）。公开对照实验表明：在固定架构与训练配方下，仅改数据管线即可拉开下游差距。例如：

- FineWeb：在 96 个 Common Crawl 快照上得到 **15T** token；配套 **FineWeb-Edu（1.3T）** 在知识/推理向基准上显著强于同规模开放网页语料（FineWeb 摘要、§4）。
- DCLM：标准化 **240T** 候选池 + 固定训练配方后，**model-based filtering** 成为组装高质量训练集的关键；其 **DCLM-BASELINE** 上训的 7B / **2.6T** tokens 模型 MMLU 5-shot 约 **64%**（摘要写 64%；Table 8 报告 **63.7**），相对先前开源数据 SOTA MAP-Neo 在更少算力下提升约 **6.6** 个百分点（摘要）。

**Infra 主线抓手：** 语料管线是「吞吐—存储—CPU/GPU 过滤成本」的系统问题（WARC 抽取贵、全局 MinHash 贵、分类器扫 15T token 要数千 H100 小时）；切词器则是训练/推理侧共享的 **self-contained 预处理资产**（SentencePiece §3.5）。
**架构思想辅线：** 「无损切词」「按快照去重 vs 全局去重」「过滤够强时 mixing 可能减分」都是对**归纳偏置放在数据侧还是模型侧**的选择，而非单纯堆 token。

## 二、Tokenizer 思想（以 SentencePiece 为枢纽）

### 2.1 要解决什么：语言相关预处理拖垮「端到端」

SentencePiece（2018）面向神经文本处理（含 NMT）：既有子词工具（如 subword-nmt）通常假设输入已按空格等**预分词**；对中日韩等无空格语言，还需外挂分词器，规则语言相关、难做多语统一（§1）。同时 Moses 类规则预处理对 NMT 的有效性未充分证明，且难复现。

SentencePiece 同时实现两类算法：**BPE**（Sennrich et al., 2016）与 **Unigram LM**（Kudo, 2018），并扩展为**可直接从原始句子训练**，从而不依赖语言特定资源（摘要、§1）。

### 2.2 核心设计（Infra + 架构）

| 设计点 | 内容（据论文） | 为何重要 |
|--------|----------------|----------|
| **四件套** | Normalizer → Trainer → Encoder → Decoder（§2） | 训练与线上一致的预处理图 |
| **无损切词（lossless tokenization）** | $\mathrm{Decode}(\mathrm{Encode}(\mathrm{Normalize}(text)))=\mathrm{Normalize}(text)$；空白当普通符号，用元符号 `_`（U+2581）转义（§3.1） | 可逆解码、不丢连续空格信息；对比 subword-nmt 的 `@@` 表示无法无损编码连续空格 |
| **直接训原始句** | 无需预分词；BPE 用堆实现 $O(N\log N)$ 合并；Unigram 训练/切分对输入规模线性（§3.2） | 无空格语言与多语统一；大规模 raw 语料可训 |
| **指定最终词表大小** | `--vocab_size`，而非仅 BPE 的 merge 次数（§3.3） | 同一接口覆盖 BPE / Unigram |
| **特殊符号与虚拟 token** | 预留 `<unk>` / BOS / EOS / pad；可自定义如 `<2ja>` 多语指示（§3.3） | 把「任务/语言上下文」编码进词表 |
| **字符规范化** | 默认 Unicode NFKC（子集，非完整 CCC 重排）；可 TSV 自定义；规则编译进 FST（§3.4） | 全角/等价字形等可复现 |
| **自包含模型** | `.model` 含词表、切分参数与规范化 FST；行为仅依赖模型文件（§3.5） | 与主模型一起分发即可复现；规避「Moses 开关/Unicode 版本漂移」 |
| **在线 API** | C++ / Python / TF；支持 Unigram 的 `SampleEncode` 做 subword regularization（§3.6、Figure 6） | 训练期随机切分；服务端 on-the-fly |

### 2.3 实验要点（仅报告文中结果）

KFTT 英日 NMT（GNMT 设定）：共享 8k SentencePiece 词表相对词级 80k 基线提升 BLEU；**无预分词**在 en→ja 上优于有预分词（21.62 vs 20.86），ja→en 上接近（29.55 vs 29.85）（Table 1）。日语 raw 上 SentencePiece 切分速度约比 subword-nmt **快 380×**（Table 2 叙述）。

### 2.4 跟读当代时的「架构思想」一句

切词器不是「把字切开」的附录，而是：

- **可复现的压缩器**（决定有效序列长度与嵌入表形状）；
- **语言无关接口**（把分段约束从规则挪到数据驱动合并/Unigram）；
- **与数据管线正交但耦合**：同一网页在不同 tokenizer 下 token 数不同，公开数据集「T tokens」必须注明 tokenizer（FineWeb 消融用 GPT-2 tokenizer；DCLM-POOL 报 **GPT-NeoX** token；Dolma 卡分别给 OLMo / Llama token 计数）。

本卡不展开各厂 BBPE 词表数字（那些写在各 TR 卡）；思想锚在 SentencePiece 的无损、自包含、双算法统一接口。

## 三、现代语料工程对照表

### 3.1 管线共性骨架

公开网页预训练语料的共识流水线（FineWeb §2–3；DCLM §4 Figure 4；Dolma 卡）：

2. **语言与安全/URL 过滤**。
3. **启发式质量/重复过滤器**（行长、标点、重复 n-gram、停用词等；MassiveText / C4 / RefinedWeb 系规则）。
4. **去重**：精确 / 模糊（MinHash）/ Bloom 近似；粒度含 URL、文档、段落、行。
5. **（可选）模型打分筛选**：分类器、困惑度、LLM 合成标注等。
6. **（可选）多源 mixing**：代码、论文、书、Wiki、指令式语料等按比例上采样。

### 3.3 对照后的 Infra 要点

1. **抽取器是一阶变量**：WET vs WARC+trafilatura/resiliparse 在小规模消融上即可拉开聚合准确率（FineWeb Fig.1；DCLM §4.2）。多数早期开放集走 WET，可能部分解释其落后（DCLM §4.2 论述）。
2. **去重「越狠越好」不成立**：FineWeb 显示**全局** MinHash 会在老快照上**上采样低质长尾**；**按 crawl 独立**去重更匹配 RefinedWeb 级表现（§3.4）。DCLM 则用可扩展 Bloom 近似换取与更贵 MinHash 管线接近的分数（§4.3）。
3. **过滤参考分布决定分类器**：DCLM 中 OH-2.5+ELI5 正例显著优于 Wiki / OpenWebText2 /「GPT-3 近似」正例（Table 5：CORE 41.0 vs 35.7/34.7/37.5）。FineWeb-Edu 用 LLM 合成「年级教育」标注，刻意避免只偏向 arXiv 极技术页（§4）。
4. **Mixing 是条件策略**：过滤弱时加点 Wiki/书/代码常涨；过滤已强时硬套 Llama/RPJ 配比可能**减分**（DCLM Table 6）。Dolma 路线则是**透明多源 + 采样比例**，与「纯 CC + 极强过滤」形成对照。
5. **基准化**：DCLM 把「数据策展」做成固定训练配方、多算力档（400M-1x … 7B-2x）、filtering / mixing 双赛道；小规模排名与 7B-1x 高相关（Pearson r 最高约 0.982，§3.2），使迭代可负担。

## 四、常见误区

1. **把 [[规模定律与预训练范式]] 的 $D$ 当成语料质量已经对齐**
 Chinchilla 等回答的是算力最优的 **token 数量级**；FineWeb / DCLM 表明同等 $D$ 下过滤与去重可改变有效难度与下游斜率。本卡补的是「token 从哪来、怎样筛」，不是重开幂律拟合。

2. **「全局去重一定优于按快照去重」**
 FineWeb §3.4：全局迭代 MinHash → 4T，350B 训练几乎无涨；对 2013-48，**被去掉的 90%** 训出来反而好于留下的 10%。假设应改为：优先去掉跨站超大重复簇；对小簇过度去重可能伤害多样性。

3. **「子词必须先分词」或「有空格语言才需要 SentencePiece」**
 SentencePiece 的卖点恰是**跳过预分词**的无损端到端；英日实验显示预分词并非稳赚（Table 1）。

4. **「词表越大越好 / merge 次数是唯一旋钮」**
 SentencePiece 统一用最终 `vocab_size`；当代还要权衡嵌入参数、稀有字 byte 回退、数字拆分等（细节见各模型 TR，此处不外推）。

5. **「混入 Wiki/书/StackExchange 总是涨点」**
 DCLM Table 6：对 C4 / RPJ-CC / RefinedWeb 有益，对 **DCLM-BASELINE 有害**。Mixing 前应先问过滤是否已饱和。

6. **「教育向过滤只有好处」**
 FineWeb-Edu 在 MMLU/ARC 大涨，但主题分布偏移、Paloma 域困惑度显示对泛网页域覆盖变弱、对 Wiki/学术域变强（§4.1–4.2）。配比需按目标能力组合，而非单一「越高质越好」。

7. **「开放数据集的 T 可直接横比」**
 Tokenizer 不同（GPT-2 / GPT-NeoX / Llama / OLMo）、是否含代码/数学、是否上采样，都会改变「T」含义。对照必须固定 tokenizer 与抽样协议（FineWeb / DCLM 消融均强调这一点）。

8. **「分类器正例用人类‘高质量’直觉即可」**
 DCLM 明确：人类质量判断识别优质训练数据的价值有限（引言）；指令式 / ELI5 正例优于传统「百科+书」正例（§4.4）。
