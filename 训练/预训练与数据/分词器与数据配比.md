## 一、问题背景

预训练叙事常把「数据」压成一个标量 D（token 数）。工程上 D 至少拆成两层：切词把 Unicode 映射成离散 id，决定同一篇文本变成多少训练 token；语料管线决定哪些文档进入训练集。开放对照表明：固定架构与训练配方下，仅改数据管线即可拉开下游差距——FineWeb 在 96 个 Common Crawl 快照上得到 15T token，配套 FineWeb-Edu（1.3T）在知识/推理向基准上显著强于同规模开放网页语料；DCLM 在标准化 240T 候选池后，指出 model-based filtering 是组装高质量训练集的关键，其 BASELINE 上训的 7B / 2.6T tokens 模型 MMLU 5-shot 约 64%（Table 8 为 63.7），相对先前开源数据 SOTA 在更少算力下提升约 6.6 个百分点（摘要）。

## 三、Tokenizer：以 SentencePiece 为枢纽

SentencePiece（EMNLP 2018）面向神经文本处理：既有子词工具常假设已预分词，对中日韩等无空格语言还需外挂规则分词器。它同时实现 BPE 与 Unigram LM，并可直接从原始句子训练（摘要、§1）。

核心设计（论文）：Normalizer、Trainer、Encoder、Decoder；Decode(Encode(Normalize(text))) = Normalize(text) 的无损切词，空白用元符号转义；用最终 vocab_size 统一接口；模型文件自包含词表、切分参数与规范化规则。KFTT 英日 NMT：共享 8k 词表相对词级 80k 基线提升 BLEU；无预分词在 英译日 上优于有预分词（21.62 vs 20.86）（Table 1）。数字以正式刊 EMNLP 版本为准。

切词器是可复现的压缩器，也是语言无关接口；公开数据集的「T tokens」必须注明 tokenizer（FineWeb 消融用 GPT-2；DCLM-POOL 报 GPT-NeoX；Dolma 论文按 Llama tokenizer 计数，Table 1 注）。

## 四、跨词 token 与词表扩展

第三节的 SentencePiece 是子词路线的通用接口。子词 BPE 本身来自机器翻译：[Neural Machine Translation of Rare Words with Subword Units](https://arxiv.org/abs/1508.07909)（Sennrich 等，v1 2015-08-31）把 BPE 压缩算法用于切分罕见词与未登录词，使模型能以有限词表处理开放词表的翻译（摘要）。多数实现在 BPE 之前先做预分词（按空格与标点切开），合并只在预分词单元内部进行，因此 token 落在词内。

**分词器选择并非无关紧要。** [Tokenizer Choice For LLM Training: Negligible or Crucial?](https://arxiv.org/abs/2310.08754)（Ali 等，v1 2023-10-12）训练 24 个 2.6B 参数的单语与多语模型做消融，结论是分词器选择会显著影响下游效果与训练成本，常用的「生育率」（每词平均 token 数）与「均等性」指标并不总能预测下游表现（摘要）。[Getting the most out of your tokenizer for pre-training and domain adaptation](https://arxiv.org/abs/2402.01035)（Dagan 等，v1 2024-02-01）在代码生成任务上表明，词表大小、预分词正则表达式与分词器训练数据都会显著影响生成速度、有效上下文长度、显存与下游效果（摘要）。

**跨词 token。** 预分词的词内限制可以放开：

- [SuperBPE](https://arxiv.org/abs/2503.13423)（Liu 等，v1 2025-03-17，据 v3）在 BPE 中加入两阶段预分词课程，先学子词，再学跨越空格的「超词」（如 "by the way"）。词表固定为 200k 时，同一段文本平均最多少用 33% 的 token；在固定模型规模、词表大小与训练算力、只改变词表学习算法的 8B 模型对照中，30 项下游任务平均绝对提升 4.0 个百分点，推理计算少 27%（摘要）。作者的解释是超词使每个 token 的预测难度更均匀，常见多词表达在语义上本就是一个单位。
- [Boundless Byte Pair Encoding](https://arxiv.org/abs/2504.00178)（BoundlessBPE，Schmidt 等，v1 2025-03-31，据 v2）指出预分词使 token 分布偏向常见完整词，词表再扩大时新增 token 出现次数越来越少；它有选择地把两个完整预分词单元合并为超词，使 token 分布更均匀，每 token 字节数最多提升 15%（摘要）。

**词表规模。** [Scaling Laws with Vocabulary](https://arxiv.org/abs/2407.13623)（Tao 等，v1 2024-07-18，据 v3）在 33M 到 3B 参数、最多 500B 字符的训练上，用三种互补方法预测算力最优词表，结论一致：最优词表随算力预算增长，更大的模型需要更大的词表；论文预测 Llama2-70B 的最优词表应至少为 216K（摘要）。输入侧把词表扩大到多元组 token、以查表方式增加容量的做法，机制见 [[条件记忆与查表稀疏Engram]]。

以上收益都在各自论文固定模型规模、词表与算力的受控设定下测得，彼此不可横比。

## 五、字节级建模：去掉分词器

另一方向是不要固定词表，直接以 UTF-8 字节为输入单位。好处是任何语言开箱可用、对噪声与拼写更鲁棒、去掉易错的预处理；代价是序列长度成倍增加，计算与上下文成本随之上升。这条路线的演进，主要是在找把字节聚合为更大计算单位的方法。

**早期路线。** [CANINE](https://arxiv.org/abs/2103.06874)（Clark 等，v1 2021-03-11）是直接处理字符序列、无显式分词与词表的编码器，用下采样缩短输入再接深层 Transformer（摘要）。[ByT5](https://arxiv.org/abs/2105.13626)（Xue 等，v1 2021-05-28）表明标准 Transformer 只需少量修改即可处理字节序列，字节级模型与 token 级模型相比有竞争力，且对噪声显著更鲁棒、在对拼写与发音敏感的任务上更好（摘要）。[MEGABYTE](https://arxiv.org/abs/2305.07185)（Yu 等，v1 2023-05-12）把序列切成补丁（patch），补丁内用局部子模型、补丁之间用全局模型，可端到端建模超过一百万字节的序列（摘要）。[SpaceByte](https://arxiv.org/abs/2404.14408)（Slagle，v1 2024-04-22）在字节级 Transformer 中间插入更大的 Transformer 块，且只在空格等通常标志词边界的字节之后使用；在固定训练与推理算力下优于其他字节级架构，并大致追平基于 token 的 Transformer（摘要）。

**动态补丁与端到端分块。** 固定长度或按空格切补丁仍是人为规则，后续工作让补丁边界随内容变化：

- [BLT](https://arxiv.org/abs/2412.09871)（Byte Latent Transformer，Pagnoni 等，v1 2024-12-13）按下一字节的熵切分动态长度补丁，数据可预测处用长补丁，复杂处分配更多计算；论文给出首个到 8B 参数、4T 训练字节的算力受控字节级缩放研究，并称在固定推理成本下，同时增大补丁与模型规模时，BLT 的缩放显著优于基于 token 的模型（摘要）。
- [H-Net](https://arxiv.org/abs/2507.07955)（Hwang 等，v1 2025-07-10，据 v2）提出与模型其余部分联合学习的动态分块机制，用一个端到端学习的分层网络替代「分词—建模—反分词」流水线；在算力与数据匹配时，单级分层的字节级 H-Net 优于在 BPE token 上运行的强 Transformer，多级分层进一步提升；在中文、代码等分词启发式较弱的数据上优势更大（摘要）。

**把子词模型改造成字节级。** 从头训练字节级模型的成本，使其难以跟上子词模型的迭代。Bolmo 的做法是「字节化」（byteification）：以两阶段转换流程把现有子词模型改造成字节级模型。本篇按其 Nature 期刊版 [Retrofitting language models to operate over bytes](https://www.nature.com/articles/s41586-026-11111-4)（Minixhofer 等，2026-10-07 在线）引述：改造所用训练量不到典型预训练预算的 1%（合计 49.1B token）；由 Olmo 3 7B 与 OLMo 2 1B 得到 Bolmo 7B 与 Bolmo 1B，并由 Qwen3 8B Base 与 Llama 3 8B 分别得到字节化模型 Bwen 8B 与 Blama 8B；架构先把字节流聚合成由一个或多个字节组成的补丁，再交给大型 Transformer 处理（正文）。期刊版标题与模型范围均不同于 [arXiv 预印本](https://arxiv.org/abs/2512.15586)（v1 2025-12-17，v2 2026-02-09），后者摘要称所得模型优于以往字节级方法、在字符级推理任务上表现突出、在标准基准上保持竞争力，并可借源模型的现有生态低成本适配。

**2026 年的改进与代价。** 2026 年的工作多在中小规模上验证，这里只写思路：

- [ByteFlow](https://arxiv.org/abs/2603.03583)（Deng 等，v1 2026-03-03，只有 v1）按潜在表示的编码率做压缩驱动的分块，并用 Top-K 选择保持静态计算图；实验规模为 0.6B 与 1.3B（表 1 表题）。
- [Fast Byte Latent Transformer](https://arxiv.org/abs/2605.08044)（Kallini 等，v1 2026-05-08，只有 v1）针对逐字节自回归生成慢的问题，为 BLT 加入辅助的分块扩散目标以每步并行生成多个字节，另有自推测与扩散后验证两种变体，以部分速度换取质量；作者估计各方法在生成任务上的显存带宽开销可比 BLT 低 50% 以上（摘要）。
- [Scratchpad Patching](https://arxiv.org/abs/2605.09630)（Zheng 等，v1 2026-05-10，只有 v1）把大补丁质量下降归因于「补丁滞后」：补丁未读完前，补丁内字节的预测只能依赖上一补丁的旧表示。它在补丁内按下一字节熵插入临时汇总，刷新补丁级上下文；每补丁 16 字节时，下游评测达到或接近字节级基线，补丁级 KV 缓存缩小 16 倍、推理计算少 3 到 4 倍（摘要）。
- [The Efficiency Gap in Byte Modeling](https://arxiv.org/abs/2605.12928)（Lee 等，v1 2026-05-13，只有 v1）做算力匹配的缩放研究，发现字节建模的性能代价并不均匀：其缩放开销在掩码扩散模型上比自回归模型更大（摘要）。

**小结。** 跨词 token 把计算单位变大，字节级建模先把单位缩到字节、再由补丁或分块重新聚合，两者方向相反，但都在回答同一个问题：计算单位是否应由一张固定词表决定。分词方式还影响不同语种的 token 成本，这一侧见 [[多语言与跨语种]]。

## 六、现代语料工程对照

公开网页预训练语料的共性骨架：语言与安全/URL 过滤，再启发式质量/重复过滤，再去重（精确/MinHash/Bloom），可选模型打分，可选多源 mixing（FineWeb §2–3；DCLM §4；Dolma §5）。

| 维度 | FineWeb | FineWeb-Edu | DCLM-BASELINE | Dolma（论文 v2，对应 v1.6） |
|---|---|---|---|---|
| 规模 | 15T（96 快照；GPT-2 tok） | 1.3T | 池 240T；BASELINE 约 3.8T；再与代码、数学数据合并为约 4.1T 后训 7B | 合计 3,059B Llama tokens（Table 1） |
| 抽取 | trafilatura 处理 WARC | 继承 | resiliparse；较 trafilatura 快约 8× | — |
| 去重 | 按快照独立 MinHash；全局去重到 4T 但 350B 消融几乎无涨分 | 继承 | Bloom 近重，与更贵 MinHash 下游接近 | URL、文档、段落三级精确去重，都用 Bloom filter（§5.4） |
| 模型筛选 | 启发式调参 | Llama-3-70B-Instruct 打教育分后再做线性回归；扫全量约 6000 H100 h | fastText，正例 OpenHermes-2.5+ELI5，保留 top-10% | 多源工具链为主 |
| 代表信号 | 逐步叠加过滤涨分 | 1.71B/350B：MMLU 从 33% 到 37%，ARC 从 46% 到 57% | 7B/2.6T：CORE 57.1，MMLU 63.7 | 以 OLMo-1B 与同规模模型对照（Table 2） |

Infra 要点：抽取器是一阶变量；「去重越狠越好」不成立（FineWeb 全局 MinHash 会在老快照上采样低质长尾）；过滤参考分布决定分类器；Mixing 是条件策略（DCLM-BASELINE 再混 RPJ extras 反而 CORE −1.2）；DCLM 把策展做成固定训练配方与双赛道基准。
