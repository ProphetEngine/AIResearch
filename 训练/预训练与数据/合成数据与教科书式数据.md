# B-8：合成数据与教科书式数据

> 攻坚线：**架构思想（主）** + **AI Infra（辅，数据管道）**
> 入口：Wang et al., *SELF-INSTRUCT: Aligning Language Models with Self-Generated Instructions*（arXiv:2212.10560；ACL 2023；官方 PDF 页眉 **v2 / 2023-05-25**）；Gunasekar et al., *Textbooks Are All You Need*（phi-1；arXiv:2306.11644；官方 PDF 页眉 **v2 / 2023-10-02**）。

## 一、动机：为何「堆真实网页」不够

预训练与后训练里，「数据」常被压成标量 $D$。B-3 已说明：同等 $D$ 下，网页语料的抽取/去重/过滤可改有效信息密度。本卡补另一条轴——**数据是否由更强模型（或同一模型）合成，以及是否按「教科书 / 习题」形态组织**：

1. **指令数据瓶颈（Self-Instruct §1）**
 指令微调依赖人类写的 instruction 数据（如 PromptSource、Super-NaturalInstructions），成本高且多样性受限：人类生成往往落在「常见 NLP 任务」附近，覆盖不到真实用户式的创意任务。需要几乎无标注、可扩规模的替代监督。

2. **代码语料「像仓库不像教材」（Textbooks §2）**
 The Stack / StackOverflow 等标准代码语料体量大、覆盖广，但人工抽检显示：大量片段非自洽、偏样板/配置、算法逻辑埋在复杂函数里、主题分布偏斜——对「学基础编程与算法推理」信号差。作者猜想 LM 同样受益于像好教科书那样的数据：**清晰、自洽、有教学性、概念均衡**。

3. **架构思想抓手**
 - Self-Instruct：把「对齐到指令」从「雇人写任务」改成**模型自举任务库 + 回灌微调**（bootstrapping）。
 - Textbooks：把 scaling 叙事从「更大 $N$、更多网页 token」扩到**数据质量轴**（引言明确跟随 TinyStories / Eldan & Li：高质量可改动 scaling 曲线形状）。
4. **Infra 辅线抓手**
 合成管线是「教师调用成本 × 过滤/去污 × 多样性诱导」的系统问题；教科书路线用 **~7B** 精选 token + **8×A100 / ~4 天** 训出 1.3B 代码模型，与「数百 B–1T 代码 token」对照（Textbooks Table 1、§2.3）。

## 二、Self-Instruct：自生成指令对齐

### 2.1 问题与主张（摘要 / §1）

SELF-INSTRUCT：用**预训练 LM 自身**生成指令、输入与输出，过滤无效或过相似样本后，再微调**同一模型**以提升指令跟随。几乎无标注；并发布约 **52K** 合成指令数据。

对 vanilla GPT-3（`davinci`）应用后：

| 结果（据摘要 / Table 3 / §4.4） | 数字 |
|--------------------------------|------|
| Super-NaturalInstructions（未见任务）相对原 GPT-3 | **+33.1** 绝对点（ROUGE-L **6.8 → 39.9**） |
| 与 InstructGPT<sub>001</sub>（同设定可比引擎） | **39.9 vs 40.8**，接近持平 |
| 再叠 SuperNI 训练 | GPT3<sub>SELF-INST</sub>+SuperNI **51.6** vs GPT3+SuperNI **49.5** |
| 人工评 252 条专家写「新用途」指令 | 可接受响应仅落后 InstructGPT<sub>001</sub> 约 **5%** 绝对差距 |

> 注：作者明确主要对照 **text-davinci-001**（与「演示监督微调」设定最接近）；更新引擎含更多数据/PPO，难直接比（摘要脚注 1）。

### 2.2 流水线（§2、Figure 2）——架构思想

半自动**迭代自举**：

1. **种子任务池**：人工写 **175** 个任务（每任务 1 条指令 + 1 个实例；作者/实验室新写，未参考测试集，§2.2 脚注 3）。
2. **Instruction Generation**：从池中采 **8** 条作 in-context（**6** 人工种子 + **2** 此前模型生成，促多样性），提示 LM 生成新指令。
3. **Classification Task Identification**：few-shot 判定是否分类任务（种子中 12 正例 / 19 非分类；小输出标签空间视为分类，脚注 4）。
4. **Instance Generation**
 - **Input-first**（多数非分类）：先生成输入字段，再生成输出。
 - **Output-first**（分类）：先生成可能类别标签，再条件生成输入——缓解「输入偏向单一标签」问题（§2.2）。
5. **Filtering / Postprocessing**
 - 新指令相对池内任一条 **ROUGE-L ≥ 0.7** 则丢弃；
 - 排除含 image/picture/graph 等 LM 难处理关键词；
 - 实例：去精确重复、同输入异输出；启发式剔除过长/过短指令、输出复读输入等。
6. 合格任务回填任务池，可多轮迭代至大规模。

微调时：指令+输入作 prompt，监督生成输出；用多种模板拼装（有无 `Task:`/`Input:`/`Output:`、换行数等）以增强格式鲁棒性（§2.3）。GPT-3 实验经 OpenAI finetuning API，默认超参，**prompt loss weight = 0**，**2 epochs**（§4.1）。

### 2.3 数据画像（§3）

| 统计（Table 1） | 值 |
|-----------------|-----|
| 指令数 | **52,445**（分类 11,584；非分类 40,861） |
| 实例数 | **82,439**（空输入 35,878） |
| 均长（词） | 指令 15.9；非空输入 12.7；输出 18.9 |

多样性：解析根动词+直接宾语（26,559/52,445 条有该结构）；Top-20 动词结构仅占全集 **14%**（Figure 3）。相对 175 种子的最高 ROUGE-L 分布显示大量低重叠新指令（Figure 4）。

质量抽检（200 指令×1 实例，作者标注，Table 2）：

| 字段 | 「有效」比例 |
|------|-------------|
| 指令描述合法任务 | **92%** |
| 输入适合该指令 | **79%** |
| 输出正确可接受 | **58%** |
| 三者皆有效 | **54%** |

作者观点：即便有噪声，多数仍格式正确或部分正确，足以作指令跟随监督（§3.3）。

### 2.4 规模与质量消融（§4.5）

在 252 用户向指令上，随合成指令数增加，人工「Rating-A」比例上升，约在 **16K** 后接近平台；用 InstructGPT<sub>003</sub> 改进输出再蒸馏可抬高曲线（Figure 7：如 51.2K 处约 **44.4% → 54.4%** Rating-A）。含义：**量有收益但有饱和；质（更好教师输出）仍是瓶颈**——与后文「教科书质量」「R1 蒸馏轨迹质量」同构。

### 2.5 Infra 辅读

- **教师即学生**：生成与微调用同一 vanilla GPT-3，省「另外部署教师」但受基座能力上限约束。
- **过滤便宜**：ROUGE-L + 关键词 + 启发式，无需再训分类器（对照 Textbooks 的 GPT-4 标注 + 随机森林）。
- **API 微调**：实验路径绑 OpenAI finetune；复现需自备等价监督微调栈。
- 代码与数据：https://github.com/yizhongw/self-instruct（摘要脚注 2）。

## 三、教科书式数据：phi-1（Textbooks Are All You Need）

### 3.1 主张与总表（摘要 / Table 1）

**phi-1**：1.3B Transformer，**8×A100 约 4 天**预训练；数据为网页上筛出的「教科书质量」代码语料（约 **6B** token）+ GPT-3.5 合成教科书与习题（约 **1B** token 量级，合计 **&lt;7B**）。
结果（self-reported pass@1）：**HumanEval 50.6%**，**MBPP 55.5%**。同管线 **350M** 的 phi-1-small 仍达 HumanEval **45%**。
对照表中多数更大模型 / 更大语料（如 StarCoder 15.5B / 1T → 33.6% / 52.7%）；文称除 GPT-4 外整体占优，WizardCoder HumanEval 更高（57.3%）但 MBPP 更低（51.8%）（Table 1 注）。

### 3.2 三块数据与两阶段（§2）

| 数据集 | 构成（据文） | 角色 |
|--------|--------------|------|
| **过滤代码—语言语料** | The Stack（去重 Python）+ StackOverflow 子集；LM 分类器筛「教育价值」→ 约 **6B** tokens | 预训练主体之一 |
| **合成教科书** | GPT-3.5 生成 Python 教科书，**&lt;1B** tokens；自然语言重、穿插相关代码；约束主题与受众促多样性 | 预训练 |
| **CodeExercises** | GPT-3.5 生成习题+解答，**∼180M**（&lt;200M）tokens；用**函数名约束**促多样性 | **微调**对齐「按 docstring 写函数」 |

合称过滤语料 + 合成教科书为 **CodeTextbook** → 预训练得 **phi-1-base**（HumanEval 已约 **29%**）；再在 CodeExercises 上微调得 **phi-1**（§2）。

**过滤管线（§2.1，Infra）：**

1. 公开 Python 语料 &gt;35M 文件 / &gt;35B tokens；
2. 用 **GPT-4** 对约 **100k** 样本标注「对学基础编程概念的教育价值」；
3. 以 codegen 模型输出嵌入为特征，训 **随机森林** 打分筛全量；
4. 作者强调 GPT-4 **仅**用于小规模标注以省人工，合成正文主要靠 GPT-3.5。

仅过滤（无合成书）已显著抬分：350M 上，未过滤 Stack 训到 ~200B tokens HumanEval 饱和 **12.19%**；过滤子集 36k steps → **17.68%**；过滤+合成教科书 → **20.12%**（§2.1，Figure 2.1 叙述）。

**多样性「技巧」（§2.2）：** 直接提示「写教科书/习题」易高度同质；借鉴 TinyStories，向 prompt **注入受控随机性**（教科书：主题/受众约束；习题：约束函数名）。

### 3.3 架构与训练超参（§2.3）——Infra

| 项 | phi-1（1.3B） | phi-1-small（350M） |
|----|---------------|---------------------|
| 层数 / 隐维 / MLP / 头 | 24 / 2048 / 8192 / 32×64 | 20 / 1024 / 4096 / 16×64 |
| 位置编码 | RoPE，rotary dim **32** | 同族 |
| 注意力 | FlashAttention 实现的 **MHA**；**MHA∥MLP 并行**（循 CodeGen / PaLM / GPT-NeoX） | 同 |
| Tokenizer | 与 codegen-350M-mono 相同 | 同 |
| 明确未用 | FIM、MQA 等 | — |

训练共性：序列长 **2048**；fp16；AdamW；linear warmup + linear decay；attention/residual dropout **0.1**；**8×A100** + DeepSpeed。

| 阶段 | 数据 | 有效 batch | max LR / warmup | weight decay | steps / 选取 | 算力叙事 |
|------|------|------------|-----------------|--------------|--------------|----------|
| 预训练 → phi-1-base | CodeTextbook | **1024** | **1e-3** / 750 | 0.1 | 共 36k；取 **24k**（≈ **8** epoch，总见 token 略超 **50B**） | 文：phi-1 / base **770 GPU hours**；&lt;4 天 |
| 微调 → phi-1 | CodeExercises | **256** | **1e-4** / 50 | 0.01 | **6,000**（每 1k 存盘选最优） | 同硬件再 **+7 hours** |

Figure 2.1：同规模下 CodeTextbook 列显著高于「The Stack+」列；微调 CodeExercises 带来 HumanEval 最大跃迁，并「解锁」基座上未见的涌现行为（§3）。

### 3.4 微调后的能力「尖峰」（§3，定性）

CodeExercises 几乎全是短 Python + 基础库，但微调后：

- 对逻辑关系更贴指令（phi-1-base 常乱；350M small 部分理解仍错解）；
- 能更好使用 **外部库**（Tkinter / PyTorch / pyplot 等定性例）；
- **聊天式**答疑也优于 base（聊天数据只在预训练侧出现，微调无聊天）（§3）。

作者解释倾向：微调可能帮助**重组/巩固预训练已学知识**，即使习题集未显式包含那些库用法。

### 3.5 污染与非常规评测（§4–§5）

| 检查 | 结论（据文） |
|------|--------------|
| 标准 n-gram | HumanEval docstring 与 CodeExercises：**4** 题出现 13-gram 重叠，核查均为假阳性；「逐字重叠极少」（§5.1） |
| 强去污：按嵌入 L2 + AST 编辑距离剪枝习题 | 剪掉 **&gt;40%** 习题（τ=0.95 时约 42.5K/879.5K 题等，§5.2）后重训，HumanEval 总准确率仍可 **≥ StarCoder-Prompted**（Table 3：剪后约 45–50.6% vs 41.5%） |
| 50 道「非常规」新题 + GPT-4 打分（0–10） | 排序与 HumanEval 一致；phi-1 Understanding **52%** vs StarCoder **51%**、phi-1-base **37%**（Table 2） |

文末说明：发布模型供社区评估，但**省略部分合成数据生成细节**（专有原因）（§1）。

## 四、与 R1 蒸馏的交叉（接口，不重写）

完整管线、GRPO、规则奖励、Dev1–3 阶段表见 **模型与技术报告/厂商报告/DeepSeekR1推理训练深读.md**（据 arXiv:2501.12948）。此处只钉「合成数据」接口：

| 维度 | Self-Instruct | Textbooks / phi-1 | DeepSeek-R1 蒸馏（TR §四） |
|------|---------------|-------------------|---------------------------|
| **合成什么** | 指令 + 输入 + 输出（任务库） | 教科书正文 + 函数习题/解答 | 长 CoT 推理轨迹（~800k SFT，Table 5 合计 **804,745**） |
| **教师** | 常为**同一** vanilla LM（自举） | **更强** GPT-3.5（+GPT-4 仅标注） | **DeepSeek-R1**（经 RL 的推理模型） |
| **学生** | 同一 GPT-3 再 SFT | 小代码 LM（1.3B/350M）从近零预训练+微调 | 开源小基座（Qwen2.5 / Llama 等）**仅 SFT 2–3 epoch，无 RL** |
| **过滤信号** | ROUGE 去重 + 启发式；输出正确率抽检约 58% | 教育价值分类器；习题侧嵌入+AST 去污 | 可验证题规则判对；拒绝采样；可读性/语言一致等（TR B.3） |
| **目标能力** | 广谱指令跟随 | 代码生成（HumanEval 向） | 数学/代码/STEM **推理**可迁移到小模型 |

**架构思想一句：** 三条线共享「用生成分布当监督」，但归纳偏置不同——Self-Instruct 扩**任务多样性**；Textbooks 抬**单位 token 教学密度**；R1 蒸馏迁移**已 RL 激励出的推理过程**。TR 作者结论（F.1）：强教师蒸馏进小模型「又省又强」；小模型只靠文中规模纯 RL 可能仍不及蒸馏——与 phi-1「小模型 + 高质量合成」叙事同向，但**信号来源**（习题文 vs 长思维链）不同。

**勿在本卡展开：** GRPO 公式、R1-Zero 无 SFT、两段 RL 奖励方程组——一律回链 TR。

## 五、与 B-3 真实网页语料划界

| | **B-3（真实网页 / 开放语料工程）** | **B-8（合成 / 教科书式）** |
|--|-----------------------------------|---------------------------|
| 原料 | Common Crawl、The Stack 等**已存在**文本 | LM **新写**的指令/教科书/习题/推理轨迹（可辅以过滤后的真实子集） |
| 典型规模 | FineWeb **15T**、DCLM 池 **240T** 量级 | Self-Instruct **~52k** 指令；phi-1 训练语料 **&lt;7B** tokens |
| 主旋钮 | 抽取器、启发式、MinHash/Bloom 去重、分类器保留率、mixing | 种子/约束设计、教师选择、相似度阈、教育价值标签、去污相对评测集 |
| 优化目标叙事 | 同等或更少 FLOPs 下**通用预训练**下游 | **指令对齐**或**窄域（代码）SOTA**、改写小模型 scaling |
| 与 FineWeb-Edu 的易混点 | FineWeb-Edu 用 LLM 打「教育分」筛**真实网页**（B-3） | Textbooks 的合成教科书是 **GPT-3.5 新写**；过滤 Stack 虽也用「教育价值」，但是**代码文件级分类器**，不是 CC 网页管线 |

交叉而非替代：现代配方常 **B-3 式大规模网页/代码底料 + B-8 式合成指令/推理/教科书** 混合；配比与冲突（例如 DCLM「过滤已强时再 mix 可能减分」）仍属 B-3 实验语法，本卡不重开。

## 六、常见误区

1. **「合成数据 = 随便让 GPT 多写一点」**
 Self-Instruct 强调种子引导、分类/非分类分支、ROUGE 去重；Textbooks 强调主题/函数名等**受控随机性**，否则高度同质（§2.2）。无约束生成易塌缩。

2. **「教科书路线否定规模定律 / 否定网页语料」**
 Textbooks 引言是**沿质量轴**改 scaling 形状、在**代码函数生成**任务上以小模型追赶；不是宣称通用网页预训练可被 7B token 取代。通用知识/长尾仍主要在 B-3 轴。

3. **「Self-Instruct 已等于 InstructGPT / RLHF」**
 Self-Instruct 是**合成 SFT 数据**方法；InstructGPT<sub>001</sub> 含私有用户数据与人类标注，更新引擎还有 PPO 等（脚注 1）。对齐与偏好优化的偏好优化不在本卡范围。

4. **「输出噪声高就不能训」**
 Self-Instruct 抽检输出仅 58% 完全可接受，但 SuperNI / 人工评仍大涨（§3.3、§4）。噪声有上限；§4.5 也显示更好教师输出仍能再涨。

5. **「HumanEval 高 = 一定泄漏了原题」**
 Textbooks §5：标准 n-gram 几乎无真阳性；强剪枝仍优于更大基线；另设 50 道非常规题交叉验证。仍须做去污，但不能把分数**默认**写成作弊。

6. **「R1 蒸馏与 Self-Instruct / phi-1 是同一件事」**
 见第四节表：任务库自举 ≠ 教科书预训练 ≠ 推理轨迹蒸馏。共同点是合成监督；差别在教师强度、是否自举、是否经 RL、目标能力。

7. **「过滤真实代码 = B-3 的 FineWeb-Edu」**
 同属「模型打分筛数据」，但域（代码文件 vs 网页）、标注题面、下游（HumanEval vs MMLU/ARC）均不同；划界见表第五节。

8. **「复现 phi-1 只需公开 7B token 配方」**
 作者**省略部分合成细节**（§1）；过滤分类器与 GPT-3.5 prompt 策略均非完全开箱。报告能复述的是公开超参、阶段与评测数字，不是完整数据生成剧本。
