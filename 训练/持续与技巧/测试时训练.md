# Test-time training：In-Place TTT + TEMPO（Modular-TTT 索引）

> **定位**：测试时训练 **P0**——相对 **[[推理时扩展TestTimeScaling]]**（不改权重的 test-time **算力/搜索**通史）与 **[[推理时树搜索ABMCTS]]**（外层答案树 AB-MCTS），补仓库缺失的 **参数级推理期适应 / Test-Time Training（TTT）** 横切：主文 **In-Place TTT**（arXiv **2604.06169**）把 MLP 末投影当可适配 fast weights；主文 **TEMPO**（**2604.19295**）对大推理模型做 actor–critic 交替校准以缓解自奖励漂移；**Modular-TTT**（**2608.07110**）仅作设计空间索引，不升主深读。
> **攻坚线**：**架构思想（主）**——fast weights 落在哪、用什么自监督/自奖励目标、如何与注意力/EM 校准共存；**评测字段（辅）**——RULER 长上下文与 AIME 等文内表。
> **硬划界**：
> - **≠ [[推理时扩展TestTimeScaling]]**：不写 o1/R1/s1 产品通史、「势」、训练期 RL 长 CoT；只取「推理期多算力」接口，本卡主战场是 **改参数**。
> - **≠ [[推理时树搜索ABMCTS]] AB-MCTS**：外层 **答案树 / Thompson 宽深** ≠ 层内 **fast weights 在线更新**；本卡不写 GEN 节点与 TreeQuest。
> - **≠ [[持续学习]] lifelong**：终身学习 taxonomy / 任务序列抗遗忘 ≠ **单次测试实例（或未标注测试题集）上的 TTT**。
> - **Modular-TTT 仅索引**：消融地图与 410M/1.45B 对标 GDN 一句带过，不展开 primitive DAG 实现。
> - **禁止编造**：主张与表数字一律锚定官方 PDF（2026-09-22 CST）；TEMPO 正文徽章未印出完整 URL 的，不强行补链。

**一句话抓手：**
- **In-Place TTT**：别换注意力、别从零训专用 TTT 层——把已有 MLP 的 **`W_down` 当场当 fast weights**，用 **NTP 对齐** 的 chunk 更新把上下文压进参数。
- **TEMPO**：自奖励 TTT 会漂、会塌多样性——用 **EM：E-step 在有标数据上重标定 critic，M-step 在无标测试题上改政策**，让多花的 test-time 算力继续换分。
- **Modular-TTT（索引）**：把 inner learner 拆成可组合模块，系统消融后再放大到 410M/1.45B。

## 三、站 1：In-Place TTT（架构思想 · 主）

### 3.1 三个障碍 → 三个设计

文 §1–2 把 LLM 生态里推广 TTT 的障碍收成三条，并一一对位：

| 障碍 | In-Place 对策 |
|---|---|
| **架构不兼容**（专用 TTT 层需从零预训练） | **原地**：不换注意力、不加随机初始化新层；把 gated MLP 的 **`W_down`（末投影）** 当可更新 fast weights；`W_up` / `W_gate` 冻结为 slow weights |
| **计算低效**（逐 token 更新卡并行） | **大 chunk 更新**（消融示意最优约 **512–1024**）；注意力仍负责 token mixing，故不必像「TTT 当主 mixer」那样死守小 chunk；可走 parallel scan / 前缀和以适配 context parallelism |
| **目标错位**（通用重构 ≠ NTP） | **LM-Aligned / NTP 对齐目标**：`V̂ = Conv1D(X₀) W_target`，让 fast weights 存**对下一 token 预测有用**的信息，而非仅记忆当前 token |

门控 MLP 形式（文 §3.1）：
`O = (φ(H W_gate⊤) ⊙ (H W_up⊤)) W_down⊤`；仅 **`W_down` 原地更新**。

### 3.2 Chunk 上的 Apply → Update

对中间激活 `Z` 与目标 `V` 切成非重叠 chunk。对 chunk `i`：

1. **Apply**：`O[i] = Z[i] (W_down)⊤`（用当前 fast weights）
2. **Update**：一步优化 `W_down ← W_down − η ∇_W L(Z[i](W_down)⊤, V[i])`

在相似性损失 `L = −⟨·,·⟩_F` 下，文给闭式（Eq.1）：
`W_down ← W_down + η V̂[i] Z[i]`。

### 3.3 理论直觉（induction head 设定，§3.3）

在「键在 `t*` 出现、查询位置 `n` 再现该键、需预测对应值」的经典设定下，文比较：

- **重构目标**：`V_t = e_{x_t}`（当前 token）
- **LM 对齐目标**：`V_t = e_{x_{t+1}}`（下一 token）

在嵌入近似正交与 key–query 对齐假设下，论证 LM 对齐更新对正确下一 token 的 logit 增益更直接对齐 NTP。细节证明见原文；本笔记只取「**为何不用纯重构**」的跟读结论。

### 3.4 评测字段（辅）

**设定 A · Drop-in 持续训练（§4.1）**
- 基座：Qwen3-4B-Base（原窗口 32k）；对照 = 同课程持续训、仅差是否 In-Place TTT。
- 课程：约 **20B** token @ **32k**，再约 **15B** @ **128k**；RoPE 用 **YaRN**。
- 评测：RULER（OpenCompass），4k–256k（256k = 超 128k 外推）。

## 四、站 2：TEMPO（大推理模型上的可扩展 TTT）

### 4.1 问题：自奖励 = 不完整的 EM

文把测试时目标写成最大化 `J(θ) = E_x[log P(Correct|x; θ)]`，而正确性在无标测试集 `D_u` 上不可直接观测。引入辅助分布 `q(y|x)` 得 **ELBO**：最大化下界等价于提高「可能正确」回答的似然，并令 `q` 贴近后验 `P(y|x, Correct)`。

**关键诊断（§1 / §5）：** TTRL、EMPO 等自奖励方法近似只做 **M-step（改政策）**、省略 **E-step（重估正确性后验）** → 政策一变，奖励跟着漂 → **平台期 + 多样性塌缩**。TEMPO 把 E-step 补回：在有标集 `D_L` 上周期性标定 critic。

全称（文 §3 / Alg.1）：**Test-time Expectation-Maximization Policy Optimization（TEMPO）**。

### 4.2 算法骨架（跟读）

**初始化：** 在 `D_L` 上用标准 **RLVR（PPO）** 同时得到 actor `π_θ` 与 critic `V_φ`。

**交替（每轮）：**

| 步 | 数据 | 做什么 |
|---|---|---|
| **E-step · Critic 重标定** | 有标 `D_L` | `L_critic = E ‖V_φ(x, y_t) − I‖₂²`，`I∈{0,1}` 为可验证对错；用末 token 价值近似正确性，构造 `q(y|x) ∝ V_φ(x,y_T) π_{θ₀}(y|x)` |
| **M-step · Policy 精炼** | 无标 `D_u` | 采样轨迹；终端奖励 `R = V_φ(x,y_T)`；token 优势 `A_t = R − V_φ(x,y_{1:t})`；政策梯度 `L_policy = −E[∑_t A_t log π_θ(y_t|…)]` |

数学实验（§4.1）：`D_L` = **DAPO-Math-17K**；测试驱动集含 AIME 2024/2025、Beyond AIME；**AIME 2026、OlymMath** 作 holdout。指标：**avg@16** 与 **pass@8**（文 Table 1 表头为 Acc / Pass@K；§4.1 定义 pass@8）。批大小等超参见原文；最大响应长 **16K**。

### 4.3 主表数字（禁编造 · 锚 Table 1）

**AIME 24 Acc（avg@16）精选：**

| 模型 | Zero-RL (PPO) | TTRL | EMPO | **TEMPO** | Δ vs Zero-RL |
|---|---:|---:|---:|---:|---:|
| OLMO3-7B-Base | 33.0 | 40.8 | 41.6 | **51.1** | **+18.1** |
| Qwen3-8B-Base | 26.3 | 29.0 | 32.3 | **42.7** | **+16.4** |
| Qwen3-14B-Base | 42.3 | 53.1 | 55.6 | **65.8** | **+23.5** |

与摘要一致：OLMO3-7B **33.0%→51.1%**；Qwen3-14B **42.3%→65.8%**。
摘要另报 AIME 2025：OLMO3 **26.3→37.0**；Qwen3-14B **37.1→44.6**（与 Table 1 Acc 列一致）。

**多样性：** 同表 Pass@K 上 TEMPO 多数保持高位；若 TTRL/EMPO 的 Acc 升而 Pass@K 掉，文解读为共识式自奖励压扁模式。例：Qwen3-14B AIME 24 Pass@K，TEMPO **73.3** vs TTRL **56.7**（表内）。正文叙述偶见 73.0 等四舍五入提法，**以 Table 1 为准**。

**非数学（Table 2 摘要）：** OLMO3-7B 上 TEMPO 相对 Zero-RL：BBH **+21.4**、AGI Eval **+24.5**、ZebraLogic **+12.9**、GPQA-Diamond Avg@8 **+10.5**（文内绝对增益行）。Qwen3-8B 增益较小但仍多为正（如 ZebraLogic **+8.2**）。

**消融（§4.5）：**（1）**冻结 critic**（去掉周期 E-step）；（2）**仅在 `D_L` 上继续 PPO**（无测试集更新）。文图显示完整 TEMPO 相对「仅 M-step」/「继续 RLVR」能持续爬升——结论跟读即可，曲线精确点待读图。

## 五、索引：Modular-TTT（不升主深读）

> 议程明确：**Modular-TTT 作 [[测试时训练]] 补链**，避免凑数升主项。此处只留地图。

- **主张**：把 TTT inner learner 建成 **DAG**；暴露 fast-weight 网络、损失、学习率、weight decay、normalization 等维度；自动组合 train-view forward / backward 与 causal query-view，免手推每种全局更新。
- **消融方向（摘要 / §4）：** 小学习率初始化、weight decay、单层非线性（如 SiLU）有益；**MSE ≈ inner-product**；更深 fast-weight 网与 normalization 易因激活过大而伤性能；残差 / gating 收益不明显。
- **放大：** 优选变体训 **410M / 1.45B**、**100B** tokens，训练损失与下游接近 **Gated DeltaNet（GDN）**；Table 8：相对官方 TTT 实现约 **2.2×–3.3×** 训练吞吐（160M、含 Norm 设定）。
- **代码：** https://github.com/ByteDance-Seed/Modular-TTT
- **本卡不写：** primitive 算子表、深层稳定化扫描、RULER 附录逐模板。
