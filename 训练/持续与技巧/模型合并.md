# Model merging / soup：MergeBench + LLM-era 综述

> **定位**：模型合并 **P1**——补仓库独立「**权值空间合并 / model soup**」深读。主文 **MergeBench**（NeurIPS 2025 D&B）标准化多域 LLM 合并评测；辅文 **LLM-era 综述**（2603.09938）用 **FUSE** 分类地图串起理论—算法—场景—生态。
> **攻坚线**：**架构思想（主）**——为何能合（LMC / basin）、如何合（soup → task vector → 稀疏化 → 结构/搜索）；**评测字段（辅）**——MergeBench 多任务归一化 / 遗忘—泛化 / runtime，以及综述对评测缺口的索引。
> **硬划界（禁止重写）**：
> - **≠ [[混合专家架构]] MoE**：不写稀疏专家**训练**通史（Switch / 负载均衡 / 激活稀疏）；综述 §5.1「MoE-*style* merging」只作「合完后仍可能保留路由」一句接口。
> - **≠ MoA / TUMIX MoA / TUMIX**：**推理期**异构聚合 / 工具策略混合 ≠ **权值算术合并**；综述开篇已钉：ensembles 在 runtime 聚合预测，merging 在 weight space 产出**单模型**、推理成本≈单模型。
> - **≠ [[持续学习]] lifelong 通史**：综述 Scenarios 里「Continual Adapt.」仅作合并可作工具的索引，不写 Internal/External 终身学习 taxonomy 与 Lifelong-MoE 全文。
> **禁止编造**：公式、表内百分点、算法名单一律锚定官方 PDF（2026-09-22 CST）；图内曲线未抽出的精确点标「待核实读图」。

**一句话抓手：**

`
权值合并 (本篇) ：θ₁,…,θ_K → 算术/稀疏/搜索 → θ_merged（部署 = 1 份权）

### 3.2 Foundations：为何权值插值往往不崩（§2）

跟读三根柱子（§2 开篇）：

1. **损失景观**：过参数化网络存在宽盆地；宽/平坦盆地使插值不易冲出低损区（§2.1；关联 SWA / flat minima 叙事）。
2. **Mode connectivity**：Garipov 等非线性低损路径；Frankle 等 **linear mode connectivity (LMC)**——尤其**共享预训练初始化再微调**时，线性插值常无高损壁垒（§2.2）。形式条件（文）：$\theta(\alpha)=(1-\alpha)\theta_1+\alpha\theta_2$，要求路径上损失不超过两端（加小 $\epsilon$）。
3. **权值对称 / 置换不变**：隐藏单元置换使「同功能不同坐标」；合并前常需对齐（§2.3；Git Re-Basin 等索引，本篇不展开证明）。

**成功前提（§2.4 方向，跟读用）：** 共享祖先 checkpoint、结构/分词兼容、任务不要表象上完全不相容。MergeBench §3.2 用反例钉死：即便同属 Llama-2 谱系，**CodeLlama 与 Llama-2-Chat** 合并可严重劣化——故他们改用**自训、结构对齐**的专科套件。

### 3.3 Unification 谱系（§3–§5）：从 soup 到稀疏到结构

#### （A）线性平均与 Model Soup（§3.1）

- **Uniform soup**：$\theta_{\mathrm{merged}}=\frac{1}{N}\sum_i\theta_i$（综述 Table 对照行；MergeBench Table 1 同式）。
- **Greedy soup**（Wortsman et al., 2022a，综述叙述）：按验证集表现贪心接纳 checkpoint，减轻「坏模型拖累平均」。
- 部署卖点（综述）：相对单模型 **无额外推理成本**（权已合成一份）。

#### （B）Task vector 算术（§4.1–§4.2；MergeBench §2 记号一致）

对共享 $\theta_{\mathrm{pre}}$ 的微调模型：

$$
\tau_i=\theta_{\mathrm{ft}}^{(i)}-\theta_{\mathrm{pre}}
$$

经典操作（Ilharco et al., 2023；综述）：

| 操作 | 直觉 | 典型式（跟读） |
|---|---|---|
| **Addition** | 多任务融合 | $\theta_{\mathrm{pre}}+\lambda\sum_i\tau_i$（MergeBench：Task Arithmetic） |
| **Negation** | 削弱某能力 / 编辑 | $\theta_{\mathrm{pre}}-\lambda\tau$（安全/幻觉等应用索引） |
| **Scaling** | 控专精度 vs 贴近基座 | 调 $\lambda$（验证集） |

#### （C）干扰与稀疏化增强（§4.3–§4.4；MergeBench Table 1 下半）

动机：微调更新稀疏且噪声多；不同任务在同坐标**符号冲突**时，朴素平均会相消（TIES 叙事）。

| 方法 | MergeBench / 综述要点（不编造超参） |
|---|---|
| **TIES** | Trim 小幅值 → Elect 主导符号 → 只合并与当选符号一致的参数 |
| **DARE** | 对 task vector 随机 dropout $m_i\sim\mathrm{Bernoulli}(p)$，再按 $1/(1-p)$ 重缩放 |
| **Consensus TA** | 先用 task arithmetic 得 $\tau_{\mathrm{MTL}}$，再按与「去掉己方后残留」的幅度关系构 mask，共识位保留 |
| **Localize-and-Stitch** | 学（或 dataless top-$k$）二值 mask 定位任务相关参数，只把局部缝回基座 |

另有 **Fisher Merging**（按对角 Fisher 加权）、**RegMean**（最小化合并激活与各专家激活差）——MergeBench 归入「系数/统计」上半块。

#### （D）结构 / 激活 / 搜索（§5，索引级）

- **MoE-style merging**（§5.1）：合完后仍可保留**专家通路 + 路由**（BTM / WEMoE / PHATGOOSE / LoRA-as-experts 等）——**≠** [[混合专家架构]] 从零训稀疏 MoE；此处是「事后把专科模型组织成可路由结构」。
- **Activation-informed**（§5.2）：用激活/表示指导合并。
- **Evolutionary / search-based**（§5.3）：搜合并配置（系数、层选择等）。

本篇攻坚以 **soup + task vector + 稀疏** 为主；§5 只建立「还有结构保留一支」的坐标。

### 3.4 Scenarios / Ecosystem（§6–§7，点到）

- **场景**：多任务与多语能力拼装；安全/对齐编辑；联邦与分布式；域专精且留通用能力；**评测方法论**（§6.5）。
- **生态**：MergeKit 等工具民主化（§1）；FusionBench、**MergeBench**、Open LLM Leaderboard 等（§6.5）。
- **失败模式（§7.4，跟读四类）**：task-level **merging collapse**（表示不相容相关、符号冲突未必主因）；参数符号/子空间干扰；**可合性不可跨方法迁移**的预测失败；以及（文后续）安全/有害行为经合并注入等开放风险——本篇不展开操作细节。

## 四、站 2：MergeBench 评测场（评测字段 · 辅）

### 4.1 设计三轴（§3 / Figure 1）

1. **任务覆盖（5 域）**：instruction following / mathematics / multilingual / coding / safety——强调 post-training 能力、技能尽量解耦、**结构可合**（刻意排除常改位置编码的长上下文任务）。
2. **模型选择（8 基座）**：Llama-3.2-3B、Llama-3.1-8B、Gemma-2-2B、Gemma-2-9B 及各自 **IT** 变体；每基座训 5 个专科 → **40** 个专科模型开源。
3. **训练与评测协议统一**：多数域 SFT；**8B/9B 数学**在 SFT 上再加 **GRPO**（反映异步专科管线）；合并侧统一辅助数据（训练统计用 1k 样本；验证集调 $\lambda$/稀疏等）。

**训练数据（Table 2，名即可）：** TULU-3 persona IF；DART-Math / NuminaMath-TIR；Aya；Magicoder；WildGuardMix / WildJailbreak。

**评测集（Table 3）：** IFEval；GSM8k / MATH；M_MMLU / M_ARC / M_Hellaswag；HumanEval+ / MBPP+；WildGuardTest / HarmBench / DoAnythingNow / XSTest（安全侧主报 **RTA**=Refuse To Answer）。

### 4.2 八种方法与两大族（Table 1）

| 族 | 方法 |
|---|---|
| **系数调谐** | Model Soup；Task Arithmetic；Fisher Merging；RegMean |
| **稀疏化（常兼系数）** | TIES；DARE；Consensus TA；Localize-and-Stitch（含 Dataless） |

### 4.3 三维评测定义（§4）

| 维 | 定义（文内） | 读图/读表 |
|---|---|---|
| **多任务** | 归一化：$\frac{1}{n}\sum_i \mathrm{perf}^{(i)}_{\mathrm{merged}}/\mathrm{perf}^{(i)}_{\mathrm{ft}}$；=1 表示追平各专科 | Figure 2；Table 8 |
| **遗忘 / 泛化保留** | 相对基座在 MMLU、TriviaQA、SQuADv2、CoQA、PubMedQA、WMT14 Fr→En 等上的归一化 | Figure 3；Table 9 |
| **Runtime** | 算法墙钟 + **验证调参**墙钟（Llama-3.2-3B）；验证成本常被低估 | Figure 4–5 |

### 4.4 文内主结论（§4.1–§4.3，可跟读）

**多任务排序直觉（§4.1 文字，非读图精确点）：**

- **Localize-and-Stitch 两变体**整体偏强（定位保专科知识）。
- 小模型上 **RegMean** 有竞争力，大模型优势减弱（文猜测大模型表征已够通用）。
- Task Arithmetic / Consensus TA / TIES 居中，**IT 基座**上明显更好。
- **DARE** 往往偏低（随机 dropout）；**Fisher** 多数场景偏低（对角近似不够）。

**更强基座更好合（§4.1）：**

- 尺度：2B/3B 预训练上，最好方法大约追回专科的 **~80%** 归一化表现；8B/9B 预训练上合并法常 **>90%**。
- 训质：IT 基座上合并法常 **>90%** 归一化——更长共享轨迹 → 专科化后参数空间更近。

**遗忘（§4.2）：**

- MTL 合训 in-domain 强，但易伤 OOD/通用；合并用**小系数 + 稀疏**作正则，更贴基座。
- Task Arithmetic 常需更大 $\lambda$ → 多任务↑、遗忘↑；TIES / Dataless L&S 的 top-$k$、L&S 的 mask 更利于留知识；DARE 随机丢弃保知识较差。

**Runtime 与实践指南（§4.3）：**

- 最快：**Model Soup**（无数据、无调参）。
- 验证贵：**TIES / DARE**（稀疏+缩放双超参网格）。
- L&S 虽训 mask，但**不调超参**，总墙钟可较短；L&S / Fisher **峰值显存≈全量微调**，内存紧时慎用。
- 效费比友好区（文）：L&S 两变体、RegMean、Task Arithmetic。
- **推荐顺序（文原文意）：** 先 Soup → 有验证集试 Dataless L&S 或 Task Arithmetic → 有原训练数据再试 L&S / RegMean；TIES/DARE 有分但验证贵，资源紧时不优先。

**读表抓手：** Gemma-2-9b-it 上若干方法 **>100**（如 Task arithmetic 104.6、Consensus TA 106.5）——合并可超过「单域专科」在该聚合度量上的平均，不等于每域都超。Llama-3.2-3B（非 IT）上 Soup 仅 57.0，对照同尺寸 IT 的 Soup 94.4，强化「基座强度/对齐轨迹」轴。

### 4.6 与既有评测对照（Table 4）

MergeBench 自称同时满足：多样模型族、>7B、真实域任务、支持梯度/统计类方法、**开源管线+专科权重**。相对 FusionBench / 组合泛化评测（偏小模型）、PaLM-2 闭源大规模、Model-GLUE（单族+MergeKit 子集）补齐空档。综述 §6.5 亦点名 MergeBench 专攻 **domain-specialized LLM merging**；并索引 Hitit et al. 等「小模型上的新方法未必迁移到 LLM」的警句。

### 4.7 Discussion 开放题（§6，跟读）

1. **合参效率**：缩放/稀疏超参仍大量试错，大规模不友好。
2. **混数据 vs 合模型**：非冲突且可均衡配比时，**MTL 仍常赢 in-domain**；合并在低资源/不均衡（细粒度安全、多语）更有叙事。专科们各自训的总算力 ≈ 一次 MTL——合并省的是**联合数据与协同训练协调**，不是无条件的算力魔法。
3. **管线位置**：Llama-3 用 soup 平均不同超参 run；Command A 类产品合专科——「合旧版 / 合通用×推理模型」仍开放。

## 六、可跟读小结（交卷用）

1. **定义**：Model merging / soup = 在**权值空间**合成多份同源微调模型 → **单份**多能力权重；与 ensemble / MoA（推理聚合）、与 MoE 训练（架构稀疏）正交。
2. **理论抓手（综述 F）**：共享预训练 → 常线性 mode-connected → 平均与 task vector 算术有几何理由。
3. **方法抓手（综述 U + MergeBench Table 1）**：Soup / Task Arithmetic / Fisher / RegMean → TIES / DARE / Consensus / L&S；干扰靠**符号选举与稀疏**缓解。
4. **评测抓手（MergeBench）**：五域 × Llama/Gemma 2B–9B；看 **归一化多任务 + 基座泛化 + 含验证的墙钟**；Overall 多任务 L&S 89.7 居首，泛化 TIES 91.7 居首；实践上从 Soup 起跳。
5. **边界**：不写 [[混合专家架构]] / MoA / TUMIX / [[持续学习]] 正文；不编造未抽到的曲线点与未核对的第三方榜分。
