# Model merging / soup：MergeBench + LLM-era 综述

> **主要来源**：[MergeBench: A Benchmark for Merging Domain-Specialized LLMs](https://arxiv.org/abs/2505.10833)；[Model Merging in the Era of Large Language Models: Methods, Applications, and Future Directions](https://arxiv.org/abs/2603.09938)（截至 2026-03-30）。MergeBench 为 He 等（UIUC）所作，NeurIPS 2025 数据集与基准赛道，首版 2025-05-16，现行 v5 2025-10-18；综述为 Song 与 Zheng（腾讯）所作，首版 2026-03-10，现行 v2 2026-03-30。
> **研究线**：架构思想（主）——为何能合（线性模式连通、损失盆地）、怎样合（权重平均、任务向量、稀疏化、结构与搜索）；评测字段（辅）——归一化多任务表现、相对基座的泛化保留与含调参的墙钟时间。
> **范围与相邻笔记**：
> - ≠ [[混合专家架构]]：本篇不写稀疏专家的训练通史，综述中「MoE 式合并」只作「合完仍可保留路由」一句接口。
> - ≠ [[MixtureOfAgents与TUMIX]]：本篇写权重空间的算术合并，不写推理期多个模型的生成聚合。
> - ≠ [[持续学习]]：本篇不写终身学习的场景分类与 Lifelong-MoE，只把合并当作持续适配的一种工具。
>
> **意义**：把多个同源微调模型在权重空间合成一份权重，就能得到多能力的单模型，推理成本与单个模型相同，也不需要原始训练数据重新联合训练。综述用 FUSE 四维（Foundations、Unification、Scenarios、Ecosystem）把理论、算法、场景与生态串成一张图；MergeBench 在 2B–9B 的 Llama 与 Gemma 上给出受控对照，把合并从经验技巧变成可横向比较的方法族，并指出更强的基座更容易合。

**一句话**：同一预训练初始化出发的微调模型常落在同一个损失盆地，因此可以做权重平均、任务向量加减与稀疏化合并；MergeBench 显示基座越强越好合，小系数与稀疏化有助于保留基座知识，但合并参数的调参开销与相对联合训练的领域内差距仍在。

---

## 一、问题背景

1. **多能力怎样合成一个模型**：领域专科模型往往由不同团队、不同数据分别训练，联合多任务训练（MTL）需要汇集全部数据并协调配比；集成或多模型聚合在推理时要付出多倍成本。综述 §1 的对照：集成在运行时聚合各模型的预测，合并直接在权重空间操作，产出一个计算成本与任一组成模型相同的单模型。
2. **既有评测不够**：此前的评测要么偏小模型（FusionBench、组合泛化评测），要么闭源（PaLM-2 上的大规模实验），要么局限于单一模型族与 MergeKit 子集（Model-GLUE）。综述 §6.5 也引用 Hitit 等的提醒：小模型上的新方法未必迁移到大模型。MergeBench 自称同时满足多模型族、7B 以上、真实领域任务、支持需梯度或统计量的方法、开源管线与专科权重（Table 4）。

## 二、脉络

| 节点 | 做法 | 留下的问题 |
|---|---|---|
| 模式连通与线性模式连通（Garipov 等；Frankle 等） | 发现低损路径；共享初始化再微调时线性插值常无高损壁垒 | 为合并提供几何依据 |
| Model Soup（Wortsman 等，2022） | 均匀平均或按验证集贪心接纳检查点 | 多任务时不同任务互相干扰 |
| 任务向量（Ilharco 等，2023） | 微调权重减预训练权重得到任务向量，可加、可减、可缩放 | 同一坐标符号冲突时相互抵消 |
| TIES、DARE 等稀疏化方法 | 剪掉小幅值、选主导符号，或随机丢弃再重缩放 | 引入更多超参，验证成本高 |
| 结构、激活与搜索类方法 | 合完保留专家与路由；用激活指导；进化搜索配置 | 方法多、评测不统一 |
| MergeBench（2025-05）与综述（2026-03） | 统一评测；FUSE 四维地图 | 见局限 |

## 三、为何能合：综述的 Foundations（§2）

1. **损失景观**：过参数化网络存在宽盆地，宽而平坦的盆地使插值不易冲出低损区（与 SWA、平坦极小值的讨论相关）。
2. **模式连通**：Garipov 等发现非线性低损路径；Frankle 等提出线性模式连通，形式为 $\theta(\alpha)=(1-\alpha)\theta_1+\alpha\theta_2$ 路径上损失不超过两端（加小 $\epsilon$），共享预训练初始化再微调时尤其常见。
3. **置换对称**：隐藏单元重排后功能不变、坐标不同，合并前常需对齐（Git Re-Basin 等）。

**成功前提**（§2.4）：共享祖先检查点、结构与分词兼容、任务不完全冲突。MergeBench §3.2 举了反例：同属 Llama-2 谱系的 CodeLlama 与 Llama-2-Chat 合并会严重劣化，因此它改用自己训练、结构对齐的专科模型套件。

## 四、怎样合：方法谱系（综述 §3–§5，MergeBench Table 1）

记共享预训练权重为 $\theta_{\mathrm{pre}}$，第 $i$ 个微调模型的任务向量为 $\tau_i=\theta^{(i)}_{\mathrm{ft}}-\theta_{\mathrm{pre}}$。

| 族 | 方法 | 要点 |
|---|---|---|
| 系数调节 | Model Soup | 均匀平均 $\frac1N\sum_i\theta_i$，无数据、无调参 |
| | Task Arithmetic | $\theta_{\mathrm{pre}}+\lambda\sum_i\tau_i$；取负号可削弱某能力（安全、幻觉编辑），调 $\lambda$ 控制专精程度 |
| | Fisher Merging | 按对角 Fisher 信息加权 |
| | RegMean | 最小化合并模型与各专科模型激活的差 |
| 稀疏化（常兼调系数） | TIES | 剪掉小幅值，选出主导符号，只合与该符号一致的参数 |
| | DARE | 对任务向量按概率 $p$ 随机丢弃，再乘 $1/(1-p)$ 重缩放 |
| | Consensus TA | 先用任务算术得到合并向量，再按与「去掉自身后的残差」的幅度关系构造掩码，只保留共识位置 |
| | Localize-and-Stitch（L&S） | 学习（或不用数据、取 top-$k$）二值掩码定位任务相关参数，只把这一部分缝回基座 |

稀疏化的动机：微调更新稀疏且噪声多，不同任务在同一坐标上符号冲突时，朴素平均会互相抵消。综述 §5 还列出三支：MoE 式合并（BTM、WEMoE、PHATGOOSE、LoRA 作专家等，事后把专科模型组织成可路由的结构，不同于从零训练稀疏 MoE）、激活引导的合并、进化或搜索式合并。

## 五、MergeBench：受控评测

### 5.1 设计（§3，Fig.1）

- **五个领域**：指令遵循、数学、多语言、代码、安全；强调后训练能力、技能尽量解耦、结构可合（刻意排除常改位置编码的长上下文任务）。训练数据为 TULU-3 persona IF、DART-Math 与 NuminaMath-TIR、Aya、Magicoder、WildGuardMix 与 WildJailbreak；评测为 IFEval、GSM8k 与 MATH、多语言 MMLU / ARC / HellaSwag、HumanEval+ 与 MBPP+、WildGuardTest / HarmBench / DoAnythingNow / XSTest（安全侧主报拒答率）。
- **八个基座**：Llama-3.2-3B、Llama-3.1-8B、Gemma-2-2B、Gemma-2-9B 及各自的指令版；每个基座训 5 个专科模型，共 40 个开源。多数领域用 SFT，8B / 9B 的数学专科在 SFT 后再加 GRPO，反映各专科管线不同步的现实。
- **合并侧统一**：训练统计量用 1k 样本，验证集用于调 $\lambda$ 与稀疏度。

### 5.2 三维评测（§4）

| 维度 | 定义 | 出处 |
|---|---|---|
| 多任务 | $\frac1n\sum_i \mathrm{perf}^{(i)}_{\mathrm{merged}}/\mathrm{perf}^{(i)}_{\mathrm{ft}}$，等于 1 表示追平各专科 | Fig.2、Table 8 |
| 遗忘与泛化保留 | 相对基座在 MMLU、TriviaQA、SQuADv2、CoQA、PubMedQA、WMT14 法译英等上的归一化表现 | Fig.3、Table 9 |
| 运行时间 | 算法墙钟加验证调参墙钟（Llama-3.2-3B）；验证成本常被低估 | Fig.4–5 |

### 5.3 主要结论

- **方法排序**（§4.1）：L&S 两个变体整体偏强；RegMean 在小模型上有竞争力，大模型上优势减弱（论文猜测大模型表征已足够通用）；Task Arithmetic、Consensus TA、TIES 居中，在指令版基座上明显更好；DARE 往往偏低、在大模型上尤甚（随机丢弃），Fisher 在多数场景偏低（对角近似不够）。
- **更强的基座更好合**：2B / 3B 预训练基座上，最好的方法约追回专科 80% 的归一化表现，8B / 9B 上常超过 90%；指令版基座上也常超过 90%，因为更长的共享训练轨迹使专科化后的参数更接近。
- **遗忘**（§4.2）：MTL 领域内强，但容易伤通用能力；合并用小系数加稀疏化起到正则作用，更贴近基座。Task Arithmetic 常需较大 $\lambda$，多任务升、遗忘也升；TIES 与无数据 L&S 的 top-$k$、L&S 的掩码更利于保留知识，DARE 的随机丢弃保留较差。
- **运行时间与实践建议**（§4.3）：Model Soup 最快；TIES 与 DARE 因稀疏度与缩放双超参网格，验证最贵；L&S 虽要训练掩码但不调超参，总墙钟可较短，不过 L&S 与 Fisher 的峰值显存接近全量微调。推荐顺序：先试 Soup；有验证集时试无数据 L&S 或 Task Arithmetic；有原训练数据再试 L&S 或 RegMean；TIES、DARE 分数不差但验证贵，资源紧时不优先。文中列为效费比友好的是 L&S 两变体、RegMean、Task Arithmetic。

- Gemma-2-9b-it 上若干方法超过 100（如 Task Arithmetic 104.6、Consensus TA 106.5），表示在这一聚合指标上可超过各专科的平均，不等于每个领域都超。Llama-3.2-3B（非指令版）上 Soup 只有 57.0，同尺寸指令版为 94.4，印证基座强度与对齐轨迹的作用。

### 5.5 讨论中的开放问题（§6）

1. **合并参数的效率**：缩放与稀疏超参仍靠大量试错，不利于大规模使用。
2. **混数据还是合模型**：数据不冲突且能均衡配比时，MTL 仍常在领域内胜出；合并更适合低资源或不均衡的场景（细粒度安全、多语言）。各专科分别训练的总算力约等于一次 MTL，合并省的是联合数据与协同训练的协调成本，而不是算力本身。
3. **在管线中的位置**：Llama-3 用 Soup 平均不同超参的训练；Command A 一类产品合并专科模型；「合并旧版本」「合并通用模型与推理模型」仍开放。

## 六、综述的场景与生态（§6–§7）

- **场景**：多任务与多语言能力拼装；安全与对齐编辑；联邦与分布式训练；领域专精同时保留通用能力；评测方法论（§6.5）。
- **生态**：MergeKit 等工具让合并普及；FusionBench、MergeBench、Open LLM Leaderboard 等用于评测。
- **失败模式**（§7.4）：任务级的合并崩溃（与表示不相容相关，符号冲突未必是主因）；参数符号与子空间干扰；可合性无法跨方法迁移、难以预测；以及合并可能注入不安全或有害行为等开放风险。

## 七、意义

- **单模型多能力、推理零额外成本**：合并让各团队分别训练的专科模型可以低成本拼装，部署仍是一份权重。
- **从技巧到方法族**：综述给出理论依据与分类，MergeBench 给出统一的多任务、遗忘与运行时间三维评测，不同方法能在同一基座、同一数据上比较。
- **指出合并的适用条件**：基座越强、共享训练越长越好合；低资源或不均衡场景比数据充足的 MTL 更适合合并。

## 八、局限与待核实

- **规模有限**：MergeBench 只到 9B，更大模型与 MoE 上的结论未覆盖。
- **领域内仍落后 MTL**：数据可汇集且不冲突时，合并的领域内表现仍常不及联合训练。
- **调参成本**：稀疏化方法的验证调参常被低估，L&S 与 Fisher 的显存接近全量微调。
- **理论缺口**：可合性缺少可预测的理论，失败模式（合并崩溃、跨方法不可迁移）仍是开放问题；合并带来的安全风险综述只作提示。
