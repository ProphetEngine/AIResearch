# Self-RAG 与 Corrective RAG：检索自省与检索纠错

> **主要来源**：[Self-RAG: Learning to Retrieve, Generate, and Critique through Self-Reflection](https://arxiv.org/abs/2310.11511)；[Corrective Retrieval Augmented Generation](https://arxiv.org/abs/2401.15884)（截至 2026-02-03）。下文「Self-RAG」指前者（Asai 等，v1 2023-10-17，迄今唯一版本）；「CRAG」指后者（Yan 等，首版 2024-01-29，现行 v3 2024-10-07）。
> **研究线**：架构思想（主）——检索何时触发、检索结果如何被评估和纠正；评测字段（辅）——短答准确率、FactScore、引用精度与召回。
> **范围与相邻笔记**：
> - ≠ [[检索增强与知识外挂]]：本篇不写稠密检索、DPR、RAG-Token 与 RAG-Sequence 等经典 RAG 内容，只用「固定取 top-K 拼进上下文」作对照。
> - ≠ [[图谱检索GraphRAG]]：本篇不写图索引与社区摘要；两篇方法都不改索引，只改检索环上的控制流。
> - ≠ [[AgenticRAG分层检索接口]]：本篇不写把检索拆成多个工具、交给智能体自由编排的做法。
>
> **意义**：经典 RAG 默认「每次都检索，检索到什么就用什么」。Self-RAG 让同一个模型学会判断要不要检索、证据是否相关、回答是否被证据支持；CRAG 承认检索可能整批出错，用轻量评估器决定是精炼、丢弃后改搜 Web，还是两者合用。两篇把 RAG 从固定流水线推向带判断的控制流，后来 Agentic RAG 讨论「由谁决定检索」就是从这里接着走的。

**一句话**：Self-RAG 靠模型自己输出的反思 token 回答「该不该检索、证据靠不靠得住」；CRAG 靠外挂评估器加 Web 回退回答「检索回来的东西不对怎么办」，并且可以直接叠在 Self-RAG 上。

## 一、问题背景

据 Self-RAG §1 与 CRAG §1：

1. **无差别检索**：标准 RAG 不论问题是否需要外部知识，都固定取 K 篇拼进上下文。开放写作这类不依赖事实的任务会被无关段落干扰，输出多样性也受损。
2. **生成不一定跟证据走**：即使检索到相关段落，模型也未必被训练成按证据作答，输出与证据不一致时没有自我检查。
3. **检索本身会失败**：RAG 的效果高度依赖检索相关性。检索器返回的段落可能全部无关，这时无关信息反而误导生成。

Self-RAG 处理前两点，CRAG 专门处理第三点。参数记忆的局限与检索–生成的基本结构等共用背景见 [[检索增强与知识外挂]]。

## 二、脉络

| 节点 | 做法 | 留下的问题 |
|---|---|---|
| RAG（Lewis 等，2020） | 检索器加生成器，固定取 top-K | 不判断是否需要检索，也不检查证据 |
| 自适应检索（Jiang 等，2023） | 在专有大模型之上按需检索 | 触发规则在模型之外，生成是否被支持仍不检查 |
| SAIL（2023） | 把固定篇数的检索结果拼在指令前做微调 | 总是插入检索结果，不区分相关与否 |
| Self-RAG（2023-10） | 模型自己输出「检索 / 相关 / 支持 / 有用」四类反思 token | 需要专门微调生成器；不处理检索整批失败 |
| CRAG（2024-01） | 外挂评估器给检索结果打分，触发精炼、Web 搜索或两者混合 | 依赖评估器阈值与 Web 质量 |
| 之后 | A-RAG 把 CRAG 归入单次检索的基础 RAG（检索质量评估），把 Self-RAG 归入预设工作流中的训练型方法，两者都不满足「自主策略」一条；A-RAG 主张把检索做成工具交给智能体编排；CatRAG 把 Self-RAG 当作多轮迭代检索的对照 | 见 [[AgenticRAG分层检索接口]]、[[HippoRAG2与CatRAG]] |

前三行据 Self-RAG §2 与 CRAG §2 的相关工作综述。CRAG 论文称自己是首次尝试为 RAG 设计纠错策略（§2）。

## 三、Self-RAG：让模型自己判断检索与证据

### 3.1 四类反思 token（Table 1）

| 类型 | 看什么 | 取值 | 作用 |
|---|---|---|---|
| Retrieve | 问题，或问题加已生成部分 | yes / no / continue | 要不要调用检索器 |
| ISREL | 问题与某段证据 | relevant / irrelevant | 这段证据是否有用 |
| ISSUP | 问题、证据与生成段 | fully / partially / no support | 生成内容是否被证据支持 |
| ISUSE | 问题与生成段 | 1–5 分 | 整体有用性，与是否检索无关 |

后三类统称 critique token。生成以「段」为单位推进，实验中一句为一段。

### 3.2 推理时怎样运作（§3.3、Algorithm 1）

1. 每生成一段前先预测 Retrieve。
2. 若为 yes：取回若干段落，对每段并行生成候选，同时输出 ISREL、ISSUP、ISUSE；用三类 critique 的加权分数做段级 beam 搜索，挑出最好的候选。
3. 若为 no：像普通语言模型一样直接生成，只附 ISUSE。

可调的地方有三处：Retrieve 为 yes 的概率超过阈值才检索（默认 0.2；引用任务 ALCE 设为 0，倾向总是检索）；三类 critique 的权重（默认 ISREL 1.0、ISSUP 1.0、ISUSE 0.5）；以及是否把「无支持」等差评候选直接过滤掉。这些都在推理时调整，不需重新训练：事实性任务可以提高 ISSUP 权重与检索频率，开放写作则可降低检索频率。

### 3.3 怎样训练（§3.2）

- **评判模型**：先用 GPT-4 少样本为各类反思 token 标注数据，再用 Llama2-7B 训练一个评判模型专门预测这些 token；论文称它与 GPT-4 的一致率在多数类别上超过 90%。
- **生成模型**：用评判模型离线给约 15 万条指令–输出数据插入检索段落与反思 token，再以普通的下一 token 目标训练 Llama2-7B / 13B；检索段落本身不计损失。
- **与 RLHF 的区别**：反思信号离线写进训练语料，不需要在线 PPO 和奖励模型；代价是依赖 GPT-4 蒸馏标签。部署时只用生成模型，不再调用评判模型。

### 3.4 关键结果（Table 2、§5）

| 模型 | PopQA | PubHealth | Bio FactScore | ASQA 引用精度 |
|---|---:|---:|---:|---:|
| ChatGPT（无检索） | 29.3 | 70.1 | 71.8 | – |
| Ret-ChatGPT | 50.8 | 54.7 | – | 65.1 |
| Llama2-FT 7B + 检索 | 48.7 | 64.3 | 78.2 | 5.0 |
| Self-RAG 7B | 54.9 | 72.4 | 81.2 | 66.9 |
| Self-RAG 13B | 55.8 | 74.5 | 80.2 | 70.3 |

- Self-RAG 在 PubHealth、PopQA、传记生成和 ASQA 的部分指标上超过不检索的 ChatGPT，引用精度超过带检索的 ChatGPT，并在全部任务上是非专有模型中的最好成绩。
- 许多「语言模型加检索」基线在 PubHealth、ARC-Challenge 上几乎没有比不检索更好。论文据此认为，问题不在有没有检索，而在模型是否学会使用证据。
- 消融（Fig.3a，用 5 万条训练数据）显示，去掉检索器或评判模型训练的变体都明显掉点；推理时总是取第一篇检索结果（即标准 RAG 做法）会让 PopQA 与 ASQA 大幅下降。

## 四、CRAG：检索出错时如何纠正

### 4.1 检索评估器（§4.2）

用 T5-large（论文称 0.77B）微调成相关性评估器，对每个「问题–文档」对单独打分（−1 到 1）。它的参数量远小于 Self-RAG 的 7B 评判模型，且与生成器解耦。在 PopQA 检索结果的相关性判断上，评估器准确率 84.3%，提示 ChatGPT 的几种做法为 58.0%–64.7%（§5.5、Table 4）。

### 4.2 三种动作（§4.3）

设上下两个阈值（附录 B 按数据集分别设定，如 PopQA 为 0.59 与 −0.99）：

| 动作 | 触发条件 | 知识来源 |
|---|---|---|
| Correct | 至少一篇文档分数高于上阈值 | 只精炼库内检索结果 |
| Incorrect | 全部文档分数低于下阈值 | 丢弃库内结果，改写查询后搜 Web |
| Ambiguous | 介于两者之间 | 库内精炼结果与 Web 结果合并 |

论文称设 Ambiguous 是为了不让系统过度依赖评估器的准确率：拿不准时同时使用两个来源。

### 4.3 精炼与 Web 回退（§4.4–4.5）

- **先分解再重组**：把文档切成一两句的「知识条」，用同一评估器给每条打分，滤掉无关条后按原顺序拼回。这样即使整篇判为相关，其中的噪声句也不会整段进入上下文。
- **Web 回退**：把问题改写为关键词式查询，调用商业搜索 API（论文用 Google Search API），优先 Wikipedia 等受监管页面，抓取后走同样的精炼步骤。论文同时提醒，大规模 Web 内容可能带来偏置与不可靠信息。
- 生成器只看精炼后的知识，任何语言模型都能接；接在标准 RAG 上称 CRAG，接在 Self-RAG 上称 Self-CRAG。

### 4.4 关键结果（Table 1–3）

| 生成器 | 方法 | PopQA | Bio FactScore | PubHealth | ARC |
|---|---|---:|---:|---:|---:|
| SelfRAG-LLaMA2-7b | RAG | 52.8 | 59.2 | 39.0 | 53.2 |
| | CRAG | 59.8 | 74.1 | 75.6 | 68.6 |
| | Self-RAG | 54.9 | 81.2 | 72.4 | 67.3 |
| | Self-CRAG | 61.8 | 86.2 | 74.8 | 67.2 |
| LLaMA2-hf-7b | RAG | 50.5 | 44.9 | 48.9 | 43.4 |
| | CRAG | 54.9 | 47.7 | 59.5 | 53.7 |
| | Self-RAG（作者复现） | 29.0 | 32.2 | 0.7 | 23.9 |
| | Self-CRAG | 49.0 | 69.1 | 0.6 | 27.9 |

- 以 SelfRAG-LLaMA2-7b 为生成器，CRAG 比 RAG 在四项上分别高 7.0、14.9、36.6、15.4 个点；Self-CRAG 比 Self-RAG 在 PopQA、Bio、PubHealth 上高 6.9、5.0、2.4 个点，ARC 基本持平。
- 换成没学过反思 token 的 LLaMA2-hf-7b，Self-RAG 明显失效，CRAG 仍有提升。这说明 Self-RAG 依赖专门的指令微调，CRAG 换生成器更灵活。复现行与 Self-RAG 原论文数字不同，两者不能混比。
- 消融（PopQA）：三种动作去掉任何一种都会掉点；去掉精炼（59.8→54.2）和查询改写（→56.2）影响最大。

## 五、两种机制对照

| 维度 | Self-RAG | CRAG |
|---|---|---|
| 核心问题 | 何时检索；生成是否被证据支持 | 检索已经发生且可能全错时怎么办 |
| 判断由谁做 | 生成模型自己（反思 token） | 独立的轻量评估器 |
| 是否改生成器 | 要专门微调 | 不需要，任意生成器可接 |
| 粒度 | 每段生成前后都判断 | 每批检索结果判断一次，再逐条过滤 |
| 库内知识不够时 | 不处理（部分实验另加 Web 检索结果作输入） | Incorrect / Ambiguous 时显式改搜 Web |
| 组合 | 可作为 CRAG 的下游 | 叠在 Self-RAG 上即 Self-CRAG |

两者是互补的：Self-RAG 管「要不要取、取到的怎么用」，CRAG 管「取到的对不对」。生产系统常见的「先判断是否检索、再评估结果、不行就换来源」的控制流，可以看作这两轴的组合。

## 六、意义

- **检索从默认动作变成决策**：Self-RAG 表明检索与否、证据是否支持都可以让模型自己预测，并在推理时按任务调权重，不必为每种任务重训。
- **承认检索会失败**：CRAG 把「检索错了」当作常态处理，给出可插拔的纠错层；评估器与生成器解耦，使它能跟着更强的生成器升级。
- **为 Agentic RAG 铺路**：两篇都把决策点写进检索环，后续工作在此基础上进一步把决策权整体交给智能体。

## 七、局限与待核实

- **依赖蒸馏与微调**：Self-RAG 的反思能力来自 GPT-4 标注加专门微调；CRAG 的实验显示，换到普通生成器后 Self-RAG 几乎失效。
- **阈值靠经验**：CRAG 的上下阈值按数据集分别设定，换领域需要重新调；评估器训练数据也来自特定数据集。
- **Web 回退的风险**：Web 内容可能带来偏置与错误信息，论文只用「优先 Wikipedia」缓解，不是完整的内容安全方案。
- **评测年代较早**：两篇都基于 Llama 2 时代的 7B / 13B 模型与 Contriever 检索，在更强基座与检索器上的增益未在本篇核对。
- **待核实读图**：Self-RAG 的检索频率–准确率曲线、critique 权重对引用精度与 MAUVE 的权衡（Fig.3b–3c）只取论文定性描述，未读图取点。
- **未复现**：本篇未复现任何实验。
