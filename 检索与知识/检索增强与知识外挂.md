# 检索增强（RAG）与知识外挂

> **主要来源**：[Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks](https://arxiv.org/abs/2005.11401)（Lewis 等，v4，2021-04-12；首次提交 2020-05-22）；近年衔接：[A-RAG: Scaling Agentic Retrieval-Augmented Generation via Hierarchical Retrieval Interfaces](https://arxiv.org/abs/2602.03442)（Du 等，v1，2026-02-03）（截至 2026-02-03）
> **研究线**：架构思想（主：参数记忆与非参数记忆的混合、检索–生成接口与两种边际化）；AI Infra（辅：切块、FAISS 与 HNSW、索引热换）
> **范围与相邻笔记**：
> - ≠ [[长上下文位置编码与系统侧]]：长窗口解决一次读得多远，本篇讲库外索引如何按需取用。
> - ≠ [[SelfRAG与CorrectiveRAG]]、[[AgenticRAG分层检索接口]]、[[HippoRAG2与CatRAG]]、[[图谱检索GraphRAG]]：自适应检索、智能体式检索与图谱检索的专篇在那四篇，本篇只写经典一次取段的配方，并在第六节用一句话分别接到它们。
>
> **意义**：RAG 把预训练 seq2seq 的参数记忆，与可整库替换的文档稠密索引接到同一概率模型里：检索器提出 top-K 潜在证据，生成器条件生成，再按 Sequence 或 Token 两种方式对文档做边际化（摘要、§2）。开放域问答上，RAG-Sequence 在 Natural Questions 上 Exact Match 为 44.5，超过当时的 DPR 与 REALM（Table 1）；换掉 Wikipedia 索引即可更新世界知识，不必再训参数（§4.5）。

## 一、问题背景

大预训练语言模型能把事实压进参数，微调后在许多任务上很强，但 Lewis 等开篇列出三道硬伤（§1）：精确操纵与取用仍有限，知识密集型任务上常落后于带检索的专用架构；出处难给，预测依赖了哪段外部证据不好直接展示；世界知识更新难，改事实往往要再训，而检索索引可以整库替换。附加风险是纯生成容易幻觉。解法是混合记忆：参数记忆负责生成，非参数记忆负责可查、可换、可检查的证据通道（Figure 1）。

## 三、核心机制：经典 RAG 组件（§2）

1. **检索器**：DPR 双塔。文档与查询各过一个 BERT，相似度用内积，top-K 用最大内积搜索，可用近似近邻。文档编码器与索引在 RAG 微调中固定，只微调查询编码器与生成器，避免像 REALM 那样周期性重建索引（§2.4）。
2. **生成器**：BART-large。把输入与检索段落直接拼接后生成；作者把生成器权重称作参数记忆（§2.3）。
3. **非参数语料**：2018-12 的 Wikipedia dump，切成互不重叠的 100-word 块，约 21M 文档；嵌入后用 FAISS 建索引，并以 HNSW 做近似检索（§3）。
4. **训练**：对每条样本最小化负边际对数似然（§2.4）；训练时每个查询取 5 或 10 份文档（§4.5）。

## 四、核心机制：两种边际化（§2.1）

把检索文档当作潜变量，用 top-K 近似边际化，差别在「怎么边际化」：

1. **RAG-Sequence**：整段输出共用同一份文档。对 top-K 中的每份文档，生成器先给出在该文档条件下生成整段序列的概率，再按检索概率加权求和，即对文档做边际化。
2. **RAG-Token**：每个目标 token 可以来自不同文档。在每个位置，生成器对 top-K 中每份文档各给出下一个 token 的分布，按检索概率加权求和后再进入下一个位置；整段概率是各位置边际概率的乘积。

分类任务把类别当成长度 1 的序列时，二者等价（§2.1）。解码上，RAG-Token 的边际化转移概率可直接塞进标准 beam；RAG-Sequence 需对每个文档分别做 beam，再对候选做 Thorough 或 Fast Decoding 近似（§2.5）。

## 五、主要结果（§4）

1. **开放域问答**（Table 1）：RAG-Sequence 在 Natural Questions 上 Exact Match 为 44.5，RAG-Token 为 44.1；对照 DPR 41.5、REALM 40.4。即使正确答案不在任一检索文档里，RAG 在 Natural Questions 上仍可达 11.8% 准确，只匹配答案跨度的模型此处为 0。
2. **抽象式问答与 Jeopardy 问题生成**：Open MS-MARCO 上 RAG-Sequence 相对 BART，Bleu 与 Rouge-L 各高 2.6（Table 2）。人工评估里 RAG 更事实的比例为 42.7%，BART 更好仅 7.1%（Table 4，452 对）。
3. **FEVER 事实验证**：标签当单 token，不用证据检索监督；三分类距当时管线约 4.3% 内，二分类距给了 gold 证据的 RoBERTa 约 2.7% 内（§4.4）。
4. **消融**（Table 6）：可学检索优于冻结检索；BM25 在 FEVER 上更好，开放域问答上稠密可微检索更重要。
5. **索引热换**（§4.5）：用 2016-12 与 2018-12 两套 Wikipedia 索引，问 82 位更替的世界领导人「Who is {position}?」。索引与年份匹配时约 70%（2016）与 68%（2018）正确；错配时约 12% 与 4%。结论是只换非参数记忆即可更新世界知识。

## 六、近年衔接：从一次取段到智能体式与图谱检索

经典 RAG 的检索决策在模型之外：算法一次取出 top-K，再拼进生成器。后续工作在「是否检索、结果是否可信、图结构与整库主题、检索工具化」上分岔，已有四篇专文，本篇不重写：

1. **自适应检索与纠错**：[[SelfRAG与CorrectiveRAG]] 在固定 top-K 环上加入「是否检索」与「结果是否可信」两层判断。
2. **智能体式检索**：[[AgenticRAG分层检索接口]] 所写的 A-RAG（[arXiv:2602.03442](https://arxiv.org/abs/2602.03442)，v1，2026-02-03）把关键词搜索、语义搜索与整块阅读做成三个工具，让模型自己跨多种粒度编排检索，而不是一次取段或预设工作流。
3. **记忆式图检索**：[[HippoRAG2与CatRAG]] 把 RAG 当成非参数持续学习，在开放知识图上做联想检索。
4. **图谱全局问答**：[[图谱检索GraphRAG]] 针对向量检索答不了的整库主题问题，用社区摘要与增量图索引。

## 七、意义

1. **知识更新改成数据面操作**：索引热换把「再训参数」换成「换 dump / 换索引」。
2. **生成接口而不只是检索超参**：Sequence 与 Token 两种边际化决定「一文档撑全文」还是「逐 token 换文档」。
3. **外挂索引是刻意架构选择**：不是长上下文不够时的失败兜底；短上下文加强检索同样成立。
