## 一、动机：为何「参数内知识」不够

### 1.1 参数记忆的三道硬伤（Lewis 摘要 / §1）

大预训练 LM 能把事实知识压进参数（Petroni et al. 等；文中 [47][51][52]），微调后在许多 NLP 任务上很强。但 Lewis et al. 开篇把局限写死：

1. **精确操纵与取用**仍有限——知识密集型任务上，纯参数模型常落后于带检索的专用架构。
2. **出处（provenance）**难给——预测依赖了哪段外部证据，参数模型不好直接展示。
3. **世界知识更新**难——改事实往往要再训；而检索索引可以整库替换。

附加风险：纯生成容易 **幻觉**（文中引 Marcus [38]）。

### 1.2 架构抓手：参数记忆 × 非参数记忆

作者把解法收成一条混合记忆配方（Figure 1）：

`
输入 x
 → 查询编码器 q(x)
 → 非参数记忆：文档稠密索引（MIPS / top-K 得 z）
 → 生成器 pθ(y | x, z, …)（参数记忆）
 → 对潜在文档 z 做边际化，得到 p(y|x)
`

关键对比：

| 记忆类型 | 本卡中的实现 | 可改什么 |
|----------|--------------|----------|
| **参数（parametric）** | 预训练 seq2seq（BART-large，约 400M） | 权重；改知识需再训 |
| **非参数（non-parametric）** | Wikipedia 稠密向量索引 + 神经检索器 | **热替换整库**（§4.5 index hot-swapping） |

REALM / ORQA 等已把可微检索接到 **抽取式** QA；RAG 的增量是：把同一套混合记忆接到 **通用 seq2seq 生成**，并可在任意 seq2seq 任务上端到端微调（摘要、§1）。

### 1.3 与 [[长上下文位置编码与系统侧]] 长上下文的划界（本卡主轴）

| | **[[长上下文位置编码与系统侧]] 长上下文** | **B-6 RAG / 知识外挂** |
|--|-------------------|------------------------|
| 知识放哪 | 同一前向 / 同一会话 KV 里「读完」 | **库外索引**，按需检索再条件生成 |
| 扩容方式 | 位置编码外推、稀疏/高效注意力、PagedAttention 等 | 切块、嵌入、ANN 索引、检索器–生成器接口 |
| 更新成本 | 改上下文内容；窗口与 KV 显存是瓶颈 | **换索引 / 改文档**即可更新世界知识（Lewis §4.5） |
| 失败模式 | 窗口不够、lost-in-middle、KV 爆显存 | 检索 miss、错误证据、边际化不当、索引陈旧 |

[[长上下文位置编码与系统侧]] 笔记已写：窗口不够时「只能靠摘要或检索外挂——外挂会丢细节、引入延迟与一致性风险」。本卡反过来写清：**外挂索引是刻意架构选择**，不是长上下文的失败兜底；二者互补，企业落地与智能体工具环常走「检索 → 生成」。

## 二、经典 RAG（Lewis et al.）：组件与两种边际化

### 2.1 组件拆解（§2）

**（1）检索器 $p_\eta(z|x)$：DPR 双塔**

- $d(z)=\mathrm{BERT}_d(z)$，$q(x)=\mathrm{BERT}_q(x)$
- $p_\eta(z|x)\propto\exp\big(d(z)^\top q(x)\big)$
- top-$K$ = **MIPS**（可用近似近邻，亚线性时间）
- 初始化：DPR 在 TriviaQA / Natural Questions 上训过的双塔；文档编码器与索引在 RAG 微调中**固定**，只微调查询编码器 $\mathrm{BERT}_q$ 与生成器（§2.4）——避免像 REALM 那样周期性重建索引。

**（2）生成器 $p_\theta(y_i|x,z,y_{<i})$：BART-large**

- 把输入 $x$ 与检索段落 $z$ **直接拼接**后喂给 BART（§2.3）。
- 作者称 $\theta$ 为参数记忆。

**（3）非参数语料**

- 单一 Wikipedia dump（2018-12，与 Lee / Karpukhin 一致）。
- 每篇切成互不重叠的 **100-word** 块 → 约 **21M** 文档（§3）。
- 文档嵌入后，用 **FAISS** 建 MIPS 索引，并以 **HNSW** 做近似检索（§3；引 Johnson et al. FAISS [23]、Malkov & Yashunin HNSW [37]）。

训练时对每个 query 取 top $k\in\{5,10\}$；测试 $k$ 用 dev 选。优化：对每条 $(x_j,y_j)$ 最小化负边际对数似然，Adam（§2.4）。

### 2.2 RAG-Sequence vs RAG-Token（§2.1）

把检索文档当作潜变量，用 top-$K$ 近似边际化——**怎么边际化**定义了两种模型：

**RAG-Sequence**（整段输出共用同一文档）：

$$
p_{\mathrm{RAG\text{-}Seq}}(y|x)\approx\sum_{z\in\mathrm{top\text{-}k}(p(\cdot|x))} p_\eta(z|x)\,p_\theta(y|x,z)
=\sum_{z} p_\eta(z|x)\prod_{i=1}^{N} p_\theta(y_i|x,z,y_{<i})
$$

**RAG-Token**（每个目标 token 可对应不同文档）：

$$
p_{\mathrm{RAG\text{-}Tok}}(y|x)\approx\prod_{i=1}^{N}\sum_{z\in\mathrm{top\text{-}k}(p(\cdot|x))} p_\eta(z|x)\,p_\theta(y_i|x,z,y_{<i})
$$

分类任务把类别当长度 1 的序列时，二者等价（§2.1）。

**解码差异（§2.5）**

- **RAG-Token**：边际化后的转移概率可塞进标准 beam。
- **RAG-Sequence**：似然不拆成常规 per-token 形式；需对每个 $z$ 分别 beam，再对候选假设做 Thorough / Fast Decoding 近似。

### 2.3 任务面与主结果（只报原文数字）

知识密集型设定：人类没有外部知识源时**不合理**指望会做的任务（§1）。

| 任务族 | 设定要点 | 文中结论（摘要 / §4） |
|--------|----------|----------------------|
| Open-domain QA | NQ / TQA / WQ / CT；报 Exact Match | Table 1：RAG 在四套上 SOTA（TQA 仅在与 T5 可比的 Wiki split 上）；RAG-Seq NQ **44.5**，RAG-Tok **44.1**（对照 DPR 41.5、REALM 40.4） |
| 抽象式 QA | Open MS-MARCO（不用官方 gold passages） | Table 2：RAG-Seq 相对 BART +2.6 Bleu / +2.6 Rouge-L |
| Jeopardy 问题生成 | SearchQA splits；Q-BLEU-1 + 人工成对评估 | RAG 更事实、更具体：人工评估中 RAG 更事实 **42.7%** vs BART 更好仅 **7.1%**（Table 4，452 对） |
| FEVER 事实验证 | 标签当单 token；**不用**证据检索监督 | 3-way 距当时管线 SOTA 约 **4.3%** 内；2-way 距「给 gold 证据的 RoBERTa」约 **2.7%** 内（§4.4） |

额外机制观察（§4）：

- 即使答案不在任一检索文档中，RAG 在 NQ 上仍可达 **11.8%** 准确——抽取式模型此处为 0。
- Figure 2：RAG-Token 的文档后验可随 token 切换（例：Hemingway → 不同文档支撑不同书名），体现「多文档内容拼合」。
- 多样性（Table 5）：RAG-Seq / RAG-Tok 的 distinct trigram 比率均显著高于纯 BART，无需专门多样性解码。

### 2.4 消融与「可热换知识」（§4.5）

Table 6（dev）：

- **冻结检索器** vs 可学检索：可学检索在各任务上更好。
- **BM25** 替换稠密检索：FEVER 上 BM25 更好（实体密集、词重叠友好）；开放域 QA 上稠密可微检索关键重要。

**Index hot-swapping（架构核心卖点）**：用 2016-12 vs 2018-12 Wikipedia 索引，对 82 位更替的世界领导人问「Who is {position}?」：

- 索引与年份匹配：约 **70%**（2016）/ **68%**（2018）正确；
- 错配：约 **12%** / **4%**。

结论（原文）：**只换非参数记忆即可更新世界知识**，不必再训参数。

测试时调大 $K$：RAG-Seq 的 NQ EM 随 $K$ 单调升；RAG-Tok 约在 $K=10$ 见峰（Figure 3 叙述）。

## 三、检索–生成接口（架构思想主线）

### 3.1 接口合同：检索器产出「潜在证据」，生成器消费「条件上下文」

Lewis 把接口写成概率图，而不是「先搜再拼 prompt」的脚本：

1. **查询侧**：$x\mapsto q(x)$（可微调）。
2. **索引侧**：固定 $d(z)$ + ANN → top-$K$ 候选与 $p_\eta(z|x)$。
3. **条件生成**：$z$ 与 $x$ 拼接进 seq2seq；训练目标是 $-\log p(y|x)$ 的 top-$K$ 边际近似。
4. **边际化策略**决定「一文档撑全文」还是「逐 token 换文档」——这是**生成接口**，不只是检索超参。

相对「retrieve-and-extract」：生成允许非逐字命中的线索仍贡献正确答；相对「closed-book」：检索提供可检查、可替换的证据通道。

### 3.2 端到端信号 vs 检索监督

FEVER 实验刻意**不用**中间证据监督（§3.4）：许多真实场景没有「该检索哪句」的标签。RAG 用下游 $y$ 的似然反传（经 top-$K$ 近似）拉动查询编码器——这是「检索为任务服务」的接口，而不是先训一个通用 IR 再冻结。

同时作者诚实保留：检索器初始化仍来自 **有检索监督** 的 DPR（NQ/TQA）。可学检索是在该先验上的任务适应，不是从零发明检索（§4.1、Table 6）。

### 3.3 参数 / 非参数如何「分工」

Jeopardy 例（§4.3）：非参数后验在书名关键 token 上尖峰，随后变平；纯 BART 能续完书名——说明**非参数负责导航到正确事实邻域，参数负责补全已内化的表面形式**。这是混合记忆的设计直觉，不是「检索替代参数」或「参数替代检索」。

## 四、AI Infra 辅线：向量库、索引与 serving 交界

本卡 Infra 只跟 Lewis 文中实际用到的栈 + 与已有笔记的交界；**不**编造当代商业向量库对比表。

### 4.1 经典栈（论文落地）

| 层 | Lewis 用法 | Infra 含义 |
|----|------------|------------|
| 切块 | 100-word 互不重叠块，21M 条 | 召回粒度 vs 上下文长度；切坏则生成再强也补不回 |
| 嵌入 | BERT 双塔文档/查询向量 | 文档塔固定 → **索引可预计算、可热换** |
| 索引 | FAISS MIPS + HNSW | ANN：召回质量 / 延迟 / 内存折中（文中作工程事实引用，未展开调参表） |
| 训练时检索 | top $k\in\{5,10\}$ | $K$ 同时影响梯度估计方差与步时延 |
| 解码 | Seq 的 Thorough vs Fast | 多文档 beam 的前向次数是 **serving 成本** 一阶项 |

Hugging Face Transformers 示例与 demo 链接见论文脚注 1（§1）：作者把「可复现配方」推到开源库，而非仅报告分。

### 4.2 与 [[AI基础设施总览]] / [[长上下文位置编码与系统侧]] 的接口（只标边界）

- **[[AI基础设施总览]]**：训练并行、FlashAttention、PagedAttention、量化——管的是**生成器侧**算力与 KV。RAG 额外引入：**索引内存、ANN 延迟、检索–生成流水线气泡**（检索未完成则生成空转，或反过来）。
- **[[长上下文位置编码与系统侧]]**：长窗口让「一次塞更多检索结果」变便宜，但**不能**取消索引——库规模可远超任何窗口；热更新仍靠非参数侧。
- 工程直觉（据 Lewis 机制，非新产品评测）：固定文档编码器 = 用「重建索引成本」换「可热换与可扩展」；若像 REALM 训文档塔，Infra 账单含周期性 re-embed + re-index。

### 4.3 索引热换作为 Infra 能力，不只是论文技巧

§4.5 的领导人实验把「知识更新」从**训练问题**改写成**数据面运维问题**：换 dump / 换索引 → 行为变。运维面需另卡深挖的（本卡只列议题，不编造 SLA）：索引版本、一致性、增量更新、embedding 模型漂移导致旧索引失效等——**待核实**当代实践文献。

## 五、误区（跟读时主动避开）

1. **「RAG = 把检索结果塞进超长上下文」**
 那是 [[长上下文位置编码与系统侧]] 的窗口问题。RAG 的核心是**外挂非参数记忆 + 对 $z$ 的概率边际化**；可以短上下文 + 强检索。

2. **「有检索就不会幻觉」**
 Lewis 主张相对纯 BART 更事实、可检查；Broader Impact 仍警告：外部库本身可有偏见与错误，RAG 也可被滥用生成误导内容。

3. **「稠密检索永远优于 BM25」**
 Table 6：FEVER 上 BM25 更好。任务实体密度与监督信号决定选型，不是口号。

4. **「必须端到端更新文档编码器」**
 RAG 固定 $\mathrm{BERT}_d$ 仍达强结果；REALM 式周期性索引更新是另一条 Infra 账单，不是本配方的必要条件（§2.4）。

5. **「开放域 QA 只能抽取 span」**
 Table 1：无约束生成可超强抽取管线；线索在文档中但答案字面不在时，生成仍可边际化到正确答。

6. **「换代产品清单可以凭记忆写进笔记」**
 Agentic / Graph RAG **待核实**；禁止编造。工具协议细节归 [[智能体工具与长程任务]] / [[智能体工具与长程任务]]。

7. **「检索监督可有可无、效果一样」**
 微调阶段可不对 $z$ 直接监督，但初始化与消融都表明：**可学检索 vs 冻结 / BM25** 有系统性差别（Table 6）。

8. **「索引热换 = 无需任何版本治理」**
 论文只证明可行性；错配年份准确率崩溃（12% / 4%）本身说明**版本对齐**是一阶问题。

## 八、一句话收束

RAG 把「会说」的参数 seq2seq 与「可查、可换、可检查」的非参数文档索引接在同一概率模型里：检索器提出 top-$K$ 潜在证据，生成器条件生成，再按 Sequence / Token 两种方式边际化——从而在开放域 QA 与知识密集型生成上超越纯参数基线，并用**索引热换**把世界知识更新从再训练改成数据面操作。与 [[长上下文位置编码与系统侧]] 的分工是：**长上下文解决「一次读得多远」；RAG 解决「知识放库外如何按需取用」**。
